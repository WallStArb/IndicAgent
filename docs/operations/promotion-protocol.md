# Alpha Promotion Protocol: From Swarm (Path B) to Kernel (Path A)

**Version:** 2.8
**Status:** current
**Last Updated:** 2026-05-02

## 1. Objective
To maintain the integrity of our real-time trading kernel by ensuring that only statistically validated, performant, and audit-ready intelligence ("Alphas") are promoted from the experimental swarm (Path B) to the production kernel (Path A).

## 2. The Promotion Ceremony (Workflow)

### Step A: The Audit (Automated)
The `AlphaPromotionWorker` (scripts/alpha_promotion.py) runs daily via CI/CD. It:
1. Queries the `alpha_multiplier_shadow` table for the last 14 days.
2. Calculates the **Pearson Correlation (ρ)** between the agent's `multiplier` and the realized `pnl_r` from the `signal_ledger`.
3. If `ρ > 0.4`, it appends the agent to `docs/reports/promotion_candidates.md`.

### Step B: The Compilation (Manual -> Automated Review)
Once a candidate appears in `promotion_candidates.md`:
1. **Researcher Audit:** A human engineer reviews the `metadata` (reasoning) generated by the LLM-Swarm.
2. **Distillation:** The engineer distills the "reasoning" into a deterministic, high-performance logic block (the "Kernel").
3. **Drafting:** The engineer implements this logic in a new `DeterministicContributor` module.

### Step C: Promotion (Governance)
1. **Validation:** The new deterministic module is unit-tested against historical data to ensure `realized_pnl` matches the theoretical swarm performance.
2. **Registration:** Update `config/intelligence_contributors.json` to set `is_production_ready: true`.
3. **Cleanup:** Remove the experimental Swarm agent from the config or downgrade its logging verbosity to save resources.

## 3. CI/CD Integration
- Any change to `is_production_ready: true` in `config/intelligence_contributors.json` requires a CI job to run the `AlphaPromotionWorker` validation check.
- If the correlation metric is not found in the recent `promotion_candidates.md`, the build fails.

## 4. Rollback Policy
If an Alpha's performance degrades post-promotion (monitored by the `ExecutionQualityObserver`), the CI/CD pipeline triggers an automated revert of the `config/intelligence_contributors.json` status to `false` and alerts the team via Slack/PagerDuty.
