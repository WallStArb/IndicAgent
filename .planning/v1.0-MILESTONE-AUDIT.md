## Integration Issues

### 1. weight_updater.py — No Production Trigger (Non-blocking)

`src/intelligence/weight_updater.py::run_weight_update(db_manager)` is never called by any service, cron job, or systemd timer. CIS weights will remain at bootstrap (`version=0`, designed weights from migration 012) indefinitely.

- **Impact:** CISScorer always uses BOOTSTRAP_WEIGHTS. The learning loop (50-sample threshold → blended weights, 100-sample threshold → learned weights) cannot activate.
- **Not a blocker:** CISScorer still fires correct signals using designed weights. The adaptive learning is a future enhancement, not required for initial operation.
- **Fix:** Add a systemd timer or service task that calls `run_weight_update()` on a schedule (e.g., daily).

### 2. Backfill SQL Stale — Phase 7 CIS Columns Missing (Non-blocking)

`production/scripts/historical_backfill.py:_INSERT_SYNC_SQL` has 24 columns (Phase 2 era). Migration 011 added `cis_score`, `bucket_scores`, `weights_version`, `signal_quality` (nullable). Future backfill runs produce signals with NULL for all CIS columns. These signals cannot feed `weight_updater` training (which requires `signal_quality IS NOT NULL`).

- **Impact:** Historical signals from backfill cannot train CIS weights. Since weight_updater also lacks a trigger, this is currently moot.
- **Not a blocking data issue:** All columns are nullable, INSERT will not fail.
- **Fix:** Update `_INSERT_SYNC_SQL` to include CIS columns with NULL defaults.

### 3. Legacy intelligence Table Write (Tech Debt)

`market_analysis_service._persist_intelligence()` (line 459) writes to the legacy `intelligence` table from migration 001. No API route or service reads this table. On production DBs that only ran migrations 009+, this write logs a warning every bar.

- **Not a data integrity issue:** The canonical persistence path is `feature_writer_service → intelligence_features`.
- **Fix:** Remove `_persist_intelligence()` call from `_run_analysis_loop()`.
