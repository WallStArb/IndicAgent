<objective>
Collect a `factor_scores` audit dict in every I7 setup plugin before its confidence composite, thread it through to the emitted signal, AND capture the `capture_signal_features()` return into `context_features` on the same emitted signal. `factor_scores` is the persisted pre-composite factor breakdown that v2.11 APR ML weight optimization regresses against `counterfactual_pnl_r`; `context_features` is the persisted top-level feature snapshot promoted out of the legacy `_shadow` dict. Without factor_scores, factor contributions die at function return and weight learning is impossible. Without the context_features callsite update, non-Phase-119 plugins emit the `{}` sentinel instead of real snapshot data, violating the locked decision (CONTEXT.md: "Every I7 plugin calling capture_signal_features(): capture return value into signal['context_features']").

Purpose: Complete ECL-03 — "all 37 I7 plugins collect factor_scores dict before compositing" — and finish the context_features promotion for every non-Phase-119 plugin touched here. (TIER_I7 has 37 entries; 2 are aggregators which do not composite per-setup factors, so the 35 setup plugins are in scope. Confirm aggregator handling in Task 3.)
Output: factor_scores dict added to every setup plugin's compute_full and passed to signal construction; context_features captured and passed to signal construction in every plugin that calls capture_signal_features(); test assertion that BOTH factor_scores and context_features are populated.

Depends on Plan 01: make_signal_from_frame must already accept the factor_scores AND context_features params (added in 123-01 Task 1). This plan only populates and passes them. Plan 01 applied the context_features callsite to the Phase-119 plugins it touched; this plan applies it to the remaining setup plugins so no setup plugin emits the `{}` sentinel.
</objective>
