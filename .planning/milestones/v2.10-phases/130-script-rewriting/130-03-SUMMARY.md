# Phase 130 Plan 03: Live Write-Path Writers — G0 Grouping + 3-Table Schema

Rewrote signal_writer and lifecycle_writer onto the 3-table signal architecture. signal_writer implements G0 grouping (group by signal_id, one signal_events row + N trade_frames rows per group, single asyncpg transaction). lifecycle_writer routes status transitions to signal_events.status and activation/exit metadata to trade_frames.frame_details. Both migrate their hardcoded batch/flush constants to APR.

## What Was Done

### Task 1: signal_writer G0 Grouping

Rewrote `services/signal_writer.py` to implement the G0 contract from Phase 128 ADR:

**G0 grouping logic** (`_payload_to_grouped_rows`):
- `groups = defaultdict(list)` keyed by `signal_id`
- For each unique `signal_id`: first signal in group provides detection-layer fields for one `signal_events` row; each signal in group provides hypothesis-layer fields for one `trade_frames` row (one per `entry_type`)
- Returns `list[tuple[signal_event_dict, list[trade_frame_dict]]]`

**signal_events detection row**:
- `direction`: converted from int (1/-1) to text "long"/"short" before INSERT (Pitfall 6)
- `SIGNAL_SCHEMA_VERSION`: passed as int constant via repository (Pitfall 7 - no `str()`)
- `factor_scores`, `context_features` (ECL Phase 123 fields) included as dict (asyncpg JSONB pass-through)
- `concurrent_signal_count`, `concurrent_plugins`: NULL per D-08 / Pitfall 5 (v2.11 populates)

**trade_frames hypothesis row**:
- `stop_basis`, `stop_type_col`, `structural_stop_distance_atr`, `adaptive_buffer_mult`, `stop_structure_age_bars`, `entry_zone_low/high` go into `frame_details` JSONB
- `target_price`: first element of `targets` list (single float8 in schema)
- `frame_id`: deterministic uuid5 generated by `SignalEventsRepository.insert_signal_with_frames`
- `counterfactual_pnl_r`: NULL (v2.11 CounterfactualTracker populates)

**APR loading** (D-12):
- `ConfigService` instantiated in `_setup()` sharing the `DatabaseManager` pool
- `feature.signal_writer.batch_size` (100), `flush_interval_secs` (5.0), `max_buffer_size` (10000)
- Instance attrs set to shadow BaseWriter class attrs; `_overflow_threshold` also synced

**Removed**: class-level `BATCH_SIZE`, `FLUSH_INTERVAL_SECS`, `MAX_BUFFER_SIZE` constants. No `SignalLedgerRepository`, `LedgerEntry`, or `signal_ledger` references. Module docstring updated.

### Task 2: lifecycle_writer 3-Table Schema

Rewrote `services/lifecycle_writer.py` to route all lifecycle transitions to the 3-table schema:

**Activation transitions** (`_flush_activation_items`):
1. `update_signal_status(signal_id, "active")` - sets signal_events.status
2. `update_frame_details(signal_id, meta)` - merges activation fields into trade_frames.frame_details JSONB:
   - `activated_at` (format_iso_ts-encoded)
   - `activation_price`, `zone_entry_pct`, `bars_to_activation`
   - `regime_at_activation` (D-08 new field: HMM regime state at activation time)

**Exit transitions** (`_flush_exit_items`):
1. `update_signal_status(signal_id, status)` - sets signal_events.status to "expired"/"stopped"/etc.
2. `update_frame_details(signal_id, meta)` - merges exit fields: `exit_at`, `exit_price`, `exit_reason`, `pnl_r`, `pnl_ticks`, `pnl_dollars`, `mae`, `mfe`, `bars_in_trade`, `outcome`

**Other transitions** (via `batch_execute`):
- `chandelier_update`, `mae_mfe_update`, `shadow_outcome`, `market_resolution` route through `self._repo.batch_execute(ttype, items)` which delegates to `update_frame_details` internally

**Removed**: `_EXIT_IDEMPOTENT_SQL` (targeted `signal_outcomes`), `_exit_to_params()`, `_flush_exit_items` old implementation. No `SignalLedgerRepository`, `signal_outcomes`, or `signal_ledger` references. Module docstring updated.

**APR loading** (D-12):
- `feature.lifecycle_writer.batch_size` (100), `flush_interval_secs` (5.0), `max_buffer_size` (10000)
- Same ConfigService pattern as signal_writer
