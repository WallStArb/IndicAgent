Run segmented fire-rate diagnostic SQL via psql:

1. Execute D6 Part 2 SQL:
   SELECT
       setup_plugin,
       symbol,
       tf,
       regime_context,
       COUNT(*) AS signal_count,
       (SELECT COUNT(*) FROM intelligence_features f WHERE f.symbol = s.symbol AND f.tf = s.tf AND f.ts >= NOW() - INTERVAL '7 days') AS bar_count,
       ROUND(100.0 * COUNT(*)::numeric / NULLIF((SELECT COUNT(*) FROM intelligence_features f WHERE f.symbol = s.symbol AND f.tf = s.tf AND f.ts >= NOW() - INTERVAL '7 days'), 0), 2) AS segment_fire_rate_pct
   FROM signal_ledger s
   WHERE ts >= NOW() - INTERVAL '7 days'
     AND setup_plugin IN (
       'trad_TrendFollowing',
       'trad_OFIContinuation',
       'trad_PatternCompletion',
       'trad_LiquiditySweepReclaim',
       'trad_AnchoredVWAPReversion'
     )
   GROUP BY setup_plugin, symbol, tf, regime_context
   HAVING COUNT(*) > 10
   ORDER BY segment_fire_rate_pct DESC
   LIMIT 20;

2. Capture top 20 segments to fire-rate report

3. Verify no segment > ~5% (hotspot = residual non-event contamination)

4. Note: If insufficient data (< 100 signals per plugin), document as "insufficient data for segmented analysis"
