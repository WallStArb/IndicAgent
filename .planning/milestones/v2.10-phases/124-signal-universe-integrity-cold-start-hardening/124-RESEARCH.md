## Architecture Patterns

### Plugin `compute_full()` Contract

**What:** All 5 plugins currently implement `compute_full(self, frames: dict[str, Any]) -> dict[str, Any]`. The `frames` dict contains the current bar's data across tiers (keys: `"main"`, `"i1"`, `"i2"`, ..., `"i6"`, `"__symbol__"`, `"__timeframe__"`).

**When to use:** Every I7 plugin receives this signature. The function must return a signal dict via `make_signal_from_frame()` or `no_signal()`.

**Verified current behavior (all 5 plugins):**


**Key insight:** The `frames` dict contains only the current bar. Any lookback (pullback detection, departure window, pattern instance tracking) must be managed via plugin state (`self._state`) using the `Parallel dicts → dataclass` pattern.

### Structural Onset Pattern (Reference Implementation)

**What:** Well-behaved plugins (SqueezeExpansion ~0.3% fire rate, SupplyDemand ~0.1%) gate on specific structural events that fire once per occurrence, not on broad continuous states.

**When to use:** All 5 over-firing plugins must adopt this pattern.

**Example (SqueezeExpansion — verified reference):**

```python
# Source: /home/bg/dev/indicagent/src/intelligence/trading/squeeze_expansion.py
def compute_full(self, frames: dict[str, Any]) -> dict[str, Any]:
    result = extract_ohlcv(frames, self.min_lookback)
    if result is None:
        return no_signal()

    features = {...}  # Merge i1-i6

    # STRUCTURAL EVENT GATE: squeeze must have JUST released (rising edge)
    squeeze_fired = features.get("squeeze_fired", 0.0)
    squeeze_active = features.get("squeeze_active", 0.0)
    if squeeze_fired != 1.0 or squeeze_active != 0.0:  # Binary event, not continuous
        return no_signal()

    # STRUCTURAL EVENT GATE: volume expansion (rising ratio)
    df = frames.get("main")
    volume = df["volume"].to_numpy(dtype=float)
    current_volume = float(volume[-1])
    volume_sma_20 = features.get("volume_sma_20")
    if volume_sma_20 is None or volume_sma_20 <= 0:
        # Fallback computation
        if len(volume) >= 20:
            volume_sma_20 = float(np.mean(volume[-20:]))
    volume_ratio = current_volume / volume_sma_20
    if volume_ratio <= 1.3:  # Threshold on structural event, not "above average"
        return no_signal()

    # Context filter (NOT the trigger): regime gate
    vol_regime = int(features.get("garch_vol_regime", 1))
    if vol_regime == 3:  # Extreme regime — context filter
        return no_signal()

    # Direction derived from structure
    momentum_bias = features.get("momentum_bias", 0.0)
    bb_middle = features.get("bb_20_2_mid", 0.0)
    if momentum_bias != 0.0:
        direction = 1 if momentum_bias > 0 else -1
    elif bb_middle > 0:
        direction = 1 if close[-1] > bb_middle else -1

    # Confidence scores derived from structural magnitude
    squeeze_bars = features.get("squeeze_bars", 0.0)
    squeeze_bars_score = clamp01(squeeze_bars / 30.0)  # Duration = magnitude
    vol_expansion_score = clamp01((volume_ratio - 1.0) / 2.0)  # Excess over threshold
    momentum_score = clamp01(abs(momentum_bias))

    raw_conf = 0.35*squeeze_bars_score + 0.35*vol_expansion_score + 0.30*momentum_score

    return make_signal_from_frame(...)  # No dedup needed — structural event is unique
```

**Pattern:**
1. **Structural trigger first:** Binary event (`squeeze_fired == 1.0`) that fires once per occurrence
2. **Magnitude gates:** Threshold on structural metric (`volume_ratio >= 1.3`)
3. **Context filters after:** Regime, trend alignment as filters (not triggers)
4. **No dedup needed:** Structural event is naturally unique; if dedup required, use `deduplicate_event()` with structural anchor (level/pattern ID)

### Parallel Dicts → Dataclass Pattern (State Management)

**What:** When a class has 3+ `dict[str, X]` attributes all keyed by the same ID, consolidate into `dict[str, MyState]` where `MyState` is a `@dataclass`. Use a `_state(key)` factory method for lazy init.

**When to use:** Plugin needs rolling lookback buffers or instance tracking (TrendFollowing pullback history, OFI streak state, PatternCompletion instance registry).

**Example (PatternCompletion instance tracking):**

```python
from dataclasses import dataclass, field
from typing import Any

@dataclass
class PatternInstanceState:
    """State for a single pattern instance."""
    pattern_name: str
    direction: int
    structural_anchor: float | int  # neckline for DT/DB, apex_bars for triangle
    fired_bars: int = 0  # Bars since fire (for re-arm logic)

class PatternCompletionPlugin:
    _state: dict = field(default_factory=dict)
    _instances: dict[str, PatternInstanceState] = field(default_factory=dict)

    def _get_instance_state(self, instance_id: str) -> PatternInstanceState:
        """Factory for lazy init of instance state."""
        if instance_id not in self._instances:
            self._instances[instance_id] = PatternInstanceState(
                pattern_name="", direction=0, structural_anchor=0
            )
        return self._instances[instance_id]

    def compute_full(self, frames: dict[str, Any]) -> dict[str, Any]:
        # ... pattern detection logic ...

        # Instance ID from structural anchor
        if pattern_name in ("double_top", "double_bottom"):
            anchor = round(float(features.get("dt_db_neckline", 0.0)), 4)
        else:
            anchor = int(features.get("tri_apex_bars", 0))
        instance_id = f"{symbol}_{tf}_{pattern_name}_{anchor}"

        # Check if this instance already fired
        instance = self._get_instance_state(instance_id)
        if instance.fired_bars > 0:
            return no_signal()  # Already fired this instance

        # Fire signal
        signal = make_signal_from_frame(...)
        instance.fired_bars = 1  # Mark as fired
        return signal
```

### Anti-Patterns to Avoid

- **Anti-pattern:** Continuous metric as primary trigger (e.g., `abs(trend_regime) >= 0.5` fires every bar while regime persists)
  - **Why it's bad:** Firing on state, not event; ML learns from non-events; raw signal universe contaminated
  - **Fix:** Demote to context filter, re-anchor trigger to structural event

- **Anti-pattern:** Confidence threshold as trigger (e.g., `confidence > 0.70` on pattern completion)
  - **Why it's bad:** Confidence is a downstream composite, not the structural event
  - **Fix:** Trigger on structural completion (target reached / neckline break)

- **Anti-pattern:** Flag that stays hot (e.g., `sweep_reclaimed == 1.0` persists for multiple bars)
  - **Why it's bad:** Fires repeatedly on same structural level
  - **Fix:** Rising-edge detection with `deduplicate_event()` using structural anchor (sweep level + type)

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Plugin state management | Custom `dict[str, dict]` sprawl | `Parallel dicts → dataclass` pattern | Co-located memory, impossible mismatched state |
| Event deduplication | Custom `frozenset` or `list` tracking | `state_utils.deduplicate_event()` | Handles re-arm logic, structural anchors |
| Consecutive state counting | Custom counter with reset logic | `state_utils.track_consecutive_state()` | Handles sign changes, windowing |
| Confidence composition | Ad-hoc weighted sums | `confidence_utils.compose_confidence()` | Clamps to [0.0, 0.95], rounds to 4dp |
| Signal framing | Manual trade dict construction | `trade_framer.frame_trade()` | Canonical stop hierarchy, zone correction |
| ATR-based distances | Recompute ATR in plugin | `atr_utils.get_atr_with_floor_from_frames()` | Null-safe, cached I1 value |

**Key insight:** The codebase has centralized utilities for all common plugin operations. Hand-rolling custom versions introduces drift and bugs.

## Common Pitfalls

### Pitfall 1: Confusing Cold-Start NULL with Genuine Neutral 0.0

**What goes wrong:** Migration or code treats `NULL` and `0.0` as equivalent, using `COALESCE(ctf_score, 0.0)` or `WHERE ctf_score IS NULL OR ctf_score = 0.0`.

**Why it happens:** Pre-Phase-123 code used 0.0 as "no data" sentinel; Phase 123 established semantic distinction (NULL = cold-start, 0.0 = genuine neutral).

**How to avoid:**
- Migration backfill: Use `NULLIF(cross_timeframe_context->>'ctf_score','')::double precision` to handle empty strings as NULL
- ON CONFLICT guard: `WHERE intelligence_features.ctf_score IS NULL` only — never include `OR = 0.0`
- Code readers: Check `ctf_score is None` (Python) or `ctf_score IS NULL` (SQL), not `ctf_score == 0.0`

**Warning signs:** Code uses `or 0.0` fallbacks, SQL uses `COALESCE(ctf_score, 0.0)`, or test mocks default ctf_score to 0.0 instead of None.

### Pitfall 2: JSONB Null vs Missing Key vs Empty String

**What goes wrong:** Migration assumes all three JSONB states are equivalent, but they have different semantics.

**Why it happens:** PostgreSQL JSONB `->>'key'` returns NULL for both missing key and `null` value; empty string is distinct.

**How to avoid:**
```sql
-- Correct backfill pattern handles all three cases
UPDATE intelligence_features
SET ctf_score = NULLIF(cross_timeframe_context->>'ctf_score','')::double precision
WHERE ctf_score IS NULL
  AND cross_timeframe_context ? 'ctf_score';  -- Key exists (handles missing key)

-- Strip all four keys in same migration
UPDATE intelligence_features
SET cross_timeframe_context = cross_timeframe_context - (
    ARRAY['ctf_score', 'ctf_trend_alignment', 'ctf_structure_alignment', 'ctf_regime_agreement']
)
WHERE cross_timeframe_context ? 'ctf_score';  -- Only if keys present
```

**Warning signs:** Migration doesn't check for key existence before backfill, or doesn't strip keys after promoting.

### Pitfall 3: Reading CTF from JSONB After Column Promotion

**What goes wrong:** Code continues reading `features.get("ctf_score")` from JSONB after migration strips the keys.

**Why it happens:** Migration adds columns but doesn't update all readers; dual source of truth leads to divergence.

**How to avoid:**
1. Grep-migrate all readers (verified list in Code Examples section)
2. Update schema definitions (`I6Confluence` in `schemas.py`, ML feature classes)
3. Update `intelligence_features` INSERT statement in `feature_writer.py`
4. Verify zero readers remain in src/ after migration

**Warning signs:** Code uses `features.get("ctf_score", ...)` instead of reading top-level column or I6Confluence fields.

### Pitfall 4: Plugin History Access Assumptions

**What goes wrong:** Plugin assumes `frames` contains history windows (`features_history[-i]`, `frames[-i]`), but `compute_full()` only receives the current bar.

**Why it happens:** Spec references history patterns that don't match the actual plugin signature.

**How to avoid:**
- If lookback needed: manage via `self._state` using `Parallel dicts → dataclass`
- If structural event needs lookback (pullback detection, departure window): add rolling buffer to state
- Verify by reading plugin source: `extract_ohlcv()` returns arrays, but only `[-1]` is guaranteed current

**Warning signs:** Plugin code uses `frames["i1"][:-N]` or assumes history is available in `frames`.

### Pitfall 5: Wrong Directory for Migrations

**What goes wrong:** Migration created in `db/migrations/` instead of `production/migrations/`, causing number conflicts (120/121 already exist in both).

**Why it happens:** Two migration directories exist; `production/migrations/` is canonical for service deployments.

**How to avoid:**
- Always use `production/migrations/` for service migrations
- Next number is 130 (max in `production/migrations/` is 129; `db/migrations/` has 121 but that directory is NOT canonical)
- Verify with `ls production/migrations/*.sql | tail -1`

**Warning signs:** Migration not in `production/migrations/`, or number conflicts with existing files.
