## Task 2: Verify row counts

<read_first>
- None — live DB state verification only
</read_first>

<action>
Run the canonical row count verification query from the ADR:

```bash
PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent -c "
SELECT
    (SELECT COUNT(*) FROM signal_ledger)      AS signal_ledger_count,
    (SELECT COUNT(*) FROM signal_events)      AS signal_events_count,
    (SELECT COUNT(*) FROM trade_frames)       AS trade_frames_count,
    (SELECT COUNT(*) FROM trade_executions)   AS trade_executions_count,
    (SELECT COUNT(*) FROM signal_events) = (SELECT COUNT(*) FROM signal_ledger) AS counts_match;"
```

Expected: counts_match = true, all three source/target counts equal 1,442,909, trade_executions = 0.
</action>

<acceptance_criteria>
- `counts_match` column = `t`
- signal_events_count = signal_ledger_count (exact match)
- trade_frames_count = signal_ledger_count (exact match)
- trade_executions_count = 0
</acceptance_criteria>

## Task 4: Write and apply migration 138 — signal_ledger read-only

<read_first>
- production/migrations/136_phase126_i7_apr_params.sql (migration file style)
</read_first>

<action>
Create `production/migrations/138_signal_ledger_readonly.sql`:

```sql
-- Migration 138: Revoke write access to signal_ledger (read-only transition)
--
-- Phase 129 data migration complete. signal_ledger is retained read-only
-- for the 48-hour transition window per Phase 129 ROADMAP success criteria.
-- Phase 130 will DROP TABLE after all writers are verified using signal_events.

REVOKE INSERT, UPDATE, DELETE ON signal_ledger FROM PUBLIC;
REVOKE INSERT, UPDATE, DELETE ON signal_ledger FROM postgres;
```

Apply it:
```bash
PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent -f production/migrations/138_signal_ledger_readonly.sql
```

Expected: `REVOKE`, `REVOKE`

Verify signal_ledger is now read-only:
```bash
PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent -c "
INSERT INTO signal_ledger (signal_id, timestamp, symbol, timeframe, setup_plugin, signal_type, direction, raw_confidence)
VALUES (gen_random_uuid(), now(), 'TEST', '1m', 'test', 'test', 1, 0.5);"
```

Expected: `ERROR: permission denied for table signal_ledger`
</action>

<acceptance_criteria>
- `production/migrations/138_signal_ledger_readonly.sql` file exists
- Applying it returns two `REVOKE` lines (no ERROR)
- Subsequent INSERT attempt returns `ERROR: permission denied for table signal_ledger`
- `SELECT COUNT(*) FROM signal_ledger;` still returns 1,442,909 (read access intact)
</acceptance_criteria>
