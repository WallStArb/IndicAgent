<objective>
Close FEED-03 gap: fix the inverted multiplier formula in `_compute_perf_multipliers()` so that outperforming setups (best Sharpe) receive the LOWEST multiplier (0.5), which with ascending sort in the aggregator causes them to rank FIRST.

Purpose: The aggregator already sorts `adjusted_rank` ascending (lower = higher priority). The bug is that the current formula awards best Sharpe → highest multiplier (~1.5), which with ascending sort pushes the best performer to the END of the list. Inverting the formula fixes the direction.

Output: Single one-line formula change in `setup_performance_updater.py`. No changes to `aggregator.py` or `test_aggregator_perf.py` — those are already correct.

```python
# Current docstring (lines 12-17) — reflects wrong direction:
#   perf_multiplier = 0.5 + (rank / n_eligible)  → range [0.5, ~1.5]
#   Best performer: rank=n-1 → multiplier approaches 1.5
#   Worst performer: rank=0  → multiplier = 0.5
#   Note: rank=n-1 for BEST because we want best Sharpe → highest multiplier.

# Current implementation (line 118 — wrong):
multipliers[plugin] = 0.5 + (rank / n)
```

Ascending sort in aggregator means: lower `adjusted_rank` → appears first.
`adjusted_rank = composite_rank * perf_multiplier`
Best Sharpe must get the LOWEST multiplier (0.5) so `adjusted_rank` is minimized → sorts first.

```python
# Correct formula:
multipliers[plugin] = 0.5 + ((n - 1 - rank) / n)
# rank 0 = worst Sharpe  → 0.5 + (n-1)/n ≈ 1.5  (highest multiplier → sorts last)
# rank n-1 = best Sharpe → 0.5 + 0/n = 0.5       (lowest multiplier → sorts first)
```
