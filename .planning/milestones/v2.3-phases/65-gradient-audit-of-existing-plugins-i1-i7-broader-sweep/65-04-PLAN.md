<objective>
Graduate I7 trading setup plugins from HMM regime equality comparisons to continuous probability weights, and replace flat confidence base values with signal-strength-derived scores.

Renaissance design principles:
- **Use the data you already have.** HMM probabilities (hmm_prob_ranging, hmm_prob_trending_up, hmm_prob_trending_down) are already computed and available in the features dict. Using `hmm_regime == 1.0` instead of `hmm_prob_trending_up` is literally discarding information.
- **Distinguish gates from scores.** Eligibility gates (return None if wrong regime) stay binary -- they're hard filters. Confidence scoring (how much to add) goes continuous -- it's a weight. Don't confuse the two.
- **Preserve existing gradients.** Several plugins already have magnitude-based CTF boosts (choch_reversal, cross_asset_divergence, ofi_divergence, supply_demand_setup, liquidity_sweep_reclaim). Don't disrupt working gradient code.
- **hmm_regime_weight enforces consistency.** All I7 plugins import from the same function, which maps "up"/"down"/"ranging" to the correct schema field names. No more scattered field name typos.

Output: 12 I7 plugins updated to use hmm_prob_* continuous weights; second_leg and vcp verified correct as-is.
</objective>

def hmm_regime_weight(features: dict, regime_direction: str) -> float:
    """Extract continuous HMM probability for a regime direction.
    regime_direction: "up" | "down" | "ranging"
    Returns: hmm_prob_trending_up for up, hmm_prob_trending_down for down, hmm_prob_ranging for ranging.
    Fallback: 0.5 if key missing or value is None.
    Clamp: [0, 1].
    """
