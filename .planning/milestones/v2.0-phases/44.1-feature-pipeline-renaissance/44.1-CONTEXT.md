# Phase 44.1: Feature Pipeline Renaissance Refactor — Context

**Gathered:** 2026-03-21
**Status:** Ready for planning
**Source:** PRD Express Path (docs/superpowers/specs/2026-03-21-feature-pipeline-renaissance-design.md)

<domain>
## Phase Boundary

Replace three sequential services (indicator_service, market_analysis_service, timeframes_builder_service) with a single unified FeaturePipelineService that runs I1–I6 in-process per bar. Simultaneously simplify SignalGeneratorService by removing its DB seed and wiring BarHistory to the incoming IntelligenceEvent stream. Deliver shared BarHistory, BarAccumulator, and typed BarMessage modules. Pipeline_latency_ms < 50ms p99. Zero change to plugin implementations, I7/I8 services, FeatureWriterService, dashboard, or TimescaleDB schema.

</domain>

<decisions>
## Implementation Decisions

### Service topology changes
- **D-01:** Three services are replaced by one: `indicator_service.py` + `market_analysis_service.py` + `timeframes_builder_service.py` → `feature_pipeline_service.py`
- **D-02:** New systemd unit: `indicagent-feature-pipeline.service`
- **D-03:** Old systemd units (`indicagent-indicator`, `indicagent-market-analysis`, `indicagent-timeframes`) deleted after cutover

### Topics
- **D-04:** `development.indicators` topic retired — no longer produced or consumed after cutover
- **D-05:** `development.market.bars` schema changes from stringly-typed dict to typed `BarMessage` — topic name unchanged
- **D-06:** `development.market.bars.htf` still published, now by FeaturePipelineService via BarAccumulator — topic name unchanged
- **D-07:** `development.intelligence` schema extended (two new fields), not renamed — fully backward compatible

### Shared module: BarHistory (`src/core/bar_history.py`)
- **D-08:** Pure class, no global state, no side effects
- **D-09:** Interface: `__init__(maxlen=200)`, `append(bar: BarMessage)`, `get(symbol, tf) -> deque[BarMessage]`, `to_dataframe(symbol, tf) -> pd.DataFrame`, `is_warm(symbol, tf, min_bars) -> bool`, `seed(symbol, tf, bars)`, `migrate_symbol(old_symbol, new_symbol)` (for futures rolls)
- **D-10:** `to_dataframe()` is the canonical path for indicator computation
- **D-11:** `is_warm()` gates plugin execution — no plugin runs on insufficient history

### Shared module: BarAccumulator (`src/core/bar_accumulator.py`)
- **D-12:** Interface: `__init__(timeframes: list[str], session: TradingSession)`, `update(bar_1m: BarMessage) -> list[BarMessage]`, `current_partial(tf) -> BarMessage | None`
- **D-13:** Window boundaries: 5m at :00/:05/:10/:15…, 15m at :00/:15/:30/:45, 1h at :00
- **D-14:** Session-aware: partial bar at session break is closed and emitted, not carried forward
- **D-15:** Does NOT synthesize bars for gaps — if no 1m bars in a 5m window, no 5m bar emitted
- **D-16:** Completed HTF bars: (a) injected into BarHistory AND (b) published to `market.bars.htf`

### Shared module: BarMessage (`src/core/schemas/bar_message.py`)
- **D-17:** `BarMessage` Pydantic model with fields: `ts: datetime`, `symbol: str`, `tf: str`, `open: float`, `high: float`, `low: float`, `close: float`, `volume: int`, `source: Literal["ibkr_named", "ibkr_seed", "htf_derived"]`, `session_type: SessionType`, `gap_preceding: bool`
- **D-18:** `SessionType` enum: `RTH="rth"`, `ETH="eth"`, `CRYPTO="crypto"`, `FX="fx"`, `CLOSED="closed"`
- **D-19:** `session_type` set by TWS daemon at publish time from instrument config
- **D-20:** `gap_preceding=True` set by FeaturePipelineService when previous expected bar is missing in BarHistory
- **D-21:** `source="htf_derived"` for bars emitted by BarAccumulator

### IntelligenceEvent schema extension
- **D-22:** Extend existing `IntelligenceEvent` in `src/intelligence/schemas.py` in-place — do NOT create a new class
- **D-23:** Two new fields with defaults: `session_type: SessionType = SessionType.RTH`, `pipeline_latency_ms: float = 0.0`
- **D-24:** All existing i1/i2/i3/i4/i5/smc/i6 JSONB tier fields retained — backward compatible with FeatureWriterService and AINarrativeService
- **D-25:** Migration to fully typed tier output models (I1Output, I2Output, etc.) is deferred to a follow-up phase

### FeaturePipelineService — startup sequence
- **D-26:** Connect to TimescaleDB BEFORE beginning bar consumption
- **D-27:** Primary seed: single ROW_NUMBER() window query for last 200 bars per (symbol, tf) across all active contracts — NOT 61×5 individual queries
- **D-28:** Fallback seed: if intelligence_features has < min_bars_for_tf(tf) rows for a (symbol, tf) pair, fill from market_data_ohlcv
- **D-29:** BarHistory.seed() for all (symbol, tf) pairs after seed queries complete
- **D-30:** Reconstruct BarAccumulator partial state by replaying 1m bars from `development.market.bars` Redpanda topic (seek to last 5m window boundary, ~5 minutes of messages) — no DB query needed for partial state
- **D-31:** Re-publish last known IntelligenceEvent per (symbol, tf) to `development.intelligence` on startup — ensures dashboard gets fresh state immediately on service restart
- **D-32:** Subscribe to `topic_system_events()` for roll events
- **D-33:** Begin consuming `development.market.bars` only AFTER seeding is complete — no cold-history processing

### FeaturePipelineService — per-bar execution
- **D-34:** Semaphore: `asyncio.Semaphore(min(32, (os.cpu_count() or 4) * 2))` bounds concurrent symbol processing
- **D-35:** `asyncio.gather(*[_bounded(b) for b in bars], return_exceptions=True)` — one symbol's exception does not block others
- **D-36:** Per-bar: `bar_history.append(bar)` → `bar_accumulator.update(bar)` → append+publish HTF bars → `is_warm()` gate → `_build_plugin_frames()` → `_run_plugin_tiers()` → `_publish_intelligence()`

### FeaturePipelineService — critical correctness details
- **D-37:** CPU-bound plugins (GARCH, HMM) wrapped with `asyncio.to_thread(_sync_compute)` backed by per-`(plugin, symbol, tf)` threading locks — same pattern as `market_analysis_service.py` lines 246–260
- **D-38:** `smc_trend_direction` rename: after SMC plugins run, `trend_direction` in SMC result is renamed to `smc_trend_direction` before merging into `frames["features"]` — prevents overwriting I3Structure's `trend_direction` — must replicate `market_analysis_service.py` lines 293–295 exactly
- **D-39:** `_prev_i1_features` dict keyed by `f"{symbol}:{tf}"`: inject as `frames["prev_features"]` before I1 runs, then store I1 result for next bar — required for I2 crossover detection (MACDEvents, RSIEvents)

### FeaturePipelineService — futures roll handling
- **D-40:** Subscribe to `topic_system_events()`, handle roll events with same logic as `indicator_service._handle_roll_event()`
- **D-41:** On roll: `BarHistory.migrate_symbol(old_symbol, new_symbol)`, then adjust price-sensitive I1 plugin state (Bollinger bands, Keltner channels, Donchian channels) by `roll_gap`
- **D-42:** Log roll event with old/new symbol, roll gap, and adjusted plugin count

### SignalGeneratorService simplification
- **D-43:** Remove `bar_history` DB seed on startup — BarHistory populated by appending bars extracted from incoming `IntelligenceEvent.bar` fields
- **D-44:** Remove subscription to `development.indicators` (topic retired)
- **D-45:** Consume typed `IntelligenceEvent` (extended schema) instead of raw JSONB dict
- **D-46:** ALL of the following stay identical: `_regime_cache`, `_cross_asset_cache`, `_htf_intel_cache`, `_plugin_states`, `frames["pattern_weights"]` injection via `pattern_reliability` TTL cache, signal ledger write logic, TIER_I7 plugin execution
- **D-47:** `_plugin_states` keyed by `(plugin_name, symbol, tf)` — NOT persisted across restarts — intentional, do not attempt to persist or seed I7 state

### Cutover sequence (Step 3 of migration plan)
- **D-48:** Single restart sequence: `stop indicagent-indicator indicagent-market-analysis indicagent-timeframes` → `start indicagent-feature-pipeline`
- **D-49:** Rollback: stop feature-pipeline, start indicator + market-analysis + timeframes

### Metrics
- **D-50:** `pipeline_latency_ms` metric exposed at `:9119` (next available port after cross-asset :9118)

### Claude's Discretion
- Exact Prometheus metric names beyond `pipeline_latency_ms`
- Internal semaphore tuning (within spec bounds of `min(32, cpu_count×2)`)
- Module docstrings and type annotations
- Order of (symbol, tf) pairs during startup seed
- Log format for per-bar processing (beyond spec-mandated structured fields)

</decisions>

<specifics>
## Specific Ideas

**Quantified improvements from spec:**
- Kafka hops in hot path: 3 → 1 (−67%)
- Bar history implementations: 3 diverging → 1 shared module
- HTF staleness at I6: 30–100ms+ (DB query) → ~0ms (in-pipeline)
- Signal latency (bar close → publish): ~200–500ms → ~20–50ms (~10× faster)
- Services in hot path: 3 → 1

**Testing strategy from spec:**
- Unit: BarHistory (append, maxlen, to_dataframe, is_warm, seed, migrate_symbol), BarAccumulator (window boundaries, session break, gap handling, current_partial), BarMessage serialization, IntelligenceEvent backward compatibility
- Integration: 200 BarMessages → all tier fields populated + pipeline_latency_ms > 0; startup seed; gap detection; roll event; _prev_features continuity; BarAccumulator partial restore
- Regression: run both old pipeline and FeaturePipelineService against identical 200-bar fixture, assert I1 values numerically identical

**Spec clarification on I6 regression tolerance:**
> "I6 CTF scores within tolerance (HTF derivation from 1m bars vs DB views may differ at window edges — document delta, accept)"

</specifics>
