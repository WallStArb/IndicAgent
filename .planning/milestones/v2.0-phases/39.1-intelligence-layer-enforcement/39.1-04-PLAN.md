`get_recent_signals()` builds WHERE clause via f-string: `tier_clause = "AND sl.was_selected = true..."` then `query = f"... {tier_clause} ..."`. This pollutes asyncpg plan cache with 3 query variants and creates an injection surface.

Rewrite to a single parameterized query using boolean parameter short-circuit logic:

```python
async def get_recent_signals(..., tier: Literal["hero", "monitored", "candidate"] = "hero"):
    # Map tier to boolean filter flags
    require_selected = tier in ("hero", "monitored")
    require_hero_gate = tier == "hero"

    query = """
        SELECT
            sl.signal_id,
            sl.symbol,
            sl.timeframe,
            ...
        FROM signal_ledger sl
        LEFT JOIN setup_performance sp ON sp.setup_plugin = sl.setup_plugin
            AND sp.timeframe = sl.timeframe
        WHERE ($1::text IS NULL OR sl.symbol = $1)
          AND ($2::text IS NULL OR sl.timeframe = $2)
          AND (NOT $4::boolean OR sl.was_selected = true)
          AND (NOT $5::boolean OR (sl.confidence >= 0.40 AND abs(sl.cis_score) > 0.35))
        ORDER BY COALESCE(sl.signal_computed_at, sl.feature_ts) DESC
        LIMIT $3
    """

    rows = await db_manager.fetch(
        query,
        resolved_symbol,   # $1
        timeframe,         # $2
        limit,             # $3
        require_selected,  # $4
        require_hero_gate, # $5
    )
```

The `NOT $4::boolean OR condition` pattern is idiomatic Postgres optional filter — when `$4=false`, the clause short-circuits to TRUE, skipping the filter entirely.

Remove the old `tier_clause` variable and f-string query construction entirely.

Note: Preserve all existing SELECT columns and JOINs — only change the WHERE clause and parameter passing.
