# Phase 39.1 Plan 04: Bug Fixes — VWAP Timezone, ShannonEntropy NaN, SQL Parameterization Summary

Fixed two production bugs that fire on every bar for all symbols (VWAP timezone crash, ShannonEntropy NaN crash), hardened /signals/recent against SQL injection surface and plan cache pollution, and auto-fixed a blocking pre-commit hook bug.

## What Was Built

### Task 1: VWAP Plugin Timezone Fix (BUG-01)

**Before:**
```python
ts = pd.to_datetime(df["timestamp"])          # crashes on tz-aware input
bar_date = pd.to_datetime(row["timestamp"]).date()  # crashes on tz-aware input
```

**After:**
```python
ts = pd.to_datetime(df["timestamp"], utc=True)
bar_date = pd.to_datetime(row["timestamp"], utc=True).date()
```

Both `compute_full()` and `compute_next()` fixed. The error `Tz-aware datetime.datetime cannot be converted to datetime64 unless utc=True` fired on every 1m bar for all 61 symbols because production data uses UTC-aware timestamps.

**Commit:** `a1c51af`

### Task 2: ShannonEntropy NaN/Inf Guard (BUG-02)

**Before:**
```python
log_returns = np.diff(np.log(close))
if len(log_returns) < 10:
    return 1.0
counts, _ = np.histogram(log_returns, bins=n_bins)  # crashes on NaN/Inf range
```

**After:**
```python
log_returns = np.diff(np.log(close))
if len(log_returns) < 10:
    return 1.0
valid_returns = log_returns[np.isfinite(log_returns)]  # filter NaN and Inf
if len(valid_returns) < 10:
    return 1.0
counts, _ = np.histogram(valid_returns, bins=n_bins)   # safe
```

The `np.log(0)` produces `-inf`, and price spikes produce `NaN` log-returns. These caused `autodetected range of [nan, nan] is not finite` on every bar for symbols with zero or extreme prices. Plugin now returns entropy=1.0 (max noise) on insufficient finite data — consistent with the design intent.

**Commit:** `c54c46d`

### Task 3: Parameterized SQL for /signals/recent (CODE-Q-05)

**Before:** f-string WHERE clause (3 query variants, asyncpg plan cache pollution, injection surface):
```python
if tier == "hero":
    tier_clause = "AND sl.was_selected = true AND sl.confidence >= 0.40 ..."
elif tier == "monitored":
    tier_clause = "AND sl.was_selected = true"
else:
    tier_clause = ""
query = f"... {tier_clause} ..."
```

**After:** Single stable parameterized query with boolean short-circuit:
```python
require_selected = tier in ("hero", "monitored")
require_hero_gate = tier == "hero"
query = """
    ... WHERE ...
      AND (NOT $4::boolean OR sl.was_selected = true)
      AND (NOT $5::boolean OR (sl.confidence >= 0.40 AND sl.cis_score IS NOT NULL AND abs(sl.cis_score) > 0.35))
    ...
"""
rows = await db_manager.fetch(query, resolved_symbol, timeframe, limit, require_selected, require_hero_gate)
```

The `NOT $N::boolean OR condition` pattern is idiomatic Postgres optional filter — when `$N=false`, the clause short-circuits to TRUE, skipping the filter entirely.

**Commit:** Included in concurrent plan 39.1-02 commit `4836f7e` (picked up working tree changes)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed pre-commit hook stdout parsing bug**
- **Found during:** Task 3 commit attempt
- **Issue:** `check_dead_imports()` captured ruff's success message ("All checks passed!") into `VIOLATIONS` variable. Under `exec > >(tee -a ...)` pipe, the stdout is consumed by tee before the `grep -v "^All checks passed"` filter can remove it, causing a false positive that blocks all commits.
- **Fix:** Replaced stdout-parsing approach with a tmpfile + exit code check: ruff writes to tmpfile, exit code 0 = pass, exit code 1 = failures.
- **Files modified:** `.git/hooks/pre-commit`
- **Commit:** Not committed separately (git hooks are not tracked by default). Applied inline before committing.
