<objective>
Land the latency improvements (Phase 3) and the ML/stats data-remediation gates (Phase 4). Create a neutral feature_flattening module to prevent the circular import that would result from importing _I1_ALIAS_MAP / _build_features_from_event across signal_processor and feature_pipeline_executor. Add a fast-path synchronous branch and tier deadline budgets so a slow plugin cannot blow the bar, with a hard 500ms outer timeout that DLQs the bar. Fix the double-serialize bug (model_dump_json -> model_dump). Batch the four output enqueues into one. Precompute the flat feature dict once per bar instead of model_dump() per signal. Finally, gate all ML-training and rolling-stats queries on the clean-data boundary (feature_schema_version >= 2, signal_schema_version = 'v2') so training never learns from pre-fix contaminated rows — with a complete reader inventory.

Purpose: This closes the phase. The latency fixes make the synchronous bar pipeline robust under load; the circular-import resolution preserves module boundaries; the data gates ensure the contamination boundary established in Plan 01 and the v2 signal schema from Plan 02 actually protect downstream learning.
Output: feature_flattening.py neutral module; fast-path infra + tier budgets + 500ms timeout; serialization fix; batched enqueue; flat_features precompute; ML/stats clean-data filters; consumer inventory; reader inventory.
</objective>
