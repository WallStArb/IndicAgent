<objective>
Build the auto-promotion runner and A/B comparison report (OPT-04). After the compile pass, the optimizer evaluates each candidate's 7-day A/B window against the precise D-09 criteria and promotes via a DB status flip — no manual review. The regime-balance guard uses the actual stored regime values `'0'`, `'1'`, `'2'` (NOT string labels — RESEARCH pitfall 3).

REVIEWS Finding 3 (no-baseline fallback): `_fetch_active_version_tag()` returns None when no candidate has ever been promoted (the common case on first runs). The A/B comparison MUST NOT fail silently in that case. Fallback: when there is no `active` prompt_version row, the baseline group is the set of `llm_calls` rows whose `prompt_version` equals the agent's FILE ACTIVE_VERSION — i.e. `AGENT_SIGNATURES[agent_id].version_tag` (e.g. baseline `prompt_version = 'skeptic_v2'` for agent_id 'skeptic', or `'correlation_v1'` for 'correlation_v1'). This is the in-file prompt that produced the pre-DSPy traffic. The candidate group is the rows whose `prompt_version` equals the candidate's `version_tag`. The promotion still gates only on the D-09 parse criteria.

CRITICAL FRAMING (REVIEWS Finding 6): the artifact being promoted is a compiled few-shot program state, not a rewritten prompt. Code comments and structlog must say "compiled program" / "candidate program", never "optimized prompt".

Purpose: Close the loop — compiled candidates become active only on evidence, with a confound guard against single-regime windows, and a defined baseline even before any prior promotion exists.
Output: promotion + report logic appended to DSPyOptimizer; unit tests for the decision function.
</objective>

    Module constants: `_PROMO_PARSE_DELTA = 0.02`, `_PROMO_MIN_N = 100`, `_PROMO_MIN_PER_REGIME = 20`, `_AB_WINDOW_DAYS = 7`.

    - `async def _fetch_ripe_candidates(self) -> list`: SELECT version_id, agent_id, version_tag, created_at FROM prompt_versions WHERE status='candidate' AND created_at <= NOW() - INTERVAL '7 days' ORDER BY created_at ASC. (Candidates younger than 7 days are not yet evaluable; un-promoted candidates stay 'candidate' and are re-checked next run — this is the automatic window extension.)

    - `async def _fetch_active_version_tag(self, agent_id) -> str | None`: SELECT version_tag FROM prompt_versions WHERE agent_id=$1 AND status='active' ORDER BY promoted_at DESC LIMIT 1. Return the tag or None.

    - `def _baseline_version_tag(self, agent_id, active_tag) -> str`: REVIEWS Finding 3 fallback. If active_tag is not None, return active_tag. Otherwise return `AGENT_SIGNATURES[agent_id].version_tag` (the file ACTIVE_VERSION, e.g. 'skeptic_v2' / 'correlation_v1') — the in-file prompt version that produced pre-DSPy traffic. This guarantees a defined baseline group even when no prior DSPy variant has been promoted.

    - `async def _fetch_ab_stats(self, agent_id, window_start, version_tags: list[str]) -> dict[str, dict]`: GROUP BY prompt_version over llm_calls WHERE agent_id=$1 AND called_at >= $2 AND prompt_version = ANY($3) AND outcome IS NOT NULL. Per version compute: n_calls=COUNT(*), parse_success_rate=AVG(parse_success::int), win_rate=AVG(CASE WHEN win IS NOT NULL THEN win::int END), and regime counts via `COUNT(*) FILTER (WHERE regime = '0')` (n_ranging), `COUNT(*) FILTER (WHERE regime = '1')` (n_trending_up), `COUNT(*) FILTER (WHERE regime = '2')` (n_trending_down). Regime values are the strings '0','1','2' (RESEARCH pitfall 3) — NEVER 'bullish'/'bearish'/'ranging'. Return `{prompt_version: {n_calls, parse_success_rate, win_rate, n_ranging, n_trending_up, n_trending_down}}`; a version absent from the result maps to a zero-filled dict.

    - `@staticmethod def _promotion_decision(candidate_stats: dict, baseline_parse_rate: float) -> tuple[bool, str]`: PURE function, no I/O, unit-testable (staticmethod so tests need no constructed pool). Returns (promote, reason). promote=True only if ALL hold:
        1. `candidate_stats["parse_success_rate"] > baseline_parse_rate + _PROMO_PARSE_DELTA` (STRICT greater — exactly +0.02 does NOT promote; document this as intentional per REVIEWS Plan 04 MEDIUM)
        2. `candidate_stats["n_calls"] >= _PROMO_MIN_N`
        3. each of `candidate_stats["n_ranging"]`, `candidate_stats["n_trending_up"]`, `candidate_stats["n_trending_down"]` >= `_PROMO_MIN_PER_REGIME`
      The reason string names the FIRST failing criterion in this order: "no_parse_improvement", then "insufficient_n", then "regime_balance_unmet"; "promote" when all pass.

    - `async def _promote(self, candidate_version_id, agent_id) -> None`: inside a single `async with conn.transaction():` run `UPDATE prompt_versions SET status='retired' WHERE agent_id=$1 AND status='active'` then `UPDATE prompt_versions SET status='active', promoted_at=NOW() WHERE version_id=$2`. (The partial unique index from Plan 01 guarantees the retire-then-promote ordering cannot leave two active rows.)

    - `async def _check_promotion(self) -> dict`: build a report dict `{"date": <UTC iso>, "agents": {}}`. For each candidate from `_fetch_ripe_candidates()`: resolve `active_tag = await _fetch_active_version_tag(agent_id)`; `baseline_tag = self._baseline_version_tag(agent_id, active_tag)`; `window_start = candidate.created_at`; `stats = await _fetch_ab_stats(agent_id, window_start, [baseline_tag, candidate.version_tag])`; `baseline = stats.get(baseline_tag, {zero})`; `cand = stats.get(candidate.version_tag, {zero})`; `(promote, reason) = self._promotion_decision(cand, baseline["parse_success_rate"])`. If promote: `await self._promote(candidate.version_id, agent_id)` and log `dspy_optimizer.promoted` (agent_id, version_tag=candidate.version_tag, baseline_tag). Else log `dspy_optimizer.promotion_deferred` (agent_id, version_tag, reason). Record into report["agents"][agent_id] a dict with: baseline_tag, candidate_tag, decision=reason, promoted=promote, and per-version blocks (baseline + candidate) each carrying parse_success_rate, win_rate, n_calls, n_ranging, n_trending_up, n_trending_down, plus parse_success_delta and win_rate_delta (candidate minus baseline). This satisfies REVIEWS Plan 04 suggestion: report parse_success AND win_rate AND regime breakdown per version, for observability, even though promotion gates only on D-09 parse criteria. Return the report dict.

    - `def _write_report(self, report: dict) -> None`: write `logs/dspy_optimizer_report_{ts:%Y%m%d}.json` with `ts = datetime.now(UTC)` captured once, atomically (tmp file on the same directory + `os.replace`/`Path.replace`) per the ml_trainer _write_report style.
