<objective>
Create the `prompt_versions` table migration and pin the `dspy` package. This is the storage substrate for OPT-02: the DSPy compiled few-shot program state (demos plus program metadata) is written here as JSONB, and the `status` field drives A/B routing and promotion via a DB-only field flip (no application code change).

NOTE on D-05 schema semantics: the `compiled_prompt` JSONB column does NOT store a rewritten instruction string. `dspy.BootstrapFewShot` compiles few-shot DEMONSTRATIONS, not instruction text. The stored artifact is a DSPy compiled program state (the demos list plus program/signature metadata produced by `program.save()`). The column name `compiled_prompt` is locked by D-05 and is kept; this plan documents in the migration header comment that the contents are DSPy compiled program state, not a prompt template.

Purpose: Establish the durable, queryable store for compiled program states before the optimizer that writes to it (Plan 02) and the promotion runner that flips its status (Plan 04) are built.
Output: `production/migrations/115_prompt_versions.sql` applied to the live DB; `dspy>=3.2.1` in `requirements.txt`.
</objective>
