<domain>
## Phase Boundary

Replace `ensemble_trainer.py`'s IC-proportional weighting with better-validated alternatives, judged empirically by Phase 142A's `EnsembleICEngine` machinery. Every variant is a new `weight_version` in the existing `ensemble_weights`/`ensemble_alpha` PKs — zero schema change needed for A/B testing.

**In scope this phase:**
- **Wave 0 — Judge readiness:** build the pooled cross-sectional pass in `EnsembleICEngine` (todo 046) and establish the baseline measurement of the current `v1` (ic_proportional) weights, before any new variant is built.
- **E1 — shrunk-IC inputs:** build todo 029's shrinkage estimator (`ic_shrunk`, `shrinkage_weight` on `feature_ic_scores`) and wire `ensemble_trainer.py` to consume it, with an out-of-fold acceptance test as a hard correctness gate.
- **E2 — mean-variance combination:** `w ∝ Σ⁻¹·IC` using the already-computed Ledoit-Wolf covariance, replacing the binary cluster-deflation heuristic with continuous decorrelation. Gate on covariance condition number.
- **A/B judging infrastructure:** a new comparison gate script (mirrors the EIC-04/EIC-05 pattern) that reads `alpha_ensemble_ic` for two `weight_version`s and applies the win rule below, per (tf, regime) stratum.

**Explicitly out of scope (deferred):**
- **E3 — hierarchical partial pooling** for sparse regime strata — deferred until E1/E2 prove insufficient (roadmap-locked; do not amend the "pooled IC is diagnostic only" load-bearing decision until then).
- **E4 — per-feature decay half-lives** — sequence after todo 029's IC decay-curve item ships (separate, unbuilt).
- Fixing the HMM regime-label look-ahead risk (todo 026/034) — carried forward as a caveat, not remediated here.
- Phase 144's true OOS validation — 142A/142B.1's `EnsembleICEngine` measures in-sample (`bar_ts < alpha.validation.oos_start`); OOS is reserved for Phase 144. Do not conflate 142B.1's A/B judging with an OOS claim.

<decisions>
## Implementation Decisions

### Judge Readiness (Wave 0 — build before E1/E2 work starts)
- **D-01:** Build todo 046's pooled cross-sectional pass in `EnsembleICEngine` as Wave 0. Weights are computed at UNIVERSE grain (one vector per tf/regime/weight_version shared by all 58 symbols) — a `symbol='POOLED'` row is the only statistically clean grain to declare a variant the winner, matching how `feature_ic_scores`/`ensemble_trainer.py` already gate feature selection on `symbol='POOLED'` rows. Without it, comparison would rely on ad hoc aggregation of 58 noisy per-symbol IC estimates.
- **D-02:** As part of Wave 0, (re)run `ensemble_ic_engine.py` to establish a baseline pooled-IC measurement of the CURRENT weights (`weight_version='v1'`, ic_proportional, computed 2026-07-01). `alpha_ensemble_ic` is currently 0 rows — there is no existing baseline to compare against. Every later weight_version must be measured against this locked v1 reference.
- **D-03:** Per-symbol IC stays as a diagnostic layer under the pooled gate (not dropped) — consistent with the project's Renaissance data-retention principle (never drop data that could contain signal) and the existing pattern where per-symbol rows support EIC-05-style diagnosis (e.g. catching a variant that wins on average but craters on specific symbols).

### E1 — Shrunk-IC Inputs
- **D-04:** Build todo 029's shrinkage estimator (item 0b) as 142B.1's first weighting-method wave, not deferred. Rationale: E2's Σ⁻¹·IC combination optimizes over whatever IC estimates it's given — running it on raw, winner's-curse-biased `ic_sharpe_hac` would bias the very inputs E2 is trying to combine optimally. Shrinking first means every later variant (E2/E3/E4) is compared on de-noised inputs, not v1's raw estimates.
- **D-05:** `ic_shrunk = w * ic_raw + (1 - w) * ic_prior`, `w = n_eff / (n_eff + k)` (empirical-Bayes, per todo 029 design). The out-of-fold acceptance test — shrunk estimates must predict next-window IC better than raw estimates, or the implementation is wrong — is a **hard gate**, not a diagnostic. If it fails, `ensemble_trainer.py` continues reading `ic_sharpe_hac` and E1 is marked failed/inconclusive rather than silently wired in.
- **D-06:** The shrinkage prior's peer-group ("feature family × regime × tf") reuses `feature_registry.group_name` as-is — 10 existing, CHECK-constrained, populated groups (momentum, volume, volatility, structure, session, oscillator, calendar, cross_tf, macro, regime; 3–11 features each, all `active`). No new taxonomy, no merging of sparse groups (cross_tf/macro at n=3) — if group-size instability shows up, the out-of-fold gate (D-05) will surface it empirically rather than pre-emptively engineering around it.
- **D-07 (taxonomy boundary, confirmed by investigation):** `feature_registry.group_name` (feature-column classification) and `instrument_tags`/`tag_vocabulary` (security classification, feeds the new `regime_group` column via Phase 151) are correctly separate, non-overlapping constructs over different entity types — not "the same taxonomy at different granularities." `tag_vocabulary` is scoped to falsifiable claims about instruments (per glossary); `feature_registry.group_name` is a definitional computational category for feature columns. No unification, no new table. E1's entire schema footprint is 2 new columns (`ic_shrunk`, `shrinkage_weight`) on the existing `feature_ic_scores` table.

### E2 — Mean-Variance Combination
- **D-08:** `w ∝ Σ⁻¹·IC` using the existing Ledoit-Wolf shrunk covariance (`compute_shrinkage_covariance` in `src/intelligence/ensemble/covariance.py`), which today is computed but only used for binary cluster-deflation. Keep the per-feature cap and `ic_sign` logic unchanged. Gate on covariance condition number (new APR key `alpha.ensemble.mv_condition_max`).
- **D-09 (roadmap-locked, carried forward, not re-litigated):** E3 (hierarchical partial pooling) and E4 (per-feature decay half-lives) are out of scope for this phase per the reasons in the Phase Boundary section above.

### Win Decision Rule
- **D-10:** A challenger `weight_version` beats the champion, per (tf, regime) stratum, on pooled cross-sectional IC, iff: `challenger.ic_ci_lower > champion.ic_ci_upper` (non-overlapping confidence intervals — a real, not noise-level, improvement) **AND** `challenger.walk_forward_stable = true` (reuses EIC-03's existing stability boolean). No new statistical test needed — both quantities are already computed by `EnsembleICEngine`.
- **D-11:** Promotion is **per-stratum**, not a forced single global winner. `weight_version` is champion independently per (tf, regime) — `ensemble_trainer.py`/`ensemble_alpha` already key by (tf, regime, weight_version), so a mixed outcome (e.g. E2 wins 1h/trending, E1-shrunk wins 5m/ranging) is directly expressible with zero schema change.
- **D-12:** The comparison logic lives in a new gate script mirroring the EIC-04/EIC-05 pattern already built in 142A (e.g. `scripts/ops/alpha/ops_ensemble_weight_compare.py`) — reads `alpha_ensemble_ic` for two `weight_version`s, applies D-10's rule per stratum, writes a structured comparison report. Repeatable across E1/E2 (and future E3/E4) rounds; not ad hoc SQL, consistent with the no-human-checkpoint execution convention.

### Regime-Stratified Caveat
- **D-13:** The known HMM regime-label look-ahead risk (todo 026/034: `regime_writer.py` fits its HMM on the full corpus before its causal decode) does **not** block per-regime weight-variant promotion in this phase. 142A already shipped and gated EIC-04 under this exact same caveat; todo 026/034's own decision gate requires empirical proof of harm before any fix is warranted, and blocking every regime-stratified measurement on an unproven risk would stall the whole v3.1 track. This caveat is carried forward, not re-litigated or remediated in 142B.1.
- **D-14:** The comparison report (D-12's gate script) MUST tag each per-stratum win/loss row with a caveat note when `regime != '_pooled'`, so promoted weight_versions that need re-validation are identifiable once the HMM refit (todo 026/034) eventually lands.

### Claude's Discretion
- Exact migration numbering/file names for the 2 new `feature_ic_scores` columns and any new APR keys (`alpha.ensemble.mv_condition_max`, plus whatever 029's shrinkage design specifies) — standard migrate-as-you-go pattern, no user preference expressed.
- Internal structure of the new comparison gate script (D-12) beyond "mirrors EIC-04/EIC-05 pattern, reads alpha_ensemble_ic, writes structured report."
- Exact wave/plan breakdown (how Wave 0 / E1 / E2 / Win-rule-script map to PLAN.md files) — planner's call.

## Existing Code Insights

### Reusable Assets
- `feature_registry.group_name` (10 populated groups) — reused as-is for E1's shrinkage prior peer group, zero new schema.
- `alpha_ensemble_ic` table (migration 195) — already has the `alpha_ensemble_ic_pooled_symbol_consistent` CHECK constraint built for `symbol='POOLED'` rows; only the dispatch loop needs fixing (todo 046).
- `compute_shrinkage_covariance` — LW covariance already computed every run; E2 needs no new covariance estimation, only a new consumption path (inversion instead of clustering-only).
- EIC-04 (`ops_ensemble_ic_gate.py`) / EIC-05 (`ops_ensemble_ic_diagnosis.py`) — direct pattern template for the new win-decision comparison script.

### Established Patterns
- APR compile-time binding: `EnsembleConfig.from_apr()` dataclass pattern in `ensemble_trainer.py` — new `alpha.ensemble.*` keys (e.g. `mv_condition_max`, shrinkage-related) should follow this exact pattern, not ad hoc `ConfigService.get()` calls scattered through the code.
- `weight_version` as the A/B mechanism — already proven in production (per-run epoch override via `--weight-version` CLI flag), zero schema change needed for any new variant.
- Pooled-gates-decision / per-symbol-diagnoses split — already the working pattern in `feature_ic_scores` (`symbol='POOLED'` gates promotion, per-symbol rows exist for diagnosis). Wave 0 extends this exact pattern to `alpha_ensemble_ic`.

### Integration Points
- `ensemble_trainer.py::_process_stratum` — E1 changes which IC column is read (`ic_shrunk` vs `ic_sharpe_hac`); E2 changes how `derive_weights`/`cluster_deflate_weights` are invoked (or replaced) after `compute_shrinkage_covariance`.
- `ensemble_ic_engine.py::_execute_inner` — Wave 0's `symbol_tf_pairs` dispatch fix point.
- New gate script reads `alpha_ensemble_ic` filtered by `weight_version` and `scored_at = max(scored_at)` per weight_version's most recent run (mirrors the deterministic-vintage pattern already locked in 142A's D-142A-R2).
