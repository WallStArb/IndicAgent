# Phase 142B.1 Plan 05: D-12 A/B Weight-Version Win-Decision Gate Summary

**New `ops_ensemble_weight_compare.py` CLI script that reads `alpha_ensemble_ic` for two `weight_version`s at their own deterministic latest vintage and reports a per-(tf, regime) WIN/LOSS/HOLD verdict using D-10's AND-rule (non-overlapping CI AND walk_forward_stable), with D-14's HMM regime-label caveat tagged on every non-pooled stratum.**

## Accomplishments
- `scripts/ops/alpha/ops_ensemble_weight_compare.py` mirrors the EIC-04 (`ops_ensemble_ic_gate.py`) + EIC-05 (`ops_ensemble_ic_diagnosis.py`) skeleton exactly: module-level parameterized SQL constant (`_COMPARE_SQL`), two pure importable decision helpers (`_evaluate_win_rule`, `_regime_caveat`), `main()` that does DB I/O via `asyncpg` and prints a markdown report, `except Exception as error` (CLAUDE.md convention), exit code always 0 (informational/per-stratum report, not a single boolean gate).
- `_COMPARE_SQL`'s `latest_per_version` CTE computes `max(scored_at)` independently `GROUP BY weight_version`, so a champion and a challenger measured at different times are each read at their own correct vintage -- never a single global `max(scored_at)` that could silently pick up a stale run for one side.
- The win rule is a pure two-line AND: `challenger.ic_ci_lower > champion.ic_ci_upper AND challenger.walk_forward_stable` -- verified via a dedicated regression test that a non-overlapping CI alone does NOT win if `walk_forward_stable` is `False`.
- D-14 caveat tagging (`_regime_caveat`) and per-stratum reporting (`_evaluate_win_rule` applied independently to every `(tf, regime)` row present for both versions -- `set(champion) & set(challenger)`, sorted) are both live in the markdown report's `flag`/`verdict` columns; no single global winner is computed or forced anywhere in the script.
- 8-test unit suite (`tests/unit/test_ensemble_weight_compare.py`) covers the win rule (win case, CI-overlap case, unstable-veto regression, CI-boundary-equal edge case), the D-14 caveat (tagged vs. untagged), and 3 SQL-text regression tests (per-version `GROUP BY weight_version`, pooled-row filter, single-lookahead-scale scoping) that fail if any of those structural guarantees regress.
- Operational smoke test run against the live `indicagent` DB (`--champion v1 --challenger v1_shrunk`, the real E1 pairing this script exists to eventually judge): confirmed the script connects, reads the live `v1` pooled baseline correctly (cross-checked the SQL directly via `psql PREPARE`/`EXECUTE` against real rows), and gracefully reports "no comparable strata" with exit code 0 rather than crashing, since `v1_shrunk` does not exist yet (E1's shrinkage weight variant is a later wave, not yet run).
