<objective>
Land the schema, APR, and controlled-vocabulary foundation for `regime_volatility`, and close the
two silent-corruption paths that open the instant new `feature_vectors` columns exist: a
`--refresh` recompute NULLing them out, and `ensemble_trainer` sweeping them into its training
matrix.

Purpose: `172-PATTERNS.md` names the column-ownership single-source-of-truth as the single most
important pattern in this phase to copy exactly rather than approximately, because the 2026-07-30
incident it exists to prevent NULLed `feature_vectors.regime` across all 36.8M rows. Separately,
`ensemble_trainer._get_feature_columns` builds its column list from
`information_schema.columns` minus a hardcoded `_META_COLS` set, so any new column is training
input by default. Both must land in the same plan as the migration that creates the columns, not
in a later cutover wave, because the exposure starts the moment the DDL applies.

This plan deliberately does NOT touch the legacy `regime` column, the `regime_hmm` CVR namespace,
or `regime_writer.py`'s trend code path. Phase 172 ships a phased cutover: `regime_volatility`
lands alongside `regime`, and retiring the legacy column is a later cleanup phase.

Output: migration 307 applied, a new Ring 1 ownership tuple, and three regression tests that fail
if any of the three exclusions is ever dropped.
</objective>
