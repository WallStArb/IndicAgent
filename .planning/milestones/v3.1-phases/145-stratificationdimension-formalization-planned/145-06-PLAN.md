<objective>
Close the loop: take the two empirical values the pilot derived, bake them into the gate cascade
as no-longer-`None` constants with full provenance, register the deferred APR migration so it is
not lost, and record the phase's verdict plus the next-candidate scoping in the canonical design
doc.

Purpose: D-06's stated rationale is that running one candidate all the way through "forces
`alpha.regime_stratification.max_correlation` (currently no default asserted) to get a real
empirically-derived value rather than remaining open-ended config," and D-04 makes deriving the
effective-N floor "a real deliverable of this phase, not a caveat to note and defer indefinitely."
This plan is where both land. It also satisfies the ROADMAP Phase 145 goal's third clause: scope
which candidate dimensions are worth planning next.

Two additions from the cross-AI review (145-REVIEWS.md). Codex HIGH #1: the two values come from
exactly one candidate dimension, one `regime_group` and one timeframe, so they ship as explicitly
provisional. A machine-readable `confirmation_status` travels with each constant, gate diagnostics
expose it to every caller, the design doc and the APR backlog say so in words, and a todo names the
cross-validation that would upgrade the status. Codex HIGH #2: the interim family-history store gets
a written retirement path into `concept_transition_log`, so the next candidate dimension's planner
inherits the family rather than starting a fresh one.

Output: updated `gates.py` constants and tests, an updated canonical design doc, an APR
calibration-backlog entry for the four deferred keys, and two filed follow-up todos.
</objective>
