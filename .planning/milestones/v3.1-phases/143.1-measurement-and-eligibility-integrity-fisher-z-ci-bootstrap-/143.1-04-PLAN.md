<objective>
Component E (todo 094, P0). Make ensemble eligibility, walk-forward validation, quality weighting, the E2 mean-variance path, AND the post-run lifecycle demote hook sign-symmetric so contrarian (negative-IC) features can reach ensemble weighting and STAY there. Root cause (Fable-reviewed, live-DB-verified): three sign-asymmetric gates exclude 100% of negative-IC features (1,527 eligible rows, zero at ic_sign=-1; alpha_events 99.99% long-only). The third gate (`_run_lifecycle_hook`, landed by Phase 143, not covered by the original plan) would silently re-demote every contrarian one lifecycle cycle after Component E lands - self-reverting the whole fix with no error anywhere.

CRITICAL wiring precision (RESEARCH Pitfall 1): the walk-forward sign fix MUST land in `_compute_cross_sectional_tf` (~1443-1447), the only block whose output carries symbol='POOLED' - the only value `_ELIGIBILITY_BASE_WHERE` accepts. CONTEXT.md's original `ic_engine.py:812-814` citation is the per-symbol block, whose output NEVER reaches the ensemble; fixing only it would compile, run, and have ZERO effect on the long/short imbalance. Fix all three blocks for consistency (resolved item 2), but the cross-sectional one is load-bearing.

CHAMPION/CHALLENGER SWITCH (Fable review BLOCKER 2): `weight_version` is a data-scoping tag only - `_ELIGIBILITY_BASE_WHERE`, `compute_quality_weight`, and the walk-forward criterion contain no reference to it, so training champion-vs-challenger under two tags alone would produce byte-identical weights and a vacuous FRAME-04 comparison. This plan introduces a real behavior switch: the boolean APR key `alpha.ensemble.sign_symmetric` (default false). Flag OFF reproduces the pre-Component-E champion exactly on the corrected corpus (equivalence property); flag ON enables sign-symmetric weighting. Plan 07's mainline champion trains with the flag OFF; Plan 08's challenger trains with it ON; promotion = flipping the APR default to true after evidence clears.

WALK-FORWARD IS UNCONDITIONAL BY DESIGN (not flag-gated): ic_engine writes ONE canonical feature_ic_scores corpus that both champion and challenger train from (ic_engine has no weight_version axis). The sign-aware walk-forward criterion is equivalence-preserving for ic_sign=1 features (fold_ic * (+1) > 0 == fold_ic > 0) - so the champion, whose flag-OFF eligibility WHERE admits only positive features, sees byte-identical passes_walkforward - while the challenger gets correct passes_walkforward for negative features from the same single corpus. Flag-gating the walk-forward instead would force building the corpus twice. The flag therefore gates only the POLICY layer (which rows get weighted, which get demoted), not the MEASUREMENT layer.

Purpose: this changes champion scoring behavior for what becomes the owner's live trading capital - shadow-mode validation (Plan 08) is mandatory before promotion. This plan lands the code + code-level tests only; the corpus re-run (Plan 07) and shadow validation (Plan 08) prove it on live data.

Output: sign-consistent walk-forward (3 blocks, unconditional), the sign_symmetric APR flag + CLI override, flag-gated sign-aware eligibility, sign-aware quality weight, sign-aware lifecycle hook, corrected E2 sign-path, stale-docstring/param fixes, ledger entry.
</objective>
