### Component A — Fisher-z CI bootstrap fix (todo 091, P0)

- **Mechanism:** `_fisher_z_ci` in `src/intelligence/statistics/ic_math.py`. Diagnostic (`docs/plans/2026-07-09-ic-null-calibration-design.md`, `scripts/ops/alpha/ops_ic_null_calibration.py`) already ran and found 38% SUSPECT rate (11/29 evaluated cells, spanning 4/8 `(tf, is_pooled)` strata — not confined to `1d`/thin-N corners).
- **Fix:** implement circular block bootstrap correctly as the production CI, replacing/supplementing `_fisher_z_ci`. The prior bootstrap implementation (removed from `ic_engine.py`) had a documented pre-ranking bug — it resampled pre-ranked values instead of raw observations re-ranked per-sample. Reuse the correct pattern already proven in `_circular_shift_null` (the diagnostic's own kernel function in `ic_math.py`).
- **Scope:** full corpus-wide replacement of `_fisher_z_ci` as the production CI — **not** targeted/boundary-only. Targeting via the CI suspected of being wrong to decide which cells get bootstrap treatment is circular; this was decided explicitly during brainstorming.
- **APR keys:** gives `alpha.ic.bootstrap_seed`, `alpha.ic.bootstrap_resamples`, `alpha.ic.bootstrap_block_size.{5m,15m,1h,1d}` (migrations 161, 165, 177 — currently dead, zero readers) their first real reader. Do not delete these keys as part of this phase — they are the reason the fix needs them.
- **Staged validation:** the new bootstrap implementation must agree with the existing 66-cell diagnostic's empirical null before any corpus-wide run is triggered.
- **Downstream exposure:** `_fisher_z_ci` gates BH-FDR pass/fail (`passes_fdr`), walk-forward validation, and the EIC-04 hard gate (currently PASS at 54/1425 = 3.79%, itself calibrated assuming this CI machinery is trustworthy). This phase does not decide whether EIC-04/Phase 142B's prior unblocking should be reconsidered as a consequence — record the fact, do not silently re-litigate the past gate decision.

### Component F — Vol-normalized return target for POOLED-strata IC (todo 097, P1)

- **Mechanism:** `return_x / trailing_sigma(symbol)` (sigma from the existing `atr_z` denominator or a trailing realized-vol window) as an alternative return target, applied inside `ic_engine`'s existing corpus load (join + divide, no migration, no new schema).
- **Why POOLED specifically:** the ensemble trains exclusively on POOLED strata (`ensemble_trainer.py:317,430,469,540`); raw-return ranks on POOLED are currently dominated by whichever symbols are running hot on a given bar — a real bias against the ensemble's training population.
- **Validation contract (locked, do not violate):** this is an **explicit A/B, not a silent swap**. Re-run POOLED strata with both raw and vol-normalized targets and compare qualifying-feature rankings directly. If rankings are materially identical to the raw-return baseline, retire the transform rather than keeping it on the strength of theory alone. This matters because Components A, E, and F all touch the same `ic_ci_lower`/`ic_ci_upper` numbers in the same corpus re-run — landing F as a silent replacement would confound attribution of any downstream change to A vs. E vs. F.
- **Sequenced after A, before E** per the locked sequence above (rides the same corpus load Components A and E already require).

### Component E — Sign-symmetric ensemble eligibility redesign (todo 094, P0)

Root cause (Fable-reviewed, live-DB-verified 2026-07-11): two sign-asymmetric gates exclude 100% of contrarian (negative-IC) features before ensemble weighting ever sees them. Verified: 1,527 eligible rows, zero at `ic_sign = -1`. `alpha_events` is 99.99% long-only (11.81M long vs 1,479 short) as a direct consequence.

**Gate 1 — eligibility** (`services/ensemble_trainer.py:92-96`, `_ELIGIBILITY_BASE_WHERE`): replace `ic_ci_lower > 0` with sign-aware bound checking — `(ic_sign = 1 AND ic_ci_lower > 0) OR (ic_sign = -1 AND ic_ci_upper < 0)`.

**Gate 2 — walk-forward** (`services/ic_engine.py:812-814`): a fold passes if `fold_ic * ic_sign > 0` (sign consistency with the full-sample estimate), not `fold_ic > 0`. Requires a full `ic_engine` re-run — stored `wf_pass_count`/`passes_walkforward` for any currently-excluded negative-IC feature is meaningless under the old criterion.

**Quality weight** (`src/intelligence/ensemble/feature_selector.py:31-38`, `compute_quality_weight()`): `qw = (ic_sign * nearest_ci_bound) * max(sharpe_floor, ic_sign * ic_sharpe)`. **Do NOT implement a naive `abs(ic_sharpe)` fix** — this was proposed, reviewed, and explicitly rejected: it would misapply magnitude weighting to the ~57-row "inconsistent" population (positive full-sample IC, negative window Sharpe — a decay signature, not a contrarian one) and up-weight decayed signals in the wrong direction.

**Score time:** `compute_alpha_score()`'s existing `ic_signs` multiplication (`src/intelligence/ensemble/alpha_score.py:73`) is unchanged — it starts doing the job it was built for but has never executed (dead code today).

**E2 sign-path fix (latent bug, must fix in same effort):** `mean_variance_weights()` must be fed sign-adjusted `ic_sign * ic_shrunk` and must keep its output in positive-magnitude space (matching E1's convention), with sign applied once at score time. Without this, `ensemble_trainer.py:260`'s call to `derive_weights(mv_raw, ...)` would silently re-zero every contrarian feature back out via `derive_weights()`'s own `> 0` filter (`weights.py:51`) — even after Gates 1-2 are fixed. If this isn't fixed alongside Gates 1-2, the post-fix E1-vs-E2 rerun is invalid.

**Interaction audit findings (apply, do not skip):**
- `cluster_deflate_weights()` clusters on `abs(corr)` — already correct for the signed world, no change needed.
- `derive_weights()`'s docstring ("features with non-positive IC Sharpe are excluded") is stale/inaccurate, and its `ic_sharpes` parameter name is misleading (it receives derived quality weights, not raw IC Sharpe). Fix in the same commit as the code change.
- Emission thresholds (`alpha.quant.threshold.{tf}`) and cost hurdles were implicitly calibrated against a score distribution with a 4-23x positive-magnitude skew. Re-measure emission volume post-fix; do not assume thresholds still mean what they meant before.

**Diagnostic sub-task:** check whether the ~57-row "inconsistent" population's positive full-sample IC is concentrated in an early, now-decayed subperiod. If so, add `ic_sign * ic_sharpe_hac > 0` as an eligibility condition to exclude them (resolves the floor question for this population without `abs()`).

**Shadow mode: mandatory, not optional.** This changes champion scoring behavior, eligibility membership, and score distribution simultaneously. Train under a new `weight_version`, score in parallel, run frames + FRAME-04 evaluation on the shadow stream, promote only on evidence. This is the owner's own future live trading capital — no exceptions to shadow-mode-first here.

**Re-run E1-vs-E2 A/B judgment** after this lands — the prior 20/20 E1-win result was produced on an all-long-vs-all-long input where E2's sign-symmetric distinguishing capability was structurally unexercisable. It does not carry forward and must not be cited as settled once the input universe becomes genuinely sign-symmetric.

### Component B — IC decomposition columns (todo 090, medium priority)

New diagnostic columns on `feature_ic_scores`, no gate change: `sign_hit_rate` (directional accuracy / sign agreement fraction) and IC conditional on large `|prediction|` (magnitude alignment). Cheap kernel additions inside the existing corpus computation. Sharpens Phase 143's decay monitors. No structural gate — practically wants a healthy `feature_ic_scores` table (satisfied once Components A/E/F land in the same re-run).

### Component C — Anytime-valid e-values pilot (todo 079, medium-high priority)

- **Scope:** pilot only, `tf=5m` only — do not roll out to all timeframes in this phase. This is genuinely new statistical machinery for the codebase (e-values / anytime-valid inference); the source doc explicitly cautions to pilot before wider rollout.
- **Mechanism:** persist a per-cell e-process updated each corpus rerun (likelihood-ratio or universal-inference e-value on IC sign is sufficient). Promotion requires cumulative e-value > 1/alpha; demotion symmetric. A kernel function (sibling to `ic_math.py`), one new column per cell, manifest plumbing. No new service.
- **Self-verification dependency:** the e-process must be checkable against the canary predictors (Component D) — canary e-values must decay toward zero. Component C therefore depends on Component D landing first (or concurrently, same commit set).
- **Purpose:** hardens the Concept Registry invariant #2 ("no re-roll on same corpus build") into "no free re-roll on *any* build" — evidence compounds across reruns instead of resetting each time.

### Component D — Canary predictors (todo 068, high priority, Component C's dependency)

- **Mechanism:** 5-10 `feature_registry` rows flagged `is_control=true`:
  - Pure noise: seeded RNG columns (seed via APR, same precedent as `HMM_RANDOM_STATE`).
  - Acausal placebo: an existing feature deliberately shifted forward (e.g. `ret_lag_1` from T+2) — must show spectacular IC; calibrates what look-ahead contamination looks like in this exact pipeline.
  - Dead features: a constant and a near-constant column, verifying degenerate-input handling.
- **Excluded from ensemble eligibility** via the existing status filter (`is_control=true` rows never reach `_ELIGIBILITY_BASE_WHERE`).
- **Orchestrator assertion (mandatory, loud failure):** any control feature clearing `ic_ci_lower > 0 AND passes_fdr` in any stratum fails the corpus run loudly — a manifest error, not a warning. Wire this into `ic_engine.py` or the corpus pipeline script.
- No new tables, no new service — this is registry rows + one assertion.

### Corrections and resolved open questions from RESEARCH.md (2026-07-11, resolved by orchestrator before planning — read RESEARCH.md's Pitfalls 1-7 and Open Questions 1-3 for full detail, this section states the resolutions, not the reasoning)

RESEARCH.md (`143.1-RESEARCH.md`) found that this CONTEXT.md's original canonical-ref line citations for Component E's Gate 2, and several scope questions, needed correcting or deciding before task-writing. These are now resolved; the planner should treat the items below as locked, superseding the corresponding line-citations above where they conflict:

1. **Gate 2's actual location (Pitfall 1, CRITICAL):** the walk-forward sign-consistency fix must land in `_compute_cross_sectional_tf()` (~line 1443-1447 in `services/ic_engine.py`), NOT `_compute_symbol_tf()` (~line 812-814, which this CONTEXT.md originally cited). Only `_compute_cross_sectional_tf()`'s output ever carries `symbol='POOLED'`, the only value `_ELIGIBILITY_BASE_WHERE` accepts — fixing only the cited per-symbol block would compile and run with zero effect on `alpha_events`' long/short imbalance, the exact failure mode this phase exists to prevent.

2. **Resolved (was Open Question 2): fix all three `fold_ic > 0` walk-forward blocks** (`_compute_symbol_tf` ~811-814, the daily context-features loop ~1040-1041, `_compute_cross_sectional_tf` ~1443-1447) for sign-consistency, not only the cross-sectional one. Only the cross-sectional block is load-bearing for ensemble eligibility, but all three share the identical bug shape, the fix is cheap (same 3-line change 3 times), and Component A's own "not targeted, not circular" principle argues against leaving two of three identical measurement blocks inconsistently unfixed. This produces correct `passes_walkforward` values for per-symbol diagnostic/dashboard consumers too.

3. **Resolved (was Open Question 1): Component A's "full corpus-wide replacement" scope is `services/ic_engine.py`'s 3 `_fisher_z_ci` call sites only** (lines ~772, ~1009, ~1418). `services/ensemble_ic_engine.py`'s EIC-04 gate CI computation (line ~778) and `scripts/ops/corpus/ops_oos_holdout_eval.py` (line ~213) stay on Fisher-z in this phase — deferred as a follow-up, consistent with this CONTEXT.md's existing deferral of "should EIC-04's PASS verdict be reconsidered" to the project owner. Record this scope boundary explicitly in the methodology-change-ledger entry for Component A (state it, don't let it read as an oversight).

4. **Resolved (was Open Question 3): Component D's "acausal placebo" canary is implemented as a genuine new `FeatureVector` field**, computed in `feature_factory.py` by deliberately mis-pairing an existing feature's value against a forward-shifted return window, uniform with the "pure noise" and "dead feature" canaries — not as a one-off measurement-time diagnostic outside the registry. This keeps all canaries uniformly iterable by the orchestrator's `is_control=true` assertion loop.

5. **Component A is not a same-signature drop-in (Pitfall 2):** `_fisher_z_ci(ic_vector, n)` cannot be swapped in-place — a correct bootstrap needs raw, unranked, paired `(X, Y)` observations, which requires a genuine signature change at all 3 call sites (each already has the raw arrays in scope pre-rank). Plan this as a signature change, not a drop-in.

6. **Component A must avoid the exact pre-ranking bug that caused the original bootstrap's removal (Pitfalls 3-5):** the removed `_circular_block_bootstrap_ic` (git commit `c6f5056b^`, `services/ic_engine.py`, restorable via `git show c6f5056b^:services/ic_engine.py`) resampled already-globally-ranked values and never re-ranked the resampled subset — this is the literal bug the 2026-07-09 diagnostic proved exists. The fix must re-rank inside the bootstrap loop on the resampled subset per iteration (`rankdata(X_raw[idx])`, `rankdata(Y_raw[idx])`). Do NOT literally call `_circular_shift_null` in a loop — that function generates a null distribution (tests "is there a relationship"), not a sampling distribution of the IC point estimate (what a CI needs); only its circular-wrap index-construction mechanic is the reusable pattern. Also reuse the removed version's per-iteration allocation shape (not a single `(n_boot, n_blocks, block_size)` broadcast, which OOMs at production scale under `ProcessPoolExecutor` — ~7.5GB/worker).

7. **Component D's real cost (Pitfall 6, corrects this CONTEXT.md's "cheap"/"registry rows only" framing):** `FeatureRegistryService.load()` enforces a hard row-count-equals-`len(FeatureVector fields)` gate that crashes `ic_engine.py` and `ensemble_trainer.py` at startup if canary rows are added without matching new `FeatureVector` dataclass fields. Component D therefore requires: new `FeatureVector` fields in `src/intelligence/schemas.py`, computation logic in `feature_factory.py`, a migration adding `feature_vectors` columns, AND `feature_registry` metadata rows (status `'candidate'`, never promoted — a second line of defense so `ensemble_trainer.py`'s active-status filter also excludes them). **Consequence for sequencing:** because this needs new `feature_vectors` columns, the "single corpus re-run" this phase bundles into must be a full pipeline run from Step 1 (`backfill_feature_factory.py --compute-only`), not a cheap `ic_engine.py`-only invocation — plan wave/timing accordingly; this is a multi-hour operation, not a quick script.

8. **Component F's implementation path:** use `true_range_pct` (already loaded in `_compute_cross_sectional_tf`'s existing query, raw/non-z-scored, zero marginal query cost) as `trailing_sigma(symbol)`'s proxy, epsilon-guarded division matching the existing `_ret_vol_ratio()` pattern in `feature_factory.py`. Do not use `atr_z` (already z-scored, unusable as a sigma-scale denominator) or build a new rolling-window vol computation (no existing column, would need new SQL window-function work) unless the `true_range_pct` A/B result is inconclusive and a smoothed-window alternative is later warranted.

9. **APR key deprecation-prefix cleanup (not previously noted):** the 6 `alpha.ic.bootstrap_*` APR keys currently carry a `[deprecated]` prefix in `config_schema.description` (added migration 177). Component A's migration must strip this prefix (`UPDATE config_schema SET description = REPLACE(description, '[deprecated] ', '') WHERE config_key IN (...)`) as part of reactivating them, or the config UI keeps surfacing them as unused despite having a real reader again.

10. **E2 sign-path fix requires threading `ic_signs` into `resolve_stratum_weights()`'s signature** (`services/ensemble_trainer.py`, currently not a parameter) — a real, small signature change, not a call-site-only fix. The call becomes `mean_variance_weights(cov_matrix, ic_signs * ic_shrunk, mv_condition_max)`.
