## Decisions Made

- **`feature_ic_scores.ic_mean` does not exist** — the plan's `<interfaces>` block and todo 030's Step 3 SQL both reference `fis.ic_mean`, but the live schema (`\d feature_ic_scores`) has `ic_value`, not `ic_mean`. Used `avg(fis.ic_value)` for the per-tf average-IC query. This is a Rule 1 auto-fix (the plan's literal SQL would crash at runtime against the real schema).
- **Gap verdict uses relative tolerance** (default 1%, computed against `max(|mean_gap|, |mean_nogap|)`) rather than an absolute epsilon, since `return_fast` values are basis-point-scale and a fixed absolute tolerance would misclassify at that scale.
- **Step 0 is a literal snapshot**, not a live recomputation — per the plan's explicit instruction ("Step 0 verdict already recorded in todo 030 ... re-emits the verdict table into its report but writes NO APR"). The 10-row verdict table from todo 030 (run 2026-07-01) is embedded as a module-level constant.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed nonexistent column reference in Step 3 SQL**
- **Found during:** Task 1 (writing Step 3's `feature_ic_scores` query)
- **Issue:** Both the plan's `<interfaces>` block and todo 030's Step 3 SQL reference `fis.ic_mean`, which does not exist in the live `feature_ic_scores` schema (verified via `\d feature_ic_scores` — actual column is `ic_value`). Running the query as specified would raise a Postgres `UndefinedColumnError` at runtime.
- **Fix:** Used `avg(fis.ic_value) AS avg_ic` instead of the plan's literal `avg(fis.ic_mean)`.
- **Files modified:** `scripts/ops/corpus/ops_cost_hurdle_calibration.py`
- **Verification:** Confirmed against live schema via `PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent -c "\d feature_ic_scores"` — `ic_value` present, `ic_mean` absent.
- **Committed in:** `cdfb6853` (Task 1 GREEN commit)
