## Decisions Made
- Clamp SQL runs entirely in Postgres (`LEAST`/`NULLIF`/`::timestamptz`) rather than bash-side date comparison — this makes the empty-oos_start degradation and the malformed-oos_start loud failure both native to the database engine's NULL/type semantics instead of ad hoc bash logic
- The harness imports `_FEATURE_NAMES` from `services.ic_engine` (derived from the `FeatureVector` dataclass) instead of hardcoding the 54 feature column names — stays in sync automatically if the Feature Factory schema changes
- NaN feature values within the OOS-valid window are mean-imputed pre-rank in the harness only (diagnostic robustness); this is intentionally simpler than `ic_engine`'s production degenerate-feature handling since the harness never gates anything
