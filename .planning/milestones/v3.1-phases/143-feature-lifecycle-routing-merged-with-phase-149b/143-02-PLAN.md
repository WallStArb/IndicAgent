<objective>
Amend the EXISTING feature_registry state machine to route feature lifecycle transitions — not build a
parallel one. Amendments per LIFECYCLE-01: (1) automated ic_demotion targets shadow_only, never
deprecated (deprecated becomes operator-only) — demotion stays the single-run materiality gate ROADMAP
specifies (weight x |ic_ci_lower| > alpha.decay.materiality_threshold, decided in Plan 03), no
consecutive-fail counter on top of it; (2) add the missing shadow_only -> active promotion, gated purely
on evidence (>= alpha.decay.recovery_min_passes consecutive passing corpus runs AND
>= alpha.decay.recovery_min_observations new independent observations since demotion, both APR-sourced,
NO calendar cooldown); (3) add consecutive_shadow_passes and observations_since_demotion as REGISTRY
columns. Provide the synchronous record_transition_sync method ic_engine's post-run hook (Plan 03) will
call — the existing async record_transition() cannot run in ic_engine's psycopg2/no-event-loop context.
Drop the three dead decay columns on feature_ic_scores (D3).

REVIEW-DRIVEN CHANGE — pre_shadow_weight is DROPPED (was ROADMAP LIFECYCLE-01 point 3). Cross-AI review
(143-REVIEWS.md HIGH finding 2) flagged that a scalar pre_shadow_weight on feature_registry has no write
path into ensemble_weights. Confirmed against code: services/ensemble_trainer.py is the SOLE writer of
ensemble_weights (line 744, only INSERT in the codebase) and recomputes every weight from scratch each
run — _process_stratum builds quality_weights from THIS run's feature_ic_scores rows (line 577), derives
weights via derive_weights/mean_variance_weights (pure functions of current IC + LW covariance, no prior
weight parameter), and writes ON CONFLICT (...) DO UPDATE SET weight = EXCLUDED.weight (line 748). There
is zero read of any prior weight as a seed/warm-start anywhere in the file. Therefore a "restored"
pre_shadow_weight scalar would be written to a column nothing reads, and is unnecessary: promotion only
needs to flip feature_registry.status back to active — the next ic_engine run then stamps
feature_status_at_eval='active' on that feature's IC rows (ic_engine.py line 1764 builds the status map
from registry status at run start), and the next ensemble_trainer run naturally recomputes a fresh weight
from the feature's current IC. Per Renaissance "ruthlessly eliminate what isn't needed," pre_shadow_weight
is removed from the migration, from record_transition_sync, from is_promotion_eligible, and from
_LOAD_QUERY. Plan 03 restores weight by the status flip + natural recompute, NOT by writing ensemble_weights
(which would violate the sole-writer DAG invariant).

REVIEW-DRIVEN CHANGE (Fable independent review, N1, HIGH) — record_transition_sync now resets BOTH
recovery counters (consecutive_shadow_passes, observations_since_demotion) to 0 whenever a transition's
to_status is shadow_only, in the same UPDATE/transaction as the status change. Without this, the counters
created by migration 216 default to 0 only once (at column creation) and are never zeroed again on
subsequent demotions — a feature that previously satisfied the recovery floors, got promoted back to
active, and later decays a second time would carry consecutive_shadow_passes/observations_since_demotion
values that already cleared the bar, making it trivially re-eligible for promotion after a single passing
run instead of re-earning >= recovery_min_passes + recovery_min_observations from scratch. This is the
exact oscillation failure mode lifecycle routing exists to prevent.

Purpose: Give Plan 03's hook a correct, blocking, transactional, idempotent write path into the one
authoritative state machine, and encode the evidence-only recovery bar so recovered features re-earn their
weight the same way everything else in this codebase does — through ensemble_trainer's next recompute.

Output: 2 migrations, new sync methods + eligibility predicate on FeatureRegistryService, extended unit
tests (TestRecordTransitionSync).

Do NOT: add pre_shadow_weight (dropped, see above); add is_decaying/decay-style columns to
feature_ic_scores (superseded design); add a feature_deprecations table; add a consecutive_shadow_fails
demotion counter (not in locked spec); add a calendar/cooldown clock to promotion; make ic_engine or this
service write ensemble_weights. Do NOT touch the existing async record_transition() /
_write_transition_record() — leave the async path as-is.
</objective>
