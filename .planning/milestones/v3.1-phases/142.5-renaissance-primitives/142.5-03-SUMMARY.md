## Decisions Made

- `ret_autocorr_1`/`ret_autocorr_5` compute an expanding-window Pearson
  autocorrelation over ALL available return history rather than a bounded
  APR-sized rolling sample, since the source spec explicitly labels these
  "Number (definitional)" with the lag as the only parameter — matching the
  `ret_lag_1/2/3` convention exactly. Implemented via an O(n) incremental
  running-sums algorithm (one new pair added per bar) rather than an O(n^2)
  full-recompute-per-bar approach.
- `variance_ratio_fast/slow` implement the classic full-sample Lo-MacKinlay
  variance-ratio specification-test estimator (overlapping N-period
  aggregate return variance divided by N times the 1-period return
  variance), both computed over ALL available history — the source spec
  names "Lo-MacKinlay" explicitly and provides no separate sample-window APR
  key, so using the full available `bars` history (already the compute()
  contract) is the correct, most faithful interpretation.
- `vol_of_vol`, `vol_asymmetry_z`, `hv_z_fast`, `hv_z_slow` all follow the
  "double-duty single window" pattern Plan 02 established for `vol_std_z`:
  the one APR window both computes the base rolling statistic and z-scores
  it against its own trailing history, since the source spec lists each of
  these as "APR-backed (single window)" and Task 3's action text gives each
  only one config field (no separate zscore_window).
- `realized_var_ratio_fast` and `realized_var_ratio_slow` are computed
  identically (both call the same series function with the same
  fast/slow window pair) since the source spec's table literally lists the
  "slow" row's formula as "same" as the "fast" row — followed the spec
  literally rather than inventing an unstated inverse or different window
  pairing.
- Followed Plan 05's precedent of having `compute()` read from the same
  precomputed `_PrecomputedSeries` arrays that `compute_batch()` indexes,
  rather than writing separate "streaming" functions for every primitive —
  this matches the codebase's pre-existing pattern for `ret_skew_z`/
  `ret_acf1_z` (baseline features with no standalone streaming
  implementation at all), extended consistently to all 21 new fields.
