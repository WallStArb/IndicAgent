## Decisions Made

- Reused `_percentile_rank` (already implemented in Plan 02 for
  `vol_percentile`) directly for `_price_percentile` rather than
  reimplementing percentile logic — same scipy-with-fallback pattern applies
  identically to price series.
- `compute()` reads the same precomputed `_PrecomputedSeries` arrays
  (`_series_last(s.<field>, fallback)`) that `compute_batch()` indexes
  (`s.<field>[i]`), rather than calling the streaming primitive functions
  directly on bounded window slices as the plan's action text literally
  described. This guarantees exact parity between the two paths by
  construction (same array) instead of relying on two independent
  implementations agreeing — verified via a manual spot-check at bar indices
  30/60/90/119 (not just the last bar), confirming fast/slow windows produce
  genuinely different values when the window boundary matters (e.g.
  `dist_from_high` differs at bar 90 but coincides at other bars, which is
  the correct behavior for a random-walk series where the recent-N-bar max
  sometimes equals the older-N-bar max).
- `new_high_flag`/`new_low_flag` use an epsilon-tolerant comparison
  (`close >= rolling_high - eps`) instead of exact equality, matching the
  codebase's `EPSILON_TOLERANCE` convention for financial float comparisons
  (CLAUDE.md) — correctly fires because the current bar's own high/low is
  always part of its own rolling window.
- Split migration 206 into two commits (Task 3: columns, Task 4: APR seeds)
  by writing the schema-only version first, then appending the APR section
  — matching the plan's task granularity exactly rather than combining them
  into one commit.
