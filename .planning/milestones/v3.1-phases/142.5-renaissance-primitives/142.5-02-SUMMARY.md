## Decisions Made

- Interpreted `vol_range_ratio` as the raw per-bar ratio (`V_t/(H-L)`)
  normalized against its own trailing-window mean, rather than a z-score —
  this is the only reading that simultaneously satisfies the test's "unbounded
  positive" assertion and its "0.0 on degenerate range" edge case (a degenerate
  numerator of 0 on the current bar always yields 0.0 after division,
  regardless of the window mean).
- `vol_std_z` uses one APR window for both the internal rolling-std
  computation and the outer z-score, matching the source doc's "single
  window" designation for this primitive (distinct from `atr_z`/`gap_z`,
  which use two separate windows for the same two-stage pattern).
- Followed the plan's literal cold-start fallback table for
  `_cold_start_vector()` even where it differs from a primitive's own
  internal window-insufficiency guard (`vol_trend_ratio` = 0.0 in
  `_cold_start_vector()` vs. 1.0 when `compute()` has bars but an
  insufficient window) — these are two distinct code paths and the plan
  specifies them independently.
- `_mfi`/`_mfi_series_full` compute the "rising" flag per bar against its
  immediate predecessor (requiring `w+1` bars of typical price), rather than
  only comparing bars within the trailing window — this correctly attributes
  a valid rising/falling determination to every bar in the money-flow sum
  instead of leaving the earliest in-window bar's direction undefined.

**2. [Rule 1 - Bug] `np.where` RuntimeWarning on degenerate H==L bars in `vol_range_ratio`**
- **Found during:** First full-suite verification pass after Task 4/6 wiring
- **Issue:** `_vol_range_ratio`/`_vol_range_ratio_series_full` computed
  `volumes / ranges` inside `np.where(ranges > eps, volumes / ranges, 0.0)`;
  numpy evaluates the division for every element before masking, producing
  `RuntimeWarning: divide by zero encountered in divide` whenever any bar had
  `H == L` (visible in `test_bar_anatomy_primitives`'s degenerate-bar case,
  which reuses the same synthetic bar generator).
- **Fix:** Guarded the divisor with a nested `np.where(ranges > eps, ranges, 1.0)`
  so the division is never actually by zero, in both the streaming and batch
  functions.
- **Files modified:** `src/intelligence/feature_factory.py`
- **Verification:** `pytest tests/unit/test_feature_factory.py -q` — no
  RuntimeWarning in the output; all previously-passing tests still pass.
