# Plan: Phase 083-07 — UAT Gap Closure

## Goal
Fix 3 UAT failures from Phase 083 observability hardening.

## Gaps to Close

### Gap 1 (major) — OTel MeterProvider never initialized
**Root cause:** `src/observability/otel.py:43` checks `__class__.__name__ == "ProxyMeterProvider"` but the SDK's actual default class is named `_ProxyMeterProvider`. Condition is always False; real MeterProvider never set; all metrics drop silently.

**Fix:** Replace the fragile string-name check with an `isinstance` guard against the real SDK MeterProvider class — if the current provider is NOT already a real `MeterProvider`, initialize one.

### Gap 2 (major) — DLQ drain service inactive
**Root cause:** Service was never enabled or started after deployment. Also has `StartLimitIntervalSec` in `[Service]` section (systemd ignores it there — must be in `[Unit]`).

**Fix:** (a) Move `StartLimitIntervalSec` to `[Unit]` section in the service file and copy to `/etc/systemd/system/`. (b) `sudo systemctl daemon-reload && sudo systemctl enable --now indicagent-dlq-drain`.

### Gap 3 (minor) — 3 orphaned Redpanda topics not deleted
**Root cause:** Topic deletion was incomplete during phase execution. Three topics remain: `intelligence.signal.audit`, `market.data.quality`, `system.health.events`.

**Fix:** `docker exec redpanda rpk topic delete intelligence.signal.audit market.data.quality system.health.events`
