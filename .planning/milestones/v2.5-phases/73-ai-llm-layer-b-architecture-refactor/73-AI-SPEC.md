## 1. System Classification

**System Type:** Multi-Agent (Hybrid) — alpha multiplier agents + narrative generation agent

**Description:**
IndicAgent's AI/LLM layer augments a quantitative trading signal pipeline (I1–I7) with LLM-driven alpha multipliers and market narrative. Alpha agents (skeptic, correlation, volume) produce multipliers (0.5–1.5×) applied to I7 signal confidence scores before aggregation and position sizing. A narrative agent generates market context prose for 5m+ timeframes for display. All agents run in shadow mode until Spearman correlation gates pass (ρ ≥ 0.15, n ≥ 30, p < 0.05 against realized PnL-R outcomes). "Good" is: zero shadow-bypasses, every LLM call in the audit trail, agents graduating and auto-demoting based purely on statistical evidence, and per-bar dispatch completing within latency budget.

**Critical Failure Modes:**
1. An alpha agent influencing live position sizing before Spearman gates pass (shadow_only=False before graduation)
2. LLM calls missing from the llm_calls audit trail (caller-driven publish omitted — MiFID II compliance gap)
3. Cache key collision returning a stale multiplier computed for a different symbol or market state
4. Narrative agent firing on 1m bars — saturates Ollama/OpenRouter at ~55 LLM calls/min with zero signal value
5. Graduation evaluating only aggregate Spearman rho, masking a negative per-regime correlation in the currently active regime

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Systematic quantitative trading / algorithmic finance (intraday futures and equities)

**User Population:** A systematic trader running automated intraday strategies on futures and equities. The trader monitors agent graduation status and signal quality dashboards but does not intervene in individual trade decisions. The AI layer is one component of a multi-tier quantitative pipeline — the trader interacts with aggregate performance metrics and shadow-mode graduation logs, not individual LLM outputs.

**Stakes Level:** High — incorrect alpha multipliers applied before statistical validation can amplify bad signals into real position-sizing decisions. Shadow-mode default provides a structural buffer, but the graduation gate is the critical control point. Once an agent graduates, its multipliers directly influence trade sizing.

**Output Consequence:** Alpha agents produce multipliers (0.5–1.5x) applied to I7 signal confidence scores. Those adjusted confidence scores feed the signal aggregator, which selects the winning signal per bar and determines position sizing. A multiplier that is systematically wrong in one regime (e.g., trending vs. mean-reversion) will silently amplify losses over many bars before appearing in PnL outcome data. Narrative agent output is informational display text only — no live trade influence.

### Known Failure Modes in This Domain

1. **Premature graduation amplifying regime-specific losses.** An agent showing positive Spearman correlation on aggregate data may be negative in the regime currently active (e.g., low-volatility mean-reversion). If graduation evaluates only aggregate rho without regime segmentation, the agent graduates and amplifies signals in the precise conditions where it destroys alpha. This is the systematic form of the failure mode identified in TradeTrap research — losses accumulate gradually, not as abrupt failures.

2. **Silent audit gaps from caller-driven publish pattern.** The existing architecture requires each caller to explicitly publish LLM call metadata. Any new agent author who does not know to call the publish function leaves all their LLM calls outside the audit trail. Under MiFID II and EU AI Act record-keeping requirements, this constitutes a compliance gap. The defect is invisible until an external audit.

3. **Narrative 1m bar cost spiral.** Without a timeframe gate, the narrative agent fires on every 1m bar for every symbol with a winning signal. At 55 symbols x multiple signals per bar, this generates hundreds of LLM calls per minute — saturating the local Ollama provider, driving all calls to the paid OpenRouter fallback, and producing market context prose for sub-minute bars where LLM latency exceeds the bar interval itself. The resulting narrative is stale by the time it is generated.

4. **Cross-symbol cache collision producing wrong multipliers.** With the 200-character cache key truncation (defect D-08), two prompts that share an identical 200-char prefix — but diverge in price level, volume, or symbol-specific data appended later — resolve to the same cache entry. An alpha agent computing for CL crude oil futures may receive a cached response built from ES S&P data. The multiplier returned is numerically valid but semantically incorrect, and the error produces no exception or warning.

### Regulatory / Compliance Context

**MiFID II Article 17 (EU) — Algorithmic Trading Record-Keeping:** Investment firms engaged in algorithmic trading must store time-sequenced records of all algorithmic decisions for a minimum of five years. This applies to the LLM layer because alpha multiplier agents constitute algorithmic decision components that influence order generation. The `llm_calls` table is the system's mechanism for satisfying this requirement — gaps in that table are a direct compliance exposure.

**EU AI Act (2024, phased enforcement):** Algorithmic trading systems that meet the EU AI Act definition of an AI system (which LLM-based multiplier agents do) must comply with transparency, audit, and risk management requirements in addition to MiFID II obligations. Shadow-mode gating with documented graduation criteria is consistent with EU AI Act risk management obligations.

**FCA Multi-Firm Review of Algorithmic Trading Controls (2025):** UK FCA observations identify audit trail completeness and algorithm inventory management as the top control gaps across reviewed firms. The auto-audit fix (D-06) directly addresses the audit trail finding. The module reorganization (mandate-based groups with clear ownership) addresses algorithm inventory management.

**Scope note:** This system is currently operated as an internal proprietary trading tool by a single systematic trader (brandon.goyette@deltainvestment.com), not as a regulated trading venue or third-party service. Full MiFID II registration obligations do not apply at this scale, but the record-keeping and audit trail practices are directly relevant as professional standard regardless of registration threshold.

## 2. Framework Decision

**Selected Framework:** Custom Agent Architecture (BaseAIAgent ABC + BaseGroupService dispatcher — bespoke, no external framework)

**Version:** N/A — bespoke implementation in src/core/ai/ and src/intelligence/ai/

**Rationale:**
Phase 73 is a structural refactor of an existing bespoke AI layer. All architectural decisions are pre-decided in the design spec: LLM provider chain (Ollama gemma4:e4b local-first, OpenRouter cloud fallback via src/core/llm/chain.py), agent base classes (BaseAIAgent ABC, BaseGroupService dispatcher), and mandate-based group organization. No external orchestration framework is introduced — the system deliberately avoids framework dependencies in the AI layer to maintain import boundary discipline (no pipeline/ or plugin imports from AI layer) and keep compute agents DB/framework-ignorant.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangGraph (already in requirements.txt) | Stateful graph model maps to BaseGroupService dispatch pattern but would bleed into hot-path compute layer, violating import boundary discipline; bespoke dispatcher is lighter and enforceable |
| LangChain | Adds unnecessary abstraction over an already-working LLMProviderChain; would introduce external state model incompatible with Kafka-first architecture |

**Vendor Lock-In Accepted:** No — bespoke implementation, Ollama local-first, model-agnostic design

### Entry Point Pattern

The minimum implementation for a new alpha agent:

```python
# src/intelligence/ai/alpha/my_agent.py
from __future__ import annotations

import json
from datetime import UTC, datetime

from src.core.ai.base_agent import BaseAIAgent
from src.core.ai.context import AIContext, Tier
from src.core.ai.output import AgentOutput
from src.core.llm.chain import LLMProviderChain

_SYSTEM_PROMPT = (
    "You are a quantitative trading analyst. "
    "Respond with valid JSON only: {\"multiplier\": float}. "
    "No markdown, no explanation. multiplier range: 0.5 to 1.5."
)


class MyAlphaComputeAgent(BaseAIAgent):
    agent_id = "my_alpha"          # unique across all groups
    group = "alpha"
    # Declare only the tiers this agent reads.
    # AIContextCache populates nothing else — keeps context tight.
    tiers_needed = frozenset({Tier.I4, Tier.I7})
    shadow_only = True             # NEVER set False manually — graduation_loop owns this
    latency_budget_ms = 3000.0     # SafeAgentWrapper enforces this as asyncio timeout

    def __init__(self, llm_chain: LLMProviderChain) -> None:
        self._chain = llm_chain

    async def _compute(self, context: AIContext) -> AgentOutput:
        # context.i4 and context.i7 are populated because tiers_needed declares them.
        # context.i1, context.i6 etc. are None — not declared, never built.
        if context.i4 is None:
            return self._neutral(error="no_i4_context", latency_ms=0.0)

        prompt = (
            f"Symbol: {context.symbol} {context.timeframe}\n"
            f"Regime: {context.i4.hmm_regime}\n"
            f"Trend regime: {context.i4.trend_regime}\n"
            f"Signal: {context.i7.winner_plugin if context.i7 else 'none'}\n"
            "Assess whether to amplify or reduce this signal's weight."
        )

        text = await self._chain.generate(
            prompt=prompt,
            system=_SYSTEM_PROMPT,
            max_tokens=64,         # JSON only — never leave unbounded
            timeout=self.latency_budget_ms / 1000.0,
            audit_context={        # required after D-06 fix — auto-audit fires from chain.py
                "signal_id": str(context.signal_id),
                "agent_id": self.agent_id,
                "symbol": context.symbol,
                "timeframe": context.timeframe,
            },
        )

        multiplier = 1.0  # neutral fallback
        if text:
            try:
                multiplier = float(json.loads(text)["multiplier"])
                multiplier = max(0.5, min(1.5, multiplier))  # clamp to valid range
            except Exception:
                pass  # parse failure -> neutral multiplier, no raise

        return AgentOutput(
            agent_id=self.agent_id,
            group=self.group,
            signal_id=context.signal_id,
            symbol=context.symbol,
            timeframe=context.timeframe,
            ts=context.ts,
            output_type="multiplier",
            payload={"multiplier": multiplier},
            shadow_only=self.shadow_only,
            latency_ms=0.0,  # BaseAIAgent.compute() wrapper sets the real value
        )
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `BaseAIAgent` ABC | Abstract base class for all agents. `compute()` is the concrete timing + error capture wrapper; `_compute()` is the abstract method you implement. `compute()` attaches `latency_ms` and catches all exceptions into a neutral `AgentOutput`. Never override `compute()`. | Extend this for every new agent (alpha, narrative, risk). Implement only `_compute()`. |
| `BaseGroupService` | Shared dispatcher that owns all infrastructure: Kafka consumers/producer, DB pool, LLM chain, `AIContextCache`, and `graduation_loop`. Subclasses declare three abstract properties: `agents`, `trigger_topics`, `output_topic`. Everything else is inherited. | Extend this once per agent group. Adding a new group = ~25 lines. Never re-implement Kafka or LLM plumbing per-group. |
| `AIContext` (frozen Pydantic) | Immutable context object passed to each agent. Universal fields (`symbol`, `timeframe`, `ts`, `signal_id`, `trigger`) always present. Tier sub-objects (`i4`, `i6`, `i7`, etc.) are `None` unless the agent declared them in `tiers_needed`. Frozen — use `model_copy(update={...})` to produce modified instances. | `AIContextCache.build(symbol, tf, agent.tiers_needed)` produces one per agent per dispatch. Agents read fields directly; they never mutate context. |
| `AgentOutput` | Universal envelope returned by every agent, including error/neutral paths. `output_type` identifies payload shape ("multiplier", "narrative", "risk_score", "neutral"). `payload` is an untyped dict — the group aggregator interprets it; the dispatcher does not. | Returned from every `_compute()` call. Infrastructure (dispatcher, `SafeAgentWrapper`, graduation task, `llm_writer_agent`) handles `AgentOutput` without knowing `payload` internals. |
| `SafeAgentWrapper` | Wraps any `BaseAIAgent` with `asyncio.wait_for(agent.compute(ctx), timeout=budget_s)`. On timeout or exception, returns a neutral `AgentOutput` so one failing agent never blocks the group. | Used implicitly by `BaseGroupService._handle_trigger` — callers do not instantiate it directly. Understand it when setting `latency_budget_ms` per agent. |
| `Tier` enum | `str` Enum (`BAR`, `I1`, `I2`, `I3`, `I4`, `I5`, `I6`, `I7`). Declares which intelligence tiers an agent needs. `AIContextCache.build()` unpacks only declared tiers from the cached `IntelligenceEvent`. | Declare as `tiers_needed = frozenset({Tier.I4, Tier.I7})` on the agent class. Omitting a tier = `None` in context at runtime, not an error. |
| `graduation_loop` | Background asyncio task (every 15 min) running when `has_graduation=True`. Queries `signal_transform_log` for the agent, calls `graduation.evaluate_all()`, auto-flips `agent.shadow_only = False` when Spearman gates pass (rho >= 0.15, n >= 30, p < 0.05). Also auto-demotes if performance degrades. | Runs automatically in `BaseGroupService._run()`. No agent-level code required. Set `has_graduation=False` for informational-only groups (e.g., narrative). |

### Common Pitfalls

1. **Dead rate limiter (D-04).** `RateLimiter.acquire()` is a correct sliding-window implementation (RPM + TPM), but `LLMProviderChain.generate()` currently never calls it. The `_rate_limiters` dict is built from settings but never consulted. Every LLM call runs with zero throttling regardless of settings. Fix: call `await limiter.acquire(tokens=max_tokens)` at the start of `generate()` before the cache lookup. The existing `RateLimiter` code needs no changes — only the call site in `chain.py` is missing.

2. **Cache key truncation causes cross-symbol collisions (D-08).** `SemanticCache._key()` currently hashes `f"{system}|{prompt[:200]}|{model}"`. Two prompts that share an identical 200-char prefix but differ in symbol-specific content appended later hash identically. In production with 55 symbols sharing identical system prompts and common prompt prefixes, CL crude and ES S&P prompts can collide and return each other's cached multipliers. Fix: remove `[:200]` — hash the full prompt string.

3. **Guardrails false-confidence when no schema registered (D-05).** The current `chain.py` branch is `if self._call_type and self._call_type in _guardrails._schemas` — so when no schema is registered for a `call_type`, guardrails are silently skipped and the caller receives an unvalidated response with no indication. The branch also accesses `_guardrails._schemas` as a private attribute from outside the class. Fix: remove the check against `_schemas`; if no schema is registered, `_guardrails.validate()` already returns `None` — just skip calling it.

4. **`shadow_only=True` must be a class-level declaration.** Every `BaseAIAgent` subclass must explicitly declare `shadow_only = True` at class level. If the attribute is omitted, Python will look up the MRO and may find a `False` value, or the graduation loop's `if agent.shadow_only` check will behave unexpectedly. Never rely on inheritance for a security-critical flag.

5. **Accessing private cache internals (D-10).** The existing `_find_lead_context` reaches into `_context_cache._cache` directly. Any internal rename breaks this silently with no test failure. Fix: expose `AIContextCache.get_lead(symbol, tf) -> AIContext | None` as a public method and call that.

6. **Mutation on a frozen Pydantic model.** `AIContext` and `AgentOutput` use `model_config = ConfigDict(frozen=True)`. Setting `context.symbol = "X"` raises `ValidationError` at runtime — not a helpful error. To produce a modified copy, use `model.model_copy(update={"field": value})`. This pattern is already used in `SwarmBaseAgent.compute()` to attach `latency_ms` to the result.

7. **Watchdog without sd_notify (D-09).** Any systemd unit with `WatchdogSec` and `NotifyAccess=main` will be killed and restarted on the watchdog interval if the Python process does not call `sd_notify("WATCHDOG=1")`. Current agents do not implement `sd_notify`. Do not add watchdog settings to new unit files — this violates the CLAUDE.md systemd watchdog discipline rule and the existing `swarm_orchestrator` unit is being deleted precisely because it has this defect.

## 4. Implementation Guidance

**Model Configuration:**

Primary: Ollama `gemma4:e4b` running locally (AMD ROCm iGPU, Docker `:11434`). 60s timeout for narrative generation (prose output); 3–5s for alpha agent calls (64-token JSON responses).

Cloud fallback: OpenRouter free-tier models, configured via `settings.openrouter_models` (comma-separated slugs). Activated when Ollama is unavailable or slow; suppressed entirely when `_budget.is_exceeded()`.

```python
# LLMProviderChain construction in BaseGroupService._setup():
from src.core.llm.chain import LLMProviderChain

self._llm_chain = LLMProviderChain(
    call_type="alpha",       # or "narrative" — governs guardrails schema + cache TTL
    settings=self._settings,
    producer=self._producer, # Kafka producer for auto-audit publish (D-06)
    cache_ttl=300.0,         # 5-min TTL; 0 disables cache for eval runs
)
```

Provider priority order (set by `LLMProviderChain._build_providers()`):
1. `OpenRouterProvider` — each slug in `settings.openrouter_models` in declared order
2. `OllamaProvider` — local `gemma4:e4b` fallback; always last

Daily token budget: `TokenBudget(daily_token_limit=1_000_000, cost_per_1k=0.001)`. When exceeded, all calls route to Ollama-only regardless of provider order. This is a module-level singleton in `chain.py` shared across all `LLMProviderChain` instances.

**Core Pattern:**

`BaseGroupService._handle_trigger()` is the canonical dispatch loop. The pattern is: build context per agent, gather in parallel, publish results, then aggregate if the group produces an aggregate output.

```python
# Inside BaseGroupService._handle_trigger() — the universal dispatch loop
async def _handle_trigger(self, event: IntelligenceEvent) -> None:
    # 1. Build per-agent context — only declared tiers populated, nothing else
    wrapped = [
        (agent, SafeAgentWrapper(agent))
        for agent in self.agents
        if (ctx := self._context_cache.build(event.symbol, event.tf, agent.tiers_needed))
        is not None
    ]

    # 2. Parallel dispatch — SafeAgentWrapper enforces latency_budget_ms per agent.
    # asyncio.gather total latency = max(individual latencies), not sum.
    # return_exceptions=False is safe: SafeAgentWrapper never raises.
    outputs: list[AgentOutput] = await asyncio.gather(
        *[wrapper.compute(ctx) for _, wrapper, ctx in wrapped]
    )

    # 3. Fan-out: publish each agent output to output_topic (per-agent audit trail)
    for output in outputs:
        await self._producer.send(self.output_topic, value=output.model_dump())

    # 4. Aggregate (alpha group only)
    if self.aggregate_topic is not None:
        aggregate = self._aggregator.aggregate(outputs)
        await self._producer.send(self.aggregate_topic, value=aggregate)

    # 5. Shadow recording (ShadowRecorder.record per output — feeds graduation gate)
    for output in outputs:
        self._shadow_recorder.record(output)
```

`_run()` launches three concurrent asyncio tasks inside an `asyncio.TaskGroup`:

```python
async def _run(self) -> None:
    async with asyncio.TaskGroup() as tg:
        tg.create_task(self._bar_loop())         # updates AIContextCache on each IntelligenceEvent
        tg.create_task(self._trigger_loop())     # dispatches agents on trigger events
        if self.has_graduation:
            tg.create_task(self._graduation_loop())  # background: auto-flips shadow_only every 15 min
    # TaskGroup propagates exceptions from any task — all three run until one fails or group is cancelled
```

**Tool Use:**

No external tool-use framework. All intelligence data is delivered to agents via `AIContext` — agents do not call external APIs or query the database directly. The `LLMProviderChain` is the only "external" call from inside `_compute()`.

The `AIContextCache` is the context delivery mechanism: `bar_loop` calls `cache.update(event)` on every `IntelligenceEvent`; `_handle_trigger` calls `cache.build(symbol, tf, tiers_needed)` to assemble each agent's context on demand.

**State Management:**

Three state layers, each with a defined owner:

1. `AIContextCache` — in-process, asyncio-safe, per `(symbol, tf)` key. Populated by `bar_loop`; read by `_handle_trigger`. TTL is 300 seconds — stale entries are rejected at `build()` with a structured log warning and a `None` return (the agent is skipped for that trigger). Can be seeded from DB on startup via `seed_from_db_row()` using `types.SimpleNamespace` proxies (see existing `SwarmContextCache.seed_from_db_row` pattern).

2. `agent.shadow_only` — mutable boolean on each agent instance. Owned exclusively by `_graduation_loop`. Set to `True` at class definition, flipped to `False` by graduation, flipped back to `True` on demotion. Never set manually. This is the only per-agent state the dispatcher carries between trigger events.

3. `signal_transform_log` (TimescaleDB) — append-only audit trail written by `ShadowRecorder` on every `AgentOutput`. The graduation loop reads this table to compute Spearman rho between agent multipliers and realized PnL-R outcomes. No other persistent state is owned by the AI layer.

**Context Window Strategy:**

`AIContextCache.build()` with `tiers_needed` filtering is the primary context window management primitive. An agent declaring `frozenset({Tier.I7})` receives only the I7 signal fields in its `AIContext` — the full `IntelligenceEvent` (I1 indicator soup, I4 GARCH/Kalman state, I6 CTF sub-scores) is not materialized into the context. This keeps prompt payloads small and cache hit rates high.

Even within a declared tier, include only fields the LLM can meaningfully act on. `context.i4` contains 13 fields — most alpha agents need `hmm_regime`, `trend_regime`, and `vol_regime`. Including all 13 adds tokens without adding signal.

The narrative TF gate (`NarrativeComputeAgent._compute()` returns neutral immediately for timeframes outside `{"5m", "15m", "1h", "4h", "1d"}`) prevents LLM calls on 1m bars entirely — eliminating ~70% of potential calls at zero information cost.

Token budget per call by agent type:

| Agent type | max_tokens | Rationale |
|------------|-----------|-----------|
| Alpha agents (skeptic, correlation, volume) | 64 | JSON multiplier: `{"multiplier": 0.8}` — 10–20 tokens actual |
| Narrative agent | 512 | Prose narrative with structured JSON wrapper |

Always specify `max_tokens` explicitly in every `generate()` call. Unbounded generation on local Ollama with 55 symbols and 5 timeframes saturates the GPU and drives all remaining calls to the cloud fallback.

## 4b. AI Systems Best Practices

> Cross-cutting patterns specific to this bespoke Multi-Agent architecture with Ollama/OpenRouter and Python asyncio.

### 4b.1 Structured Outputs with Pydantic

`AgentOutput` is the universal output envelope. Its `payload` dict is intentionally untyped at the infrastructure level so the dispatcher, `SafeAgentWrapper`, graduation task, and `llm_writer_agent` handle all output types without knowing payload internals. Payload typing lives at the consumer: the alpha aggregator reads `payload["multiplier"]`; the narrative consumer reads `payload["text"]`. Adding a new output type requires zero changes to infrastructure.

For LLM response validation, register a Pydantic schema with `GuardrailsValidator` at startup. After the D-05 fix, `LLMProviderChain.generate()` calls `validate()` only when a schema is registered:

```python
# In BaseGroupService._setup() — register schema for guardrails
from pydantic import BaseModel, field_validator
from src.core.llm.guardrails import _guardrails  # module-level singleton in chain.py


class AlphaMultiplierSchema(BaseModel):
    multiplier: float

    @field_validator("multiplier")
    @classmethod
    def clamp_range(cls, v: float) -> float:
        if not (0.5 <= v <= 1.5):
            raise ValueError(f"multiplier {v} outside valid range [0.5, 1.5]")
        return round(v, 4)


# Register once at group service startup — all calls with call_type="alpha" are validated
_guardrails.register("alpha", AlphaMultiplierSchema)
```

Retry behavior: `LLMProviderChain.generate()` returns `None` on guardrails rejection. Agents must handle `None` and return neutral — do not retry inline. The circuit breaker in `LLMChain` handles provider-level retries (different provider on failure). Record the rejection in `AgentOutput.error` so it appears in the shadow recording and audit log.

```python
# Correct pattern in _compute() — handle None, no inline retry
text = await self._chain.generate(
    prompt=prompt,
    system=_SYSTEM_PROMPT,
    max_tokens=64,
    timeout=self.latency_budget_ms / 1000.0,
    audit_context={
        "signal_id": str(context.signal_id),
        "agent_id": self.agent_id,
        "symbol": context.symbol,
        "timeframe": context.timeframe,
    },
)
if text is None:
    # All providers failed or guardrails rejected — neutral multiplier, no raise
    return self._neutral(error="llm_none", latency_ms=0.0)

try:
    data = AlphaMultiplierSchema.model_validate_json(text)
except Exception as exc:
    return self._neutral(error=f"parse_failed:{exc}", latency_ms=0.0)

return AgentOutput(
    agent_id=self.agent_id,
    group=self.group,
    signal_id=context.signal_id,
    symbol=context.symbol,
    timeframe=context.timeframe,
    ts=context.ts,
    output_type="multiplier",
    payload={"multiplier": data.multiplier},
    shadow_only=self.shadow_only,
    latency_ms=0.0,  # BaseAIAgent.compute() sets the real value
)
```

### 4b.2 Async-First Design

The entire AI layer is asyncio-native. Key rules for this architecture:

`asyncio.gather()` is the group dispatch primitive. The alpha group runs `SkepticAgent`, `CorrelationAgent`, and `VolumeAgent` concurrently. Total group latency is `max(individual latencies)`, not `sum()`. With three agents at 3000ms budget, worst-case group latency is 3000ms, not 9000ms.

`asyncio.wait_for()` inside `SafeAgentWrapper` enforces `latency_budget_ms` per agent. On `asyncio.TimeoutError`, the wrapper returns a neutral `AgentOutput` — the gather continues with the remaining agents unaffected. This is the correct isolation boundary: one slow LLM call does not block the group.

The one common mistake: calling `asyncio.run()` inside a running event loop. The `bar_loop`, `trigger_loop`, and `graduation_loop` all run as tasks inside `BaseGroupService._run()`. Do not call `asyncio.run()` from any of these coroutines — use `await coroutine()` or `asyncio.create_task()`. For test code, use `pytest-asyncio` with `@pytest.mark.asyncio` rather than wrapping in `asyncio.run()`.

`graduation_loop` background task — the correct pattern for periodic work that must not kill the group on error:

```python
async def _graduation_loop(self) -> None:
    while True:
        await asyncio.sleep(900)  # 15 minutes
        try:
            for agent in self.agents:
                df = await self._query_signal_transform_log(agent.agent_id)
                result = graduation.evaluate_all(df)
                if result["is_graduated"] and agent.shadow_only:
                    agent.shadow_only = False
                    logger.info(
                        "graduation.promoted",
                        agent_id=agent.agent_id,
                        spearman_rho=result["spearman_rho"],
                        n=result["n"],
                        p_value=result["p_value"],
                    )
                elif not result["is_graduated"] and not agent.shadow_only and result.get("degraded"):
                    agent.shadow_only = True
                    logger.warning("graduation.demoted", agent_id=agent.agent_id)
        except Exception:
            # Graduation failure must not kill the group service dispatch loop
            logger.exception("graduation_loop.error")
```

Stream vs. await: use `await` (non-streaming) for all alpha agents — the response must be fully received before Pydantic validation runs. Use streaming only if building a UX that progressively renders narrative text in the dashboard. For background services writing to Kafka, always await the complete response.

### 4b.3 Prompt Engineering Discipline

**System vs. user prompt separation.** The `system` parameter is a static string defining role, output format, and constraints. It is stable across calls and benefits maximally from semantic caching — two calls with the same system and same market state hash identically and return the cached response. The `prompt` parameter is the per-bar dynamic payload — it changes on every call and is the cache discriminator.

```python
# Correct: system is stable across all calls, prompt is dynamic per bar
_SYSTEM_PROMPT = (
    "You are a quantitative trading analyst. "
    "Respond with valid JSON only: {\"multiplier\": float}. "
    "multiplier must be between 0.5 and 1.5. No markdown or explanation."
)

async def _compute(self, context: AIContext) -> AgentOutput:
    # Dynamic content goes in prompt, not system
    prompt = (
        f"Symbol: {context.symbol} {context.timeframe}\n"
        f"Regime: hmm={context.i4.hmm_regime} trend={context.i4.trend_regime:.3f}\n"
        f"Volatility: {context.i4.vol_regime:.3f} (pct={context.i4.vol_percentile:.1f})\n"
        f"Signal: {context.i7.winner_plugin if context.i7 else 'none'} "
        f"dir={context.i7.winner_direction if context.i7 else 0}\n"
        "Should this signal be amplified or reduced given current regime?"
    )
```

**Few-shot examples.** Inline static examples in the system prompt for alpha agents — response format is short (a single JSON object) so 2–3 examples fit within budget. Do not use dynamic retrieval for alpha agents. For narrative agents, inline 2–3 example (regime, signal type, narrative) pairs to establish prose tone and length.

**Token budget — always explicit.** Every `generate()` call must pass `max_tokens`. Alpha agents: 64 tokens (JSON only — actual usage is 10–20 tokens). Narrative agents: 512 tokens (prose + JSON wrapper). The `TokenBudget` tracks estimated spend (1 token = ~4 chars) and switches to Ollama-only when the daily cap is reached — a missing `max_tokens` means the budget tracker has no upper bound to record against.

**Regime-aware prompts.** Include `hmm_regime` and `trend_regime` from `context.i4` in every alpha agent prompt. A momentum signal in a ranging regime (hmm_regime=0) warrants a different multiplier than in a trending regime (hmm_regime=1/2). Stripping regime context produces regime-blind multipliers that defeat the purpose of the alpha layer and produce positive overall correlation masking regime-specific losses.

### 4b.4 Context Window Management

**Tier filtering as the primary control.** `AIContextCache.build(symbol, tf, tiers_needed)` is the context window management primitive. An agent declaring `frozenset({Tier.I7})` receives only I7 signal fields in its `AIContext` — the full `IntelligenceEvent` with I1–I6 data is not materialized. This means:
- Prompt size is bounded by agent declaration, not by what the cache holds
- Agents cannot accidentally include data from tiers they did not declare
- Adding a new tier to the cache schema does not affect existing agents

**Narrative TF gate — hard reject before LLM call:**

```python
_NARRATIVE_TFS = frozenset({"5m", "15m", "1h", "4h", "1d"})


async def _compute(self, context: AIContext) -> AgentOutput:
    if context.timeframe not in _NARRATIVE_TFS:
        # Return neutral immediately — zero LLM cost, zero latency impact
        return AgentOutput(
            agent_id=self.agent_id,
            group=self.group,
            signal_id=context.signal_id,
            symbol=context.symbol,
            timeframe=context.timeframe,
            ts=context.ts,
            output_type="neutral",
            payload={},
            shadow_only=self.shadow_only,
            latency_ms=0.0,
            error=f"tf_gate:{context.timeframe}",
        )
    # Proceed to LLM call only for 5m+ timeframes
```

At 55 symbols on 1m bars, the ungated narrative service generates 55+ LLM calls per minute. The gate eliminates ~70% of calls (1m is the highest-frequency timeframe) at zero information cost.

**Semantic cache as context deduplication.** After the D-08 fix (full-prompt SHA-256), the cache correctly deduplicates prompts with identical market state. In low-volatility sessions where regime and signal features are stable across multiple bars, alpha agent cache hit rates can reach 30–50% — eliminating those LLM calls entirely. The 300-second TTL (configurable via `cache_ttl`) balances cache effectiveness against stale market data risk.

### 4b.5 Cost and Latency Budget

**Per-call cost at production volume (55 symbols, 5 timeframes, I7 winner signals):**

| Agent | Trigger frequency | max_tokens | Est. tokens/call | Est. daily tokens |
|-------|------------------|-----------|-----------------|-------------------|
| SkepticAgent | ~5 calls/min (signal-triggered) | 64 | ~120 | ~86,400 |
| CorrelationAgent | ~5 calls/min | 64 | ~120 | ~86,400 |
| VolumeAgent | ~5 calls/min | 64 | ~120 | ~86,400 |
| NarrativeAgent | ~5 calls/min (5m+ gated) | 512 | ~800 | ~576,000 |
| **Total** | | | | ~835,200/day |

At OpenRouter free tier: $0. At paid tiers (~$0.001/1k tokens): ~$0.84/day. Well within `TokenBudget(daily_token_limit=1_000_000)`.

**Latency budget enforcement:**

- Per-agent: `SafeAgentWrapper` enforces `latency_budget_ms` via `asyncio.wait_for()`. Default is 5000ms. Tune to 3000ms for alpha agents once baseline P95 latency is measured on production hardware.
- Per-group: `asyncio.gather()` makes group latency = max(agent latencies). With three alpha agents at 3000ms, worst-case group latency is 3000ms, not 9000ms.
- Ollama baseline on AMD ROCm iGPU: `gemma4:e4b` at 64 tokens out = ~800ms measured. At 512 tokens (narrative) = ~4–8s. Size `latency_budget_ms` to 2x measured P95, not average.

**Three-layer caching strategy:**

1. `SemanticCache` (in-process, LRU + TTL): catches identical `prompt + system + model` combinations within the 5-minute window. After D-08 fix, keys are collision-free. Primary latency reducer for stable market conditions.

2. `TokenBudget.is_exceeded()` (daily cap): once the daily token budget is hit, all calls are routed to local Ollama regardless of provider order. Zero cloud cost in budget-exceeded state; performance degrades gracefully to local-only.

3. `RateLimiter.acquire(tokens=max_tokens)` (per-provider, after D-04 fix): sliding-window limiter (RPM + TPM) prevents burst exhaustion on OpenRouter. Configure via `settings.LLM_RATE_LIMITS = {"openrouter": {"rpm": 60, "tpm": 100_000}}`. The limiter backs off exponentially (`asyncio.sleep`) when limits are approached — it does not drop requests.

**Sub-task model routing:** Alpha agents (short JSON responses, fast decisions) use local `gemma4:e4b` as primary fallback. If adding a binary classification or routing sub-task in the future (e.g., "is this bar's regime ambiguous?"), use Ollama `phi4-mini:3.8b` — faster inference, lower VRAM, suitable for classification-only calls.

## 6. Guardrails

> This system is not user-facing in the consumer sense — the output reaches a single systematic trader via dashboards and position-sizing automation. "Online" guardrails here mean guardrails that run on every bar dispatch and block or neutralize bad outputs before they reach the signal aggregator. "Offline" means sampled batch checks feeding the improvement loop.

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Shadow mode enforcement** | Every `AgentOutput` produced by any agent — checked before passing output to the SwarmAggregator | If `agent.shadow_only == True`, the aggregator ignores the multiplier and uses 1.0 (neutral). Output is still recorded to `signal_transform_log` for graduation data collection. No exception raised — shadow agents participate in the dispatch loop silently. |
| **Multiplier range clamp** | Any alpha agent `AgentOutput` with `output_type="multiplier"` that reaches the aggregator | `AlphaMultiplierSchema` (Pydantic) registered with `GuardrailsValidator` enforces `0.5 <= multiplier <= 1.5`. Values outside range fail schema validation; `LLMProviderChain.generate()` returns `None`; agent returns neutral. An out-of-range multiplier never reaches the aggregator. |
| **SafeAgentWrapper timeout** | Any `_compute()` call that exceeds `latency_budget_ms` | `asyncio.wait_for()` cancels the coroutine and `SafeAgentWrapper` returns a neutral `AgentOutput` with `error="timeout"`. The dispatch loop continues with remaining agents. One timed-out agent never blocks the bar cycle. |
| **Narrative TF gate** | Every `NarrativeComputeAgent._compute()` call | If `context.timeframe not in {"5m", "15m", "1h", "4h", "1d"}`, return neutral immediately before any LLM call. Zero tokens consumed. Prevents 1m bar cost spiral (failure mode 3 from Section 1b). |
| **Import boundary enforcement** (build-time) | CI/CD pipeline on every commit to `src/core/ai/` or `src/intelligence/ai/` | `tests/unit/ai/test_import_boundaries.py` fails the build if any forbidden import is found. Prevents AI layer from acquiring intelligence pipeline dependencies that would make it impossible to test in isolation. |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| **Spearman graduation gate** | `graduation_loop` queries all rows in `signal_transform_log` for each agent every 15 minutes; evaluated on full population (not sampled) | If a graduated agent's rolling rho drops below 0.10 (below gate threshold with degradation margin) over the most recent 30 outcomes, `graduation_loop` sets `agent.shadow_only = True` (auto-demotion) and emits a structured log `graduation.demoted` event. Agent returns to shadow mode until it re-qualifies. |
| **Per-regime rho disaggregation** | Same 15-minute graduation query; `graduation.evaluate_all()` returns per-regime rho in addition to aggregate | If aggregate rho passes (>= 0.15) but any single regime rho is negative (< 0.0) with n >= 15 in that regime, graduation is blocked. Trader receives a structured log entry `graduation.regime_veto` with the offending regime and its rho. Human review: trader decides whether to retrain or adjust prompt to address the regime-specific weakness. |
| **LLM audit completeness check** | Scheduled query every 15 minutes: count rows in `llm_calls` WHERE `ts > now() - interval '15 min'`; compare to Kafka consumer group lag delta for `topic_intelligence_i7_signals` during the same window | If the gap between expected calls (trigger events) and actual audit rows exceeds 0 for two consecutive 15-minute windows, emit a structlog `audit.gap_detected` warning with the missing count. This indicates a new agent was added without `audit_context`, or the auto-audit fix (D-06) regressed. |
| **Token budget utilization** | Checked on every `LLMProviderChain.generate()` call by `TokenBudget.is_exceeded()`; daily rollup logged at midnight UTC | If daily token spend exceeds 80% of `daily_token_limit` by 2pm ET, emit `token_budget.warn` — signals high narrative call volume or a missing TF gate. If 100% is hit, all calls route to Ollama-only (auto-degradation, not a crash). |
| **LLM call multiplier deviation sampling** | Sample `AgentOutput` rows from `signal_transform_log` WHERE `abs(multiplier - 1.0) > 0.3` (i.e., the agent is actively pushing signals, not hovering near neutral) | Human review: trader examines the 10 most recent high-deviation outputs per agent per week. Purpose: detect prompt drift or regime mismatch producing extreme multipliers before they appear in PnL data. Not automated — manual spot-check on the Grafana dashboard. |

## 7. Production Monitoring

**Tracing Tool:** structlog (existing, already in all services) + OpenTelemetry SDK (already in `requirements.txt`: `opentelemetry-sdk>=1.20.0`, `opentelemetry-exporter-otlp-proto-http>=1.20.0`). No external platform is introduced — all trace data flows to the existing observability stack (Prometheus + Grafana at `192.168.68.53`).

The AI layer emits structured log events on every significant state transition. These are the authoritative trace events:

| Event key | Emitted by | Fields |
|-----------|-----------|--------|
| `graduation.promoted` | `_graduation_loop` | `agent_id`, `spearman_rho`, `n`, `p_value`, `regime_rhos` |
| `graduation.demoted` | `_graduation_loop` | `agent_id`, `trigger_rho`, `n` |
| `graduation.regime_veto` | `_graduation_loop` | `agent_id`, `offending_regime`, `regime_rho`, `regime_n` |
| `agent.timeout` | `SafeAgentWrapper` | `agent_id`, `symbol`, `timeframe`, `latency_budget_ms` |
| `agent.neutral` | `BaseAIAgent._neutral()` | `agent_id`, `symbol`, `timeframe`, `error` |
| `audit.gap_detected` | audit completeness check | `expected_count`, `actual_count`, `window_start`, `window_end` |
| `token_budget.warn` | `TokenBudget` | `used_tokens`, `daily_limit`, `pct_used` |
| `cache.collision_impossible` | `SemanticCache._key()` (debug) | omit in prod; enabled only when `LOG_LEVEL=DEBUG` |

**Key Metrics to Track:**

1. **`agent_latency_ms` by `agent_id` and `timeframe`** — P50, P95, P99 per rolling 1-hour window. Source: `AgentOutput.latency_ms` recorded in `signal_transform_log`. Alert when P95 for any alpha agent exceeds `latency_budget_ms`.

2. **`graduation_status` by `agent_id`** — boolean (shadow=1, graduated=0) tracked as a gauge in Prometheus. Changes are driven by `graduation.promoted` / `graduation.demoted` log events. Allows the trader to see at a glance which agents are live vs. shadow on the Grafana dashboard.

3. **`llm_cache_hit_rate` by `agent_id`** — ratio of cache hits (no actual LLM call) to total `generate()` calls. Source: `llm_calls` table: `count(WHERE cache_hit=true) / count(*)`. A hit rate below 10% for alpha agents in low-volatility sessions indicates prompt construction is not stable (high cache miss = high cost + latency).

4. **`audit_row_gap`** — count of trigger events in `topic_intelligence_i7_signals` minus count of rows in `llm_calls` for the same 15-minute window. Must be 0. Source: offline flywheel query (Section 6). Non-zero value triggers `audit.gap_detected` log event.

5. **`token_budget_utilization_pct`** — daily tokens consumed / `daily_token_limit` as a percentage, refreshed hourly. Source: `TokenBudget` module-level counter. Grafana panel with threshold lines at 50%, 80%, 100%. At 100%, all calls route to Ollama-only automatically.

**Alert Thresholds:**

| Alert | Condition | Severity | Action |
|-------|-----------|----------|--------|
| Agent latency breach | P95 `latency_ms` for any alpha agent > `latency_budget_ms` for 2 consecutive hours | High | Check Ollama container health; check if OpenRouter rate limiter is throttling and backing off; review logs for `agent.timeout` events |
| Audit gap detected | `audit_row_gap` > 0 for two consecutive 15-min windows | High | Inspect `llm_calls` table for the affected window; check if a new agent was added without `audit_context` in `generate()` call; verify D-06 fix is present in `chain.py` |
| Agent demoted | `graduation.demoted` log event emitted | Medium | Trader reviews per-regime rho breakdown in `signal_transform_log`; no automated action — demotion is the correct safe response; investigation is discretionary |
| Token budget at 80% by 2pm ET | `token_budget_utilization_pct >= 80` before 14:00 ET | Medium | Check narrative agent call volume; confirm TF gate is active (no 1m bar narrative calls); consider reducing `cache_ttl` to improve cache hit rate |
| Shadow gate violation | `graduation.promoted` log event with `n < 30` or `p_value >= 0.05` | Critical | This should be impossible if `graduation.evaluate_all()` enforces the gate correctly — but if it fires, immediately set `agent.shadow_only = True` manually and open a bug. Indicates a regression in `src/intelligence/swarm/graduation.py`. |

**Smart Sampling Strategy:**

Priority ordering for human review of `signal_transform_log` rows:

1. **High-deviation multipliers** — rows WHERE `abs(multiplier - 1.0) > 0.3`. These are bars where the agent is actively pushing signals far from neutral. Review the prompt inputs (symbol, timeframe, hmm_regime, winner_plugin) to confirm the agent is responding to genuine regime signal rather than noise.

2. **Graduation transition events** — all rows surrounding a `graduation.promoted` or `graduation.demoted` event (the 10 bars before and after the transition). Purpose: confirm that the bars triggering graduation reflect genuine market conditions, not an outlier period.

3. **Timeout events** — all `agent.neutral` rows WHERE `error="timeout"`. A cluster of timeouts on a specific symbol or timeframe indicates the LLM provider is overloaded on that input type (often long narrative prompts on complex regimes). Use to tune `latency_budget_ms` or adjust prompt length.

4. **Audit gap windows** — all `llm_calls` rows in the 15 minutes surrounding an `audit.gap_detected` event. Cross-reference with `signal_transform_log` to identify which agent's calls are missing from the audit trail.

Sampling is manual (trader-initiated from Grafana dashboard) — no automated LLM judge is used, because the ground truth for correctness is the numerical `pnl_r` outcome in `signal_ledger`, not a subjective quality judgment.
