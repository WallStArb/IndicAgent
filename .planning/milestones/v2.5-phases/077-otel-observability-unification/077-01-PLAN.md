Per D-01: Deploy OTel Collector as infrastructure only, no agent changes.

1. Create `production/otel-collector-config.yaml` with the following content:

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 10s
  resource:
    attributes:
      - key: deployment.environment
        value: ${INDICAGENT_ENV}
        action: upsert

exporters:
  prometheusremotewrite:
    endpoint: http://prometheus:9090/api/v1/write
    resource_to_telemetry_conversion:
      enabled: true
  otlp/tempo:
    endpoint: tempo:4317
    tls:
      insecure: true
  loki:
    endpoint: http://loki:3100/loki/api/v1/push
    default_labels_enabled:
      exporter: false

service:
  pipelines:
    metrics:
      receivers: [otlp]
      processors: [batch, resource]
      exporters: [prometheusremotewrite]
    traces:
      receivers: [otlp]
      processors: [batch, resource]
      exporters: [otlp/tempo]
    logs:
      receivers: [otlp]
      processors: [batch, resource]
      exporters: [loki]
```

NOTE: The design doc shows `prometheus` exporter (which exposes a scrape endpoint), but Prometheus Remote Write is the correct choice for pushing metrics into Prometheus. The design doc's scrape approach also works; use `prometheusremotewrite` for push-based architecture which avoids the need for Prometheus to discover scrape targets.

2. Add the OTel Collector service to `production/docker-compose.yml` after the `tempo` service block:

```yaml
  otel-collector:
    image: otel/opentelemetry-collector-contrib:0.102.0
    container_name: indicagent-otel-collector
    restart: unless-stopped
    command: ["--config=/etc/otelcol/config.yaml"]
    environment:
      - INDICAGENT_ENV=${INDICAGENT_ENV:-dev}
    ports:
      - "4317:4317"   # OTLP gRPC receiver
      - "4318:4318"   # OTLP HTTP receiver (existing agents already send here)
    volumes:
      - ./otel-collector-config.yaml:/etc/otelcol/config.yaml:ro
    depends_on:
      - prometheus
      - tempo
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

3. Also add Loki service to docker-compose.yml (needed by the logs pipeline in the Collector config):

```yaml
  loki:
    image: grafana/loki:2.9.6
    container_name: indicagent-loki
    restart: unless-stopped
    ports:
      - "3100:3100"
    volumes:
      - loki-data:/loki
```

4. Add `loki-data` to the `volumes:` section at the bottom of docker-compose.yml.

Per D-01 and the Prometheus config collapse design: configure Prometheus to receive
metrics from OTel Collector via remote_write, and add Loki as a Grafana datasource.

1. Update `production/prometheus.yml` to add `remote_write` config that receives from
   the OTel Collector. The existing per-service scrape targets remain for now (removed
   in Plan 03 per D-03). Add the remote_write block at the top level:

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

remote_write:
  - url: "http://otel-collector:8889/api/v1/write"
    # OTel Collector pushes to Prometheus; this is for bidirectional compatibility

# Existing scrape configs remain unchanged for now (removed in Plan 03)
```

IMPORTANT: The design doc says "Prometheus exporter :8889" which means the Collector
EXPOSES metrics for Prometheus to scrape. The simpler approach is to keep the existing
Prometheus scrape targets AND add a single scrape target for the Collector's Prometheus
exporter at port 8889. This way we can see Collector metrics immediately.

So actually: add ONE new scrape target to prometheus.yml pointing at the Collector's
built-in Prometheus exporter (which the Collector uses to self-report its own health
metrics), but do NOT remove existing targets yet:

Append to the scrape_configs list in prometheus.yml:
```yaml
  - job_name: "otel-collector"
    static_configs:
      - targets: ["host.docker.internal:8889"]
```

But WAIT -- the OTel Collector config uses `prometheusremotewrite` exporter which PUSHES
to Prometheus. Prometheus needs to be configured to accept remote_write. This requires
adding the remote_write receiver to Prometheus startup flags.

The simpler path that matches the design doc's intent: use the `prometheus` exporter in
the Collector config (not `prometheusremotewrite`) so the Collector exposes a scrape
endpoint at :8889, and Prometheus scrapes it. This preserves existing dashboard queries.

REVISE the Collector config from Task 1: change the metrics exporter from
`prometheusremotewrite` to `prometheus`:

```yaml
      insecure: true
  loki:
    endpoint: http://loki:3100/loki/api/v1/push
    default_labels_enabled:
      exporter: false
```

And update the metrics pipeline:
```yaml
service:
  pipelines:
    metrics:
      receivers: [otlp]
      processors: [batch, resource]
      exporters: [prometheus]
```

Also expose port 8889 in the docker-compose OTel Collector service:
Add `- "8889:8889"` to ports list.
