<threat_model>
ASVS L1 considerations:
- **V1.4 Trust boundary**: Inference agent receives AIContext from internal swarm dispatch (trusted source). Loads model artifacts from MLflow loopback (no network).
- **V5 Input validation**: Feature extraction clamps and defaults missing fields to safe values (0.0 for missing numeric shadow keys; empty string / unknown for categoricals). No untrusted user input on inference path.
- **V7 Error handling**: Inference exceptions caught and converted to _neutral(error=...) — never raise to caller. Avoid crashing the swarm dispatch loop.
- **V8 Data protection**: Models are LightGBM artifacts (binary trees); no PII embedded.
- **V10 Communications**: SIGUSR1 is local-process; only the systemd unit's user can send it (`systemctl kill` requires either root or the unit's user).
- **V12 Files & resources**: Signal handler must be sync; async work scheduled via asyncio.create_task (per Pitfall 5). The loop MUST be captured via asyncio.get_running_loop() inside _setup() (not get_event_loop()) — otherwise the wrong loop is bound and the handler never fires.
- **Threat: SIGUSR1 abuse triggering memory churn** — Mitigation: SIGUSR1 only sent by the trusted training agent via systemctl; rate-limited by the once-nightly timer cadence. No external surface.
- **Threat: Bad model produces extreme multipliers** — Mitigation: clamp(multiplier, 0.0, 2.0) in _build_multiplier_output; shadow_only=True means it never actually affects trade decisions until promotion (a separate manual gate, not in this plan).
- **Threat: Race during hot-swap** — Mitigation: model dict assignment is atomic in CPython; brief inconsistency during reload is acceptable for shadow-only inference.
- **Threat: Training/inference feature-shape drift** — Mitigation: self._feature_cols is loaded from the MLflow shap_importance.json artifact authored by Plan 03 training; _extract_features projects to this exact column order. If artifact is unavailable, agent falls back to default ordering and logs a warning (degraded but safe).
</threat_model>
