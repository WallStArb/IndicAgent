<objective>
Settings Singleton in BaseAgent — Eliminate Boilerplate and Fix Config-Before-Super Bug

Implement Change 1 from design doc: BaseAgent.__init__() sets `self.settings = get_settings()` using the existing singleton in `src/config/settings.py`. Rename all `self._settings` references in agents to `self.settings`. BaseProviderAgent passes `settings=get_settings()` to super().__init__() to avoid duplicate creation.

Purpose: Every agent independently writes `self._settings = Settings()` — 15+ times, with inconsistent placement (before super, after super, in `_setup()`). This is a maintenance smell and a config-before-super ordering gotcha (see `base_provider_agent.py` comments at line 59).

Output: All agents inherit `self.settings` from BaseAgent. No `self._settings` references remain. BaseProviderAgent uses passthrough pattern.
</objective>
