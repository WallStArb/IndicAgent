Fix the false-connected state bug in `production/daemons/high_frequency_tws_daemon.py`.

**Location:** Main loop, around line 394–408 (the `while self.running:` block).

**Current code (lines ~394–408):**
```python
while self.running:
    try:
        # Attempt reconnect if disconnected
        if not self.connected:
            logger.warning("Disconnected from TWS, attempting reconnect...")
            ...
        now_ts = time.time()
        ...
```

**Change:** Insert a secondary check BEFORE the existing `if not self.connected:` block. This check uses `self.provider.is_connected()` to detect cases where `self.connected` is True but the provider has silently dropped its connection (e.g., overnight TWS reset):

```python
# Secondary disconnect detection: catches false-connected state
# (self.connected=True but provider actually disconnected)
if self.connected and self.provider and not self.provider.is_connected():
    logger.warning(
        "Provider reports disconnected — correcting false-connected state",
        connected_flag=self.connected,
    )
    self.connected = False
    self._on_disconnected()
```

Add this block immediately before the `if not self.connected:` block. Do NOT change any other logic.

**Tests** — create `tests/unit/daemon_tests/test_tws_daemon_reconnect.py` (create `tests/unit/daemon_tests/__init__.py` if it doesn't exist):

Test cases:
1. `test_false_connected_triggers_reconnect`: When `self.connected=True` but `provider.is_connected()` returns False, verify `self.connected` gets set to False and `_on_disconnected()` is called.
2. `test_true_connected_no_trigger`: When both `self.connected=True` and `provider.is_connected()` returns True, verify `_on_disconnected()` is NOT called.
3. `test_disconnected_flag_no_secondary_check`: When `self.connected=False`, the secondary check (which guards on `self.connected and self.provider`) is skipped — provider.is_connected() is not called.

Use `unittest.mock.MagicMock` for the provider. Do NOT import `ib_insync` in tests. Instantiate the daemon class directly with mock dependencies or test the logic in isolation via a small helper function if the class constructor is too heavyweight.

Note: If `HighFrequencyTWSDaemon.__init__` is complex, extract the secondary check into a method `_check_provider_connection(self)` and test that method directly. The goal is testing the boolean logic, not starting the full daemon.
