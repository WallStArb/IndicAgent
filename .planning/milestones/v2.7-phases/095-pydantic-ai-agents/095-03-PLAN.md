<objective>
Implement `LLMAdapter` as a pydantic-ai `FunctionModel` factory (`make_llm_adapter()`) at `src/core/ai/llm_adapter.py`. The returned FunctionModel routes pydantic-ai's structured-output request through `LLMProviderChain.generate()`, passing the result_type JSON schema as `response_format` (grammar-constrained Ollama output) and a per-request `audit_context` (preserving the `llm_calls` trail and circuit breaking).

Purpose: This is the only novel bridge code in the phase (RESEARCH.md). pydantic-ai owns validation and retry; `LLMProviderChain` owns circuit breaking, rate limiting, budget, and audit. The bridge intercepts pydantic-ai's ToolOutput-mode request, extracts the schema, calls the chain, and wraps the raw JSON in a `ToolCallPart` that pydantic-ai validates against `result_type`.

Retry-audit policy (REVIEWS HIGH): one `call_id` per physical LLM request. The closure receives an `audit_context` *base* (built by `_run_typed()` without a meaningful call_id), and each `_request` invocation copies that base and stamps a fresh `call_id` + `called_at`. If pydantic-ai retries output validation it calls `_request` again, producing a distinct `llm_calls` row instead of a duplicate sharing one `call_id`. This makes each chain.generate() audit row map 1:1 to a real model call.

Output: `make_llm_adapter()` returning a `FunctionModel`; per-call construction with audit_context base captured by closure and per-request call_id minting; explicit ModelRequest part decoding (latest UserPromptPart -> prompt, caller `system` preserved); a fail-fast guard when output_tools is empty; a prose-stripping JSON fallback for gemma4 preambles; unit tests covering schema extraction, response_format pass-through, audit pass-through, per-request call_id uniqueness, ToolCallPart wrapping, the None-response path, the empty-output_tools guard, and prose-fallback extraction.
</objective>

    Define `def make_llm_adapter(worker_context, system, max_tokens, timeout, audit_context) -> FunctionModel` with types `worker_context: "WorkerContext"`, `system: str`, `max_tokens: int`, `timeout: float`, `audit_context: dict[str, Any]`. The `audit_context` passed in is the BASE (agent_id, symbol, signal_id, prompt_version, regime, prompt, etc.); its call_id/called_at are placeholders the adapter overwrites per physical request. Capture `chain = worker_context.llm_chain` and `audit_base = audit_context` in the closure.

    Define an inner `async def _request(messages: list, info: AgentInfo) -> ModelResponse`:
    1. Output-tool guard (REVIEWS HIGH/MEDIUM): if `not info.output_tools`, raise `RuntimeError("typed output tool schema missing - result_type may be unset or pydantic-ai selected text mode")`. Do NOT silently default a schema. After the guard set `tool = info.output_tools[0]`, `tool_name = tool.name`, `schema = tool.parameters_json_schema`.
    2. Prompt extraction (REVIEWS HIGH - adapter request shape): the prompt sent to the chain is the latest user message. Iterate `reversed(messages)`; for each `ModelRequest`, scan its `.parts` in reverse for the first `UserPromptPart` and take its `.content` as `prompt`; break once found. Ignore all other part types (SystemPromptPart, ToolReturnPart, RetryPromptPart) and any non-`ModelRequest` message - they do not contribute to the prompt. Do NOT derive the system prompt from message parts: the caller-provided `system` string (closured) is always the system prompt. If `UserPromptPart.content` is a list (multipart), join only the `str` elements with a single space and ignore non-string (binary/image) parts. If no UserPromptPart is found at all, set `prompt = ""`.
    3. Per-request audit (REVIEWS HIGH - retry call_id policy): build `req_audit = dict(audit_base)`, then set `req_audit["call_id"] = str(uuid4())` and `req_audit["called_at"] = format_iso_ts(datetime.now(UTC))`. This guarantees one call_id per physical chain.generate() call; a pydantic-ai validation retry re-enters `_request` and mints a NEW call_id so audit rows never collide.
    4. Build a `response_format` value from `schema` suitable for litellm/Ollama JSON-schema grammar: `{"type": "json_schema", "json_schema": {"name": tool_name, "schema": schema}}`.
    5. Call `raw = await chain.generate(prompt=prompt, system=system, max_tokens=max_tokens, timeout=timeout, audit_context=req_audit, response_format=response_format)`. Do NOT call litellm/acompletion directly (D-06, anti-pattern).
    6. If `raw is None`, return `ModelResponse(parts=[])` (pydantic-ai will surface this as a model-behavior error which the agent's compute() wrapper converts to neutral - covered by Plan 05).
    7. Prose-strip fallback (REVIEWS LOW - gemma4 preambles): define a module-level helper `_extract_json(text: str) -> str` that returns the substring from the first `{` to the last `}` (inclusive) when both are present and the opening brace precedes the closing brace; otherwise returns the original text unchanged. Apply `args = _extract_json(raw)`. This is a safety net only - response_format already constrains gemma4; do NOT json.loads the result (Pitfall 4 - pydantic-ai validates the args string itself).
    8. Return `ModelResponse(parts=[ToolCallPart(tool_name=tool_name, args=args, tool_call_id=str(uuid4()))])`.

    Return `FunctionModel(_request)`. Add a module + function docstring noting: the FunctionModel is single-use per `_run_typed()` call (Pitfall 3); `audit_context` is a base whose call_id/called_at are stamped fresh per physical request (one call_id per LLM call, not per `_run_typed()`); `system` is always the caller-provided string (never from message parts); and the empty-output_tools guard fails fast.
