# Phase 100.5: Plugin Infrastructure Hardening

**Goal:** Eliminate silent failure in the plugin system by enforcing structural contracts, wiring production-grade observability, and migrating 24 incremental plugins from ad-hoc state management to IncrementalMixin.

**Depends on:** Phase 100 (IncrementalMixin + ATR reference), Phase 093 (mathematical correctness)

**Spec:** `docs/plans/2026-05-22-plugin-infrastructure-hardening-design.md`
**Implementation plan:** `docs/plans/2026-05-22-plugin-infrastructure-hardening.md`

**Architecture:** Three mutually reinforcing layers:
1. PluginObserver — single recording surface for all plugin metrics, injected into PluginExecutor
2. IncrementalMixin — owns the _state lifecycle for every incremental plugin
3. emit_signal() — enforces validate_signal() at construction so invalid signals never enter the pipeline

Frame pre-validation in the executor removes 104 in-plugin df guards.

---

## BLOCKING CONSTRAINTS

- **gauge-type-split:** `gauge()` in `metrics.py` returns `UpDownCounter` (use `.add(delta)`). `point_gauge()` returns `create_gauge` (use `.set(value)`). Do NOT change `gauge()` — 21 `.add()` callers exist. Only use `point_gauge()` for new absolute-value metrics.
- **No callback injection:** `_used_incremental` flows through result dict as a key, extracted by executor. Do NOT inject callbacks into plugins for telemetry — plugins are module-level singletons.
- **emit_signal() hard enforcement:** validate_signal() MUST be called at construction inside emit_signal() and MUST raise ValueError on failure. No soft warning.

**Files:** `src/intelligence/pipeline/executor.py`, `tests/unit/pipeline_helpers.py`, `tests/unit/intelligence/test_executor_pre_validation.py`

- Rewrite `_collect_plugin_results` to use observer methods instead of inline metric recording
- Add frame pre-validation (min_lookback check) in `run_i1`, `run_tier`, `run_i7_plugins` with opt-out:
  ```python
  df_main = frames.get("main")
  min_lb = getattr(plugin, "min_lookback", 0)
  allows_partial = getattr(plugin, "allows_partial_output", False)
  if not allows_partial and (df_main is None or len(df_main) < min_lb):
      self._observer.record_warmup_skip(plugin_name, tier_key)
      continue
  ```
  Plugins may set `allows_partial_output = True` to opt out of the warmup skip (e.g. session-boundary plugins that emit valid partial outputs). Default is `False` — safe for all existing plugins.
- Update `pipeline_helpers.py` to inject `NoOpPluginObserver()` at executor construction

### Task 14 — Migrate Group 3: Model-state plugins (BOCPD, HMM, GARCH, Kalman)
**Files:** `src/intelligence/context/bocpd_plugin.py`, `hmm_plugin.py`, `garch_plugin.py`, `kalman_plugin.py`
**Note:** Location is `src/intelligence/context/` — NOT features/
- BOCPD: O(R) run-length posteriors — document algorithmic bound in source
- HMM: O(K^2) Viterbi state — document algorithmic bound in source
- GARCH: rolling variance state
- Kalman: state covariance matrix
- **Plugin-specific equivalence strategies** (not uniform 0.1% tolerance):
  - GARCH/Kalman: seed with fixed random state, compare variance/covariance outputs with `atol=1e-6` after 200-bar burn-in (deterministic given same seed)
  - HMM: compare regime labels (not raw probabilities) for bars 200+ — `assert migrated_regime == legacy_regime` for ≥95% of stable-region bars
  - BOCPD: compare run-length MAP estimate and posterior normalization (`sum(posteriors) ≈ 1.0, atol=1e-5`) — not numeric output values
- 2000-bar synthetic frames (longer history required for model convergence)
