<objective>
Add the three-line oneshot completion counter contract (D-06) to ml_training, shadow_auditor,
and roll_batch, AND guarantee delivery of that counter to the OTLP collector by explicitly
flushing the OTel meter provider before process exit. Grafana can then alert if any oneshot
has not emitted a success in >25h even when systemd reports `inactive (dead)` correctly
(which is normal between runs).

Why the flush matters (REVIEWS.md Plan 06 HIGH concern): a short-lived oneshot can exit
before the OTLP exporter's default periodic export window fires. Without
`provider.force_flush()` + `provider.shutdown()`, the `job_completed_total` counter is
emitted in-process but never reaches the collector, defeating the entire SLO.

Purpose: HEAL-03 closes one more visibility gap - timer-triggered scripts are invisible
to RED dashboards unless they emit a single counter at exit AND drain the exporter.

Output: Three oneshot scripts emit JOB_COMPLETED_TOTAL on every run with status label
and explicitly drain the OTel provider so the counter actually reaches the collector.
</objective>
