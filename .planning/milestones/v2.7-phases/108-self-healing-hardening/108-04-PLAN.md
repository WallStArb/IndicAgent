<objective>
Close two HEAL-03/HEAL-04 visibility gaps:
1. Stuck consumer detection: lower ServiceAuditor stall threshold from 360s to 120s and
   add an OTel counter so Grafana can alert on stall rate (HEAL-04 half). Sanity-check
   that 120s is greater than the observed inter-message interval for every monitored
   daemon (CONTEXT.md D-23 plus current journal sample) before deploying.
2. Circuit breaker open events: detect plugin CB transitions to OPEN in the intelligence
   pipeline bar loop and emit a structured log per CLAUDE.md structlog conventions
   (HEAL-03). The pipeline accesses CB state through a new `circuit_breakers` read-only
   property on PluginExecutor (not the private `_plugin_circuit_breakers` attribute) and
   wraps the scan in try/except so any unexpected CB object shape can never break the
   bar loop. Replace the deferred Kafka system.health.events route with the OTel gauge
   already in place from Phase 106 (D-18) plus structured logs.
3. End-to-end latency: add bar_e2e_latency_ms histogram (D-15) reusing the existing
   pipeline_latency_ms value.

Purpose: Three observability signals land in the same files; consolidating keeps the
restart blast radius small (one restart of service-auditor, one of intelligence-pipeline).

Output: PluginExecutor has a public `circuit_breakers` property; ServiceAuditor restarts
stalled agents 3x faster with OTel visibility; pipeline emits structured CB-open logs
Grafana Loki can alert on; end-to-end bar latency available as a single histogram for
SLO alerting.
