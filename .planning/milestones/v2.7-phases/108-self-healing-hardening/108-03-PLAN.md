<objective>
Add DB-level DLQ quarantine to prevent infinite retry loops from hiding behind silence.
After this plan: every DLQ message increments a rolling 24h counter keyed by
(agent, source_topic, error_type); the counter is seeded from dlq_events on startup so
restarts cannot reset it; when the cumulative count strictly exceeds DLQ_MAX_RETRIES=3
(the 4th occurrence in 24h is the first to be quarantined), the row is stored with
quarantined=TRUE and the dlq_quarantine_total OTel counter fires so Grafana can alert.

Quarantine threshold semantics (unambiguous):
- `DLQ_MAX_RETRIES = 3`
- Quarantine condition: `count > DLQ_MAX_RETRIES` (i.e. count >= 4).
- 1st, 2nd, 3rd occurrence in the 24h window: NOT quarantined.
- 4th and subsequent occurrences: quarantined = TRUE.

Purpose: HEAL-04 (DLQ quarantine half). No re-delivery loop exists today; quarantine is
DB-level counting, not a Kafka dead-final topic (deferred per D-22).

Output: Migration 099 adds the column, DLQDrainAgent extended with DB-seeded occurrence
counter + DLQ_QUARANTINE_TOTAL increment, and the INSERT writes the new quarantined flag.
</objective>
