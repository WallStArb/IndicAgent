<objective>
Wire `LiteLLMBackend` into `LLMProviderChain`, remove the now-dead `_build_providers` method and old provider imports from `chain.py`, delete the `OllamaProvider`/`OpenRouterProvider`/`LLMChain` class definitions from `providers.py`, audit and fix the rate-limiter key format for LiteLLM provider ID strings, and update the existing provider unit tests to match. Run a live smoke test against Ollama and restart the affected services.

**Scope:** LLM-INFRA-05 requires zero class references in production code. Delete the three dead classes from `providers.py` and rewrite or remove any unit tests that directly cover them — those tests no longer have a subject to test. Tests covering `LLMProviderChain` behavior (via `LiteLLMBackend`) are migrated to `test_litellm_backend.py` in Plan 01.

**Rate-limiter key audit:** The old providers used colon-style IDs (`ollama:nemotron-3-nano:4b`); LiteLLM uses slash-style (`ollama/nemotron-3-nano:4b`). If `LLM_RATE_LIMITS` in `chain.py` still uses colon-format keys, per-provider rate limiting silently falls back to the first limiter for all providers. This must be fixed.
</objective>

<threat_model>
ASVS L1 threats for this plan:

- **Regression: _generate_inner interface breakage (mitigated):** Plan 01 ensures LiteLLMBackend.generate() returns `str | None` matching LLMChain's interface. The only change to _generate_inner is indirect (it now calls LiteLLMBackend instead of LLMChain); the body must remain byte-identical.
- **Regression: close() TypeError (mitigated):** After swap, `self._inner.providers` is `list[str]`. The existing `for provider in ... if hasattr(provider, "close"): await provider.close()` loop is harmless but misleading. Replace with `pass` or a no-op comment since LiteLLM manages its own HTTP pool internally.
- **Regression: rate-limiter silent degradation (mitigated):** Colon-to-slash key format mismatch causes per-provider rate limits to miss, falling back to the first limiter for all calls. Audited and fixed in Task 2.
- **Test disruption (mitigated):** Deleting `OllamaProvider`/`OpenRouterProvider`/`LLMChain` from `providers.py` will break any unit test that imports them. Audit `tests/unit/intelligence/test_llm_providers.py` first; remove tests whose subject no longer exists and migrate any surviving coverage to `test_litellm_backend.py`.
- **Service disruption (mitigated):** Smoke test runs BEFORE service restart to confirm LiteLLMBackend produces valid output; if smoke fails, abort service restart and investigate.
</threat_model>

<task id="4" name="Smoke test LiteLLMBackend against live Ollama">

Run the live smoke test inline:

```bash

import asyncio, os
os.environ["OLLAMA_API_BASE"] = "http://localhost:11434"
from src.core.llm.litellm_backend import LiteLLMBackend
from unittest.mock import MagicMock

s = MagicMock()
s.ollama_enabled = True
s.ollama_model = "nemotron-3-nano:4b"

s.ollama_num_ctx = 4096
s.openrouter_api_key = ""
s.openrouter_models = ""

async def run():
    result = await backend.generate(
        prompt='Return exactly: {"ok": true}',
        system="OUTPUT ONLY RAW JSON. NO PROSE. NO EXPLANATION. NO PREAMBLE. Begin your response with { and end with }.",
        max_tokens=50,
        timeout=30.0,
    )
    print(f"provider: {backend.last_provider_id}")
    print(f"result: {result}")
    print(f"tokens: {backend.last_token_usage}")
    assert result is not None, "Expected non-None result from Ollama"
    assert backend.last_provider_id == "ollama/nemotron-3-nano:4b", f"Wrong provider: {backend.last_provider_id}"

asyncio.run(run())
print("SMOKE TEST PASSED")
EOF
```
