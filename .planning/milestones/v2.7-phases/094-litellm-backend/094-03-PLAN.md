<objective>
Add Instructor-based structured output to the LiteLLM stack. Implement multi-provider fallback and audit trail correctness (including on failure) in `generate_structured()`. Create typed `BaseModel` result classes for the 4 swarm agents that currently use JSON (skeptic, correlation, counterfactual, regime_coherence), delete the per-agent `_validate_*_fields` boilerplate they replace, and measure parse failure rate before and after.

**Scope boundary:** Narrative agent is explicitly excluded — it returns prose text, not JSON; Instructor adds no value there.

**Latency constraint:** Instructor default retries = 3. With gemma4:e4b at ~50s/call, 3 retries = 150s — over the 120s `latency_budget_ms` of all swarm agents. The instructor client MUST use `max_retries=1`.

**Audit correctness:** A failed structured call (instructor exhausted retries, provider down, circuit open) MUST create an `llm_calls` row with `succeeded=False, parse_success=False` BEFORE returning None. Without this, `_report_parse_failure()` has no row to update, and STRUCT-OUT-03 measurement is broken for the failure case.

**Multi-provider fallback:** `generate_structured()` MUST iterate through ALL providers with the same fallback semantics as `generate()` — try each in order, skip if circuit open, move to next on exception. `providers[0]`-only behavior is not acceptable.

**Token usage:** Use `create_with_completion()` instead of `create()` to get both the validated model AND the raw completion object. Extract `last_token_usage` from `raw_completion.usage`.

**Migration order:** Migrate Skeptic FIRST as the reference implementation. Verify it works (unit tests pass, no log errors) before migrating the remaining 3 agents. Reduces blast radius if a BaseModel has semantic drift.
</objective>

<threat_model>
ASVS L1 threats for this plan:

- **Latency blowout (mitigated):** Default instructor retries=3 x ~50s = 150s > 120s budget. Mitigated by passing `max_retries=1` to every `generate_structured()` call. Documented in code comment.
- **Audit trail gap on failure (mitigated):** `generate_structured()` on the chain publishes an audit row on BOTH success AND failure. On failure: `_publish_audit()` called with `response_str=""`, `succeeded=False`, `parse_success=False`, `failure_reason` set. This ensures `_report_parse_failure()` always has a row to update.
- **Failure taxonomy blurring (mitigated):** `failure_reason` field distinguishes `"circuit_open"`, `"all_providers_exhausted"`, `"instructor_validation_failed"`, `"provider_error"`. Only instructor/parse failures count toward STRUCT-OUT-03 parse failure rate; provider-unavailability failures are categorized separately.
- **Circuit breaker bypass via method switching (mitigated):** `generate_structured()` uses the same module-level `_OLLAMA_CB`/`_REMOTE_CB` instances as `generate()`. Failures on the structured path trip the same breaker. Test M6 verifies this explicitly.
- **Validator semantic drift (mitigated):** Each `BaseModel` field validator replicates the exact `clamp()` and coercion logic from the deleted `_validate_*_fields` function. Acceptance criteria requires matching output for the same inputs.
- **Narrative agent accidental migration (mitigated):** Explicit exclusion in scope. Narrative agent remains on `_llm_generate()` / `response.strip()` path — no changes to `narrative_agent.py`.
- **Token usage missing from Instructor path (mitigated):** `create_with_completion()` returns `(model, raw_completion)`; token usage extracted from `raw_completion.usage` via existing `_normalize_usage()`.
- **Simultaneous agent migration risk (mitigated):** Skeptic migrated first and verified before remaining 3 agents. One-at-a-time migration limits blast radius of BaseModel semantic drift.
</threat_model>

   ```python
       self.last_failure_reason: str | None = None

       if not self.providers:
           self.last_failure_reason = "all_providers_exhausted"
           return None

       messages = [
           {"role": "system", "content": system},
           {"role": "user", "content": prompt},
       ]

       for provider in self.providers:
           cb = self._circuit_breaker_for(provider)
           if not cb.allow_request():
               self.last_failure_reason = "circuit_open"
               continue

           extra_kwargs = self._build_extra_kwargs(provider)
           try:
               validated_model, raw_completion = (
                   await self._instructor_client.chat.completions.create_with_completion(
                       model=provider,
                       response_model=response_model,
                       messages=messages,
                       max_tokens=max_tokens,
                       timeout=timeout,
                       max_retries=1,
                       **extra_kwargs,
                   )
               )
               cb.record_success()
               self.last_provider_id = provider
               self.last_token_usage = self._normalize_usage(
                   getattr(raw_completion, "usage", None)
               )
               self.last_instructor_retries = 0
               self.last_failure_reason = None
               return validated_model
           except Exception as exc:
               cb.record_failure()
               # Distinguish validation failure from provider/network failure
               exc_str = str(exc).lower()
               if "validation" in exc_str or "pydantic" in exc_str:
                   self.last_failure_reason = "instructor_validation_failed"
               else:
                   self.last_failure_reason = "provider_error"
               logger.warning(
                   "litellm_backend.generate_structured.provider_failed",
                   provider=provider,
                   error=str(exc)[:120],
                   failure_reason=self.last_failure_reason,
               )

       self.last_failure_reason = "all_providers_exhausted"
       return None
   ```
