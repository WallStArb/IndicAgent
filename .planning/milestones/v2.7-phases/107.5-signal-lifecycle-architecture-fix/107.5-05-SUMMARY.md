## Decisions Made

- **bar_time is the TTL time source:** `evaluate_signal` uses the BAR timestamp for TTL comparison, making the function deterministic under replay. Wall clock (`datetime.now`) is used only in the startup cleanup path where there is no historical bar.
- **NULL = data-integrity bug, not fallback:** Per D-17, a NULL `expires_at` is treated as a pager-worthy alert — counter + warn + skip. The bar-count fallback is fully removed.
- **Stage-gated deploy:** Writer first so new signals have `expires_at` before evaluators switch. Between Plans 04 and 05, the old signal-writer wrote 2681 rows without `expires_at` — a targeted inline SQL backfill was applied before Stage C.
- **Gap backfill inline vs script:** 2681 rows is small enough to backfill via direct SQL in Stage B rather than a separate script. No batching or throttling needed at this scale.

**1. [Rule 1 - Bug] Gap backfill of 2681 rows written by old signal-writer between Plans 04 and 05**
- **Found during:** Task 3 (Stage B gate check)
- **Issue:** Plan 04 backfilled all rows up to that point, but the old `signal_writer_agent` continued running and wrote 2681 new rows (1m + 5m signals) without `expires_at` in the gap between plans
- **Fix:** Inline SQL `UPDATE signal_ledger SET expires_at = timestamp + ttl_bars * CASE feature_tf ... END * INTERVAL '1 second' WHERE expires_at IS NULL AND ttl_bars IS NOT NULL AND feature_tf IN ('1m','5m','15m','1h','4h','1d')` - same CASE expression as the backfill script
- **Files modified:** None (DB update only)
