<objective>
Stage-gated deployment of `expires_at`-based TTL: write `expires_at` at signal creation in `signal_writer_agent.py`, switch both evaluators (`lifecycle_tracker.py` and `signal_tracker_compute_agent.py`) to wall-clock TTL via the BAR timestamp, wire `LedgerEntry` and all repository read paths to carry the field, and deploy in ordered stages rather than a single simultaneous restart.

Purpose: After Plan 107.5-04, `expires_at` is populated for all in-retention signals. This plan switches both TTL evaluators to use it. The live per-bar evaluator (`evaluate_signal`) must compare against the BAR time, not `datetime.now(UTC)`, so replay of historical bars stays deterministic. NULL `expires_at` after backfill is a data-integrity bug — surfaced via counter + warning + skip, never a silent bar-count fallback (D-17).

Output: Four files modified, deployed in stages (writer first, verify, then evaluators together).
</objective>
