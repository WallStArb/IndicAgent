<objective>
Flip `get_active_contracts()` so non-futures come from the `instruments` table instead of `settings.contracts`. Update the two API call sites (`api/main.py` startup seeding and `api/utils.py` resolve_contract) so they no longer touch `settings.contracts`. This is the "registry flip" - after this plan, the DB is the single source of truth for non-futures instruments, but the `Settings.contracts` field still exists as a transitional shim (removed in Plan 091-04).

Purpose: Realize INST-01 (DB single source of truth) and INST-04 (count-gated bootstrap from env var).
Output: Pipeline reads instruments from DB end-to-end; startup seeding is idempotent and conditional.
</objective>

<threat_model>
- Empty cold-start: if DB is unreachable on first call and cache is empty, function returns `[]` which would silently start the pipeline with no instruments. Mitigation: emit a CRITICAL log line. The intelligence_pipeline_agent already has its own assertion on non-empty contracts at startup.
- Count-gated seeding race: two API instances starting simultaneously could both see COUNT=0 and both attempt seed. Mitigation: `upsert_instruments` is idempotent via ON CONFLICT - duplicate seed is a no-op.
- IBKR_CONTRACTS_JSON parsing: malformed JSON crashes startup. Mitigation: wrap in try/except; log and skip seed on parse failure.
- resolve_contract performance: querying DB on every API call would add latency. Mitigation: rely on existing 60s TTL cache in `get_active_contracts()`.
</threat_model>
