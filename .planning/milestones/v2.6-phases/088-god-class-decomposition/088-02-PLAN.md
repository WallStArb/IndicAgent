<objective>
Extract PluginStateManager as the second DAG node. This class owns plugin state dicts (keyed by `(plugin_name, symbol, tf)`), per-(symbol,tf) threading locks, and the checkpoint file. It also introduces a self-managed background checkpoint loop (Renaissance automation principle: caller starts it once, class owns the timing).

Purpose: Single writer for plugin_states; eliminate ~70 lines from orchestrator; lay the cross-owned-checkpoint pattern (extra_state passed in, with plugin_states OWNED INTERNALLY) that plans 03 and 05 will plug into.
Output: PluginStateManager class wired into the orchestrator, dedicated unit tests, pipeline_helpers.py updated, _write_local_checkpoint / _read_local_checkpoint methods removed from the god class.

**State key contract (HIGH finding 1 from REVIEWS.md):** The current god class keys `_plugin_states` by `(plugin_name, symbol, tf)`. The decomposed DAG must preserve this — the executor needs per-plugin state slots. The PluginStateManager exposes two read APIs:
- `get_state(key: tuple)` where `key = (plugin_name, symbol, tf)` — single-plugin read.
- `get_all_states_for(symbol: str, tf: str) -> dict[str, dict]` — returns mapping keyed by plugin_name for all plugin states matching this (symbol, tf). This is what the executor consumes per bar.
- `get_lock(key: tuple)` where `key = (symbol, tf)` — per-bar serialization lock (NOT per-plugin).

`update_batch(updates: dict)` writes back keyed by full `(plugin_name, symbol, tf)` tuples — matching the `state_updates` dict returned by `_collect_plugin_results` (plan 04). This preserves current behavior exactly.

**Checkpoint payload contract (HIGH finding 5):** `write_checkpoint(extra_state: dict)` is the ONLY API for producing a checkpoint payload. It builds the payload as:
```python
payload = {"version": _AGENT_VERSION, "ts": ..., "plugin_states": _tag_value(self._plugin_states)}
for k, v in extra_state.items():
    if k == "plugin_states":
        raise ValueError("extra_state must not contain 'plugin_states' — PluginStateManager owns it")
    payload[k] = _tag_value(v)
```
PluginStateManager is the SINGLE writer of `plugin_states`. The orchestrator's `_assemble_checkpoint_extra()` returns only `{kalman_state, tod_priors, last_bar_offset, setup_last_fire}`.

**Interim-state hazard (read before executing):** After this plan lands but BEFORE plans 03/05, the orchestrator helper `_assemble_checkpoint_extra()` reads orchestrator-owned attributes `self._kalman_state`, `self._tod_priors`, `self._setup_last_fire`. Plan 03 will remove `self._tod_priors` (replaces it with `self._cache_mgr.tod_priors`), and plan 05 will remove `self._kalman_state` / `self._setup_last_fire` (replaces them with `self._sig_proc.get_kalman_state()` / `.get_setup_last_fire()`). This is a hidden ordering hazard: between waves, anyone touching `_assemble_checkpoint_extra` must update both the producer and the helper in lockstep. Task 2 below adds a standalone test that exercises the interim form so the hazard is loud, not silent.
</objective>
