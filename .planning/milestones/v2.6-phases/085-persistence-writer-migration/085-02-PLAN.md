<objective>
Apply two targeted bug fixes to persistence writers that do not depend on the schema definitions
being created in Plan 01.

PERSIST-02: Delete the `_do_flush()` override in `feature_snapshot_writer_agent.py` that clears
the buffer on error. After deletion, the base `_do_flush()` re-raise contract takes effect: flush
failure re-raises, buffer stays intact, systemd restart reprocesses from the last committed Kafka
offset. Zero new code — behavioral correction via deletion.

PERSIST-03: In `llm_writer_service._process_outcome_message()`, make DB errors during outcome
writes visible. Currently they fall through without incrementing the error counter. Add an explicit
`except Exception as db_exc` around the `execute_batch` call that increments the error counter,
logs `"outcome_write_failed"` as a structured event, and re-raises.

Purpose: Eliminates silent data loss (PERSIST-02) and silent metric blindness (PERSIST-03) without
touching any schema or base class code.

Output: `feature_snapshot_writer_agent.py` with `_do_flush` method removed; `llm_writer_service.py`
with explicit DB error handling in the outcome write path.
</objective>
