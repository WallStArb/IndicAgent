<objective>
Harden the bar aggregation layer against the four high/medium findings from the 2026-04-22 Kafka→DB pipeline audit:

1. **AGG-DLQ**: bar_aggregator_agent has no dead-letter queue — malformed bars are silently dropped with only a counter. Add DLQ topic + routing.
2. **AGG-TIMESTAMP-GUARD**: bar_accumulator.update() doesn't validate that curr_ts > prev_ts. Clock skew or out-of-order delivery silently corrupts accumulator state. Add forward-only guard.
3. **AGG-EMIT-ONCE**: On restart, BarAccumulator loses in-memory state and auto_offset_reset="latest" means partial re-accumulation, which can emit a duplicate HTF bar for the same period. Add a simple last-emission registry (symbol, tf, period_ts) to suppress duplicates.
4. **AGG-BACKPRESSURE**: bar_aggregator_agent processes 1m bars one-at-a-time with no cap. A burst after reconnect (e.g., 1440 bars in 1 second) consumes unbounded memory. Add a semaphore cap.

Out of scope: full BarAccumulator state persistence to compacted topic (too large for Phase 68 — deferred as backlog).
</objective>

**Emit-once guard (AGG-EMIT-ONCE):**

Add an in-memory set tracking the last emission per (symbol, tf):

```python
# In __init__:
self._last_emitted: dict[tuple[str, str], datetime] = {}

# After BarAccumulator emits HTF bars — before publishing to Kafka:
for htf_bar in completed_bars:
    key = (htf_bar.symbol, htf_bar.tf)
    if self._last_emitted.get(key) == htf_bar.ts:
        self.logger.warning(
            "htf_duplicate_suppressed",
            symbol=htf_bar.symbol,
            tf=htf_bar.tf,
            period_ts=htf_bar.ts.isoformat(),
        )
        continue
    self._last_emitted[key] = htf_bar.ts
    await self._publish_htf_bar(htf_bar)
```

The `_last_emitted` dict is in-memory only (lost on restart), which is intentional — it prevents duplicates within a single run. Between restarts, the downstream consumer (intelligence_pipeline_agent) must handle idempotency via `(symbol, feature_ts, feature_tf)` unique constraint.
