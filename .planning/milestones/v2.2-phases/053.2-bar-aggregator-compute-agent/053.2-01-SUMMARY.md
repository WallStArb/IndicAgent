# Phase 053.2 Plan 01: is_flat_bar Schema Field Summary

`is_flat_bar: bool = False` added to BarMessage with accumulator-level ANDed propagation; DataProviderAgent stamps True on flat-price fills and False on normal RTB-derived bars.

## What Was Built

### BarMessage Schema (D-08)
- `is_flat_bar: bool = False` field added after `gap_preceding`
- Docstring updated with field description (flat fill vs real trade activity)
- Backward compatible — all existing deserialization continues to work

### BarAccumulator Propagation (D-09, D-10)
- New `all_flat` key in accumulator dict, initialized from `bar_1m.is_flat_bar` on new window start
- Updated on each constituent bar: `acc["all_flat"] = acc["all_flat"] and bar_1m.is_flat_bar`
- `_build_bar()` sets `is_flat_bar=acc.get("all_flat", False)` — safe default for all paths
- Session-break emitted partial bars also carry correct is_flat_bar (all_flat propagated throughout window)

### DataProviderAgent Emission (D-07)
- Flat bar path (zero-volume prev_close fill): `"is_flat_bar": True`
- Normal bar path (5s RTB derived): `"is_flat_bar": False`
- Official-data fallback path: falls through to normal bar_data dict which emits `False` — correct

## TDD Execution

- `test_is_flat_bar_all_flat_htf` — all-flat 1m bars → HTF is_flat_bar=True

- `test_is_flat_bar_all_real_is_not_flat` — all real bars → HTF is_flat_bar=False
- `test_is_flat_bar_session_break_propagation` — partial bar at session break carries correct is_flat_bar

## Decisions Made

1. **all_flat AND logic**: HTF bar `is_flat_bar=True` only when every constituent 1m bar was flat. One real-volume bar in the window makes the HTF a real bar. This correctly implements D-10.

2. **Backward compat default=False**: All existing bars (ibkr_named, ibkr_seed, htf_derived) default to False. No schema migrations, no downstream breakage.

3. **acc.get("all_flat", False) in _build_bar**: Safe accessor handles edge case where `current_partial()` is called on an accumulator created before this change deployed.
