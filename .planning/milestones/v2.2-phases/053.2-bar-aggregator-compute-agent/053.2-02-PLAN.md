    **Step 1 — Create `services/bar_aggregator_agent.py`:**

    Follow the BaseAgent pattern from `services/roll_compute_agent.py`. Key structure:

    ```python
    #!/usr/bin/env python3
    """BarAggregatorComputeAgent — standalone 1m->HTF bar aggregation.

    Consumes 1m bars from topic_market_bars, runs BarAccumulator,
    publishes completed HTF bars to topic_market_bars_htf.

    DB-ignorant ComputeAgent — no database access.
    Metrics port: :9120
    """
    ```

    Class `BarAggregatorComputeAgent(BaseAgent)`:

    a) **Constructor** (config-before-super pattern per Phase 52.2):
    ```python
    def __init__(self) -> None:
        self._settings = Settings()
        self.env_name = self._settings.env_name
        metrics_port = 9120
        super().__init__(name="bar_aggregator_agent", metrics_port=metrics_port)
        self._bar_accumulator = BarAccumulator()
        self._kafka_producer: KafkaProducerClient = KafkaProducerClient(
            bootstrap_servers=self._settings.kafka_bootstrap_servers
        )
        self._kafka_consumer: KafkaConsumerClient | None = None
        # Golden Signals (per D-16)
        self._events_consumed = counter("events_consumed_total", "Bars consumed", ["agent"])
        self._htf_bars_produced = counter("htf_bars_produced_total", "HTF bars produced", ["agent", "tf"])
        self._aggregation_latency = histogram("bar_aggregation_latency_seconds", "Aggregation latency", ["agent"])
        self._aggregation_errors = counter("aggregation_errors_total", "Aggregation errors", ["agent"])
    ```
    Use `from src.observability.metrics import counter, histogram` (same pattern as other agents) to prevent duplicate Prometheus registration.

    b) **topics_consumed / topics_produced properties**:
    ```python
    @property
    def topics_consumed(self) -> list[str]:
        return [topic_market_bars(self.env_name)]

    @property
    def topics_produced(self) -> list[str]:
        return [topic_market_bars_htf(self.env_name)]
    ```

    c) **_setup()**: Start producer, create consumer with `group_id="bar_aggregator_consumer"`, `auto_offset_reset="latest"` (per D-14), start consumer.

    d) **_run()**: Async for loop over `self._kafka_consumer.messages()`. For each message:
    - Parse payload to BarMessage via `BarMessage.model_validate(payload)` (handle the dict payload that comes from Kafka — note DataProviderAgent sends string values for OHLCV, so use the same bar normalization approach as feature_compute_agent).
    - Read the feature_compute_agent's `_process_bar_message` or `_parse_bar_payload` for how it deserializes the Kafka payload into a BarMessage. The payload dict from DataProviderAgent has string values (`"open": "5250.0"`) and keys `timestamp`, `symbol`, `timeframe`. Use the same parsing approach: construct BarMessage from the raw dict fields, parsing floats and datetime.
    - Call `self._bar_accumulator.update(bar_1m)`.
    - For each completed HTF bar, publish via `self._kafka_producer.publish(topic_market_bars_htf(self.env_name), bar.model_dump(mode="json"), key=message_key(bar.symbol, bar.tf))`.
    - Increment `_events_consumed` for each 1m bar, `_htf_bars_produced` for each HTF bar (with `tf` label).
    - Observe `_aggregation_latency` per bar.
    - On exception: increment `_aggregation_errors`, log error, continue (don't crash on single bar failure).

    e) **_teardown()**: Stop consumer and producer.

    f) **`__main__` block**: Same pattern as other agents:
    ```python
    if __name__ == "__main__":
        import sys
        from pathlib import Path
        project_root = Path(__file__).parent.parent
        sys.path.insert(0, str(project_root))
        from src.core.service_utils import setup_service_logging
        from src.observability.otel import init_tracing
        setup_service_logging("bar_aggregator_agent")
        init_tracing("bar_aggregator_agent")
        import asyncio
        agent = BarAggregatorComputeAgent()
        asyncio.run(agent.start())
    ```

    **IMPORTANT**: Look at how `feature_compute_agent.py` parses the bar payload from Kafka (search for where it constructs BarMessage from the consumer message). The DataProviderAgent publishes raw dicts with string values. The agent needs to handle this deserialization. Check `feature_compute_agent._process_message` or similar method for the pattern. The bar payload from DataProviderAgent has keys: `timestamp`, `symbol`, `timeframe`, `open`, `high`, `low`, `close`, `volume`, `source`, `bar_close_ts`, `is_reconciled`, `drift_detected`, `is_flat_bar`. Parse these into a BarMessage.
