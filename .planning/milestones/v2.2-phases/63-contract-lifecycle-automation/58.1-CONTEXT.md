# Phase 58.1: Contract Lifecycle Automation - Context

**Gathered:** 2026-04-02
**Status:** Ready for planning
**Source:** PRD Express Path (docs/superpowers/specs/2026-04-02-contract-lifecycle-automation-design.md)

<domain>
## Phase Boundary

Four-stage DAG that eliminates all manual futures roll tasks:
- **Stage 1 (SEED):** `ContractMetadataWriterAgent._seed_missing_contracts()` bootstraps `contract_metadata` from `settings.py` on first deployment — idempotent INSERT only
- **Stage 2 (DETECT):** `RollComputeAgent` (already running in shadow) graduates to live — z-score + calendar gate → `market.events.roll`
- **Stage 3 (PROMOTE):** New `ContractMetadataWriterAgent` consumes `market.events.roll` → atomically promotes front-month in `contract_metadata` → broadcasts `market.events.contract_update`
- **Stage 4 (AUDIT):** `BarAuditorAgent` uses session-aligned windows (not midnight-to-midnight UTC) and derived completeness ceiling instead of hardcoded 95%

</domain>

<decisions>
## Implementation Decisions

### Component 1: ContractMetadataWriterAgent (New)

- **File:** `services/contract_metadata_writer_agent.py`
- **Class:** `ContractMetadataWriterAgent` (WriterAgent role — DB-aware, no compute/signal logic)
- **Systemd unit:** `indicagent-contract-metadata-writer.service` at `/etc/systemd/system/`
- **Metrics port:** `:9124`
- **Consumes:** `market.events.roll` (topic from `stream_keys.py`)
- **Produces:** `contract_metadata` (DB) + `market.events.contract_update` (Kafka)

**Startup `_seed_missing_contracts()`:**
- Runs once in `_setup()` before consuming events
- For each futures instrument in `settings.py` that has no row in `contract_metadata`, INSERT with `is_front_month=true`
- SQL: `INSERT INTO contract_metadata (symbol, base_symbol, asset_class, exchange, is_front_month) VALUES ($1, $2, 'futures', $3, true) ON CONFLICT (symbol) DO NOTHING`
- If a row exists for the base symbol: skip — DB is authoritative

**Live `_handle_roll_event()`:**
1. Validate `old_contract` and `new_contract` are both non-empty; send to DLQ (`market.events.roll.dlq`) if malformed
2. Execute in one transaction: `UPDATE contract_metadata SET is_front_month = false WHERE symbol = old_contract` + `INSERT ... ON CONFLICT (symbol) DO UPDATE SET is_front_month = true, roll_from = old_contract, roll_detected_at = detection_ts, confirmation_count = ...`
3. Publish `ContractUpdateEvent` to `market.events.contract_update`
4. Invalidate `get_active_contracts()` cache by zeroing `_active_contracts_last_refresh`

**Graceful degradation:**
- DB unavailable at startup → hard fail (refuse to start) — NOT silent degradation
- Roll event for unknown symbol → DLQ, continue, do not crash
- Duplicate roll event → idempotent UPSERT, no side effects

**Golden Signals metrics (all via `src/observability/metrics.py`):**
- `contract_writer_rolls_processed_total` (Counter)
- `contract_writer_roll_errors_total` (Counter)
- `contract_writer_seeds_inserted_total` (Counter)
- `contract_writer_processing_latency_seconds` (Histogram)

### Component 2: `market.events.contract_update` Topic (New)

- New Kafka topic; add `topic_contract_updates()` to `src/core/stream_keys.py`
- Payload: `ContractUpdateEvent { base_symbol, old_contract, new_contract, promoted_at }` — add to `src/core/schemas/market_events.py`
- Also add `topic_roll_dlq()` to `stream_keys.py` for `market.events.roll.dlq`
- Purpose: cache invalidation latency optimization — NOT required for correctness

### Component 3: BarAuditorAgent — Session-Aligned Windows

**Fix 1: `TradingSession.session_window_for_date(target_date) → (start_utc, end_utc)`**
- New pure method on `TradingSession` in `src/core/models.py`
- Same-day (NYSE 09:30–16:00 ET): `target_date 09:30 ET → target_date 16:00 ET` in UTC
- Overnight (CME 18:00 CT prev → 17:00 CT): `(target_date - 1d) 18:00 CT → target_date 17:00 CT` in UTC
- All-day (crypto, FX): `target_date 00:00 UTC → (target_date + 1d) 00:00 UTC`
- Replaces hardcoded `datetime(year, month, day, 0, 0, 0, tzinfo=UTC)` in `_detect_gaps()`
- `BarGapRequest.start_ts` / `end_ts` carry session-aligned timestamps

**Fix 2: `TradingSession.max_achievable_pct() → float`**
- Derived entirely from session definition: `expected_bars / session_minutes`
- No magic numbers, no per-instrument constants
- CME overnight with breaks fully encoded → `max_achievable = 1.0`

**Fix 3: Derived threshold (replaces `_COMPLETENESS_THRESHOLD = 0.95`)**
- New constant: `_COMPLETENESS_GATE = 0.97` (system-wide)
- Per-session threshold: `threshold = session.max_achievable_pct() * _COMPLETENESS_GATE`
- No per-instrument overrides — ever

**Fix 4: Subscribe to `market.events.contract_update`**
- On receipt: zero `_active_contracts_last_refresh` so next audit cycle fetches fresh contracts
- Topic absence → degrade to TTL cache only (60s lag), not failure

### Component 4: RollComputeAgent Graduation

- **Back-test script:** `production/scripts/roll_backtest.py` — standalone, runs against live DB
- Validates: roll fires within known roll window, zero false positives in 30-day pre-window, cooldown prevents double-fire
- Known rolls to test against: H6→M6 transitions 2026-03-16 for all quarterly contracts
- If passes → `sudo systemctl enable --now indicagent-roll-compute.service`
- No IS_SHADOW flag to remove — it is simply disabled in systemd today

### Component 5: `settings.py` SoT Cleanup

- Remove front-month symbols from `build_contracts()` defaults
- Replace with base-symbol templates: keep `symbol=base`, `exchange`, `point_value`, `tick_size`, `session_id`, `sector` — remove live contract codes like `ESM6`
- `get_active_contracts()` unchanged: DB-first for futures, config-file for non-futures
- **Sequencing constraint:** `ContractMetadataWriterAgent` MUST run first (seed needs current front-months in `settings.py`). Only after seed completes should `settings.py` be cleaned up.

### Component 6: BarWriterAgent Base Symbol Resolution (Plan 06)

**Root cause:** Phase 50 schema mismatch — `market_data_ohlcv.base` contains contract codes (ESM6) instead of base symbols (ES) because BarWriterAgent queries `instruments` table (which only has base symbols) instead of `contract_metadata` table (which has contract→base mappings).

**Fix:** Refactor BarWriterAgent to query `contract_metadata` for contract→base resolution and subscribe to `topic_contract_updates` for cache invalidation on roll promotions.

**Impact:**
- Unblocks Phase 50 D-21 validation (can query `WHERE base = 'ES'`)
- Fixes ML training data foundation (v2.3) — base symbols available for feature grouping
- Enables "all ES contracts" queries — contract codes aggregate under base symbol

**Changes:**
- `_load_instruments_cache()` → `_load_contract_cache()` with new SQL query
- `_instruments_cache` → `_contract_cache` dict
- Subscribe to `topic_contract_updates` in `_setup_kafka_clients()`
- Add `_handle_contract_update()` method to invalidate cache on promotions
- Update unit tests to reflect new cache logic

### Deployment Order (strict)

1. Deploy `ContractMetadataWriterAgent` (seed runs at first startup)
2. Verify `contract_metadata` rows seeded correctly
3. Run `roll_backtest.py` — must pass
4. `sudo systemctl enable --now indicagent-roll-compute.service`
5. Update `settings.py` — base-symbol templates (same commit as step 4)
6. Deploy `BarAuditorAgent` session-aligned windows
7. **Deploy BarWriterAgent base symbol fix (Plan 06)** — query `contract_metadata`, subscribe to `topic_contract_updates`, cache invalidation

### Claude's Discretion

- BaseAgent inheritance pattern and constructor signature for `ContractMetadataWriterAgent`
- Exact asyncpg pool usage (follow `database_manager.py` patterns)
- Test fixture patterns (follow existing `tests/unit/` conventions)
- DLQ topic naming (use `topic_roll_dlq()` in stream_keys.py per convention)

</decisions>

<specifics>
## Specific Ideas

- `get_active_contracts()` API must remain unchanged — all callers unaffected
- `RollComputeAgent` internals untouched — z-score algorithm not modified
- `contract_metadata` schema unchanged — all needed columns already exist
- `market.events.roll` topic unchanged — already published to by RollComputeAgent
- IBKRProviderAgent restart on roll remains manual (acceptable for quarterly events)
- systemd units in `/etc/systemd/system/` — `production/systemd/` is reference only

</specifics>
