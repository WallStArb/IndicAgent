**Create `production/scripts/benchmark_thread_pool.py`:**

Script structure:
```python
#!/usr/bin/env python3
"""Thread pool throughput benchmark for intelligence pipeline.

Measures bars/sec throughput at various ThreadPoolExecutor pool sizes
using synthetic plugin workloads. Does not require live Kafka or DB.

Usage:
    .venv/bin/python production/scripts/benchmark_thread_pool.py

Output: CSV to stdout + summary table to stderr.
"""

import asyncio
import csv
import os
import sys
import time
from concurrent.futures import ThreadPoolExecutor

POOL_SIZES = [28, 48, 64, 96, 128]
NUM_PLUGINS = 27  # Match TIER_I1 count
NUM_BARS = 200  # Bars to process per pool size
PLUGIN_SLEEP_MS = 1.0  # Simulated per-plugin latency (1ms)
```

Core logic:
1. `_synthetic_plugin_work()` — `time.sleep(PLUGIN_SLEEP_MS / 1000)` then returns a small dict. This simulates realistic I/O-like plugin latency.
2. `async def _benchmark_pool_size(pool_size: int, num_bars: int) -> dict` — Creates `ThreadPoolExecutor(max_workers=pool_size)`. For each of `num_bars` bars, submits `NUM_PLUGINS` tasks via `asyncio.gather(*[loop.run_in_executor(executor, _synthetic_plugin_work) for _ in range(NUM_PLUGINS)])`. Records total wall time. Returns `{"pool_size": pool_size, "bars_per_sec": num_bars / elapsed, "total_sec": elapsed, "avg_bar_ms": (elapsed / num_bars) * 1000}`.
3. `async def _amain()` — Iterates POOL_SIZES, runs benchmark for each, collects results.
4. CSV output to stdout: `pool_size,bars_per_sec,total_sec,avg_bar_ms`
5. Summary table to stderr showing best pool size.
6. Entry point: `asyncio.run(_amain())`

Add docstring header explaining: "Results depend on hardware (24-core system), GIL behavior, and plugin I/O vs CPU mix. Re-run after significant plugin count changes."
