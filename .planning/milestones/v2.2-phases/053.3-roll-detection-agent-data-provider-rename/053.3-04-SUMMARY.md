## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] feature_writer_agent read wrong timestamp field**
- **Found during:** Task 2 (verifying feature_writer_agent._handle_roll_event)
- **Issue:** `_handle_roll_event` read `event.get("detected_at")` which is the old dict-payload field; RollEvent schema uses `detection_ts`. Without fix, every roll event would use `datetime.now()` as the boundary timestamp instead of the actual detection time.
- **Fix:** Changed `event.get("detected_at")` to `event.get("detection_ts")` in feature_writer_agent.py line 564
- **Files modified:** `services/feature_writer_agent.py`
- **Verification:** FeatureWriterRollEvent tests pass with correct timestamp extraction
- **Committed in:** `8e18ed0` (Task 2 commit)

**2. [Rule 1 - Bug] FeatureWriterRollEvent tests used old dict format, failing after schema migration**
- **Found during:** Task 2 (test suite run)
- **Issue:** `test_writes_roll_boundary_marker_to_db` and `test_roll_boundary_marker_format` passed old-format dicts (`event_type/old_symbol/new_symbol`) which no longer validate against RollEvent schema. This caused `parse_roll_event` to return None → no DB write → test assertions failed.
- **Fix:** Updated event dicts in both tests to RollEvent schema (`symbol/old_contract/new_contract/roll_gap_price/roll_gap_pct/detection_ts/volume_zscore/confirmation_count`); also fixed dict-vs-JSON-string assertion in marker format test
- **Files modified:** `tests/unit/test_roll_kafka_events.py`
- **Verification:** All 5 FeatureWriterRollEvent tests pass
- **Committed in:** `8e18ed0` (Task 2 commit)
