# Plan 54-04: ProviderMergerAgent + Zero-Downtime Cutover

## Objective

Build the canonical gateway that routes raw provider bars to `market.bars`. Execute zero-downtime cutover from `DataProviderAgent` to the new two-service stack (IBKRProviderAgent + ProviderMergerAgent). Update CLAUDE.md to reflect the new architecture.

Purpose: The merger is the single canonical author of `market.bars`. All 8 downstream consumers are untouched. Auto-failover on primary silence means no human intervention required. Even in single-provider mode, the merger collects per-bar latency as a quality signal.

Output: ProviderMergerAgent, systemd unit, cutover executed, CLAUDE.md updated.

**2. `services/provider_merger_agent.py`** — `ProviderMergerAgent(BaseAgent)`:

Constructor:
- `self._settings = Settings()` before `super().__init__(name="provider_merger_agent", metrics_port=9130)`
- Pre-cache labeled metric children for each configured provider
- `self._promoted: dict[str, str] = {}` — symbol -> promoted provider (populated on failover)
- `self._last_bar_ts: dict[str, dict[str, datetime]] = {}` — provider -> {symbol -> last_ts}

`_setup()`:
- Build raw topic list: `[topic_market_bars_raw(env, p) for p in settings.provider_raw_topics]`
- Start `KafkaConsumerClient(*raw_topics, group_id="provider_merger_consumer")`
- Start `KafkaProducerClient`

`_run()`:
- Main loop: consume from raw topics
- For each message: deserialize `BarMessage.model_validate(payload)`
- Extract provider from topic name: split on `.` and take last segment (e.g., `dev.market.bars.raw.ibkr` -> `"ibkr"`)
- Look up active instrument for `bar.symbol` -> determine `asset_class`
- Check `_promoted.get(bar.symbol)` first; if not promoted, use `settings.provider_routing_config[asset_class]`
- If bar is from authoritative provider:
  - Publish to `topic_market_bars(env)` (BarMessage unchanged, source preserved)
  - Publish `ProviderQualityEvent(event_type="bar_received", latency_ms=..., publish_ts=bar.ts, consume_ts=datetime.now(UTC))` to `topic_market_data_quality(env)`
  - Update `_last_bar_ts[provider][symbol] = bar.ts`
  - Increment `MERGER_BARS_ROUTED_TOTAL.labels(provider=provider)`
  - Observe `MERGER_BAR_LATENCY_SECONDS.labels(provider=provider).observe(latency_s)`
- If bar is NOT from authoritative provider:
  - Update secondary tracking `_last_bar_ts[provider][symbol]`
  - Increment `MERGER_BARS_DROPPED_TOTAL.labels(provider=provider)`
  - Call `_check_failover(bar.symbol)`

`_check_failover(symbol)`:
- Silence detection formula (explicit):
  ```python
  silence_seconds = (datetime.now(UTC) - _last_bar_ts[primary][symbol]).total_seconds()
  bar_interval_seconds = {"1m": 60, "5m": 300, "15m": 900, "1h": 3600, "4h": 14400, "1d": 86400}.get(bar.tf, 60)
  if silence_seconds >= self._settings.provider_silence_bars_threshold * bar_interval_seconds:
  ```
- If primary has been silent >= threshold AND secondary has recent data:
  - Set `_promoted[symbol] = secondary`
  - Publish `ProviderQualityEvent(event_type="failover", promoted_provider=secondary)`
  - Increment `MERGER_FAILOVERS_TOTAL.labels(from_provider=primary, to_provider=secondary)`

Recovery logic:
- When primary resumes (bar received from previously-silent primary on a promoted symbol)
- Publish `ProviderQualityEvent(event_type="recovery")`
- Delete `_promoted[symbol]`

`_teardown()`: Drain producer, stop consumer.
