# Phase 53.1: BarWriterAgent + BarAuditorAgent — Context

**Gathered:** 2026-03-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Two new persistence agents:

1. **BarWriterAgent** — subscribes to `market.bars` (1m) + `market.bars.htf` (5m–1d); batch-writes to `market_data_ohlcv`; removes `_ohlcv_buffer` from `feature_compute_agent` hot path.
2. **BarAuditorAgent** — startup + periodic audit of `market_data_ohlcv` gaps vs expected counts; publishes `BarGapRequest` to `market.events.gap_requests`; retires `gap_fill_service`.
3. **DataProviderAgent gap-requests consumer** — adds `_gap_requests_loop()` to the existing DPA asyncio loop; fetches historical bars from IBKR; re-publishes to `market.bars`.

**Out of scope:**
- Phase 50 graduation (ROLL_MONITOR_ENABLED, DualDivergence) — depends on 53.3
- BarHistorySeeder / intelligence warmup changes
- Adding `is_flat_bar` column to `market_data_ohlcv` schema (planner's discretion — see Claude's Discretion below)

</domain>

<decisions>
## Implementation Decisions

### Gap-Fill Loop Architecture (D-01)

- **D-01:** DataProviderAgent is the **sole IBKR access point** (Renaissance SoC invariant). BarAuditorAgent is IBKR-ignorant — it publishes `BarGapRequest` events to Kafka and nothing more.
- **D-01a:** Phase 53.1 adds `_gap_requests_loop()` coroutine to `DataProviderAgent`. This coroutine is submitted to the **existing asyncio event loop** (`self.loop`) alongside `_rtb_loop`, `_official_bars_loop`, and `_heartbeat_task`. No new threads, no new event loops — reuse the pattern already established in `run()`.
- **D-01b:** Consumer group: `data_provider_consumer`. On receipt of a `BarGapRequest`: parse schema, call `self.provider.fetch_historical_bars(symbol, tf, start_ts, end_ts)`, re-publish each bar to `topic_market_bars(env)` with `source="ibkr_gap_fill"`. BarWriterAgent persists via its normal consumer path. ON CONFLICT DO NOTHING makes this idempotent.
- **D-01c:** `topic_gap_requests(env_name: str)` added to `src/core/stream_keys.py`. Topic string: `{env}.market.events.gap_requests`. (Named after payload concept `BarGapRequest` — follows `topic_roll_events` precedent, not full-path encoding.)

### BarWriterAgent Specification (D-02 — D-07)

- **D-02:** `BarWriterAgent(BaseAgent)` in `services/bar_writer_agent.py`. Follows BaseAgent lifecycle: SIGTERM drain, structlog (`self.logger`), `init_tracing(name)`, metrics port :9121.
- **D-03:** `topics_consumed = [topic_market_bars(env), topic_market_bars_htf(env)]` (single consumer group `bar_writer_consumer`, subscribed to both topics). `topics_produced = []` (persistence-only agent).
- **D-04:** Writes to `market_data_ohlcv`. UPSERT strategy: `ON CONFLICT (timestamp, symbol, timeframe) DO NOTHING`. First write wins — idempotent on replay. `source` column: `"live_1m"` for 1m bars, `"live_htf"` for aggregated HTF bars.
- **D-05:** Batch flush strategy: same pattern as existing `_flush_ohlcv` in FCA — buffer up to batch size or flush on time interval. Planner determines batch size and interval (current FCA uses 25 rows / 5s).
- **D-06:** Golden Signals per design doc:
  - Traffic: `events_consumed_total`, `bars_written_total{tf}`
  - Latency: `persistence_batch_latency_seconds`
  - Errors: `write_errors_total`, `conflict_skips_total`
  - Saturation: `persistence_consumer_lag`
- **D-07:** Systemd unit: `indicagent-bar-writer.service`. **Installed and enabled** in this phase — essential infrastructure (not a feature gate). Must start before feature_compute_agent can benefit from DB-ignorant hot path.

### FeatureComputeAgent Cleanup (D-08)

- **D-08:** After BarWriterAgent is running, remove from `feature_compute_agent`:
  - `self._ohlcv_buffer: list[tuple]`
  - `_queue_ohlcv_write()` method
  - `_flush_ohlcv()` method
  - The `_queue_ohlcv_write(bar)` call site in `_process_bar()`
  - The flush trigger in the main loop (line ~1155: `len(self._ohlcv_buffer) >= _OHLCV_BATCH_SIZE`)
  - `ohlcv_writes_total` Prometheus counter
  - `_OHLCV_BATCH_SIZE` constant
  - DB pool usage from the hot path (but **keep** `self._db` — FCA retains DB access for `_seed_bar_history` warmup)

### BarAuditorAgent Specification (D-09 — D-14)

- **D-09:** `BarAuditorAgent(BaseAgent)` in `services/bar_auditor_agent.py`. Not DB-ignorant — reads `market_data_ohlcv` to detect gaps.
- **D-10:** `topics_consumed = []` (no Kafka consumption). `topics_produced = [topic_gap_requests(env)]`. Audit loop is asyncio-scheduled, not event-driven.
- **D-11:** **Full multi-asset coverage.** Expected bar counts derived from `instrument.session` (existing `TradingSession` in `src/core/models.py`) + `get_active_contracts()`:
  - `crypto_24_7`: 1440 1m/day, 7 days/week — no session gap
  - `fx_24_5`: ~1440 1m/day, Sun–Fri — session closes Fri 17:00 ET, reopens Sun 17:00 ET
  - `futures_24_5`: session-dependent per `TradingSession` (CME hours)
  - `nyse`: RTH only (09:30–16:00 ET, Mon–Fri) → 390 1m/session
  - TradingSession already has `trading_days`, `open_time`, `close_time` — use these to compute expected minutes per day
- **D-12:** Audit schedule: **on startup** (covers restart catch-up + new symbol onboarding) + **every 5 minutes during market hours** (continuous coverage). "Market hours" = any active TradingSession is currently open across active contracts.
- **D-13:** Gap detection query: for each `(symbol, tf, date)` tuple, compare actual row count in `market_data_ohlcv` vs expected count from TradingSession. Publish `BarGapRequest{symbol, tf, start_ts, end_ts}` for any window with fewer rows than expected (threshold: < 95% completeness to allow minor timing edges).
- **D-14:** Golden Signals per design doc:
  - Traffic: `audits_run_total`, `gap_requests_published_total`
  - Latency: `audit_duration_seconds`
  - Errors: `audit_errors_total`
  - Saturation: `canonical_completeness_pct{symbol,tf}` ← key operational metric (Prometheus gauge per symbol+tf)
- Systemd unit: `indicagent-bar-auditor.service`. Installed and enabled.

### gap_fill_service Retirement (D-15)

- **D-15:** `gap_fill_service.py` is retired in this phase:
  - Disable systemd timer (`indicagent-gap-fill.timer`) if installed
  - Archive or delete `services/gap_fill_service.py`
  - BarAuditorAgent inherits all its responsibilities and expands scope

### CLAUDE.md Updates (D-16)

- **D-16:** `CLAUDE.md` "Active Services" table gains two rows:
  - `Bar Writer | indicagent-bar-writer | market.bars→market_data_ohlcv | :9121`
  - `Bar Auditor | indicagent-bar-auditor | gap detection → market.events.gap_requests | :9123`
- **D-16b:** `market_data_ohlcv` description updated: remove "backfill only" — after this phase, BarWriterAgent writes live bars continuously. New description: "raw OHLCV (backfill + live via BarWriterAgent; keep forever — ground truth)."

### Claude's Discretion

- **Batch size / flush interval** for BarWriterAgent: planner chooses. Current FCA uses `_OHLCV_BATCH_SIZE` and 5s flush interval — same defaults reasonable.
- **`is_flat_bar` in DB**: `market_data_ohlcv` currently has no `is_flat_bar` column. Planner should decide whether to add it via migration (enables downstream queries for flat bar filtering) or defer. Renaissance principle ("never drop data that could contain signal") suggests adding it; cost is one migration + one nullable column.
- **`BarGapRequest` field completeness**: The stub schema in `market_events.py` has 4 fields (`symbol`, `tf`, `start_ts`, `end_ts`). Planner should determine if `request_id` (UUID for correlation) or `source` field should be added for DLQ traceability.
- **DLQ**: whether `market.events.gap_requests.dlq` is needed for unprocessable gap requests. Follow CLAUDE.md Renaissance DAG Principles (DLQ for unprocessable payloads).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `BaseAgent` (`src/core/agent/base.py`) — Both agents inherit this. Same pattern as Phases 52.x + 53.x agents.
- `KafkaProducerClient` — BarAuditorAgent uses for publishing `BarGapRequest`. BarWriterAgent uses `KafkaConsumerClient`.
- `IBKRProvider.fetch_historical_bars()` — Used by DataProviderAgent's new `_gap_requests_loop()` (not by BarAuditorAgent directly).
- `get_active_contracts()` + `Instrument.session` — BarAuditorAgent derives expected bar counts from these. `TradingSession.trading_days`, `.open_time`, `.close_time` already encode all necessary session info.
- `_flush_ohlcv()` in `feature_compute_agent.py` (~line 654) — reference implementation for asyncpg batch insert to `market_data_ohlcv`. BarWriterAgent reuses the same INSERT SQL and executemany pattern.
- `_INSERT_OHLCV_SQL` constant in `feature_compute_agent.py` — copy to BarWriterAgent.

### DPA Event Loop Pattern
- `DataProviderAgent.loop` is an asyncio event loop running in a daemon thread (`self.loop_thread`).
- `asyncio.run_coroutine_threadsafe(coro, self.loop)` is how existing tasks are submitted.
- `_gap_requests_loop()` follows the same pattern as `_rtb_loop()`, `_official_bars_loop()`.
- Started in `run()` after `self.loop` is initialized and producer is started.

### Established Patterns
- `config-before-super` constructor pattern.
- `topics_consumed`/`topics_produced` properties for ProcessManifest.
- `init_tracing(name)` in `__main__` block.
- `@pytest.mark.asyncio` explicit on all async tests (STRICT mode).
- Service `__new__` pattern in `tests/unit/service_tests/`.

<specifics>
## User Specifics

- **Renaissance framing is mandatory:** Every design decision passes the "Jim Simons test" — modularity, SoC, no manual steps, prefer automation.
- **DPA = single IBKR access point.** This is non-negotiable. BarAuditorAgent publishes gap requests to Kafka; it never touches IBKR directly.
- **Full multi-asset coverage from day one.** Instrument.session already encodes the session logic. Use it — don't hardcode asset classes.
- **Service enable/disable = feature gate** (consistent with CROSS_ASSET_ENABLED removal). Both BarWriterAgent and BarAuditorAgent are installed AND enabled — essential infrastructure.
- **Zero manual steps.** gap_fill_service ran on a cron + required human monitoring. BarAuditorAgent replaces it with a continuous automated loop.
