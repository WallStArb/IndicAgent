## Implementation Decisions

### Test Migration (Full Sweep — Renaissance-Aligned)

- **D-01:** All 4 test files that reference `signal_lifecycle_service` must be migrated in this phase. No compatibility shim. No deferred debt. Clean module boundary from day one.
  - `tests/unit/service_tests/test_signal_lifecycle_service.py` → `test_signal_tracker_agent.py`
  - `tests/unit/service_tests/test_lifecycle_freshness.py` → update imports + patch paths
  - `tests/unit/service_tests/test_lifecycle_active_index.py` → update imports + patch paths
  - `tests/unit/intelligence/test_lifecycle_tracker.py` → update imports + patch paths

- **D-02:** Patch paths in all 4 test files must be updated to the correct canonical module. Module-level DB function patches (e.g., `patch("services.signal_lifecycle_service.record_zone_resolution")`) become repository method mocks: inject `MagicMock()` at `svc._ledger_repo` and assert method calls on the mock. DO NOT create new module-level function shims just to preserve old patch paths.

### Pre-Existing Test Failures (Fix in Phase 52.4)

- **D-03:** 6 tests currently fail with `AttributeError: 'services.signal_lifecycle_service' does not have the attribute 'update_signal_status'` (and similar). These failures are caused by a prior incomplete refactor — module-level functions (`update_signal_status`, `record_activation`, `record_zone_resolution`, `record_market_resolution`, `record_zone_resolution_with_activation`) were moved to `SignalLedgerRepository` as methods but the service call sites were not updated.
  - The service still calls: `await record_activation(self.db_manager, sid, ...)` — old API, raises `NameError` at runtime
  - Fix: all call sites become `await self._ledger_repo.record_activation(sid, ...)` — remove `db_manager` first-arg pattern
  - After migration, all 6 failures must be resolved. Zero pre-existing failures accepted in the final state.

### Repository: Extend, Don't Create

- **D-04:** `SignalLedgerRepository` **already exists** at `src/persistence/repository/signal_ledger_repository.py`. The existing plan's Task 1 (create the repo) is outdated. Planner must extend the existing repo, not create a new one.
  - The repo uses `DatabaseManager` (not asyncpg pool directly) — do NOT change this contract. All existing test instantiations pass a `DatabaseManager` mock; switching to asyncpg pool would break 15+ test files for no benefit.
  - New methods needed (not yet in repo): `record_chandelier_vol_source()`, `record_shadow_tracking_start()`. The `_UPDATE_CHANDELIER_SQL` and `_UPDATE_SHADOW_SQL` constants defined in `signal_lifecycle_service.py` must move to the repo.
  - `_active_index_reseed_loop` uses `self.db_manager` directly for a `SELECT` — this query must also be extracted to a new `fetch_all_active_signals()` repo method (or reuse `get_active_signals(symbol=None)` if it returns the correct columns).

### BaseAgent Integration Pattern

- **D-05:** Follow `IndicatorComputeAgent` (`services/indicator_compute_agent.py`) as the canonical BaseAgent integration pattern:
  - Override `start()` (not `_run()`) to: call `self._register_signal_handlers()`, initialize DB + repo, initialize Kafka, then launch task group via `asyncio.gather()`
  - Launch tasks: `_process_loop()`, `_health_monitor_loop()`, `_active_index_reseed_loop()` (equivalent to IndicatorComputeAgent's 3-task gather)
  - Override `stop()` to drain `_pending_tasks`, stop Kafka clients, close DB
  - `_run()` is NOT used by the concrete agent (leave as BaseAgent default or `pass`)
  - Use `self._stop_event` (from BaseAgent) as the shutdown signal. Remove the existing service's custom `self.running`, `self.shutdown_requested`, `self.shutdown_event` — replaced by `self._stop_event`

### DB Injection Pattern

- **D-06:** `SignalTrackerAgent` creates `DatabaseManager` internally in `start()` and constructs `SignalLedgerRepository(db_manager)` assigned to `self._ledger_repo`. This follows the same self-contained bootstrap as `SignalLifecycleService.__init__` (optional `db_manager` param for test injection) and the `__new__` test pattern: `svc = SignalTrackerAgent.__new__(SignalTrackerAgent); svc._ledger_repo = MagicMock()`.

### Metrics + Naming

- **D-07:** All metric labels updated from `signal_lifecycle_service` → `signal_tracker_agent`. Log file: `logs/signal_tracker_agent.log`. Systemd unit: `indicagent-signal-tracker.service`. Consumer group: keep existing (idempotent on restart) or update to `signal_tracker_group` — Claude's discretion.

### Claude's Discretion

- Consumer group name: keep `signal_lifecycle_group` (idempotent, no Redpanda topic offset reset needed) or rename to `signal_tracker_group` — either is fine
- Whether to delete `signal_lifecycle_service.py` immediately vs keeping a 2-line deprecation comment file pointing to the new location — delete is cleaner, keep if any external script references it

<specifics>
## Specific Ideas

**Renaissance framing (user explicit):** This refactor is not just a rename. The user wants the result to embody the DAG microservices principles:
- `SignalTrackerAgent` is DB-ignorant in its core processing path — all SQL via `self._ledger_repo`
- Clear separation: agent owns lifecycle state and Kafka I/O; repository owns all SQL
- No module-level DB functions in the agent module — those are a coupling anti-pattern
- The `__new__` test injection pattern (`svc._ledger_repo = MagicMock()`) makes the agent independently testable

**No scope creep:** No new lifecycle features, no schema changes, no new signal types. Pure structural refactor with test cleanup.

</specifics>
