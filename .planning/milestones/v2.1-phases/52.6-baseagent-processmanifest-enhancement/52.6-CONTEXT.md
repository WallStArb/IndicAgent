<decisions>
## Implementation Decisions

### Migration Scope

- **D-01:** Full fleet migration in this phase. All four concrete agents (`IndicatorComputeAgent`, `SignalGeneratorAgent`, `IntelligenceComputeAgent`, `FeatureWriterAgent`) inherit `BaseAgent` and implement the new contract. Sync `signal.signal()` handlers are broken invariants — Renaissance demands zero tolerance for broken invariants. Structural changes only (signal handlers, `_setup`/`_teardown`, topic declarations) — low blast radius, correctness gain is immediate.

### FeatureWriterService Rename

- **D-02:** `FeatureWriterService` → `FeatureWriterAgent` as a standalone pre-condition commit before any behavior changes. Naming IS correctness (CLAUDE.md invariant: persistence agents use `WriterAgent` suffix). Affected: class name in `services/feature_writer_service.py`, log references, systemd unit check, test class names. Commit message: `refactor(naming): rename FeatureWriterService → FeatureWriterAgent`.

### BaseAgent Changes

- **D-03:** `BaseAgent.__init__` signature becomes `(name: str, metrics_port: int | None = None)`. `self._metrics_port` stored, auto-started in `start()` via `start_metrics_server(port=self._metrics_port)` if set.

- **D-04:** `self.tracer = get_tracer(name)` added to `BaseAgent.__init__`. This is the agent-level operation only — acquiring a named tracer from the already-initialized provider. `init_tracing()` is a process-level singleton and belongs in each service's `if __name__ == "__main__"` block, NOT in `BaseAgent.start()`. Calling it in `start()` puts a process-level concern inside an agent-level lifecycle method — wrong scope.

- **D-05:** `_setup()` and `_teardown()` lifecycle hooks added with no-op default implementations. `IndicatorComputeAgent.start()` override is eliminated — replaced by `_setup()` (Kafka producer start, DB init, seed bar history, publish seeded state) and `_teardown()` (close Kafka consumer/producer, close DB pool). All other agents follow the same pattern.

- **D-06:** Revised `start()` lifecycle order:
  ```
  start()
   ├── _register_signal_handlers()
   ├── start_metrics_server()  if metrics_port set
   ├── logger.info("agent.starting")
   ├── await _setup()
   ├── lag_task = create_task(_report_consumer_lag())
   ├── try:
   │    └── await _run()
   ├── except Exception:
   │    └── logger.exception("agent.run_failed", agent=self.name)  → re-raise
   └── finally:
        ├── lag_task.cancel()
        ├── await _teardown()
        └── await stop()
  ```

- **D-07:** `topics_consumed`, `topics_produced`, `lag_threshold_messages` added as `@property` methods with default empty list / 1000 threshold. Concrete agents override these — they are the foundation of `ProcessManifest` topology and the self-describing DAG.

- **D-08:** `running` property: `return not self._stop_event.is_set()`. All agent main loops use `while self.running:` instead of `while not self._stop_event.is_set():`.

- **D-09:** Structured exception capture in `start()`:
  ```python
  except Exception:
      self.logger.exception("agent.run_failed", agent=self.name)
      raise
  ```
  Ensures crashes appear in the structured service log file, not just journald.

- **D-10:** `_send_to_dlq(payload: dict, error: Exception) -> None` added. Default implementation: log error + discard (per agent-standard.md current spec). Single upgrade point when DLQ topics are provisioned. This is a no-op method that earns its place by establishing the interface.

### ProcessManifest

- **D-11:** `ProcessManifest` replaces `AgentRegistry`. Not a singleton — passed explicitly (dependency injection, not global state). Safe to instantiate multiple times in tests. Location: `src/core/agent/manifest.py`.

- **D-12:** `ProcessManifest` API:
  - `__init__(agents: list[BaseAgent])` — stores `{a.name: a}` dict
  - `topics_consumed` property → set of all consumed topics across agents
  - `topics_produced` property → set of all produced topics across agents
  - `topology()` → dict describing each agent's consumes/produces/lag_threshold
  - `health()` → per-agent `{"running": bool}` snapshot
  - `start_all()` → `asyncio.gather(*[a.start() for a in agents])`
  - `stop_all()` → `asyncio.gather(*[a.stop() for a in agents])`
  - `validate_topics(admin_client)` → **stub with `NotImplementedError`** and clear docstring explaining intent. Full implementation in Phase 52.7 when Tempo infra is being wired.

- **D-13:** `AgentRegistry` deleted (`src/core/agent/registry.py`). `src/core/agent/__init__.py` exports `ProcessManifest` instead of `AgentRegistry`. `test_agent_registry.py` deleted; replaced by `test_process_manifest.py`.

### Agent Migration Pattern (all four agents)

- **D-14:** Migration template for each agent:
  1. Parse config first (pure function, no side effects)
  2. `super().__init__(name="...", metrics_port=cfg.get("metrics_port", PORT))`
  3. Remove `signal.signal()` calls — handled by `BaseAgent._register_signal_handlers()`
  4. Remove manual `start_metrics_server()` call — handled by `BaseAgent.start()`
  5. Move Kafka setup, DB init, seeding to `_setup()`
  6. Move Kafka/DB teardown to `_teardown()`
  7. Add `topics_consumed`, `topics_produced`, `lag_threshold_messages` properties
  8. Use `while self.running:` in main loop
  9. Remove custom `self.running`, `self.shutdown_requested`, etc. — replaced by `self._stop_event`

- **D-15:** `IndicatorComputeAgent` config-before-super pattern:
  ```python
  class IndicatorComputeAgent(BaseAgent):
      def __init__(self, config_file=None):
          cfg = self._load_config(config_file)  # pure — reads file, returns dict
          super().__init__(
              name="indicator_compute_agent",
              metrics_port=cfg.get("metrics_port", 9109),
          )
  ```
  Note: `_load_config` must be a `@staticmethod` or called as a class method before `super().__init__()`.

### OTel Integration (closes todo 009)

- **D-16:** `init_tracing(service_name="<agent_name>")` added to each service's `if __name__ == "__main__"` block, called BEFORE `asyncio.run(agent.start())`. This closes todo `009-add-opentelemetry-distributed-tracing.md`. The OTel SDK is already in `requirements.txt`; spans are no-ops until `OTEL_EXPORTER_OTLP_ENDPOINT` is set in systemd unit files (done in Phase 52.7 Tempo infra).

### Testing

- **D-17:** Unit test coverage required:
  - `tests/unit/test_base_agent.py` — updated for: new `__init__` signature (`metrics_port`), `tracer` attribute, `_setup()`/`_teardown()` called in correct lifecycle order, `running` property, `_send_to_dlq()` default behavior, structured exception capture
  - `tests/unit/test_process_manifest.py` — new file replacing `test_agent_registry.py`. Tests: topology(), health(), start_all(), stop_all(), `validate_topics()` raises `NotImplementedError`
  - Per migrated agent: verify `_setup()` is called before `_run()`, `_teardown()` called after, `topics_consumed`/`topics_produced` return correct values, no `signal.signal()` calls remain, `running` property used in main loop
  - Zero pre-existing test failures accepted in final state

### Claude's Discretion

- `_load_config` implementation in agents that don't currently have a pure config loader — Claude decides whether to extract to `@staticmethod` or use a module-level function
- Whether `_report_consumer_lag()` loop in `BaseAgent` uses `self.running` or `not self._stop_event.is_set()` — both are equivalent after D-08
- Order of `_teardown()` operations within each agent (e.g., close consumer before producer or vice versa)
- Whether `ProcessManifest.__init__` validates that agent names are unique (raise on duplicate) — Claude decides; raises is safer

<specifics>
## Specific Ideas

**Renaissance framing (user explicit):** Jim Simons would demand zero broken invariants. Every agent that uses `signal.signal()` instead of `BaseAgent._register_signal_handlers()` is a bug waiting to surface under async load. The full fleet migration is not optional — it's the correctness requirement.

**Automation over manual tasks:** The `_send_to_dlq()` stub makes DLQ routing a single-file change when topics are provisioned. The `validate_topics()` stub makes startup validation a drop-in implementation. The `ProcessManifest.topology()` makes the DAG self-describing — no manual documentation required. Every design choice here reduces future manual intervention.

**Separation of concerns — the key OTel insight from the design doc:**
- `init_tracing()` = process-level singleton → belongs in `if __name__ == "__main__"`
- `self.tracer = get_tracer(name)` = agent-level operation → belongs in `BaseAgent.__init__`
- These are different scopes. Conflating them would be a design error.

**Design doc is the primary reference:** `docs/ideas/base-agent-enhancement.md` contains code examples for every change above — planner should read it directly.

</specifics>
