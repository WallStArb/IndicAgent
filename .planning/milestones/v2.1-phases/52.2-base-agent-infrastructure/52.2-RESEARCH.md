## Summary

The agent already has `start()`, `stop()`, and signal-handler methods — these need to be reconciled with the `BaseAgent` contract rather than replaced wholesale.

**The most important complication:** four test files import from `services.indicator_service` (a module that does not exist), causing `ModuleNotFoundError` at collection time. **Primary recommendation:** Create `BaseAgent` and `AgentRegistry` using `abc.ABC` + `asyncio.get_running_loop()` (not the deprecated `get_event_loop()`), then reconcile `IndicatorService.__init__` with `super().__init__(name="indicator_compute_agent")`, update broken test imports, and wire `PERSISTENCE_CONSUMER_LAG` in the `_report_consumer_lag()` override.

### Pattern 1: asyncio.get_running_loop() — NOT get_event_loop()

**What:** The PLAN.md draft uses `asyncio.get_event_loop()` inside `_register_signal_handlers()`. This is **deprecated in Python 3.10+ and emits a DeprecationWarning in Python 3.13** (the project runtime).

**What to use instead:** `asyncio.get_running_loop()` — only valid when called from within a running event loop, which is exactly when `_register_signal_handlers()` is called (from within `start()`).

```python
# CORRECT for Python 3.13
def _register_signal_handlers(self) -> None:
    loop = asyncio.get_running_loop()
    for s in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(s, self._stop_event.set)
```

**Confidence:** HIGH — Python 3.13 stdlib docs.

### Pattern 2: IndicatorService Lifecycle Reconciliation

**Current state of `IndicatorService`:**
- `__init__` takes `config_file: str | None = None` — not `name: str`
- Has `self.running` (bool) and `self.shutdown_requested` (bool) for flow control
- Has `self.logger = structlog.get_logger(__name__)` — set *after* `signal.signal()` calls
- Uses `signal.signal(signal.SIGINT, self._signal_handler)` — the synchronous stdlib signal API, not `loop.add_signal_handler()`
- Has `async def start(self)` and `async def stop(self)` already — these will override `BaseAgent.start()/stop()`

**Reconciliation approach:** `IndicatorComputeAgent.__init__` should call `super().__init__(name="indicator_compute_agent")` first. The `BaseAgent.__init__` sets `self._stop_event` and `self.log`. The existing `self.running` / `self.shutdown_requested` flags can remain for internal loop control; `_stop_event` is the BaseAgent-layer signal. `_register_signal_handlers()` can replace the `signal.signal()` calls in `__init__`, or `IndicatorComputeAgent` can call `super()._register_signal_handlers()` from `start()`.

**CRITICAL:** `IndicatorComputeAgent.start()` overrides `BaseAgent.start()`. The planner must decide: either `IndicatorComputeAgent.start()` calls `super().start()` and puts all logic in `_run()`, OR `IndicatorComputeAgent` keeps its own `start()` implementation and only inherits `_stop_event`, `log`, and `_report_consumer_lag()`. Given the complexity of the existing `start()` method (metrics server, DB seed, Kafka setup), the **simpler safe path** is to keep `IndicatorComputeAgent.start()` as-is and only have `BaseAgent` provide the scaffolding, not call `_run()` from `start()` automatically. The PLAN.md's `BaseAgent.start()` auto-calls `_run()` — this conflicts with the existing service's approach. The planner must choose one path.

### Pattern 3: `_report_consumer_lag()` Override

**What:** The `KafkaConsumerClient` (`src/core/kafka_utils.py`) has no partition end-offset API — confirmed in Phase 52.1 decisions (`STATE.md`). The only available proxy is buffer size.

**Implementation approach:**
```python
# In IndicatorComputeAgent
async def _report_consumer_lag(self) -> None:
    while not self._stop_event.is_set():
        if self._kafka_consumer is not None:
            # No partition end-offset API; use in-flight message count as proxy
            from src.observability.metrics import PERSISTENCE_CONSUMER_LAG
            PERSISTENCE_CONSUMER_LAG.labels(agent_id="indicator_compute_agent").set(0)
        await asyncio.sleep(15)
```

This matches the Phase 52.1 decision pattern used in `llm_writer_service.py`.

### Pattern 4: AgentRegistry Singleton

The `__new__`-based singleton in PLAN.md is correct Python. One important note: `AgentRegistry` test isolation requires resetting `AgentRegistry._instance = None` between tests (or using a fresh instance). The PLAN.md test `test_registry_is_singleton` will pass as written.

### Anti-Patterns to Avoid
- **`asyncio.get_event_loop()` in `_register_signal_handlers()`:** Deprecated in Python 3.10+, emits DeprecationWarning in Python 3.13. Use `asyncio.get_running_loop()`.
- **Importing `BaseAgent` inside service files with a try/except fallback:** The import is unconditional — `src/core/agent/base.py` must exist before any service imports it.
- **Setting `self.logger` in `BaseAgent.__init__` as `self.log` but the existing `IndicatorService` uses `self.logger`:** After rename, either use `self.log` (from BaseAgent) consistently, or keep `self.logger` as an alias. Mixing both in the same class causes confusion. The plan should pick one name and update all call sites in `indicator_compute_agent.py`.

## Common Pitfalls

### Pitfall 1: asyncio.get_event_loop() deprecation
**What goes wrong:** `asyncio.get_event_loop()` in `_register_signal_handlers()` emits `DeprecationWarning: There is no current event loop` in Python 3.10+ when called outside a running loop, and raises `RuntimeError` in Python 3.12+.
**Why it happens:** The PLAN.md draft code uses `get_event_loop()`. Python 3.13 (the project runtime) requires `get_running_loop()` when inside a coroutine or `asyncio.run()`.
**How to avoid:** Use `asyncio.get_running_loop()` in `_register_signal_handlers()`. This is always called from within `start()` which is always called from `asyncio.run()`.
**Warning signs:** `DeprecationWarning` in test output, `RuntimeError: no running event loop` in CI.

### Pitfall 2: Logger attribute naming collision
**What goes wrong:** `BaseAgent.__init__` sets `self.log = structlog.get_logger().bind(agent=name)`. The existing `IndicatorService.__init__` sets `self.logger = structlog.get_logger(__name__)`. After rename, the class will have both `self.log` and `self.logger`, with 700+ lines of code using `self.logger`.
**Why it happens:** Naming mismatch between new base class convention and existing code.
**How to avoid:** Either (a) name the `BaseAgent` attribute `self.logger` to match existing usage, or (b) add `self.logger = self.log` as an alias in `IndicatorComputeAgent.__init__`. Option (a) is cleaner. The PLAN.md uses `self.log` — this creates a naming split.

### Pitfall 3: BaseAgent.start() auto-calls _run() but IndicatorComputeAgent overrides start()
**What goes wrong:** `BaseAgent.start()` in the PLAN.md calls `await self._run()` after registering signals and launching the lag task. But `IndicatorComputeAgent` has its own `async def start()` that manages Kafka setup, DB warmup, and the main loop directly — it does not route through `_run()`.
**Why it happens:** The existing `start()` method is 60+ lines with complex initialization logic that runs before the main loop. Overriding `start()` completely skips `BaseAgent.start()`.
**How to avoid:** The planner must choose: (a) restructure `IndicatorComputeAgent.start()` to call `super().start()` and move main-loop logic into `_run()`, or (b) have `IndicatorComputeAgent.start()` call `self._register_signal_handlers()` directly without calling `super().start()`, using `BaseAgent` only for the scaffolding attributes. Option (b) is lower risk for this phase.

### Pitfall 4: AgentRegistry singleton leaks between tests
**What goes wrong:** `AgentRegistry._instance` persists across test runs; `test_registry_is_singleton` passes but other tests that create a `FakeAgent` and register it see stale state from prior tests.
**Why it happens:** Module-level singleton pattern; Python test isolation doesn't reset class variables.
**How to avoid:** Add `AgentRegistry._instance = None` teardown in tests, or use `@pytest.fixture(autouse=True)` to reset. Document this in test file.

### Pitfall 5: `__new__` pattern test isolation with BaseAgent subclasses
**What goes wrong:** Tests that use `IndicatorComputeAgent.__new__(IndicatorComputeAgent)` to bypass `__init__` must also manually set `self._stop_event`, `self.name`, and `self.log` (or `self.logger`) because `BaseAgent.__init__` now sets these. The existing broken tests set `svc._i1_plugin_states`, etc. — they will also need the new BaseAgent attributes.
**Why it happens:** CLAUDE.md: "Any new instance attribute added in `__init__` must also be manually set in test."
**How to avoid:** After adding `BaseAgent.__init__`, update all `__new__`-pattern tests to also set `svc._stop_event = asyncio.Event()`, `svc.name = "test"`, `svc.log = MagicMock()` (or `svc.logger`).
