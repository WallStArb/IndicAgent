    **CRITICAL CORRECTION from research:** compute_next() falls back to compute_full() when state is uninitialized (line 147-148). compute_full() with 200 bars processes all 200, so bars_processed=199 >= 20 = warmed up. The warm-up=False state is only observable in compute_full() if the df has exactly min_lookback to min_lookback+vol_window bars (but the guard at line 110 returns {} if < min_lookback). So warm-up=False is primarily a defensive flag for edge cases.

    For a reliable warm-up test, test with a df that has exactly 21 bars (just above min_lookback=20), where bars_processed after compute_full = 20 returns = 20 >= 20 = warmed_up=True. To test warm-up=False, we need bars_processed < min_lookback, which cannot happen from compute_full() since the guard returns {} when len(df) < min_lookback.
