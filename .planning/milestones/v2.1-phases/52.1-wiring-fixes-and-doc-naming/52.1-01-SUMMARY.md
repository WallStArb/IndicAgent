## What Was Fixed

### `topic_feature_processed` crash

`feature_writer_service.py` imported and subscribed to `topic_feature_processed` — a topic function removed during the Phase 52 DAG refactor. This caused `ImportError` on service startup. Fixed by replacing all references with `topic_intelligence_journal`.

Additionally added `topic_audit()` to `src/core/stream_keys.py` — referenced by `ParityAuditorAgent` plans but absent from the module.

### Naive UTC datetimes

`indicator_service.py` lines 204 and 616, `market_analysis_service.py` lines 92 and 744 all used `datetime.now()` (naive) for `start_time` initialization and uptime calculation. Both files already import `UTC` — replaced with `datetime.now(UTC)` per CLAUDE.md mandate.

### Persistence metrics gap

`PERSISTENCE_BATCH_LATENCY` (Histogram) and `PERSISTENCE_CONSUMER_LAG` (Gauge) were defined in `src/observability/metrics.py` with `agent_id` labels but never called in either writer service. Wired in `_maybe_flush()` of both `feature_writer_service.py` and `llm_writer_service.py`:
- `PERSISTENCE_CONSUMER_LAG` set to buffer size immediately before batch write
- `PERSISTENCE_BATCH_LATENCY.observe()` called with wall-clock duration after successful write
- `PERSISTENCE_CONSUMER_LAG` zeroed after successful flush

### [Rule 1 - Bug] Test detection logic for naive datetime

**Found during:** Task 3 RED phase
**Issue:** Initial `_find_naive_now()` function returned False because it checked if `datetime.now(UTC)` was absent from the entire file — but the files had both naive and UTC calls, so the condition was incorrectly True.
**Fix:** Rewrote to use per-line regex matching `datetime.now()` without `(UTC` or `(tz=` on the same line.
**Files modified:** `tests/unit/test_utc_awareness.py`

### [Rule 2 - Missing critical] PERSISTENCE_CONSUMER_LAG proxy approach

**Found during:** Task 4
**Issue:** `KafkaConsumerClient` does not expose a partition end-offset/lag API — there is no `consumer_lag()` method.
**Fix:** Used buffer length as consumer lag proxy. Records in buffer = records consumed but not yet persisted = practical lag. This is accurate for the metric's purpose (alerting on backpressure).
**Files modified:** `services/feature_writer_service.py`, `services/llm_writer_service.py`
