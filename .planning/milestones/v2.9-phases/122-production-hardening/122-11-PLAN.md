<objective>
Revert the intelligence_features tier-code column names (i1/i3/i4/i5) back to functional names (technical_indicators/regime_features/confluence_scores/pattern_detections).

Migration 125 renamed these columns to tier codes. That was wrong — a quant reading the schema cold cannot understand what i1/i3/i4/i5 contain without a reference. Functional names are self-documenting. The Renaissance naming principle (whiteboard test) demands it. Also remove the Tier 2 exemption from the naming doc that permitted i1-i8 as DB column names — that exemption was itself a violation of the principle.

Note: i2, smc, cross_timeframe_context, market_context are NOT renamed — i2 was just added in migration 124 and has no prior functional name in the schema; smc and cross_timeframe_context are already functional names.
</objective>

<tasks>

<task id="1" name="Create migration 126">
Create `production/migrations/126_revert_tier_column_names.sql`:

```sql
-- Migration 126: Revert tier-code column names to functional names.
-- i1/i3/i4/i5 are internal pipeline codes, not domain concepts.
-- A quant reading the schema must understand columns without a reference.
ALTER TABLE intelligence_features RENAME COLUMN i1 TO technical_indicators;
ALTER TABLE intelligence_features RENAME COLUMN i3 TO regime_features;
ALTER TABLE intelligence_features RENAME COLUMN i4 TO confluence_scores;
ALTER TABLE intelligence_features RENAME COLUMN i5 TO pattern_detections;
```

Apply it:
```bash
PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent -f production/migrations/126_revert_tier_column_names.sql
```

Verify:
```bash

```

Commit: `feat(122-11): migration 126 — revert i1/i3/i4/i5 to functional column names`
</task>
