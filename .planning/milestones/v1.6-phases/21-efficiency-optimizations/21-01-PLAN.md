<objective>
Implement buffer management optimization in indicator_service to invalidate DataFrame cache only when buffer capacity is exceeded.

Purpose: Reduce DataFrame rebuild operations from every-bar to only-when-necessary, reducing CPU overhead. Currently _df_cache is invalidated on every bar (_df_cache[key] = None), causing redundant pd.DataFrame() construction. Renaissance principle: "let the system run" — no premature optimization without measurement, but cache invalidation every bar is clearly inefficient.
Output: indicator_service with lazy DataFrame cache invalidation.
</objective>

# Current implementation (lines 252-255, 313-317)

Current _get_df() (always rebuilds on miss):
```python
def _get_df(self, key: str) -> "pd.DataFrame":
    if self._df_cache.get(key) is None:
        self._df_cache[key] = pd.DataFrame(list(self.bar_history[key].values()))
    return self._df_cache[key]
```

history = self.bar_history[key]

# Buffer management pattern from market_analysis_service.py (line 108)

market_analysis_service uses deque with maxlen:
```python
self.bar_history: dict[str, deque] = defaultdict(lambda: deque(maxlen=200))
```

But indicator_service uses OrderedDict with manual maxlen enforcement:
```python
self.bar_history: dict[str, OrderedDict] = defaultdict(OrderedDict)
self._bar_history_max = 200
```

# Optimization target

Only invalidate _df_cache when buffer capacity is actually exceeded:
- When len(history) < _bar_history_max: cache remains valid (new bar appended)
- When len(history) == _bar_history_max: cache is invalidated (oldest bar removed)
