<objective>
Remove the `_signal_entry_stale()` check from the SSE snapshot loop so that signal entries replay correctly on reconnect/refresh.

Purpose: The 2×TF age threshold is far shorter than any realistic signal lifetime (a 1m signal can live minutes to hours before resolving). The `count=2` xrevrange already limits snapshot replay to the 2 most recent entries per stream — that is the correct recency guard. The staleness filter is redundant and actively harmful: it drops every signal entry on reconnect, leaving the dashboard blank until a new live signal fires.

The `_signal_entry_stale()` function itself is retained (it is still tested and may be useful for a live-loop guard in future). The call is simply removed from the snapshot loop.

Output: Updated `sse.py` snapshot loop without age filter + updated test suite confirming snapshot replay behavior.
</objective>
