## Phase 126 Design Doc — Full Specification

### Root cause of 47.6% stopped_at_entry

`_resolve_zone_bounds()` in `trade_framer.py` uses raw feature-level zone values with NO ATR-relative minimum:
- Supply/demand: `nearest_demand_low`/`nearest_demand_high` (I3/SMC features)
- FVG: `fvg_bottom`/`fvg_top` (SMC features)
- OB: `ob_bottom`/`ob_top` (SMC features)

These bypass `zone_engine.py`'s `MIN_ZONE_WIDTH_ATR = 0.25` entirely.

ETF reality: ATR on 1m bar ~$0.50-$1.00. Observed zones: $0.01-$0.06. Zone/ATR ratio: 0.02-0.08. Any bar touching the zone extends well past the stop below it.

Forex reality: ATR on 1m bar ~0.0003-0.0008. Typical zones: 0.0010-0.0050 (2-10 pips). Zone/ATR ratio: 3-15x. This is why forex produces 47-64% WR and equities produce 8-22% WR on the same plugins.

Stop geometry is CORRECT (stop below entry and below zone for longs). The zone is simply not wide enough to matter.

### The fix

In `_resolve_zone_bounds()`, after resolving zone bounds, add:
```python
zone_width = zone_high - zone_low
min_width = atr * _cfg("feature.zone_engine.min_zone_width_atr", MIN_ZONE_WIDTH_ATR)
if zone_width < min_width:
    return no_signal()  # zone too narrow — not structural support/resistance
```

Use `no_signal()` not zone-widening. A 2-cent zone on QQQ is not real supply/demand — widening it to $0.50 artificially invents structure that doesn't exist.

APR key: `feature.zone_engine.min_zone_width_atr` (already a Tier C key after Phase 125, but currently only applied inside zone_engine). Seeds:
- Equity ETF: 0.5
- Forex: 0.25
- Futures: 0.35

Asset class detection: `Instrument` type from `settings.py` `get_active_contracts()`.

### Wave structure for design doc

**Wave 1** (blocks everything else):
- P126-01: Zone width enforcement in `_resolve_zone_bounds()` + asset-class APR seeds + replay subset validation (stopped_at_entry < 15%)

**Wave 2** (parallel after Wave 1):
- P126-02: I7 plugin completeness — delete `_I7_I6_EXEMPT`, set `requires_i6_confluence = True` on 8 plugins, fix `trad_MeanReversion` dual-gate conflict
- P126-03: Asset-class parameter seeds in APR for zone/risk geometry (if not fully handled in P126-01)

**Wave 3** (after Wave 2):
- P126-04: Detection correctness audit — sample 100 signals per plugin from replay, verify claimed detection condition is present in OHLCV+features at signal time, flag unverifiable plugins

### Success criteria (Renaissance standard)

1. `_resolve_zone_bounds()` returns `no_signal()` when `zone_width < min_zone_width_atr × ATR` for ALL zone source types (supply_demand, fvg, ob, structural)
2. `feature.zone_engine.min_zone_width_atr` in APR with per-asset-class seeds; asset class determined from `Instrument` type at signal emission
3. `stopped_at_entry` rate < 15% on 10K-signal replay sample (from 47.6%)
4. `_I7_I6_EXEMPT` frozenset deleted; all 8 plugins have `requires_i6_confluence = True` and call `capture_signal_features()`
5. All 37 registered I7 plugins emit > 0 signals in 30-day replay window
6. `trad_MeanReversion` fires meaningfully (> 100 signals/30d) or is retired with documented rationale
7. Detection correctness audit doc produced: per-plugin verification result; unverifiable plugins explicitly flagged
8. `pytest tests/unit/ -q` green
