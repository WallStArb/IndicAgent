## Renaissance Decision Framework

### Why This Can't Be Deferred

**My previous (wrong) reasoning:**
> "No incidents YET from dropped bad data. Data quality issue, not urgent."

**Renaissance correction:**

**1. Bad payloads are NEGATIVE training samples**
- A payload that crashes an agent tells us what patterns break the system
- A payload that fails validation tells us what data quality issues exist
- These are LABELED TRAINING SAMPLES for future improvements
- **Renaissance principle:** "Every signal outcome, feature vector, and LLM call is a labeled training sample. Once gone, it cannot be recovered."

**2. DLQ routing IS graceful degradation**
- Without DLQ: Agent crashes on bad payload → entire pipeline stops
- With DLQ: Agent logs error, routes to DLQ → pipeline continues
- **Renaissance principle:** "Degrade gracefully, adapt automatically. Systems that require manual tuning are fragile."

**3. Storage is the cheapest thing we own**
- DLQ storage cost: ~1 GB per month (assuming 1000 bad payloads/day, 1 KB each)
- Value of one recovered signal: Immeasurable (could be the winning trade)
- **Renaissance principle:** "Never drop data that could contain signal."

**4. DLQ enables FEEDBACK LOOPS**
- DLQ payloads tell us WHAT patterns are failing
- DLQ payloads tell us WHERE data quality issues exist
- DLQ payloads tell us WHEN the system is degrading
- **Renaissance principle:** "Build feedback loops that self-correct."

### Renaissance Verdict

**DO IT NOW.** Here's why:

1. ✅ **Data Quality:** Bad payloads are captured, not dropped
2. ✅ **Graceful Degradation:** Agents continue running, pipeline doesn't stop
3. ✅ **Training Samples:** Negative samples for future improvements
4. ✅ **Feedback Loops:** DLQ depth tells us system health
5. ✅ **Simplicity:** Single pattern (`_dlq_topic()` override, `_send_to_dlq()` call)
6. ✅ **Modularity:** Each agent implements DLQ independently
7. ✅ **Reuse:** BaseAgent `_send_to_dlq()` already exists
8. ✅ **Storage Cost:** Negligible (~1 GB/month)

**Jim Simons would say:**
> "Why would you throw away data? Every bad payload is a negative training sample. Route it to DLQ, analyze it, and fix the root cause. Storage is cheap. Data is priceless."

## Threat Model

- **DLQ bloat:** Possible if agents emit massive volumes of bad payloads. Mitigation: (1) Fix root cause, (2) Set TTL on DLQ topics (7 days), (3) Grafana alert on DLQ depth > 1000.
- **DLQ never consumed:** Possible if we don't build DLQ consumers. Mitigation: Plan 067-07 only implements PRODUCER side. Consumer side is future work (when we have DLQ data to analyze).
- **Sensitive data in DLQ:** Possible if payloads contain PII or secrets. Mitigation: (1) No credentials in payloads (verified), (2) No PII in market data (verified), (3) DLQ topics have same security as production topics.
- **Kafka topic proliferation:** 15 new DLQ topics. Mitigation: (1) Follow naming convention (`<domain>.<agent>.dlq`), (2) Set retention (7 days), (3) Document in stream_keys.py.

**Goal:** Define standard DLQ payload schema.

- [ ] **Define DLQ payload schema:**
  ```python
  # src/core/schemas/dlq_payload.py
  from pydantic import BaseModel
  from datetime import datetime, UTC

  class DLQPayload(BaseModel):
      """Standard Dead Letter Queue payload.

      All agents route unprocessable payloads to DLQ using this schema.
      Enables systematic analysis of data quality issues.
      """
      agent: str  # Agent name that routed to DLQ
      source_topic: str  # Kafka topic where payload was consumed
      error_type: str  # Exception class name (e.g., "ValidationError", "KeyError")
      error_message: str  # Human-readable error message
      payload: dict  # Original payload that failed processing
      timestamp: datetime  # When routed to DLQ (UTC)
      retry_count: int = 0  # Number of retry attempts (0 = first attempt)

      class Config:
          json_encoders = {datetime: lambda v: v.isoformat()}
  ```

### Task 4: DLQ Metrics + Grafana Alerting

**Goal:** Track DLQ depth and alert on anomalies.

- [ ] **Add DLQ depth metric:**
  ```python
  # src/observability/metrics.py
  DLQ_DEPTH = Gauge(
      "dlq_depth",
      "Number of messages in Dead Letter Queue",
      ["agent", "topic"]
  )
  ```

- [ ] **Emit DLQ depth metric when routing to DLQ:**
  ```python
  # BaseAgent._send_to_dlq() override in concrete agents
  async def _send_to_dlq(self, payload: dict, error: Exception) -> None:
      """Route to DLQ and track depth."""
      if not hasattr(self, "_producer") or self._producer is None:
          return

      from src.core.stream_keys import topic_bar_audit_dlq
      from src.core.schemas.dlq_payload import DLQPayload
      from src.observability.metrics import DLQ_DEPTH

      dlq_topic = topic_bar_audit_dlq(self._settings.env_name)
      dlq_payload = DLQPayload(
          agent=self.name,
          source_topic=self._topics_consumed[0] if self._topics_consumed else "unknown",
          error_type=type(error).__name__,
          error_message=str(error),
          payload=payload,
          timestamp=datetime.now(UTC),
          retry_count=0
      )

      try:
          await self._producer.produce(dlq_topic, dlq_payload.model_dump())
          DLQ_DEPTH.labels(agent=self.name, topic=dlq_topic).inc()
          self.logger.info("dlq_routed", topic=dlq_topic, error_type=type(error).__name__)
      except Exception as exc:
          self.logger.error("dlq_route_failed", error=str(exc))
  ```

- [ ] **Add Grafana alert rule:**
  ```yaml
  # production/grafana/provisioning/alerting/alert-rules.yml
  - name: DLQDepthAlert
    expr: dlq_depth > 1000
    for: 5m
    labels:
      severity: high
  ```
