# Phase 44.2 Plan 02: SignalGeneratorService In-Process Pipeline Wiring Summary

**One-liner:** Replaced 8-hop Kafka DAG dispatch with 6 in-process pure function calls per bar, adding bounded audit queue, BarIntelligenceRecord publish, and resilient DB write with ledger_written tracking.

## What Was Built

### In-Process Pipeline (`services/signal_generator_service.py`)

Replaced the DAG architecture (8 Kafka round-trips per signal set) with direct in-process calls:

```
apply_quality_gate → apply_regime_gate → apply_tod_adjustment →
apply_calibration → rank_signals → select_winner
```

All 6 calls are synchronous, per-bar, with no Kafka overhead in the hot path.

### New Methods

| Method | Purpose |
|--------|---------|
| `_process_event()` | Calls all 6 pipeline stages, gate check, ledger write, record publish |
| `_drain_audit_queue()` | Background task: drain audit queue to pipeline.* topics |
| `_queue_stage_audits()` | Non-blocking put_nowait; drops on overflow with counter |
| `_to_ranked_signal()` | Maps post-pipeline signal dict to RankedSignal Pydantic model |

### New Prometheus Counters

| Counter | Description |
|---------|-------------|
| `signal_generator_pipeline_stage_input_total[stage]` | Signals entering each stage |
| `signal_generator_pipeline_stage_output_total[stage]` | Signals exiting each stage |
| `signal_generator_ledger_write_failures_total` | DB write failures (pipeline continues) |
| `signal_generator_audit_queue_drops_total` | Audit queue overflow drops |

### Deleted

- `_consume_winner_signals()` method (~220 lines) — entire Kafka DAG consumer removed
- `_dag_winner_consumer` attribute — no longer needed

### Preserved

- `_check_gate()` / `_update_gate()` — moved from `_consume_winner_signals` to `_process_event`
- `development.signals.aggregated` publish — backward compat for SignalLifecycleService
- `development.intelligence.i7` scorecard publish — backward compat for dashboard
- All refresh loops, DB loading, regime cache, CIS scorer

### New Publish: `BarIntelligenceRecord`

Every bar now publishes a `BarIntelligenceRecord` to `development.intelligence.record`:
- Full `IntelligenceEvent` (all tiers)
- All `RankedSignal` models after pipeline
- Funnel counts: signals_evaluated, _after_quality, _after_regime, _after_tod, _after_calibration
- `ledger_written=False` when DB write fails (pipeline never crashes)
- `pipeline_latency_ms` computed from monotonic clock
