<decisions>
## Implementation Decisions

### Renaissance Design Lens

User framing (verbatim): *"Design this like Renaissance would. How would a senior engineer/quant
at Renaissance think about this? What would Jim Simons demand? Ensure alignment with core
principles: modularity, reuse, separation of concerns, microservices DAG. Balance efficiency with
simplicity. Keep compute costs in mind. No manual tasks — prefer automation."*

This translates to:

**Separation of concerns (no leakage):**
`kafka_utils.py` is the transport layer. Context propagation is a transport-layer concern. Agents
must not know about `traceparent` headers — `self.tracer` is their only OTel surface. The inject/
extract logic lives entirely in `KafkaProducerClient.publish()` and `KafkaConsumerClient.messages()`.

**Zero overhead when tracing is disabled:**
The OTel propagators API is no-op when no `TracerProvider` is configured (or when
`OTEL_EXPORTER_OTLP_ENDPOINT` is unset). No conditional `if tracing_enabled:` guards needed —
the SDK handles this. Compute cost of `propagate.inject({})` with a no-op provider is negligible.

**No per-message spans:**
`with self.tracer.start_as_current_span("kafka.message")` inside `messages()` would create one
span per consumed message. At 1m bars × 5 symbols × 6 TFs = 30 events/minute minimum, this is
O(1) at current scale but O(N) at future scale. The Renaissance rule: measure the cost before
paying it. Context propagation (inject/extract headers) has near-zero cost; per-message spans do
not. This phase injects/extracts only — agents own their span creation.

**Header format — W3C traceparent only:**
W3C `traceparent` is the OTel standard. No Jaeger/B3 headers. The carrier is a plain `dict[str,
str]` passed to `propagate.inject()` / `propagate.extract()`. AIOKafka headers are
`list[tuple[str, bytes]]` — the carrier adapter converts between them.

**Minimal surface change:**
`KafkaProducerClient.publish()` injects context into headers before `send_and_wait()`.
`KafkaConsumerClient.messages()` extracts context from `msg.headers` and attaches it to the
current context before yielding. The yield tuple stays `(topic, key, payload)` — no signature
change visible to callers.

**Automation — no manual steps:**
Phase 52.7 sets `OTEL_EXPORTER_OTLP_ENDPOINT` in systemd units. After this phase, context
propagation is automatic — no agent code changes required, no operator steps.

### AIOKafka header format

`AIOKafkaProducer.send_and_wait()` accepts `headers: list[tuple[str, bytes]]`.
`AIOKafkaConsumer` message `.headers` is `tuple[tuple[str, bytes], ...]`.

The carrier adapter:
```python
class _KafkaHeadersCarrier:
    def __init__(self) -> None:
        self._headers: dict[str, str] = {}

    def get(self, key: str) -> list[str] | None:
        val = self._headers.get(key)
        return [val] if val is not None else None

    def set(self, key: str, value: str) -> None:
        self._headers[key] = value

    def keys(self) -> list[str]:
        return list(self._headers.keys())

    def items(self) -> list[tuple[str, str]]:
        return list(self._headers.items())

    def to_aiokafka_headers(self) -> list[tuple[str, bytes]]:
        return [(k, v.encode()) for k, v in self._headers.items()]
```

This is a private implementation detail of `kafka_utils.py` — not exported.
