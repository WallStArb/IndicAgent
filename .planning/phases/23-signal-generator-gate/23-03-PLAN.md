<objective>
Clean up dead `InputSpec(timeframe="1m")` declarations across all 17 I7 plugins (change to `".*"`) and add explicit comments to both services documenting that 4h/1d processing is intentionally excluded for day-trading focus.

Purpose: Remove misleading dead code. The timeframe field on InputSpec is defined in the dataclass but never read at runtime — signal_generator_service passes the current-TF OHLCV regardless. Leaving "1m" implies plugins only run on 1m data, which is false and confusing. The 4h/1d comment prevents future devs from assuming it was accidentally omitted.

Background (confirmed research finding): InputSpec.timeframe is defined in src/intelligence/plugins.py but is never read after construction — no enforcement in registry or service code. grep confirms only reference is signal_ledger.py (a different `timeframe` attribute). The change to ".*" is therefore dead-code cleanup only, not a behavioral change.

Output: 17 plugin files updated, 2 service config comments added.

NOTE: This plan is Wave 3 (after Plan 02) because Task 2 adds a comment to signal_generator_service.py, which Plan 02 also modifies. Sequential execution prevents file conflicts.
The 17 plugin edits are mechanical one-liner find/replace operations — no logic changes involved. Executor should use a single sed or search-and-replace pass across all 17 files rather than editing each manually.
