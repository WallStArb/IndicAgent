<objective>
Build D-04's comparison machinery: criteria 1 (net-of-cost delta CI), 2 (gross-spread
non-degradation), and 3 (turnover diagnostic), exposed as a fourth read-only CLI mode.

Purpose: D-04.1 explicitly rejects "two separately-overlapping point estimates." RESEARCH
confirms every prior candidate-vs-baseline gate in this repo (including
`gate166_frame_recalibration_eval.py`) uses independent single-arm CIs — the exact anti-pattern.
Phase 168 is the first paired-delta gate here. The key reuse insight: `frame_gate_passes` is
domain-agnostic over `(value, cluster_id)` pairs, so feeding it a per-bar delta series yields the
delta CI with ZERO new bootstrap code. All new work is the two-partition alignment and the
non-degradation reinterpretation.

Output: `--evaluate-delta-gate` runs end to end and writes a `gate_delta` verdict artifact whose
`gate_delta_passes` is explicitly `null` with an "incomplete" verdict text — the stateful
shuffled null (D-04.4) lands in Plan 05 and the gate must not be able to report a pass without it.
