Wrap the message processing inside the consume loop:

```python
async def _run(self) -> None:
    assert self._consumer is not None
    async for _topic, _key, payload in self._consumer.messages():
        if self._stop_event.is_set():
            break
        if not isinstance(payload, dict):
            continue
        self._record_message_consumed()
        self._on_message_consumed(payload)

        with self.tracer.start_as_current_span(
            "writer.process_message",
            attributes={"agent": self.name},
        ):
            rows = self._parse_payload(payload)
            if rows is not None:
                self._buffer_rows(rows)
            else:
                self._parse_failures_total.inc()
                await self._maybe_route_to_dlq(payload, Exception("Parse failed"))

        if len(self._buffer) > self._alert_threshold:
            await asyncio.sleep(0.5)

        await self.maybe_flush()
```

1. In `src/core/agent/base.py`:
   - REMOVE: `from prometheus_client import Counter as _Counter`

   - The module-level AGENT_CRASH_TOTAL, AGENT_SETUP_SUCCESS_TOTAL, etc. will now use
     OTelCounter/OTelHistogram wrappers. The API is identical (.labels().inc(), .observe()).

   Actually, these module-level metrics use `prometheus_client.Counter` and
   `prometheus_client.Histogram` with labelnames parameter. The OTelCounter/OTelHistogram
   wrappers need to match this pattern. Let's verify:

   Current: `Counter("agent_crash_total", "...", ["agent"])`
   Wrapper: `OTelCounter("agent_crash_total", "...", ["agent"])`

   The wrapper's __init__ signature is: `(name, documentation, labelnames)`.
   The prometheus_client Counter signature is: `(name, documentation, labelnames)`.
   These match. So we can just swap the import.

   BUT WAIT: The wrappers use `opentelemetry.metrics.get_meter()` internally.
   This means the meter must be initialized before these module-level globals are
   created. Since module-level globals are created at import time (before any agent
   starts), the meter might not be initialized yet.

   SOLUTION: Lazy initialization. The wrapper should NOT create the counter at __init__
   time; instead, create it on first use. OR, use the ProxyMeterProvider that OTel
   provides -- get_meter() returns a ProxyMeter that queues calls until a real
   MeterProvider is set.

   OTel's ProxyMeterProvider handles this: `get_meter()` returns a proxy that
   queues metric creation until a real provider is set. So creating OTelCounter at
   module level is safe -- the actual counter is created lazily when
   MeterProvider is initialized.

   So the import swap is safe.

   Changes to `src/core/agent/base.py`:
   - Replace `from prometheus_client import Counter as _Counter` with
     `from src.observability.metrics import OTelCounter as _Counter`
   - Replace `from prometheus_client import Histogram as _Histogram` with
