<objective>
B2: research kernels under phase 186's registry contract and the `kernel_source` adapter that runs
them on an S0 panel at spec-pinned windows (design D5 revision 3, section 5, D7 guard 5).

Purpose: `kernel_source` is only for windows the stored table does not carry (D5: never a second
implementation of a stored feature). The two stored originals are too slow for 5m (one scipy call
per bar; an O(n x w) loop), and the stored VWAP deviation is cumulative from index 0
(path dependent), so research needs vectorized, bounded-memory equivalents under the same
contract and the same causality and memory probes.

Placement (RESEARCH Finding 3, Pitfall 5): a sibling package `src/intelligence/features/research_kernels/`
that `discover_kernels()` never scans, so no stored column, schema test or rebuild import closure
changes.

Output: the research_kernels package, `research/kernel_source.py`, two test files.
