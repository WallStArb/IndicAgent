## Objective

Implement `_seed_bar_history_from_db()` method in `signal_generator_service.py` that queries `intelligence_features` for recent bar history and seeds `bar_history` before the service begins consuming live stream data. Eliminates the 50-minute warmup delay after service restarts.

## Why This Matters

Currently, `signal_generator_service` requires ~50 live 1m bars (min_bars_for_tf(1m) = 120, but only 2 bars/min with 4 timeframes = 0.5 bars/minute, so ~4 hours) before signals fire. During service restarts, `bar_history` is empty, causing full warmup delay. This blocks quick iteration on signal logic and leaves gaps in signal_ledger during restart windows.

By seeding from `intelligence_features` on startup, the service fires on the first incoming live bar with no delay.

## Technical Approach

1. Add `_seed_bar_history_from_db()` method to `SignalGeneratorService` class
2. Query `intelligence_features` for `min_bars_for_tf(tf)` bars per (symbol, tf) ordered by timestamp DESC
3. Store bars in `bar_history` dict keyed by `(symbol, tf, ts)` tuple (matching existing structure)
4. Call this method in `start()` between `_connect_database()` and `_setup_consumer_groups()`
5. Graceful degradation: if DB query fails (PostgresError, connection issues), log WARNING and proceed with empty `bar_history` (live warmup fallback)
6. Log seeding completion with bar counts per symbol/TF

## Key Constraints

- Do not block startup if `intelligence_features` is unavailable (graceful fallback to live warmup)
- Maintain existing `bar_history` structure: `dict[tuple[str, str, int], pd.DataFrame]` keyed by `(symbol, timeframe, timestamp)`
- Seeding must happen before `_setup_consumer_groups()` so consumer group doesn't start consuming live data first
- Query must use `ORDER BY ts DESC LIMIT N` to get most recent N bars, then reverse for chronological order

```python
async def _seed_bar_history_from_db(self) -> None:
    """
    Seed bar_history from intelligence_features to eliminate warmup delay on restart.

    Queries min_bars_for_tf(tf) recent bars per (symbol, tf) from
    intelligence_features table and populates bar_history dict.

    Gracefully degrades if DB unavailable: logs WARNING and proceeds
    with empty bar_history (live warmup fallback).
    """
    if not self.db_manager:
        logger.warning("DB seed failed - falling back to live warmup")
        return

    active_contracts = get_active_contracts()
    seeded_count = 0

    try:
        for symbol in active_contracts:
            for tf in self.active_timeframes:
                min_bars = min_bars_for_tf(tf)

                query = f"""
                    SELECT ts, bar
                    FROM intelligence_features
                    WHERE symbol = %s AND tf = %s
                    ORDER BY ts DESC
                    LIMIT {min_bars}
                """
                result = await self.db_manager.execute_query(
                    query, (symbol, tf)
                )

                if result and len(result) > 0:
                    # Convert to DataFrame and reverse for chronological order
                    df = pd.DataFrame(result, columns=['ts', 'bar'])
                    df = df.sort_values('ts').reset_index(drop=True)

                    # Store in bar_history using existing key structure
                    for _, row in df.iterrows():
                        key = (symbol, tf, row['ts'])
                        self.bar_history[key] = row['bar']
                        seeded_count += 1

        logger.info(f"Seeded bar_history: {seeded_count} entries across "
                      f"{len(active_contracts)} symbols, {len(self.active_timeframes)} TFs")

    except Exception as e:
        logger.warning(f"DB seed failed - falling back to live warmup: {e}")
        # bar_history remains empty, service proceeds with live warmup
```
