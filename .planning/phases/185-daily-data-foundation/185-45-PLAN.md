plan takes the dormant v2.x and AI stack out of the tree, the database and Docker, split from

records an earlier intent to keep v2.x revivable; this plan honours it through the archive, not the
tree: a git tag and table dumps make a revival a restore, not a rebuild.

Pre-registered rules (write them in the SUMMARY before running any removal):
- No live consumer means all of: `systemctl list-units --all 'indicagent-*'` shows no enabled or active
  unit running the code (a failed or inactive unit that nothing triggers counts as no consumer and is
  removed with the code); `docker ps` shows no running container for a compose service; `grep -rn`
  over services, src, scripts, production and tests finds no import or reference outside the code being
  removed together; for a table, no reader or writer remains after the code removal (the 185-44 reader
  guard).
- Redpanda: remove the service, its compose entry and production_redpanda-data only if no enabled or
  active unit produces to or consumes from Kafka and no live module imports the Kafka client outside
  code removed here; the streaming path is a spec non-goal and CLAUDE.md calls it dormant, not deleted,
  so if any kept daemon (BaseDaemon services the streaming path would revive) still depends on it, keep
  the service and record the evidence. Redpanda is transport, not state: its topic data is never a
  reason to keep it.
- Candidates found by the census but not named here are listed, not removed; they go to a pending todo.

Archive location: data/backups/185-45/ (gitignored), kept 30 days unless the owner says otherwise;
MANIFEST.md lists each archive, size, sha256 and restore command. Sudo for systemctl and docker volume
work: user_sudo_password memory file. `production/docker-compose.yml` changes take effect with
`cd production && docker compose up -d --remove-orphans` (the logging caps on other services stay).
No em dashes; no AI attribution.
</objective>
