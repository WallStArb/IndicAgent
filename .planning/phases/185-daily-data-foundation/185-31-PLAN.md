Diagnosis (live, 2026-10-06): the 7 symbols hold 15 to 40 stored ibkr_named 15m/1h rows each
whose archived observation under the same key differs (one-cent prices, a few hundred to a few
thousand shares, 2026-09-28 to 10-01; two observations inside IBKR's revision window), plus 99
never-archived rows on A, AAP and ADBE. The archive keeps the first write (`ON CONFLICT DO NOTHING`
on its (timestamp, symbol, timeframe) key), so the table's observation can be neither added nor
deleted.

Design: a sibling table instead of re-keying the archive. The archive is a compressed hypertable
(86 of 87 chunks compressed, 92.8M rows, 3.7 GB); changing its unique key means decompressing every
chunk, and the lane writes to it continuously. A small uncompressed append-only
`ohlcv_intraday_raw_revision` (archive columns plus observed_at default now(), origin
'table_segment' or 'fetch', batch_id), unique on (symbol, timeframe, "timestamp", open, high, low,
close, volume) so identical repeats collapse, holds every later observation that disagrees with the
archived one. Readers that need one row per key (`_d1_gaps` answered windows) keep reading the
archive unchanged.

Lane constraint: `services/intraday_raw_archive.py` is imported by the running HTF lane
(`infrastructure_run_historical_pipeline.py` calls `insert_fetched_archive_rows`). Edits there:
(1) add `REVISION_FROM_TABLE_SQL` (new constant, not used by the lane); (2) inside
`insert_fetched_archive_rows`, after each chunk's archive insert, one more statement that inserts the
chunk's rows whose archived row under the key differs into the revision table (origin 'fetch',
ON CONFLICT DO NOTHING), returning nothing new to the caller; (3) delete the dead
`source <> 'synthetic_fill'` filter in `ARCHIVE_FROM_TABLE_SQL` (zero synthetic rows since 185-25;
the fetched-path refusal of synthetic fills stays). The lane picks the change up at its next
attempt's process start; the extra statement is one join of at most `batch_size` rows against the
archive's (symbol, timeframe, timestamp) index. Migration 443 must be applied before the edit lands
on disk, or the lane's next attempt fails on a missing table. Phase 189's fetcher files
(`_history_fetch_item.py`, fetch queue, coverage writer) are not touched.

Migration 443: re-check it is free right before `psql -f`, else use the next free number and
record it; apply and commit together. The grid run honors the grid lane guard
(`scripts/ops/bars/ops_grid_lane_guard.py`, D-31): if a target symbol is in the lane's current unit,
wait for the guard rather than overriding it. Unit tests use fakes (todo 494); the integration test
is read-only. No em dashes; no AI attribution.
