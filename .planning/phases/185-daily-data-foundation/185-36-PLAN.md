<objective>
Spec step 3, first half (`docs/plans/2026-10-06-data-layer-integrity-design.md` sections 2 and 4,
owner-approved 2026-10-06): one source policy table and one daily rule, d2-v2, merging `derive_daily`
(d2-v1) and the Tradier loader's inline rule (tradier-v1). This reverses the owner-accepted override
that allowed a second 1d writer (185-VERIFICATION override 2) as the spec decides; it does not reopen
Tradier as primary. The cutover (loader raw-only, lineage view, live re-derivation) is 185-38; this plan
builds and measures the rule without changing a stored bar.

Decisions implemented (spec section 2): 1d primary Tradier for every name, fallback IBKR SMART TRADES;
head admitted with a seam record; interior hole admitted only within the basis tolerance, else NaN;
admitted fallback volume NULL in the tradeable view; per-name exception rows only on evidence (185-37
writes them). 5m direct IBKR, 15m/1h/4h derived from 5m (policy rows only; this plan derives nothing
intraday).

Discretion choices, documented here:
- The admitted fallback source label is `ibkr_fallback` (new value, added to CANONICAL_1D_SOURCES), so
  the tradeable view can NULL its volume by source exactly as it does for `ibkr_venue`, with no join to
  the policy table on every read.
- The head seam record is a non-quarantine `bar_quality_flag` row, rule `fallback_seam`, on the first
  primary bar after the head, its `detail` holding the overlap ratio, the window and the number of
  common sessions. The policy table stays a table of decisions with one writer, not of per-name
  measurements.
- Interior holes: the nightly Tradier load is a whole-history fetch, so its latest answer is the
  re-ask the spec asks for; d2-v2 judges a hole against the latest Tradier answer.
- Split scale: d2-v1's `split_staleness_threshold` applies to both vendors' observations (an
  observation fetched before a split's recorded_at, for a date before its effective date, is stale).
- `fallback_basis_window_sessions` seeds 20 and `fallback_basis_tolerance_bp` seeds 10, both
  `[initial_estimate]` (the spec measured 96% of interior IBKR bars agreeing within 10 bp). Neither is an
  ML learning target.

Contract kept for phase 189 (do not break): `services/bar_derivation.py` keeps
`_SELECT_DAILY_CHANGED_SINCE_SQL` by that name with its `tradier_owned` column, because
`ibkr_history_fetcher.py` (a phase 189 file, not edited here) imports it as `_DAILY_SOURCE_PROBE_SQL`.
185-38 redefines the column's meaning; 189-10 replaces the fetcher's use of it.

Constraints: migration 446, re-check free, apply and commit together. Fixture extraction is read-only.
No live `--apply` in this plan. `src/intelligence/bars/` is not under research/ or statistics/, so no
repro_frozen run. Unit tests use fakes (todo 494). No em dashes; no AI attribution.
</objective>
