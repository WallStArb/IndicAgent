<objective>
The checks that would have caught gap A. Today `check_d2_landed` tests row existence (one d2-v1
lineage row per symbol, one digest row per month), which passed 743 names whose lineage and digests
describe IBKR values the table no longer holds. After 185-27 and 185-30 the data is right; this
plan makes staleness loud from now on.

Design: the expensive truth (value equality and digest recomputation over about 7M 1d bars) is
computed once a night by D7, which already runs on every nightly path (185-23), and is recorded as
integrity facts. The rebuild gate reads those facts plus a freshness rule (the facts must be newer
than the latest 1d write), so it stays cheap and read-only. A gate that recomputed everything itself
would duplicate D7 and run minutes inside a precondition check.

created it; todo 489 added check_d2_landed in 0a653ff6a). Phase 185 edits them because the gate
checks 185's data contract and the change of canonical rules is 185's. The rebuild writer
(`services/backfill_feature_factory.py`) imports this module (CoverageRow), so its
`code_content_key` covers it: before editing, confirm no 186-26 rebuild run is live or resumable
(no process, no completed rebuild cells). Keep `fetch_d2_inputs`'s callers working (grep them;
widen `rule_version` to a tuple with the old default behavior covered by the new set) and say so in
the commit message so the 186 session sees it.
