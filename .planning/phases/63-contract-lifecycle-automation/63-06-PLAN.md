## Problem Statement

**Current behavior (BROKEN):**
```
IBKR publishes: symbol="ESM6" (contract code)
instruments table has: symbol="ES", base="ES" (base symbols only)
BarWriterAgent cache lookup: cache.get("ESM6") → None
Fallback: base = "ESM6" (WRONG - should be "ES")
```

**Evidence:**
```sql
SELECT symbol, base FROM market_data_ohlcv WHERE symbol LIKE '%M6' LIMIT 5;
-- Result: CLK6 | CLK6  (WRONG - should be C or ZC)
```

**Impact:**
- D-21 validation blocked (Phase 50) — can't query base symbols
- ML training data corrupted (v2.3) — features grouped by contract code instead of base
- Cannot query "all ES contracts" — contract codes don't aggregate

**Root cause:**
- `instruments` table stores base symbols (ES, NQ, CL)
- IBKR publishes contract codes (ESM6, NQM6, CLM6)
- BarWriterAgent cache lookup fails → uses contract code as base

---

## Solution Design

### Architecture Decision: Use contract_metadata as Source of Truth

**Rationale:**
- Phase 63-02 built `contract_metadata` table specifically for this purpose
- `contract_metadata` has both `symbol` (contract code) AND `base_symbol` (base)
- ContractMetadataWriterAgent keeps it current on roll promotions
- Single source of truth aligned with Renaissance DAG principles

**Schema:**
```sql
SELECT symbol, base_symbol FROM contract_metadata;
-- Result:
-- symbol  | base_symbol
-- --------|------------
-- ESM6    | ES
-- ESU6    | ES
-- NQM6    | NQ
-- CLM6    | CL
```

### BarWriterAgent Cache Refactor

**Current (BROKEN):**
```python
# services/bar_writer_agent.py line 171
query = "SELECT symbol, base FROM instruments WHERE base IS NOT NULL;"
self._instruments_cache = {row["symbol"]: row["base"] for row in rows}
# Cache: {"ES": "ES", "NQ": "NQ", "CL": "CL"}
base = self._instruments_cache.get("ESM6", "ESM6")  # FAILS
```

**Fixed (Plan 06):**
```python
# Query contract_metadata instead
query = """
SELECT symbol, base_symbol
FROM contract_metadata
WHERE symbol IS NOT NULL AND base_symbol IS NOT NULL;
"""
self._contract_cache = {row["symbol"]: row["base_symbol"] for row in rows}
# Cache: {"ESM6": "ES", "ESU6": "ES", "NQM6": "NQ", "CLM6": "CL"}
base = self._contract_cache.get("ESM6", "ESM6")  # WORKS ✅
```

### Cache Invalidation on Contract Promotions

**Problem:** When RollComputeAgent detects a roll (ESM6→ESU6), ContractMetadataWriterAgent updates `contract_metadata`, but BarWriterAgent cache goes stale.

**Solution:** Subscribe to `topic_contract_updates` and invalidate cache on promotion.

```python
# services/bar_writer_agent.py

# In _setup_kafka_clients(), add topic:
topics = [
    topic_intelligence_journal(self._env_name),
    topic_roll_events(self._env_name),
    topic_cross_asset(self._env_name),
    topic_contract_updates(self._env_name),  # NEW
]

# In _process_loop(), add handler:
if kafka_topic == contract_updates_topic:
    await self._handle_contract_update(payload)
    await self._load_contract_cache()  # Invalidate + reload
    continue
```

   ```python
   async def _handle_contract_update(self, payload: dict) -> None:
       """Handle ContractUpdateEvent from ContractMetadataWriterAgent.

       Invalidate contract cache on front-month promotion so BarWriterAgent
       uses new contract codes for base symbol resolution.

       Args:
           payload: ContractUpdateEvent dict from Kafka
       """
       try:
           event = ContractUpdateEvent.model_validate(payload)
           self.logger.info(
               "contract_update_received",
               base_symbol=event.base_symbol,
               old_contract=event.old_contract,
               new_contract=event.new_contract,
               promoted_at=event.promoted_at,
           )
           # Reload cache to pick up new contract codes
           await self._load_contract_cache()
           self.logger.info("contract_cache_reloaded", cache_size=len(self._contract_cache))
       except Exception as e:
           self.logger.error("contract_update_handler_failed", error=str(e))
           # Don't crash — cache will refresh on next restart
   ```
