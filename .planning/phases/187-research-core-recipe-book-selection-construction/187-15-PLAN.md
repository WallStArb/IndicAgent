<objective>
`generated_family` support in the spec (design 6.1, R-187-20): discovery without preconceptions, where the only preconception is a grammar registered before any run. This plan delivers the grammar, its spec form, enumeration, causal operators, derived memory, block-wise computation, and the S0 fields the design's primitive list needs. Grammar (design 6.1 item 1):
- primitives: log returns at the panel clock and at session level, volume (log), range (log high/low), gaps (overnight: open over prior close; intraday leg: close over open), time-of-day slot index and calendar position (day of week, day of month, month), cross-sectional aggregates (market mean of a primitive) and sector aggregates (SCH sector mean, point in time);
- operators, causal: lag(k), diff(k), ts_mean(w), ts_zscore(w), ts_rank(w) over trailing windows, cs_demean, cs_rank, product of two terms;
- windows from a fixed menu declared in the spec; max depth 2 to start (the spec pins it; the loader cap is a schema identifier constant, not tunable);
- expressions are canonical strings (sorted operands for the commutative product) so enumeration order and dedup are deterministic.
Memory per candidate = sum of nested trailing windows and lags (in rows), plus 1 for diff; cross-sectional operators add none. Missing inputs give NaN (no fill); generated members pass the missing-member rule (plan 09) like any member.

S0 fields: today the panel carries open, close and volume only, and S0 stopped filling sector labels because a present-day label on a historical panel is lookahead. New optional PanelSpec field `fields: list[Literal["high", "low", "sector_pit"]]` (in `_OPTIONAL_PANEL_FIELDS`, dropped while unset). When requested, S0 selects high and low from `market_data_ohlcv_tradeable` alongside the existing columns, and builds sector_pit as an [n_sessions, m] integer code array of each name's SCH sector as of each session date through `current_level_name_sql()` or ClassificationService's as-of read (point_in_time invariant), with the code table in the manifest. Panel serialization writes the new arrays only when present, so `panel_81fa9178ca4ad603` and every saved panel load and verify unchanged (store.verify equal to the recorded snapshot_hash).
