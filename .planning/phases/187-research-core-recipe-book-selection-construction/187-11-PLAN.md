Recipe content (design 10.2.2), built by a pure function so the hash is deterministic: code pointer (`module:function` of the member signal, family module, combiner class, construction rule class, `pod.run_pod`), code commit (the run's code_commit), pinned params (member params, combiner fields, construction fields, horizon rule), apr_values (APR keys the run reads with their values at run time, from the RunContext; empty when none), inputs (panel spec fields and, for books, parent concepts, which also get concept_parent edges as today), universe selector (panel members_universe or the snapshot universe rule), cvr_codes (construction rule name, combiner kind, timeframe; validated against controlled_vocabulary namespaces seeded in this migration: `research_construction_rule`, `research_combiner`, `research_timeframe`), mechanism and sources (spec prior_source path), author (git config user.name at run time). recipe_hash = sha256 of the canonical JSON of everything except code_commit and author, so a re-run at a new commit of the same definition reuses the version. Version = 1 + max(version) for the concept when the hash is new.

Research stage view `concept_research_stage` (glossary `research stage`), one row per concept, first matching rule wins:
- confirmed: domain book and status active (the production lifecycle has promoted it);
- frozen: domain book and status shadow_only;
- refused: status deprecated, or every terminal attempt is refused or guard_failed, or its only attempts are legacy_verdict;
- tested: a completed or failed attempt exists;
- registered: an attempt exists and none is terminal (started);
- specified: a recipe exists and no attempt;
- idea: no recipe.
