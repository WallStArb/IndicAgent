# Phase 49.1 Plan 01: Regime Gate Fix — Write All Signals to Signal Ledger Summary

Decoupled signal_ledger writes from winner selection in `signal_generator_service._process_event()`. Regime-suppressed signals and gate-suppressed bars now write unconditionally to the ledger whenever `all_ranked` is non-empty. Populated `hmm_regime_at_fire` and `regime_type_at_fire` on every `LedgerEntry` for per-regime ML segmentation.

## Key Decisions Made

1. **Collapse trend direction in `_HMM_REGIME_LABEL`** — hmm_regime=1 (trend-up) and hmm_regime=2 (trend-down) both map to "trending". Consistent with `aggregator._REGIME_MAP`. ML segmentation benefits from regime type, not direction (direction is already in `LedgerEntry.direction`).

2. **`_winner_signal_id == ""` guard for `_is_winner_entry`** — When gate fires, `_winner_signal_id` stays `""`. Guard `if _winner_signal_id != "" else False` ensures all entries get `was_selected=False` without needing to check `winner is None` in the expression.

3. **`signals_written_total` tracks suppressed-only** — Counter increments only `if not winner` after successful DB INSERT. Allows monitoring how many bars write solely suppressed signals (operational visibility into regime gate activity).
