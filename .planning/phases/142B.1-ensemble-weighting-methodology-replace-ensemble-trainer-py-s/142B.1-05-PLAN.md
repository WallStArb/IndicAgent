<objective>
Build the A/B judging infrastructure (D-12): a new gate script `ops_ensemble_weight_compare.py` that reads `alpha_ensemble_ic` for two `weight_version`s, applies D-10's win rule per (tf, regime) stratum, reports per-stratum promotion (D-11), and tags regime-caveat rows (D-14). Mirrors the EIC-04/EIC-05 pattern already built in 142A. Repeatable across E1/E2/E3/E4 rounds — not ad hoc SQL.

Purpose: A weight variant is only a winner where it is a real, not noise-level, improvement on the statistically-clean pooled grain — `challenger.ic_ci_lower > champion.ic_ci_upper` (non-overlapping CIs) AND `challenger.walk_forward_stable = true` (D-10). Promotion is per-stratum (D-11): E2 can win 1h/trending while E1-shrunk wins 5m/ranging — directly expressible since everything keys by (tf, regime, weight_version) with zero schema change. Because the regime labels carry the known HMM look-ahead caveat (D-13), every promoted non-pooled stratum is tagged so it is re-validatable once the HMM refit lands (D-14). No new statistical test is needed — both CI quantities and walk_forward_stable are already computed by EnsembleICEngine.

Output: `ops_ensemble_weight_compare.py`, unit test for the win rule + caveat tagging.
</objective>

D-10 win rule (per (tf, regime) stratum, on pooled cross-sectional IC):
  challenger beats champion iff (challenger.ic_ci_lower > champion.ic_ci_upper) AND challenger.walk_forward_stable
  Both conditions ANDed — walk_forward_stable=False vetoes even a non-overlapping-CI win.

D-11: per-stratum promotion — no forced single global winner. Report one row per (tf, regime).
D-14: when regime != '_pooled', tag row with "HMM regime-label look-ahead caveat (todo 026/034) — re-validate once fixed".

Deterministic-latest-vintage pattern (D-142A-R2, mirror it) — per weight_version, not global:
  WITH latest_per_version AS (
    SELECT weight_version, max(scored_at) AS ts FROM alpha_ensemble_ic
    WHERE weight_version IN ($1, $2) GROUP BY weight_version)
