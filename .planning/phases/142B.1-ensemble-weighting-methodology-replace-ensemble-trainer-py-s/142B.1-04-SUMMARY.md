# Phase 142B.1 Plan 04: E2 Mean-Variance Weight Combination Summary

**`ensemble_trainer.py` now derives per-stratum weights via `w ~ Sigma^-1.IC` (Grinold-Kahn) when `alpha.ensemble.weight_method='mean_variance'`, reusing the already-computed Ledoit-Wolf covariance and falling back to the proven binary cluster-deflation path with a logged record whenever the covariance is ill-conditioned.**

- **Completed:** 2026-07-03
- **Tasks:** 2
- **Files modified:** 3 (2 modified, 1 new test file)

## Accomplishments

- `EnsembleConfig` gained `weight_method` (default `'ic_proportional'`) and `mv_condition_max` (default `1000.0`) fields, both loaded via the established `_cfg(cfg, key, default)` pattern in `from_apr` — no ad hoc `ConfigService.get()` calls.
- Extracted the weight-construction branch/fallback decision out of `_process_stratum` into a new pure function `resolve_stratum_weights()` (returns a `StratumWeightResult` with `raw_weights`, `weights`, `method_used`, `condition_number`), independently unit-testable without a DB connection:
  - `weight_method='ic_proportional'` (default): identical `derive_weights` → `cluster_deflate_weights` call shape as before — v1 preserved byte-for-byte.
  - `weight_method='mean_variance'`: calls `mean_variance_weights(cov_matrix, ic_sharpes, mv_condition_max)` using the covariance `_process_stratum` already computes every run. On success, reuses `derive_weights()` wholesale on the raw MV output for cap+filter (D-08) and **skips `cluster_deflate_weights` entirely** (Sigma⁻¹·IC already decorrelates continuously — binary cluster capping on top would double-penalize).
  - Ill-conditioned covariance (`mean_variance_weights` returns `(None, cond)`): falls back to the exact same `cluster_deflate_weights` path the `ic_proportional` method uses, and `_process_stratum` emits a structured `ensemble_trainer.weight_method_fallback` log record (`condition_number`, `mv_condition_max`, `fallback_to`) — never a silent skip (T-142B1-04-03).
  - Unknown `weight_method` value raises `ValueError` (fail loud), matching the `_resolve_ic_input_column` convention from Plan 03.
- Fixed a pre-existing gap: `mean_variance_weights` (added to `weights.py` by Plan 02) was never added to `src/intelligence/ensemble/__init__.py`'s `__all__`/import list, so `ensemble_trainer.py` could not import it from the package's public surface. Added the export (Rule 3, blocking).
- 18 new unit tests in `tests/unit/test_ensemble_trainer_weight_method.py` covering: MV-success skips cluster deflation (mocked `cluster_deflate_weights.assert_not_called()`), ill-conditioned MV falls back and produces output identical to the `ic_proportional` path on the same inputs, `ic_proportional` calls the real `cluster_deflate_weights` exactly once, unknown method raises, per-feature cap is genuinely applied post-MV (6-feature non-degenerate shape mirroring `test_ensemble_math.py`'s own cap test), `EnsembleConfig` APR binding (default + override for both new fields), and grep-style source-structure assertions (fallback log key present, `_cfg` calls present, no new `event=` kwarg collisions, `ConfigService.get` count unchanged, original `ic_proportional` call block preserved verbatim).

## Decisions Made

- **mean_variance path reuses `derive_weights()` wholesale, not a new cap-only function** — the plan's own action text says "reuse derive_weights' per-feature cap logic on the raw MV output"; calling `derive_weights(mv_raw, max_feature_weight)` is the most literal, lowest-complexity implementation of that instruction and also inherits `derive_weights`' existing non-finite/non-positive filter as a defensible extra safety net on a matrix solve, rather than writing bespoke cap-only logic that duplicates `derive_weights`' redistribution loop.
- **`raw_weight` column meaning is method-conditional** — for the MV success path it stores the uncapped Sigma⁻¹·IC solve output (the genuine "pre-cap" value for that method); for `ic_proportional` and the fallback path it stores `derive_weights(aged_quality_weights, cap)` exactly as before. This keeps `raw_weight` meaning "the pre-cap value the final weight vector for THIS stratum actually derived from," not a value from a method that didn't run.
- **`ic_sharpes` (not a separate `ic_shrunk` fetch) feeds `mean_variance_weights`** — per the plan's explicit instruction to alias consistently with Plan 03's E1 `ic_input` resolution; this makes E2 automatically combine over whatever E1 currently has live (`ic_shrunk` in production today per Plan 03's SUMMARY) without E2 needing its own APR read.
