<objective>
Implement E1: compute shrunk IC estimates, validate them against a hard out-of-fold acceptance gate, and wire `ensemble_trainer.py` to consume `ic_shrunk` — but only if the gate passes (D-05). Build the shrinkage as a small standalone oneshot (`ops_ic_shrinkage.py`) using the `bulk_update_by_key` pattern, keeping `ic_engine.py`'s large audited write path untouched (RESEARCH Open Question 2). E1 ships before E2 (D-04) so every later variant is combined on de-noised inputs.

Purpose: Raw `ic_sharpe_hac` carries winner's-curse selection bias; feeding it directly into ensemble weights (and later into E2's Σ⁻¹·IC) bakes that bias into "optimal" weights. Empirical-Bayes shrinkage toward a leave-one-out peer-group prior corrects it. The correction is only trusted if it empirically beats raw at predicting next-window realized IC — that out-of-fold test is a HARD GATE, not a diagnostic: on failure, `alpha.ensemble.ic_input` stays `'ic_sharpe_hac'`, E1 is marked failed/inconclusive, and nothing worse than v1 ships.

Output: `ops_ic_shrinkage.py` (compute + gate), `ensemble_trainer.py` ic_input wiring, corpus pipeline sequencing, unit test.
</objective>

Internal batch compute over already-validated data. Boundaries are data-integrity (wrong shrinkage math or self-contaminated prior) and decision-integrity (shipping a worse-than-v1 estimator because the gate was soft).

| Boundary | Description |
|----------|-------------|
| feature_ic_scores (raw) → ic_shrunk (derived) | in-process computation; risk is self-contaminated prior or NaN writes |
| out-of-fold gate → alpha.ensemble.ic_input flip | the flip is a live decision; a soft/wrong gate would silently ship a worse estimator |
