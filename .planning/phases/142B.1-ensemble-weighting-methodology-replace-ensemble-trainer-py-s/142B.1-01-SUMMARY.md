## Decisions Made
- Migration 196 restructured from a batched multi-row `VALUES` INSERT (my first draft, matching migration 195's Section 2 style) to one INSERT per key per table, because the plan's acceptance criteria explicitly requires `>= 8` `ON CONFLICT (config_key) DO NOTHING` occurrences (4 keys x 2 tables) -- a single batched INSERT per table only produces 2 occurrences regardless of key count. PATTERNS.md's own copy-paste example already showed the per-key shape; migration 195's batched style for its top-level 7 keys was the wrong analog to follow for this specific acceptance criterion.
- Pooled aggregation is a Python pure function (`_aggregate_pooled_series`) fed by a raw, un-aggregated SQL fetch (`_POOLED_WORKER_FETCH_SQL`, same joins as the existing per-symbol `_WORKER_FETCH_SQL` minus the `ae.symbol = %s` filter), not a `GROUP BY`/`AVG` done in SQL. This was required by Task 3's explicit instruction to factor the grain logic into an importable, DB-free pure function -- an in-SQL aggregation would have made the Pitfall-5 regression test (different regime labels at the same `bar_ts` must not be mixed) impossible to write without a live database.
- Because `market_regimes` is `asset_class`-scoped (not per-symbol), every equity symbol shares exactly one `regime_label` at a given `(tf, bar_ts)` -- confirmed by reading the existing `_WORKER_FETCH_SQL` join (`mr.asset_class = 'equity' AND mr.tf = ae.tf AND mr.ts = ae.bar_ts`, no symbol join key). This means grouping by `(regime_label, bar_ts)` within a fixed `tf` context is exactly equivalent to grouping by the full `(tf, regime, bar_ts)` triple that RESEARCH.md Pitfall 5 requires -- `_aggregate_pooled_series` still takes `tf` as an explicit parameter and includes it in the group key for defensive correctness / grep-verifiability, even though it is constant across all rows in a single call.
- The pooled worker task reuses the existing `_run_ensemble_ic_worker` function unchanged rather than introducing a second worker function -- `is_pooled = symbol == _POOLED_SYMBOL` already existed at line 467 pre-plan; only the fetch-query branch and one dispatch-dict entry were added. This guarantees the pooled cell's IC/walk-forward/Sharpe computation is byte-identical machinery to every per-symbol cell, with zero duplicated statistical logic.
