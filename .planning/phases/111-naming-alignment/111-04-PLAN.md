**If violations are found during this pre-flight, you MUST resolve them BEFORE adding the hook — do NOT add the hook while current violations exist, because it will block ALL commits (every `git commit` will fail).** Resolution procedure for each violation:
1. Identify the offending import and the file it lives in (e.g. `src/core/ai/context.py` importing `from src.intelligence...`).
2. Move the violating import to the correct ring: relocate the importing symbol/module into `src/intelligence/` (Ring 1) if it depends on domain layers, OR invert the dependency so Ring 0 no longer imports upward (pass the domain object in as a parameter / inject it, rather than importing it).
3. Re-run the pre-flight grep until it prints `CLEAN`.
4. Only then proceed to Step 2 (writing the hook).

The `from src\.config` term is handled separately below (Settings is foundational, not a domain layer) — it is removed from the enforced pattern, NOT treated as a violation to fix. The violations you must fix are upward imports from `src.intelligence`, `src.providers`, `src.self_healing`, or `services` only.

NOTE: `src/core/agent/base.py` imports `from src.config.config_consumer import ConfigConsumerMixin` and `from src.config.settings import Settings, get_settings`. These ARE Ring 0 violations per the spec. Check the design doc §Ring0 section — the spec says `from src.config` is a violation. If BaseDaemon imports from src.config, those imports must be resolved first OR the Ring 0 hook pattern must be adjusted to allow src.config (since Settings is foundational). Verify against CONTEXT.md D-06 exact grep pattern before adding the hook.

```
"from src\.intelligence\|from src\.config\|from src\.providers\|from src\.self_healing\|from services"
```

If BaseDaemon (Ring 0) imports from src.config, the hook as written will fail on the existing codebase. Two options:
1. Remove `from src.config` from the pattern (settings is imported everywhere, not a domain layer violation)
2. Move Settings import out of BaseDaemon (architectural change, out of scope)

Use option 1 — adjust the grep pattern to remove `from src\.config` since Settings is a cross-cutting infrastructure concern, not a domain layer. The Ring 0 boundary is about domain intelligence layers (src.intelligence, src.providers, services), not foundational config.

**Final hook grep pattern (adjusted):**

```bash
grep -rn \
  "from src\.intelligence\|from src\.providers\|from src\.self_healing\|from services" \

```

**Step 2: Write .git/hooks/pre-commit** (append to existing content if any, or create new):
```bash
#!/usr/bin/env bash
set -euo pipefail

# Ring 0 boundary check: src/core/ and src/observability/ must not import domain layers
RING0_VIOLATIONS=$(grep -rn \
  "from src\.intelligence\|from src\.providers\|from src\.self_healing\|from services" \
  src/core/ src/observability/ --include="*.py" 2>/dev/null | grep -v "^\s*#" || true)

if [ -n "$RING0_VIOLATIONS" ]; then
  echo "FAILED: Ring 0 boundary violation — src/core/ or src/observability/ imports domain layer"
  echo "$RING0_VIOLATIONS"
  exit 1
fi
```

If a pre-commit file already exists with other checks, append the Ring 0 block after the existing content (don't replace it). Make the file executable: `chmod +x .git/hooks/pre-commit`.
