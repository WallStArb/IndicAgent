<objective>
Build the data-integrity tool this phase cannot run without: a checked-in, resumable, per-cell
NULL-out and provenance-verification script for `feature_vectors`' 8 regime-writer-owned columns.

Purpose: RESEARCH.md's Critical Finding proved that running `regime_writer.py --refit` with
walk-forward enabled against the CURRENT corpus silently blends two labeling methods in one
column. 26,791,341 of 36,854,099 rows already carry the retired full-history-fit method's output;
`_discover_symbols()` skips fully-labeled symbols entirely, `_bulk_update_by_key` leaves untouched
rows unchanged, and the walk-forward path deliberately writes nothing for warmup-prefix bars or
degenerate segments. The intersection is stale pre-fix values persisting indefinitely under a
column nobody audits — structurally the same failure shape as the already-closed todo 205
incident, and precisely the "silent wrong answers are worse than loud crashes" case CLAUDE.md
forbids. `_compute_symbol_tf_walk_forward`'s own docstring names this as an unenforced
precondition. This script enforces it.

Output: `scripts/ops/corpus/ops_regime_null_out_and_verify.py` plus unit coverage. This plan
builds the tool only; plans 171-05 and 171-06 run it against real data.
</objective>

  <action>
Implement the two verify modes on the argparse surface Task 1 established.

`verify-post-null`: per cell, run the same "any of the 8 owned columns non-NULL" count Task 1
uses as its post-condition. Report per cell and in aggregate. Issue no UPDATE.

`verify-post-relabel`: per cell, run two queries. First, `SELECT count(*) FILTER (WHERE regime IS
NOT NULL), min(bar_ts) FILTER (WHERE regime IS NOT NULL) FROM feature_vectors WHERE symbol = %s
AND tf = %s`. If the labeled count is 0, record `no_labels` with the reason that
`_compute_symbol_tf_walk_forward` returns None for cells with insufficient history and continue.
Otherwise, `SELECT count(*) FROM feature_vectors WHERE symbol = %s AND tf = %s AND bar_ts < %s`
using the earliest labeled `bar_ts`, and assert the result is at least
`initial_warmup_bars` for that tf.

Why this specific assertion rather than recomputing an obs-matrix boundary timestamp: the
walk-forward path labels only `obs_matrix[initial_warmup_bars:]`, so a clean single-method cell
must have at least `initial_warmup_bars` unlabeled rows preceding its first label. A smaller
count means either the NULL-out did not cover the cell or a stale full-history-fit value survived
in the warmup prefix. The check is pure SQL against `(symbol, tf, bar_ts)` and needs no obs-matrix
rebuild, so it cannot drift from the labeling code's own feature-window logic.

Load `initial_warmup_bars` per tf from `config_state` via a direct query on
`alpha.hmm.walk_forward.initial_warmup_bars.<tf>` (this is a read-only ops script; a plain SELECT
against `config_state` is sufficient and avoids pulling the async ConfigService into a synchronous
script). Fall back to `_WALK_FORWARD_DEFAULT_PARAMS` imported from `services.regime_writer` and log
loudly when the fallback is used.

Write a machine-readable result file alongside the manifest —
`cache/regime_relabel_provenance_report.json` — with one record per cell containing `symbol`,
`tf`, `labeled_rows`, `first_labeled_bar_ts`, `rows_before_first_label`, `initial_warmup_bars`,
and `verdict` in {`pass`, `fail`, `no_labels`}. Plans 171-05 and 171-06 attach this file as their
completion evidence.

Print a final banner block in the `"=" * 80` style used by this repo's pilot scripts, with an
explicit `REQ-3 PROVENANCE: PASS` or `FAIL` line naming the failing cells. Exit non-zero on any
`fail`.

Extend `tests/unit/scripts/test_ops_regime_null_out_and_verify.py`: (a) `verify-post-relabel`
passes when `rows_before_first_label >= initial_warmup_bars`; (b) it fails and exits non-zero when
that count is one less than `initial_warmup_bars`; (c) a cell with zero labeled rows yields
`no_labels` and does not fail the run; (d) both verify modes issue zero UPDATE statements;
(e) the warmup count is read from the mocked `config_state` row, not from the module constant,
when the key is present.
  </action>
