<objective>
Build the D-03 shadow-mode diagnostic: a read-only `scripts/analysis/` script that reports what
breadth-universe and peer-pool membership WOULD change if
`services/cross_sectional_regime_model.py` switched from `source = 'human'`-only to
`human OR materiality-eligible empirical`.

Purpose: this is the artifact the user and the cross-AI reviewers (D-03, D-07) judge before any
consumer query is ever allowed to change. It is the gate, not a step on the way to one.
Output: one committed script, its unit tests, and its actual measured output recorded in the
plan SUMMARY.

**Shadow-mode boundary (D-03, non-negotiable):** this plan does NOT modify
`src/intelligence/regime_signals/breadth_vol.py` or
`services/cross_sectional_regime_model.py`. It *imports from* the latter (read-only reuse of
`_resolve_group_symbols` / `_load_group_configs`) so both arms are resolved by the same code
the live service uses, and it writes nothing anywhere. Cutting either consumer over is
explicitly a separate, later phase gated on this diagnostic's findings.
</objective>

    - `attribute_gate_failures` additionally reports, per gate, how many rows fail THAT gate and no other (a `sole_failure` count alongside the total failure count).     - `gate_value_distributions(empirical_rows, thresholds)` returns, for each of the four scalar gates (`sample_n`, `partial_loading`, `ci_low`, `incremental_r2`), the count, min, median and max of the FAILING rows' own statistic values. NaN/NULL values are excluded from the distribution and counted separately, never coerced to zero.
    - `gate_value_distributions` uses no numeric literal as a cut point: it reports order statistics of the observed values, so no new threshold is introduced by the diagnostic itself.
