**Planner resolutions carried by this plan** (RESEARCH.md Open Questions, resolved here and
subject to the D-07 cross-AI review gate before execution):

- **R-03 (Open Q3 - control set):** four control legs only (`SPY`, `TLT`, `HYG-IEF`, `UUP`),
  no DBC commodity leg. Stored as an APR **JSON list** (`control_factor_series`) rather than a
  Python constant, per CLAUDE.md's APR category 2 ("behavioral lists - lists controlling WHAT
  the algorithm processes → APR as JSON"). Adding DBC later, if the shadow diagnostic surfaces
  commodity-cycle confounding, becomes an APR edit rather than a code change or a
  `tag_vocabulary` mutation (wiring DBC as a `factor_series` would also make it a measurement
  *target*, a side effect this phase does not want).
- **R-04 (`passes_materiality` semantics):** `passes_materiality` encodes the **statistical**
  gate ONLY. The temporal gate (`discovery_state = 'confirmed'`, todo 125) and the expiry gate
  (`valid_to IS NULL`, todo 126) are separate columns AND-ed by the reader. This follows
  RESEARCH.md Pitfall 4's explicit warning sign ("a `passes_materiality` boolean that changes
  value purely because `discovery_oos_days` elapsed, with no new measurement having run -
  this would indicate the two gates got merged") over 175-PATTERNS.md line 132's contradicting
  one-line restatement. The three columns are stored, not collapsed, so a future per-consumer
  cutover (D-02) can still calibrate its own bar.
- **R-05 (Codex's lower-CI gate retained):** `partial_loading_ci_low` is a real column and a
  real gate, not dropped. Codex proposed five gate components; all five ship.
