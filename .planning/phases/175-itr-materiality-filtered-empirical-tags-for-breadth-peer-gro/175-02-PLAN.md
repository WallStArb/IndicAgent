<objective>
Add the four pure statistical kernels Pass 4 needs to
`src/intelligence/statistics/factor_math.py`, each with unit tests written before the
implementation. These are the only genuinely-new statistics in the phase; everything else is
plumbing.

Purpose: D-01 says one measurement engine, not N copies of the orthogonalization math. Putting
the kernels in the shared statistics module (rather than inline in `tag_calibrator.py`) is what
makes a future per-consumer cutover reuse rather than re-derive.
Output: four new public functions in `factor_math.py`, one private residualization helper,
and unit tests covering known values, degenerate inputs, and the null-arm contract.

**Planner resolutions carried by this plan** (RESEARCH.md Open Questions, resolved here and
subject to the D-07 cross-AI review gate before execution):

- **R-01 (Open Q1 - Pearson vs. Spearman):** **Pearson**, on centered raw returns, NOT
  `ic_math.partial_spearman_ic`'s rank transform. Rationale: (a) Codex's `abs(partial_beta)
  >= 0.35` and AGY's `|beta| >= 0.30` are standardized-OLS-beta numbers, not rank
  correlations; (b) Pass 1's existing `loading` column and every live
  `tag_vocabulary.loading_threshold` (0.2) are Pearson-calibrated, so a rank-based
  `partial_loading` sitting in the adjacent column would invite an apples-to-oranges
  comparison (RESEARCH.md Pitfall 1's exact warning sign); (c) the kernel still reuses
  `partial_spearman_ic`'s *shape* (shared-`lstsq` two-column residualization + the
  `check_condition_number` gate + the `n < k + 4` floor), so nothing is re-derived - only the
  rank transform is dropped.
- **R-06 (incremental R² definition):** `incremental_r2` is **ΔR² = R²_full - R²_controls**
  (the added explanatory power of the target factor over a controls-only regression of the
  candidate's return), NOT the squared partial correlation. Rationale: (a) ΔR² ≤ squared
  partial correlation always, so it is the stricter reading of Codex's `>= 0.05`, matching
  D-05's "seed the more conservative" instruction; (b) the squared partial correlation is
  exactly `partial_loading ** 2`, information the adjacent column already carries - storing it
  again would be a redundant column, while ΔR² is genuinely new information.
- **R-05 (Fisher-z CI level):** the lower-CI gate reuses the project's existing
  `alpha.tag_calibrator.fdr_alpha` (0.05) as its two-sided level rather than introducing an
  11th APR key for the same number.
