Implement ONE shared O(n) helper and derive all 10 from it — do not write ten near-duplicate bodies:

  `_bars_since_rolling_extreme_series_full(values: np.ndarray, window: int, mode: str) -> np.ndarray`

  `result[i]` == the number of bars elapsed since the maximum (`mode="max"`) or minimum
  (`mode="min"`) of `values[max(0, i-window+1) : i+1]` was last attained, as a float in
  `[0, window-1]`. `result[i] == 0.0` means the extreme is the current bar. Implement with a
  monotonic deque (O(n) total) or with `_sliding_rolling_max`'s existing window machinery plus an
  argmax over each window slice — the deque form is preferred for the 5m corpus size (25.4M rows).

  **Binding design constraint (todo 180 Fable review, restated in `151-RESEARCH.md` Pattern 1):**
  this MUST be a bounded rolling-window statistic in `[0, window-1]`. Do NOT reuse
  `_ret_autocorr_series_full`'s expanding-window shape here. An expanding "bars since all-time
  high" is a different, non-stationary statistic and is explicitly rejected.

Wire the 10 fields from that helper:
  `bars_since_high_fast` ← `(highs, config.dist_window_fast, "max")`
  `bars_since_high_slow` ← `(highs, config.dist_window_slow, "max")`
  `bars_since_low_fast`  ← `(lows,  config.dist_window_fast, "min")`
  `bars_since_low_slow`  ← `(lows,  config.dist_window_slow, "min")`
  `bars_since_52w_high`  ← `(highs, <the high_52w window config field>, "max")`
  `bars_since_52w_low`   ← `(lows,  <the high_52w window config field>, "min")`
  `bars_since_extreme_move_fast/slow` ← build a derived event-indicator series first:
      `abs_log_ret = np.abs(np.diff(np.log(np.maximum(closes, 1e-10))))`, zero-padded to length n;
      `sigma` = the rolling std of `abs_log_ret` over the SAME window (fast/slow respectively);
      the event indicator is `abs_log_ret > config.extreme_move_sigma_threshold * sigma`.
      Then `result[i]` = bars since the most recent True inside the trailing `window`, clamped to
      `[0, window-1]`; when no event occurred in the window, emit `float(window - 1)` (the
      saturating value), NOT 0.0 and NOT NaN — 0.0 would falsely assert "an event just happened."
      Reuse the same bars-since-most-recent-True scan for the vol-spike family; factor it as
      `_bars_since_event_series_full(events: np.ndarray, window: int) -> np.ndarray`.
  `bars_since_vol_spike_fast/slow` ← event indicator is `rel_volume > config.vol_spike_threshold`,
      using the already-computed `rel_volume` series (`s.rel_volume`), same
      `_bars_since_event_series_full` helper and same saturating convention.

the `compute()`/`compute_batch()` constructor sites via `_series_last(s.<field>, <saturating value>)`.
