<objective>
Implement ROADMAP Phase 151's "Regime-conditioned cluster membership" item: make feature
collinearity clustering condition on the per-symbol HMM regime axis in addition to the
cross-sectional regime axis it already uses.

Purpose: Features uncorrelated in a trending HMM state may be 0.8 correlated in a ranging one.
Cluster-representative BH-FDR selection that never sees that axis systematically mis-deflates
redundancy for exactly the strata where redundancy matters most.

Correction to ROADMAP text (from `151-RESEARCH.md` State of the Art + `151-PATTERNS.md`):
ROADMAP describes Phase 140 P2's clustering as "global." It is NOT — `_cluster_features()` is
already called once per `(symbol, tf, regime_label)` cell inside `_compute_one_regime_cell()`.
The real gap is that the second (per-symbol HMM) axis only runs when a symbol's routed regime
group has `dual_write_symbol_hmm=true` (live: `rates` only, migration 247). This plan adds an
independent APR gate so the second axis runs for every routed symbol.

Also correcting ROADMAP's "one cluster membership table per HMM state": no new table. `cluster_id`
already persists per `feature_ic_scores` row and rows are already tagged by `regime_scope`
(live values: `cross_sectional` 176,026 / `pooled` 37,900 / `symbol_hmm` 29,928). Adding a
stratification pass is the lighter-weight and comparability-preserving implementation, per
`151-RESEARCH.md` Open Question 3's recommended default.

Output: 1 new APR key, a widened gate on the existing `regime_passes` mechanism, unit coverage,
and an empirical no-regression check on existing rows.
</objective>
