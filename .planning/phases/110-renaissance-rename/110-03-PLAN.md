<objective>
Rename all 33 Ring 2 daemon process classes to their role-noun + category-suffix names per Section 9 of the naming spec. This is Wave 3 of the atomic rename. It depends on Wave 2 (Plan 02) because some daemons inherit from `BaseSwarmCoordinator` (renamed in Wave 1) and construct the renamed evaluators (Wave 2).

This plan renames CLASS IDENTIFIERS ONLY. File names stay unchanged in Wave 3 (file renames + systemd ExecStart updates are Wave 4 / Plan 04).

THE CRITICAL CONSTRAINT — `agent_id` operational exception:
Two things derived from old class names MUST be PRESERVED in this wave because they are the `agent_id` metric label / structlog field (existing Grafana dashboards + Prometheus alert rules depend on them):
1. The `name="..."` string literal passed to `super().__init__(name=...)` in each daemon. Some daemons pass class-name-style strings (e.g. `name="SignalTrackerComputeAgent"`), others pass snake_case (e.g. `name="bar_aggregator_agent"`). DO NOT CHANGE ANY of these strings.
2. The keys of `_AGENT_ID_TO_UNIT` in `services/service_auditor_agent.py` (e.g. `"SignalTrackerComputeAgent": "indicagent-signal-tracker-compute"`). These keys are agent_id values, not class references. DO NOT CHANGE the keys.

Because the rename is word-boundary-based on the CLASS identifier and these are inside string literals, a naive `sed 's/\bSignalTrackerComputeAgent\b/SignalTracker/g'` WOULD wrongly rewrite the `name="SignalTrackerComputeAgent"` literal and the `_AGENT_ID_TO_UNIT` key. The executor MUST guard against this — see Task 4's approach (rename class identifiers, then restore any string literals / dict keys that were incorrectly changed).
