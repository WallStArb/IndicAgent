# Phase 182 Plan 03: indicagent_v1 seed data, renderer and migration 365 Summary

**This plan adds a validated seed renderer with three SQL guards (node immutability, assignment disagreement, active coverage) and a reviewed 118-node, 295-assignment indicagent_v1 snapshot. Migration 365 is rendered from that snapshot, pinned to it byte for byte by a unit test, and not applied yet.**

## Performance

- **Duration:** about 27 min of execution (first commit 08:56, review commit 09:22 local)
- **Tasks:** 3 (Task 1 split RED/GREEN)
- **Files:** 7 created

## Accomplishments

- `classification_seed.py`: `validate_seed` reports every problem in one ValueError. It covers
  the code regex, level and parent consistency, duplicates, unknown codes and source_refs, GICS in
  scheme fields, the authority, unused non-equity or equity level-4 nodes, empty bases, and (new)
  duplicate names within a level.
- `render_seed_sql` is deterministic. It writes the scheme insert with an authority guard, node
  staging with the D-01 immutability guard, and a node insert whose `path` comes from
  `WITH RECURSIVE` and whose only update is `DO UPDATE SET name`. It then writes assignment
  staging with a disagreement guard, an append-only assignment insert joined to `instruments`, a
  NOTICE for absent symbols, and the D-09 coverage guard. `valid_from` is always
  `(now() AT TIME ZONE 'UTC')::date` (D-07). Basis text never reaches the SQL.
- `classification_seed_data.py` (generated by a scratch script so single-name bases are copied
  from the CSV exactly):
  - 7 roots, 12 equity sectors and all 25 industry groups
  - 53 used level-4 industries and 21 non-equity nodes
  - 168 single names (`ibkr_contract_details+review`), 105 ETFs (`fund_mandate`) and 22 inactive
    futures/FX (`contract_spec`)
- A rolled-back dry run of the full render against the live DB (`BEGIN; ... ROLLBACK;`) inserted
  118 nodes and 295 assignments. Every guard passed and the path arrays were correct. Afterwards
  the live `classification_scheme` still had 0 rows.
- Both review passes are recorded in 182-03-REVIEW.md. Seven assignments changed, one node was
  renamed and four override reasons were added. Every disagreement was decided on the evidence:
  return correlations from `market_data_ohlcv_tradeable` plus fund index methodology.

- **Found during:** Task 3

- **Fix:** Ran the independent pass as `claude -p --model opus --tools ""` on the same review table
  and D-03..D-06 prompt. That run had no tools and no access to the executor's reasoning or

  182-03-REVIEW.md says so. A cross-vendor AGY re-check can run once the quota resets, if wanted.
- **Commit:** `a24bc8b8e`

**2. [Rule 2 - Correctness] Level-2 name collision and a new uniqueness rule**
- **Found during:** Task 3 (independent pass)
- **Issue:** CMD.ENERGY and EQ.EN were both named "Energy". Under D-10 the level-2 name becomes
  `Instrument.sector`, so crude and gas futures would have silently merged with energy equities.
- **Fix:** Renamed CMD.ENERGY to "Energy commodities", which departs from the pinned name.
  `validate_seed` now rejects duplicate names within a level, with two new unit tests.
- **Files:** src/config/classification_seed.py, tests/unit/test_classification_seed.py, data module
- **Commit:** `a24bc8b8e`

**3. [Rule 1 - Data] RSPG's instruments name is wrong**
- **Found during:** Task 2
- **Issue:** The DB name says Equal Weight Consumer Staples, but RSPG is Equal Weight Energy
  (correlation 0.98 with XLE, 0.15 with XLP).
- **Fix:** The seed maps it to EQ.EN.ENERGY and cites the evidence in its basis. The DB name fix is
  out of scope and logged in deferred-items.md.

**4. Departures from the plan's recommended ETF placements, each with a basis:** XTL and IYZ
(recommended EQ.COM.TELECOM) go to EQ.BROAD, JETS to EQ.IND.TRANSPORT, and CCJ's single-name
industry is Metals & Mining. The plan allows overrides that carry a basis saying why. The evidence
is in 182-03-REVIEW.md.
