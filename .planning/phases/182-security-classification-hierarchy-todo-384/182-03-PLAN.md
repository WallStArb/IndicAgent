<objective>
Produce the reviewed data deliverables of D-02..D-06 and the seed migration generated from them:
the `indicagent_v1` node list, one assignment for every `instruments` row, and migration 365
rendered from that data with the D-01 node-immutability guard and the D-09 seed-time coverage guard.
The migration is NOT applied here; Plan 07 applies it after the human review that ends this plan
(D-06, 182-VALIDATION.md manual row).

Purpose: one source of truth for seed data (a Python data module), a deterministic renderer, and a
CI-enforced equality check, so the reviewed file and the applied SQL cannot diverge.

Output: `src/config/classification_seed.py` (renderer/validator), `src/config/classification_seed_data.py`
(data), migration 365 (rendered, committed, unapplied), two unit test files.

Scope decision recorded here: the seed classifies every `instruments` row (295 at plan time: 273
active plus 18 inactive futures and 4 inactive FX pairs), not only the 273 active ones D-09
requires. Reasons: (1) reactivating an instrument with a raw UPDATE is the drift gap D-09 names, and
a pre-classified inactive row closes it; (2) the integration-suite rebuild replays post-baseline
migrations against a 2026-07-18 instrument snapshot (tests/integration/conftest.py), and the coverage
guard must not fail there on a row that is active in that snapshot. Inactive futures/FX use
`source_ref = 'contract_spec'` (Plan 01's SOURCE_REF_CONTRACT_SPEC), a third value because D-06
covers only single names and ETFs.
</objective>
