<objective>
D-10: move both `Instrument.sector` builders off the flat `contract_details->>'sector'` label onto the
classification (sector = level-2 node name), which fixes `src/api/routes/signals.py` transitively.

Design choice (discretion, recorded): both builders read the current assignment through Plan 01's
`current_level_name_sql()` fragment added as one extra column to the queries they already run, not
through a registered `ClassificationService`. `get_active_contracts()` is synchronous psycopg code
called from many processes that never prewarm anything; routing it through a process-global service
would return `unclassified` for everything in any process that forgot to register one, a silent wrong
answer. The SQL fragment reads the same tables, keeps one definition of "current level-2 node", and
fails loudly if the tables are missing. The unclassified fallback label comes from Plan 01's
`label_or_unclassified`, the same string `ClassificationService` returns (D-08).

Between this plan landing and Plan 07 applying the seed, every sector reads `indicagent_v1:unclassified`.
That window is expected; the only consumer is the archived-pipeline signals endpoint.

Out of scope (RESEARCH Pitfall 5): `src/intelligence/research/snapshot.py` and `panel.py` read
`contract_details->>'sector'` as frozen provenance ("as S0 captured it") and are not touched.
</objective>
