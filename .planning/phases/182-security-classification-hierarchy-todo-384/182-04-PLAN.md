<objective>
Enforce D-09 point 2: `onboard_instrument()` (the single sanctioned add-an-instrument path) requires a
classification for every new instrument and hard-fails without one, with no skip-reason escape
hatch (CONTEXT D-09, deliberately unlike `metadata_skip_reason`). The classification row is written
inside the function's existing transaction, so onboarding stays all-or-nothing. Also stop writing
the flat `sector` key into `contract_details` (D-10: the JSON field is frozen historical data).

Purpose: new instruments can never enter the universe unclassified, so seed-time coverage (Plan 07)
does not decay.

Output: updated onboarding module and tests; the two onboarding scripts updated to the new required
argument.
</objective>
