# Fix I6 Confluence Violations (Renaissance Principle Violations)

**Issue:** 4 I7 plugins compute I6 `ctf_*` scores but don't consume them in confidence calculations, violating "never drop data that could contain signal."

**Plugins Affected:**
1. `fvg_fill.py` - Only uses `apply_exhaustion_boost`, missing `ctf_fvg_alignment`, `ctf_ob_alignment`
2. `choch_reversal.py` - Only uses `hmm_regime`, missing `ctf_structure_alignment`, `ctf_trend_alignment`, `ctf_score`
3. `liquidity_sweep_reclaim.py` - Uses `ctf_score` only as binary gate (>0.3), doesn't incorporate magnitude
4. `supply_demand_setup.py` - Uses `ctf_score` but likely as binary gate

**Renaissance Principle Violation:** Computing I6 scores costs CPU cycles but the signal value is discarded. This violates "earn the right through proof" - if we compute it, we must use it OR prove it has no value.

## Approach

### Phase 1: Investigation (Read Before Fixing)

**Task 1.1: Read All 4 Plugins**
- Understand current confidence calculation
- Identify WHERE I6 scores should be incorporated
- Document current formula

**Task 1.2: Read Working Examples**
- Find 2-3 I7 plugins that DO consume I6 correctly
- Document the pattern
- Use as reference

**Task 1.3: Verify I6 Data Availability**
- Check that `ctf_fvg_alignment` and `ctf_ob_alignment` are actually computed in I6
- Verify they flow through `intelligence_i6` event schema
- Confirm data reaches I7 plugins

### Phase 2: Hypothesis (One Per Plugin)

For each plugin:
1. State WHERE I6 score should be injected (exact line)
2. State HOW it should affect confidence (formula)
3. State EXPECTED impact (higher confidence when aligned, lower when not)

### Phase 3: Implementation (Atomic Commits)

**For each plugin (4 separate commits):**

1. **Create Test** (before fix)
   - Write test that verifies I6 score flows through
   - Test should FAIL with current code
   - Commit: `test(i7): add I6 confluence test for <plugin>`

2. **Implement Fix**
   - Add I6 score consumption to confidence calculation
   - Keep change minimal (10-15 lines per plugin)
   - Commit: `fix(i7): consume I6 ctf_* scores in <plugin> (Renaissance violation)`

3. **Verify**
   - Run tests: `pytest tests/unit/test_<plugin>.py -v`
   - Run full suite: `pytest tests/unit/ -v`
   - Check shadow capture data unchanged

### Phase 4: Validation

**After all 4 fixes:**
1. Run `/simplify` to verify no new issues
2. Run `/coderabbit:code-review` for safety
3. Verify all 36 I7 plugins consume relevant I6 scores (grep audit)

## Success Criteria

- [ ] All 4 plugins consume their relevant I6 `ctf_*` scores
- [ ] No regressions in signal quality (shadow mode)
- [ ] All tests passing (2664+)
- [ ] Atomic commits with clear messages
- [ ] Code review approved
