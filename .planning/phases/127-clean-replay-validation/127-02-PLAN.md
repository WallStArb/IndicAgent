<critical_corrections>
1. **NO WELCH'S T-TEST. NO CROSS-POPULATION PNL_R COMPARISON.** ROADMAP SC-04 forbids it. The before/after populations are not exchangeable. Do NOT implement `_welch_t_test`. Do NOT report `pnl_t_stat`/`pnl_p_value`. If you find yourself computing `(after_std**2/after_n) + (before_std**2/before_n)`, STOP - that is the forbidden statistic.

2. **NO CALIBRATION CORRELATION. NO BOOTSTRAP CI.** The replay corpus has NO PnL outcome target (127-RESEARCH.md Issue 4). `counterfactual_pnl_r` is NULL by design; `trade_executions.actual_pnl_r` is absent (the table is empty - replay never writes it). A calibration query would join against an empty table and yield n<30 for every setup - empty columns dressed up as evidence. Do NOT implement `_calibration_corr` or `_bootstrap_calib_ci`. The earlier "use actual_pnl_r as fallback" reasoning is FALSE and must not be reinstated. Calibration moves wholesale to v2.11.

3. **FIRE RATE IS EMISSION FREQUENCY, REPORTED NOT GATED.** `fire_rate_pct = 100.0 * COUNT(signal_events WHERE setup_plugin=X) / COUNT(intelligence_features bar-instances in the replay window)` (D6 methodology from Phase 124-07). It is NOT `selected/total_signals`. It is DESCRIPTIVE ONLY: report the distribution per setup_plugin and compare to the Phase 124 pre-fix onset_guard leak (15-30%/bar) as the single structural claim (leak closed). Do NOT encode `< 3%` as a PASS/FAIL verdict. A valid signal firing at 10% with edge is good; a 0.5% signal without edge is not. Edge is unmeasurable this phase (Issue 4) - fire rate is not a substitute for it.

4. **3-TABLE SCHEMA ONLY.** No signal_outcomes, no signal_ledger_full, no signal_type/bucket_scores/staleness_score. Join chain for execution-layer data (if ever needed): `signal_events.signal_id -> trade_frames.signal_id -> trade_frames.frame_id -> trade_executions.frame_id`. `trade_executions` has NO `signal_id` column.

5. **CTF = context_features coverage.** "CTF as feature" (ROADMAP) is operationalized as context_features JSONB not-null/not-empty coverage on the non-cold-start subset. This IS a valid hard gate (>99%, SC-02) because it is a data-completeness check, not a signal-quality judgment.

6. **stopped_at_entry IS NOT MEASURABLE.** It is an execution-layer outcome; replay does not populate `trade_executions`. The count is structurally 0 and means nothing. Record it as "not measurable in replay; requires executions" - do NOT report 0 as a pass.
</critical_corrections>
