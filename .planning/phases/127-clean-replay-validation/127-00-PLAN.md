<objective>
Eliminate the 3-table read-path migration debt that Phase 130 left behind. Phase 130 migrated the WRITE paths (signal_events + trade_frames - verified correct) but left ~9 live src/services readers and several scripts querying the dropped `signal_outcomes` table and absent `signal_ledger` view columns. Two of those readers are live hazards: `shadow_validator.py` JOINs the dropped table (runtime crash on next timer fire) and `shadow_auditor.py` computes ev_r=0.0 on an empty corpus (spurious demotion every cycle). This plan is a WAVE 0 precondition - it must land before Plan 03 (ml-training) and before any reliance on the ML/graduation/shadow/weight feedback loops. It is the work that makes the "ML-ready corpus" claim honest.

Purpose: a corpus is not ML-ready if the readers that consume it crash or misbehave. Jim Simons does not ship a milestone with enabled services carrying SQL time-bombs against dropped schema. We fix the debt first, as a precondition, then do clean replay and validation on a sound foundation.

Output: all listed files migrated to the 3-table read vocabulary; obsolete scripts retired; tests green; committed atomically per logical group on this branch.
</objective>
