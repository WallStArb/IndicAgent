<objective>
Prove the fresh IC engine computes the same numbers as the stored pooled cells. A test-scoped
parity harness replays each sampled stored POOLED cell's observation set (label bars, peer
symbols, (bar_ts, symbol) order, stride) and computes point IC with the 186-10 `pooled_rank_ic`
twice: with the table's targets, which must reproduce the stored `ic_value` to float tolerance,
and with kernel targets, where every difference is attributed to gap rows or end-of-window NaNs
with counts; 1h horizons 20/60 are excluded with a count (D-21 as replaced by R-06). The report
is committed, and it carries a dedicated writer-path parity cell section: one frozen stored pooled
cell recomputed through ic_measure's production assembly (`build_target_panels` ->
`stack_targets` -> `align_features` -> `pooled_rank_ic`) and compared to the harness's replayed
value. Same function, two callers, one expected number. A difference beyond float tolerance stops
the phase (a sign check is not parity). Nothing is deleted in this plan: the legacy
`feature_ic_scores` table stays untouched (D-15) exactly until 186-28 drops it whole after the
fresh run (D-35); D-19 and R-07 are discharged by that drop.

Purpose: 186-23's one-change deletion of the old ic_engine is gated on this parity report (harness
replay plus the writer-path cell), and 186-28 runs the fresh writer and drops the legacy table on
its strength.

Output: parity harness with CI-clean synthetic tests, and a committed parity report whose
writer-path cell section records the production-assembly recomputation and the comparison.
</objective>
