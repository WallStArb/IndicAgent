## Rules every card in this plan follows

1. Numbers (D-05). Copy from the ledger row, the docs it cites, or `concept_registry.metadata`.
   Never rerun a script or recompute a statistic. Where a doc and the ledger disagree, record both
   with their sources and say which the ledger froze. Normalize Unicode minus signs and em dashes
   when copying: YAML numbers use ASCII `-`, prose uses a dash, comma or semicolon (global style).
   Row 10 records the corrected 2026-09-13 numbers in `results` and the originally recorded ones
   plus the 10x spread-constant bug in `known_defects`.
2. `recipe_commit`. The last commit touching `recipe.script` (or `recipe.spec` when script is
   null) at or before the date of the numbers the card records:
   `git log -1 --format=%H --before="<date> 23:59:59" -- <path>`. When the ledger or spec names an
   explicit run or freeze commit (rows 15-16 f461bdc54, row 17 0c33a2596, row 18 da0548a96),
   resolve it to its full 40-hex with `git rev-parse <short>` and use it if `git cat-file -e
   <commit>:<script>` succeeds; otherwise use the date rule and record the named commit as a
   `results` entry `{name: run_commit, value: "<40-hex>", source: <ledger or spec path>}`.
   Record the command used per card in "Where the numbers came from".
3. `tables`. The union of (a) tables the ledger row or primary doc names as the data source and
   (b) tables in `FROM`/`JOIN` clauses of `recipe.script` at `recipe_commit`
   (`git show <commit>:<script> | grep -oiE "(from|join)\s+[a-z_]+" | sort -u`), keeping only real
   relation names (confirm with `SELECT to_regclass('<name>')` or a `CREATE TABLE`/`CREATE VIEW`
   in `production/migrations/`; a dropped v2.x name is still valid if a migration created it).
   Non-drop tables such as `feature_ic_scores`, `market_data_ohlcv_tradeable` or
   `market_regimes` are listed when used; `tables` records provenance, not only drop coverage.
   Row 11 must include `ensemble_alpha`, `forward_returns` and `alpha_frames` (its Gate 1 and
   Gate 2 inputs). Row 18 must include `ensemble_weights` if phase 179's code reads it; if it
   re-derives weights through `ensemble_trainer`'s selection on `feature_ic_scores`, list that
   table and say so in the prose.
4. `spans_looked_at` and `forward_span_looks`. Spans come from the doc or spec (in_sample when
   the data ends before 2025-12-24; full_history when the doc used the whole history without a
   split). `forward_span_looks` counts looks at data at or after 2025-12-24 that the card's own
   process made and no other card already counts; state the basis in prose. Row 11 is 0 because
   its two forward-span looks are counted on `legacy-phase148-oos-gates`; say so.
5. `related_cards`. Row 11 lists `legacy-phase148-oos-gates`, `legacy-phase148-score-01-03`,
   `legacy-ensemble-champion`. Row 18 lists `legacy-ensemble-champion` and `legacy-tsmom-sleeve`.
   Rows 10 and 14 link each other; rows 15 and 16 link each other; rows 6 and 7 link each other;
   row 17 links row 18. Others may be empty. 186-01's cards are not edited.
6. Prose: title line, then `Author: Claude Opus 5.5, <date>` and `Informed by:` naming the ledger
   row and primary doc. Sentence-case headings, no em dashes, no bold lead-ins. `reproducible:
   false` on every card; the "Why closed" section states why the verdict cannot be rerun as-is
   (recipe code deleted by 186-16, `feature_vectors` rebuilt, E15 changed the gates).
