<design>
**Steps.**
1. `data_gate`: calls 186-32's run_data_gate for the run's universe and horizon. In one
   transaction (warning 2): UPDATE corpus_run.data_gate with the result's counts; append the
   survivorship caveat to corpus_run.caveats only when no element with its code is present (so a
   retried step never duplicates it, and the append-only trigger holds); mark the step completed
   with the counts in its summary. A refusal marks the step failed with the counts and failing
   lists in its summary and writes no caveat.
2. `pin_gate`: runs inside the detached worktree at corpus_run.code_commit (created by --new-run,
   docs/reference/gotchas.md scratch-worktree procedure, with the main checkout's .env symlinked
   into the worktree per the same gotchas entry). It refuses unless: HEAD equals code_commit; the
   rebuild code key equals corpus_run.code_key; services.__file__ (and the imported
   backfill_feature_factory module) resolves under the worktree path, never the main checkout;
   FetcherLock is not held (probe acquisition, released at once; this also catches a manual
   fetcher run); for each unit in APR infra.corpus_rerun.blocking_timers, `systemctl is-enabled`
   is not enabled and `systemctl is-active` on its .service is not active (warning 3: a run the
   timer already started still moves bars); no live-run process (D-32a); rebuild preconditions
   pass; the disk guard (check_disk_guard with the span term, below) for the next stage passes.
3. `pilot`: two pieces at the pin, under the run id, both ordinary units of the real stages that
   stay: stage_1d's first symbol chunk (run_rebuild_stage timeframes=[1d], chunk_indices=[0]) and
   one 1h unit of span 1 (run_rebuild_stage timeframes=[1h], span = the first calendar year of
   span 1, chunk_indices=[0]; a Jan-1-aligned sub-span, so it plans exactly chunk 0's 1h unit
   starting that year and s1.1h later skips it as completed). G1-G5 run on the pilot rows (G1-G3
   the column screen on stored rows, G4-G5 ops_pilot_compute_gate). Records per-unit wall time,
   the extrapolated wall clock per stage, DB load against the other lanes (D-32a), and the 1d and
   intraday bytes per row and stored-per-spool ratio into corpus_run.measured. Then it re-projects
   the run's spans (plan budget below) with the larger bytes-per-row figure; if any span's peak
   exceeds the fraction limit the pilot step fails before stage_1d runs (warning 4; spans are
   immutable, so the recovery is a new run, which picks more spans).
4. `stage_1d` (resumes after the pilot chunk): the whole history in one pass; its rows spread
   over every chunk and stay uncompressed until each chunk's intraday rows are written too.
5. Per span s in corpus_run.spans order: `s.1h`, `s.15m`, `s.5m`, each
   run_rebuild_stage(symbols=None, timeframes=[tf], run_id, span=s, disk guard). A span step fails
   on summary units_failed > 0, and on any planned unit of its (tf, span) without a completed
   provenance row whose run_id equals this run. After s.5m, compression_bound has moved past s's
   end, so s's chunks compress at that stage's end; the step also fails unless every chunk whose
   range_end is at or before s's end is compressed (the chunk straddling the boundary compresses
   after the next span).
6. `feature_complete`: every planned unit of the full scope has a completed provenance row with
   this run_id; no started or failed row under the run; the stage summaries' digest_blind_symbols
   is empty (a blind symbol cannot detect a revised bar inside a completed unit); the column screen
   passes per tf.
7. `ic_measure` under the run id, then `d19_bound` (no feature_ic_scores row at or after
   alpha.validation.oos_start), then `canary --run-id` (186-30). The ic_measure and canary step
   summaries carry corpus_run.caveats verbatim.

**Recovery.** A unit completed under another run id (or a stale started row) fails
feature_complete with its batch keys listed. The runbook's procedure: supersede those provenance
rows through the sanctioned completed -> superseded transition (migration 416), delete their rows
with the unit's replace_where, and retry the stage step under the same run id; the runner never
does this silently. A disk refusal: let the stage's compression finish, check free space, and
re-run the same step; the refused unit has no provenance row and resumes as pending.

**Interface.** --new-run (runs the span planner, records free_bytes_at_launch and spans, creates
corpus_run and the worktree, prints the run id); --run-id X --step S; --run-id X --through S. A
completed step re-invoked is a no-op reporting its stored outcome; a failed step retries after its
cause is fixed and never skips ahead. Logs go to logs/corpus_rerun.log under the main checkout's
absolute logs directory (/home/bg/dev/indicagent/logs, derived from `git rev-parse
--git-common-dir`, never the worktree's own logs/), and the rebuild spool root goes there too;
job_completed_total{job, status} per step.
</design>

<disk_budget>
Lead requirement, non-negotiable. Every figure below is an APR key seeded by 186-32's migration 579
or a live measurement; none is a literal in code.

Inputs:
- free_bytes_at_launch: recorded on corpus_run by --new-run (statvfs of the database volume).
- infra.corpus_rerun.max_disk_fraction = 0.70: the run's growth from launch never exceeds this
  share of free_bytes_at_launch.
- infra.corpus_rerun.disk_reserve_bytes = 50e9: free space never drops below it (replaces the 50 GB
  literal reserve).
- infra.corpus_rerun.bytes_per_row_uncompressed = 1379 (186-26 1d pilot, indexes included, 324
  columns; 311 now); infra.corpus_rerun.compression_ratio = 6.0 (old table, about 230 bytes per
  row compressed). The pilot measures 1d and intraday bytes per row and the larger figure is used
  from then on.
- infra.corpus_rerun.stored_bytes_per_spool_byte: the guard uses the larger of the seed and every
  value measured so far in the run (relation size delta over spool bytes per loaded unit).
- max_wal_size: SHOW max_wal_size, live.

Per-span size: for the compute_1d universe from each name's proven start to the horizon, the
tradeable bar count per tf per calendar year (market_data_ohlcv_tradeable), times bytes per row.

Projected peak of span k (services/corpus_rerun_budget.py, pure function of the counts, the chunk
boundaries read from timescaledb_information.dimensions, and the inputs):
uncompressed bytes of span k's intraday rows
+ the straddling chunk carried over from span k-1 (span k-1's rows inside the chunk that crosses
  its end, uncompressed)
+ the compressed bytes of every earlier span's rows outside that chunk
+ the 1d rows: uncompressed in chunks not yet compressed, compressed in the rest
+ max_wal_size
+ the largest group spool of span k (its rows times the spool bytes per row).
plan_spans picks Jan-1-aligned boundaries of about equal intraday rows for n = 1, 2, ... up to the
number of years and returns the smallest n whose max over k of the projected peak is at or below
max_disk_fraction times free_bytes_at_launch; none fits -> --new-run refuses with the table. The
same function re-projects fixed spans for the pilot's check.

At the 534 target (186-26 counts scaled by about 1.9 for the pre-2016 intraday history; 1d
unchanged), for orientation only (the runner computes the real value):

| tf | Rows | Uncompressed | Compressed |
|---|---|---|---|
| 1d | 7.1M | 10 GB | 2 GB |
| 1h | about 57M | about 79 GB | about 13 GB |
| 15m | about 208M | about 287 GB | about 48 GB |
| 5m | about 600M | about 830 GB | about 138 GB |
| all | about 870M | about 1,200 GB | about 200 GB |

With 699 GB free (2026-11-05) the limit is about 489 GB. Three spans peak near 400 + 130
compressed + 60 straddle + 10 + 16 WAL, about 620 GB: over. Five spans peak near 240 + 160 + 60 +
10 + 16, about 485 GB: at the limit. Expect five or six spans.

Guards:
- pin_gate, before every stage: check_disk_guard(projected_compressed_bytes, span_peak_bytes,
  wal_bytes, free_bytes, reserve_bytes). The "largest chunk working set" term becomes
  span_peak_bytes (the next span's projected peak less its compressed part); margin_bytes becomes
  wal_bytes (max_wal_size); reserve_bytes comes from infra.corpus_rerun.disk_reserve_bytes; run_all's
  disk mapping and its tests follow the rename. A second check refuses when growth since launch
  (free_bytes_at_launch minus free now) plus the remaining projected peak exceeds the fraction limit.
- _write_group, before each unit's COPY (hard guard): projected unit bytes = the unit's spool file
  sizes summed times stored_bytes_per_spool_byte (the measured max). Refuse when growth since
  launch plus projected unit bytes plus max_wal_size exceeds max_disk_fraction times
  free_bytes_at_launch, or when free now minus projected unit bytes minus max_wal_size is below
  disk_reserve_bytes. Refusal: _bulk_load is not called (no provenance row, so the unit stays
  pending and resumable), summary units_failed += 1 with reason disk_guard and the numbers,
  an error log line, and the stage stops dispatching further groups; the stage's end-of-run
  compression still runs (it frees space), and the span step fails on units_failed. The guard is
  always on: run_rebuild_stage takes a UnitDiskGuard; under a run it is built from corpus_run,
  standalone from free space at stage start and the same APR keys.
</disk_budget>

<failure_modes>
What fails silently, and what stops it:
- A gate passes on rows from another run: every gate reads by run_id (186-30), so a cell or unit
  without it fails the gate.
- A unit completed under an earlier run is skipped and counted as done: span steps and
  feature_complete count only this run's completed units.
- The data gate passes on incomplete data: 186-32 tests every calendar session per name-year and
  refuses names without a start or sessions.
- A survivorship-biased sample reads as clean: the caveat is on corpus_run and in the ic_measure
  and canary summaries; a half-written data_gate step cannot leave it missing or duplicated (one
  transaction, append skipped when present).
- A subset stage never compresses or keys units differently: no --symbols, ever; the pilot's units
  are real units of the real stages.
- Code moves between stages: the detached worktree pins the code; corpus_run's identity is
  immutable; pin_gate re-checks HEAD, the code key and where services is imported from; the
  fingerprinted writer refuses a changed key.
- Bars move under the run: a held fetcher lock, an enabled blocking timer or an active timer
  service are refused at pin_gate; the run's horizon pins every unit's reads; a revised bar
  renames its unit, which fails completeness loudly; a digest-blind symbol fails feature_complete.
- Disk runs out mid-stage: span count from the fraction limit, re-projected on measured intraday
  bytes before stage_1d, a guard per stage and per unit.
- A step is skipped on resume (the old --from-step trap): no skip flag exists.
</failure_modes>
