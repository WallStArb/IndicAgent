<objective>
Fix trad_AnchoredVWAPReversion gate ordering bug that causes zero emissions despite 6,462 ESM6 1m bars with sigma >= 1.5.

Root cause: The reclaim bar — the bar where price returns across VWAP — is precisely the bar where sigma crosses from |sigma| >= sigma_min back toward zero. The current gate at line 152 checks `if abs(sigma) < sigma_min:` and immediately clears departure state + returns no_signal() BEFORE checking whether a reclaim has occurred. So the plugin always clears state on the reclaim bar without ever detecting the reclaim.

Fix (D-04 specifies the exact ordering):
1. detect reclaim
2. emit signal
3. clear departure state
4. return

The fix restructures compute_full() to check reclaim BEFORE clearing departure state. When `abs(sigma) < sigma_min` AND `departure_sigma is not None` (actively tracking a departure), the plugin should evaluate the reclaim condition. If reclaim confirmed: emit signal, then clear state. If reclaim not confirmed: clear state (no signal — the departure ended without a reclaim event).

Purpose: This plugin is mean-reversion on VWAP departures — one of the most theoretically sound setups. Zero emissions is not a data problem; it is a logic ordering bug that prevents the plugin from ever firing.

Output: anchored_vwap_reversion.py with corrected gate ordering.
</objective>
