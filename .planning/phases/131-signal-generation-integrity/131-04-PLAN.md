<objective>
Fix the A7 root cause: ctf_score=0.0 corpus-wide because _last_events is empty when I6 runs for the first bar of each (symbol, tf).

Root cause (confirmed): feature_pipeline_executor.py builds frames["intel_{other_tf}"] from _last_events (lines 183-194). On bar 1 of a replay, _last_events is empty — there is no prior bar from this run, and the cache is not seeded from DB. extract_trend_sign() returns 0 for None values, so score_trend_alignment() returns 0 for all TFs → ctf_score=0.0 for every bar in the corpus.

Fix: Add _seed_last_events_from_db() to FeaturePipelineExecutor. This method queries intelligence_features for the most recent row per (symbol, tf), reconstructs a minimal IntelligenceEvent from I3-tier fields (trend_direction, trend_strength, etc.), and populates self._last_events[f"{symbol}:{tf}"]. Called once per symbol at replay startup, before the bar event loop.

The replay script (run_historical_pipeline.py) is a script that instantiates FeaturePipelineExecutor only in the live path — the replay path uses replay_symbol() which calls run_analysis_pipeline() directly and manages its own intelligence_cache dict. The seed in the replay path must populate intelligence_cache (used at line 1729-1731 to build intel_{tf} frames) rather than _last_events on the executor instance.

CRITICAL DESIGN NOTE: replay_symbol() does NOT use FeaturePipelineExecutor. It has its own intelligence_cache dict (line 1650) that serves the same purpose as _last_events in the live executor. The seed must populate intelligence_cache, not a FeaturePipelineExecutor instance. The _seed_last_events_from_db() method on FeaturePipelineExecutor is for the live executor path; replay_symbol() needs an equivalent standalone seed function.

Purpose: ctf_score=0.0 across 537K signals makes the entire corpus corpus-corrupted for ML. This is the highest-severity fix in Phase 131.

Output: FeaturePipelineExecutor with _seed_last_events_from_db() + replay_symbol() with intelligence_cache DB seed + --no-seed CLI flag.
</objective>
