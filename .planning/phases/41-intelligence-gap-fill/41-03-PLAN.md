<objective>
Three changes in one plan, grouped by shared concern of "making HTF context and session guards work end-to-end":

1. **HTF context injection** (INTEL-05): `signal_generator_service` adds `_htf_intel_cache`, populates it from the existing `intelligence:SYMBOL:1h` stream, injects `frames["htf_1h"]` for short-TF bars, and merges `htf_1h_*` prefixed VP fields into `features` before calling `frame_trade()`.

2. **VWAP/session TF guards**: Six intraday-only plugins receive a 2-line guard at the top of `compute_full()` that returns `_no_signal()` for non-intraday TFs. The `timeframe` key is injected into `frames` by `signal_generator_service` alongside the HTF injection.

3. **Aggregator + plugin state write-back comments** (from pending todos): Documentation-only — CRITICAL comments at the `active` derivation line in `aggregator.py` and at plugin computation loops in `market_analysis_service.py` and `indicator_service.py`.

Purpose: Plan 02 added `_select_vp()` and `_vp_regime_active()` to `trade_framer.py`. This plan wires them into the live pipeline — the HTF `poc_price`/`vah`/`val` levels need to arrive in `features` via `htf_1h_*` prefixed keys, which `_select_vp()` already knows how to read (fallback branch added in Plan 02).

Output: HTF context flows from stream to features to trade_framer. Six plugins cannot fire on 1h bars. Two critical invariants are documented at their most likely failure points.
</objective>
