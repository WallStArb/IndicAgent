# Phase 52.3 Plan 01: Dual-Write Shadow Writer Summary

**One-liner:** FeatureSnapshotWriterAgent deployed as independent shadow consumer writing `feature_snapshots_shadow` hypertable with live row production confirmed within 2 minutes of startup.

## What Was Built

Deployed `FeatureSnapshotWriterAgent` as an independent shadow consumer of `development.intelligence.journal`. It writes an identical copy of every `BarIntelligenceRecord` to `feature_snapshots_shadow`, enabling automated parity validation (Phase 52.5) before any primary-write cutover. Two consumer groups read the same topic independently — no coupling, no shared state, no coordinated writes.

```
intelligence.journal topic
  ├── feature_writer_group         -> intelligence_features       (existing primary)
  └── feature_snapshot_writer_group -> feature_snapshots_shadow   (new shadow)
```

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Missing unique index on feature_snapshots_shadow**
- **Found during:** Task 4 (service startup)
- **Issue:** `ON CONFLICT (ts, symbol, tf) DO NOTHING` in FeatureRepository SQL requires a unique index on those columns. `CREATE TABLE LIKE intelligence_features INCLUDING DEFAULTS INCLUDING CONSTRAINTS` does NOT copy primary keys/indexes from a TimescaleDB hypertable source. TimescaleDB creates its own time-partitioned index only.
- **Fix:** Added `CREATE UNIQUE INDEX IF NOT EXISTS feature_snapshots_shadow_ts_symbol_tf_idx ON feature_snapshots_shadow (ts, symbol, tf)` to migration 051 and applied to running DB
- **Files modified:** production/migrations/051_feature_snapshots_shadow.sql
- **Commit:** 41cc644
