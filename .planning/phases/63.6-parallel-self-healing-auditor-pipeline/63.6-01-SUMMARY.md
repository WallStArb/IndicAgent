# Phase 63.6 Plan 01: Batch SQL Audit Utilities + BarAuditorAgent Refactor Summary

Batch SQL utilities for auditor agents (354 DB roundtrips/cycle → 1), new `SignalReplayRequest` schema + topic, and BarAuditorAgent refactored to publish gap requests for all TFs.

## What Was Built

### Task 1: `src/core/audit_utils.py`

New module with two pure async functions:

- `batch_bar_completeness(pool, instruments, lookback_days=3) → list[BarCompletenessResult]`
  — Builds UNNEST arrays for all (instrument × date × tf) combinations (1m + all HTF), executes a single parameterized LEFT JOIN query against `market_data_ohlcv`. LEFT JOIN guarantees zero-bar sessions appear as `actual=0` rows (plain GROUP BY would silently drop them).

- `batch_signal_coverage(pool, instruments, coverage_tfs, lookback_days=1) → list[SignalCoverageResult]`
  — Builds UNNEST arrays for all (instrument × tf) pairs, executes a single parameterized LEFT JOIN query against `signal_ledger` with `percentile_cont` for P50/P95 lag in the same pass.

Both functions:
- Have no Prometheus, Kafka, or structlog imports (pure functions — callers own observability)
- Use asyncpg parameterized UNNEST arrays ($1, $2...) — no string interpolation (T-63.6-01-A mitigated)
- Are covered by 8 unit tests in `tests/unit/test_audit_utils.py`

### Task 2: Topic + Schema

Added `topic_signal_replay_requests()` to `src/core/stream_keys.py`:
- Returns `{env}.market.events.signal_replay_requests`
- Documents producer (SignalAuditorAgent) and consumer (BarReplayAgent) in docstring

Added `SignalReplayRequest` to `src/core/schemas/market_events.py`:
- Fields: `request_id: UUID`, `symbol: str`, `tf: str`, `session_start: datetime`, `session_end: datetime`, `requested_at: datetime`
- All datetimes UTC-aware; `request_id` auto-generates UUID4; `requested_at` auto-generates `datetime.now(UTC)`

### Task 3: BarAuditorAgent Refactor

Replaced the entire `_detect_gaps` body:
- **Before:** nested `for instrument × for days_back × await conn.fetchval()` — 354 DB roundtrips + additional `conn.fetch()` for HTF counts
- **After:** single `await batch_bar_completeness(self._db_pool, instruments, lookback_days)` call — 1 roundtrip

Key behavioral changes:
- Gap requests now published for **all TFs** (1m, 5m, 15m, 1h, 4h) when completeness below threshold
- Dedup key changed from `(symbol, date_str)` to `(symbol, date_str, tf)` — per-TF to prevent infinite retry on one TF from blocking others
- `_requested_today` type annotation updated from `set[tuple[str, str]]` to `set[tuple[str, str, str]]`

Tests updated in `tests/unit/service_tests/test_bar_auditor_agent.py`:
- Removed `TestDetectGaps` class (mocked DB pool directly — no longer valid)
- Added `TestDetectGapsBatch` class (patches `services.bar_auditor_agent.batch_bar_completeness`)
- 5 new tests: low-completeness 1m → gap, HTF low-completeness → gap with correct tf, high-completeness → no gap, dedup blocks second call, gauge labeled with tf
