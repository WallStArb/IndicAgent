<!-- The window definition every later plan must match. Derived from D-04's corrected window. -->

Corrected earnings-season window (D-04, supersedes the todo's 0-42 day window):
  in-season iff START_DAYS <= days_since_quarter_end <= END_DAYS, with START_DAYS=14, END_DAYS=42
  quarter ends: Mar 31, Jun 30, Sep 30, Dec 31
  days_since_quarter_end = (bar_ts.date() - most_recent_quarter_end).days, always >= 0

Reference implementation verified during research (Spearman rho 0.935 vs. the live
`quarter_position` column, n=4018):

    def days_since_quarter_end(d: date) -> int:
        quarter_ends = [date(y, m, day) for y in (d.year - 1, d.year)
                        for m, day in ((3, 31), (6, 30), (9, 30), (12, 31))]
        last_qe = max(qe for qe in quarter_ends if qe <= d)
        return (d - last_qe).days

SQL identifier safety (psycopg 3 is this project's driver — `requirements.txt` line 16,
`psycopg[binary,pool]>=3.2`; psycopg2 was removed 2026-08-03, so the psycopg 3 `sql` module is
available and is the required composition mechanism):

    from psycopg import sql
    QUERY_TEMPLATE = sql.SQL("SELECT fv.bar_ts, fv.{feat}, fr.{ret} FROM ...")   # plain literal
    query = QUERY_TEMPLATE.format(
        feat=sql.Identifier(validated_feature),
        ret=sql.Identifier(validated_return_column),
    )

Note the template is a plain string literal passed to `sql.SQL`, never an f-string — the `{feat}`
placeholders are consumed by `sql.SQL.format`, not by Python string interpolation.

Values (`--tf`, the window bounds) stay as `%s` placeholder parameters — only identifiers go
through `sql.Identifier`.

DB access (CLAUDE.md): PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent
Measurement read path: `feature_vectors` joined to `forward_returns`, filtered
`return_type = 'executable_open_to_open'` (CLAUDE.md Invariant 1 — theoretical close-to-close
returns overstate IC and are not acceptable).
