<objective>
Wire the cross-sectional half of the regime-conditioning workstream: after a cross-sectional cell's
`X_raw` / `returns_mat` / `complete_mat` / `bar_ts_arr` arrays are already materialized, derive an
in-memory season mask from the `earnings_season_flag` column already present in `X_raw`, and call
the existing `_compute_one_cross_sectional_cell` once more per season state with row-sliced arrays.

Purpose: D-01a gates this workstream on plan 176-01's multi-feature sweep (see the pre-execution
gate above); once that gate passes, D-03 locks reuse of existing machinery. `ic_engine.py`'s
cross-sectional cell path has a documented OOM history (todos 357/358/371) and
`_compute_one_cross_sectional_cell`'s own docstring states it has no internal mask step because
"the caller's chunked fetch scopes to exactly this (tf, regime_label) cell." Adding a third
DB-fetch dimension (group x regime_label x season) would multiply the expensive chunked fetches —
exactly the cost class that produced the todo-371 OOM. Masking post-materialization is strictly
cheaper than the primary cell computation and reuses 100% of the bootstrap/CI/FDR/walk-forward
internals untouched.

Explicitly rejected (do not build): a Phase-144-style `regime_group`. That mechanism partitions the
universe into disjoint peer sets with their own fitted regime signal. Earnings season is a calendar
boolean every equity symbol experiences simultaneously — it does not partition symbols at all, and
building a `regime_group` for it would drag in `_build_symbol_regime_class`'s
`AmbiguousRegimeGroupError` mutual-exclusivity machinery for no reason.

Output: two extra cross-sectional sub-cells per parent cell, under `regime_scope='earnings_season'`,
with a memory guard and no new fetches.

This is the riskiest plan in the phase. Read `docs/foundation/performance-investigation-sop.md`
before touching this code — measure before theorizing, and treat chunk count / compression status
as first-class suspects if anything gets slow.
</objective>

New season calls go AFTER the broadcast call and BEFORE the `finally:` that closes/unlinks the
memmap — `X_raw` is still valid there, and the existing comment block marks the broadcast call as
"the last consumer of X_raw before the finally below runs" (that comment must be updated).

`_compute_one_cross_sectional_cell` currently HARDCODES its emitted `"regime_scope":
"cross_sectional"` (~line 4066) and `"regime_label_source": "market_regimes"`. It needs a new
keyword parameter `resolved_regime_scope: str = "cross_sectional"` used in place of the literal.
Leave `regime_label_source` as-is: the parent cell's labels still come from `market_regimes`; the
season qualifier is an additional stratification of the same rows.

`feature_ic_scores` uniqueness (verified): the cross-sectional INSERT uses
`ON CONFLICT (feature_name, symbol, tf, regime, lookahead_bars, training_window_end)
 WHERE is_pooled = true AND symbol = 'POOLED' DO NOTHING`. `regime_scope` is NOT part of the key.
`_compute_cross_sectional_tf` is invoked once per (regime_group, tf, regime_label), so a bare
`"in_season"` label would collide across parent cells within the same tf and silently DROP rows.
Season sub-cell labels MUST therefore be parent-qualified:

    f"{regime_label}__in_season"    and    f"{regime_label}__off_season"

(double underscore separator, chosen to stay distinguishable from the single-underscore
`"{tier1}_{tier2}"` composition `market_regimes` labels already use).

This qualification is a correct workaround, not a fix: it encodes scope into the `regime` string
because the uniqueness key omits `regime_scope`. The schema-level fix is deliberately OUT of scope
for this phase and is filed as
`.planning/todos/pending/391-feature-ic-scores-uniqueness-key-excludes-regime-scope.md` — cite that
todo in the helper docstring so the next scope author finds the reasoning instead of rediscovering
the silent-row-drop the hard way.

Memory/ceiling helpers already in the file: `_check_cell_size(n_rows, config, description)` raises
`CellTooLargeError`; `use_disk` is the flag that routed this cell's `X_acc` to a memmap;
`config.max_cell_rows` / the pre-flight estimate block sit just above the fetch.

APR switch: `config.earnings_season_conditioned` (added by plan 176-04).
Season label helper: `_earnings_season_labels(flag_column)` (added by plan 176-04) — reuse it, do
not write a second mapping.
Flag column position: `_FEATURE_NAMES.index("earnings_season_flag")` — the same module-level
precomputed index plan 176-04 introduced.
