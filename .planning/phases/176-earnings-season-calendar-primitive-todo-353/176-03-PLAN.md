<objective>
Ship the two calendar-group primitives — `earnings_season_flag` (tier-1 event flag) and
`days_since_quarter_end` (tier-1 continuous companion) — through every site the
`opex_flag`/`quad_witching_flag` precedent touches: pure functions, config, field-to-group dict,
`FeatureVector` dataclass, the persistence column-order slice, both `compute()` and
`compute_batch()` construction sites, `_cold_start_vector()`, both APR prewarm paths, and the
test fixtures that would otherwise fail at pytest collection.

Purpose: D-02 locks shipping both fields. D-03 locks reuse of the existing calendar-group pattern
and forbids hardcoded window literals. The naming is `earnings_season_flag`, NOT CONTEXT.md's
`is_earnings_season` — `naming-system.md` §7a's fixed 4-form calendar vocabulary permits a
window-selecting binary only as a tier-1 `<event>_flag`, and the codebase already corrected
`is_opex_day` for the identical reason.

Output: both fields computed and persisted, all unit tests green, zero positional-index drift.

Non-negotiable sequencing inside this plan (Pitfall 4): `FeatureVector` fields have no defaults.
Adding them to the dataclass without simultaneously updating every construction site breaks
pytest at COLLECTION time across several unrelated-looking files. Task 2 is therefore a single
atomic commit spanning the schema field, all four production construction sites, the persistence
slice, and both test-fixture files. Do not split it.
</objective>
