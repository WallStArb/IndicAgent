<objective>
Populate `earnings_season_flag` and `days_since_quarter_end` on the already-existing
`feature_vectors` corpus. Migration 350 (plan 176-02) added the columns as NULL on every
pre-existing row; plan 176-03 made new rows compute them. Nothing yet fills the ~40M rows that
already exist, and `ic_engine` cannot condition on a column of NULLs.

Purpose: CONTEXT.md's Phase Boundary ends this phase at "a real `feature_ic_scores`
FDR/walk-forward gate pass". That gate measures persisted values. D-03's SoC principle explicitly
forbids the cheap shortcut (having `ic_engine` derive the calendar flag from `bar_ts` in memory) —
the measurement layer reads the persisted column, so the column must actually be written.
`services/backfill_feature_factory.py --refresh`'s own help text names this exact situation:
"default mode will silently leave new columns NULL on every pre-existing row otherwise."

Output: both columns populated across a recorded scope, with the wall-clock cost measured rather
than assumed, and a written manifest of exactly what was covered.

Sequencing is load-bearing, not advisory. STATE.md's Roadmap Evolution section sequences this
phase's recompute behind todo 340 and Phase 175 for corpus-contention reasons, and a live
`backfill_feature_factory.py --compute-only --symbols IHF --workers 1` run (todo 340's
confirmation re-run) was observed active at plan time on 2026-09-22 16:45. Task 1's pre-flight gate
is the enforcement point — do not launch this recompute blind.
</objective>

Recompute entrypoint (the only supported path — there is no `--tf` flag; scope control is
symbols-only, so staged runs are symbol batches):

    .venv/bin/python services/backfill_feature_factory.py --compute-only --refresh \
        --symbols SYM1,SYM2,... [--workers N]

`--refresh` semantics (verified in services/backfill_feature_factory.py): switches the write from
`FEATURE_VECTOR_INSERT_SQL_PSYCOPG` (ON CONFLICT DO NOTHING) to `FEATURE_VECTOR_UPSERT_SQL_PSYCOPG`
(ON CONFLICT (symbol, tf, bar_ts) DO UPDATE), and bypasses the `backfill_status.status='complete'`
checkpoint skip.

Collateral-damage safety, already structural (do NOT re-derive, just verify it held):
`src/intelligence/features/feature_vector_persistence.py`'s `_UPDATE_SET_SQL` excludes
`_EXTERNALLY_OWNED_COLUMN_NAMES` = `REGIME_WRITER_OWNED_COLUMN_NAMES` (regime, hmm_prob_trending_up,
hmm_prob_ranging, hmm_prob_trending_down, hmm_regime_prob, hmm_entropy, hmm_duration, hmm_churn)
| `REGIME_VOLATILITY_WRITER_OWNED_COLUMN_NAMES` (regime_volatility, hmm_vol_prob_calm,
hmm_vol_prob_elevated, hmm_vol_prob_turbulent, hmm_vol_regime_prob, hmm_vol_entropy,
hmm_vol_duration, hmm_vol_churn) | {regime_label_source}. That exclusion exists because a
2026-07-30 `--refresh` run nulled `feature_vectors.regime` across all 36.8M rows. This plan does
not need to re-run `regime_writer` afterwards — but it MUST prove the exclusion held, because
plan 176-04's per-symbol pass depends on `regime_volatility` being intact.

STATE.md corpus gotcha (Corpus Pipeline Gotcha section): `--compute-only` silently skips ALL
symbols if `backfill_status` is empty. Pre-flight must assert it is populated.

CLAUDE.md orphan-process rule: killing `backfill_feature_factory.py`'s main PID does NOT reap its
forkserver workers. If a batch must be aborted:
    ps aux | grep backfill_feature_factory.py | awk '{print $2}' | xargs kill
and confirm zero remain before starting anything else.

Cost priors (from logs/corpus_pipeline/step_timings.jsonl, the durable append-only step record):
the single historical full-corpus step-1 `feature_factory` entry is 16,432s (~4.6h) on 2026-08-12,
and that was a checkpointed (non-`--refresh`) run on a smaller universe. Treat it as an order-of-
magnitude prior only; Task 1 measures the real per-symbol cost.

DB access (CLAUDE.md): PGPASSWORD=postgres psql -U postgres -h localhost -d indicagent
Reference window classifier for correctness spot-checks: the pure functions in
`scripts/analysis/earnings_season_conditional_ic_reverification.py` (plan 176-01).
Progress monitor: `scripts/ops/corpus/ops_corpus_progress.py` (no arguments).
