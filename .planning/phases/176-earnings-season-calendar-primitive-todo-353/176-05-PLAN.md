<objective>
Stop the new `regime_scope='earnings_season'` rows from silently becoming ensemble training inputs,
and produce a written audit of every other `feature_ic_scores` consumer.

Purpose: Pitfall 2, made concrete during planning. Cross-sectional earnings-season cells will be
written with `symbol='POOLED'`, `is_pooled=true` and a non-`_pooled` regime label — which is
exactly the shape `ensemble_trainer._eligibility_where()` selects on today
(`symbol = 'POOLED' AND is_pooled = true AND regime != '_pooled' AND ...`). Left alone, plan
176-06's output would silently add new `(tf, regime)` strata to ensemble weighting and alpha
emission. This project's standing rule is shadow mode first and prove edge before wiring
production consumers; this phase ends at a measurement gate, not a promotion, so the new scope must
be measurement-only.

The regime-routing bug class is not theoretical here: commit `b8af2b749` (2026-09-17) fixed a
corpus-wide `ic_engine.py` regime-*group* routing bug that blocked the engine entirely, and commit
`d1ce8d6bb` fixed a sibling tag-routing contamination the same week.

Output: a one-clause eligibility exclusion with tests, plus `176-SCOPE-CONSUMER-AUDIT.md`.

This plan runs in parallel with 176-04: it touches `services/ensemble_trainer.py`, not
`services/ic_engine.py` (whose own in-file scope consumers are 176-04's Task 2).
</objective>
