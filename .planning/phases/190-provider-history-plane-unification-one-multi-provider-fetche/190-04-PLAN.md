## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| leaf -> loop | vendor-native failures (socket loss, 429s) cross into loop state as outcomes |
| registry entry -> vendor mechanics | dispatch is the only route to vendor code; a bypass would run the wrong mechanics on a foreign item |
| loop -> ledger | outcome writes are the only fetcher writes, via the writer module |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-190-06 | DoS | concurrent hypertable writers | mitigate | Unchanged structural guarantee: one process, one queue, one writer connection; lanes are priorities, never lock contenders (registry dispatch preserves this) |
| T-190-13 | Tampering (data) | foreign item running IBKR mechanics | mitigate | The loop reaches vendor code only via entry.fetch; a test asserts a raising fake entry surfaces as an outcome with no IBKR fallback; IBKR mechanics are fenced inside the ibkr entry's reach (Task 3) |
