<objective>
Build `CounterfactualTracker` — the `BaseBatch` oneshot that fills each open frame's geometry from the
T+1 open, scans the subsequent price path to close it via the four-trigger state machine
(FRAME-02/03), scores counterfactual P&L, and evaluates the FRAME-04 exit gate (bootstrap CI per
(tf, regime)). Depends on Plan 01's migration and AlphaFrameWriter output.

Purpose: this is where hypothetical positions become measured counterfactual outcomes — the number
that answers Phase 142B's binary question (can a sensible frame capture the IC as positive P&L). The
correctness-critical requirement is fidelity to the codebase's proven anti-OOM patterns on BOTH
sides: a plain psycopg2 cursor on the read side (crashed production twice this week) AND unbounded
client-side row accumulation on the write side (the same OOM shape moved to the aggregation step).

Output: `services/counterfactual_tracker.py` (pure-fn exit/gate cores + service + gate mode), an
IC-staleness gauge, service registration, RED→GREEN tests, and the D-10 follow-on todo.
</objective>
