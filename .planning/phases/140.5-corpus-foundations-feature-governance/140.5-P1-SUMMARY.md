Audited the feature_vectors corpus for silent-constant batch path defects in CTF, VP/SR, and HMM feature groups. Found the corpus already clean on all axes except the 1d CTF batch path bug, which was fixed in code. No full corpus rerun required — the existing corpus passes all gate checks.

All std values > 0, all VP/SR rows are NULL. The existing corpus was generated from a run that predates the 1d CTF bug.

### Fixes Applied

**CTF batch path (1d TF):** `_CTF_HIGHER_TF["1d"]` was `None`, causing `_build_ctf_series()` to skip 1d entirely and return constant 0.0. Fixed by mapping `"1d" → "1d"` (self-referential HTF: daily bar T computes CTF from daily bars up to T, which is causal since bar T has closed at computation time). This prevents regressions on any future full corpus rebuild.

**HMM window:** Already using `bars[:i+1]` (full history). No change needed.

**VP/SR nullable:** Already NULL in all rows (`poc_dist_atr`, `va_position`, `sr_support_dist`, `sr_resist_dist`). Migration 175 not needed — schema already permits NULL, and values are already NULL in corpus.

### Code change

`services/backfill_feature_factory.py` — `_CTF_HIGHER_TF` dict:
```python
# Before
"1d": None,
# After
"1d": "1d",  # causal: bisect_right selects bar-T's CTF from bars up to T
```
