# Phase 140.5 Plan 5: Context Features Table + Writer + IC Engine Join Summary

One-liner: Daily-cadence macro features (vix_z, flight_quality, yield_slope_z) moved to context_features table; IC engine measures them at their true daily observation frequency via DISTINCT ON join, eliminating ~78x bar duplication for 5m TF.

## What Changed and Why

### The Problem: Artificial Autocorrelation in IC Measurement

Before this plan, vix_z, flight_quality, and yield_slope_z injected the same daily value into every intraday bar row for a calendar day. For a 5m TF with ~78 bars/day, a VIX reading at 9:30 and 9:35 are not independent observations — they are the same reading replicated 78 times. The IC engine's stride correction (`scale_stride = max(min_stride, lookahead_bars)`) corrects temporal dependence at the bar level but does NOT fix date-level duplication: with stride=5, a daily VIX value still appears in 78/5 = ~16 "independent" subsampled observations per day.

### The Fix: One Observation Per Calendar Day

The DISTINCT ON (DATE(fv.bar_ts)) idiom selects exactly one bar per calendar day — the earliest intraday bar (first 5m bar ~9:30am). This is causally correct: the daily context value pairs with the opening bar's forward return. With 2995 trading days since 1997, all three features easily exceed the 1000-obs daily gate.

## P5-T2: context_features_writer.py — Populate Daily-Cadence Macro Features

`production/scripts/context_features_writer.py`:

Ported `_build_cross_asset_series()` from `services/backfill_feature_factory.py` into a standalone oneshot script. Uses bisect-based cursor alignment and deque-based incremental rolling windows (O(1) per date, O(D) total).

Computation:
- **vix_z**: SPY realized-vol z-score. log_return per day → rolling std over 20 bars (`cross_asset_rv_window`) → z-score over 252-bar history (`vix_zscore_window`)
- **flight_quality**: TLT/SPY cumulative total-return divergence from series start. `(tlt_close/tlt_first - 1) - (spy_close/spy_first - 1)` — measures risk-off demand
- **yield_slope_z**: (TLT log-return - SHY log-return) daily, z-scored over 252-bar history (`yield_curve_zscore_window`)

Row counts after run:

| vix_z          | 2995   | -2.5790  |  6.8965 |

All rows use `symbol=''`, `source='derived'`. No NULL values.

APR window keys loaded at runtime (no hardcoded numbers):
- `feature.vix.zscore_window = 252`

Only dates where both spy_realized_vol_history and yield_ratio_history reach their full window (warmup period met) are written. Dates with partial warmup values (0.0 as initial state) are excluded.

### Context Features Section in _compute_symbol_tf

Added between end of regime loop and BH-FDR pass. For each feature in `sorted(CONTEXT_FEATURES)` (deterministic order):

1. Query daily observations via DISTINCT ON join:
```sql
SELECT DISTINCT ON (DATE(fv.bar_ts))
    DATE(fv.bar_ts) AS obs_date,
    cf.value AS feature_value,
    fr.return_fast, fr.return_mid, fr.return_slow, fr.return_extended,
    fr.complete_fast, fr.complete_mid, fr.complete_slow, fr.complete_extended
FROM feature_vectors fv
INNER JOIN context_features cf
    ON DATE(fv.bar_ts) = cf.feature_date
    AND cf.feature_name = %(feature_name)s
    AND cf.symbol = ''
INNER JOIN forward_returns fr
    ON fv.symbol = fr.symbol AND fv.tf = fr.tf AND fv.bar_ts = fr.bar_ts
WHERE fv.symbol = %(symbol)s AND fv.tf = %(tf)s AND fv.bar_ts <= %(training_window_end)s
ORDER BY DATE(fv.bar_ts), fv.bar_ts ASC
```

2. Apply `min_obs_daily` gate (1000 obs). Standard 20K intraday gate does not apply.

3. For each scale: compute Spearman IC, p-value, bootstrap CI, walk-forward.

4. `ic_sharpe = None` (NaN) by design: `sharpe_window_size=2000` calibrated for intraday bars. With 2995 daily obs, `n // 2000 = 1 < sharpe_min_windows=30`. This is documented expected behavior.

5. `regime_label_source = 'context_features'` for audit trail.

6. `cluster_id = 10000 + cf_idx` — each context feature enters BH-FDR as its own cluster (no collisions with per-symbol clustering which produces IDs 1-61).

7. Results added to `all_results` before BH-FDR pass — context features participate in BH-FDR alongside intraday features.

Results use `is_pooled=True, regime='_pooled'` — written via `_POOLED_INSERT_SQL`.
