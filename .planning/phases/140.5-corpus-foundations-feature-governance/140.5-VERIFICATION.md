## Gaps Summary

Two gaps block full goal achievement, both involving services that were wired but not run:

**Gap 1 — regime_writer not run with K=5 (P2):** The BIC study correctly identified K=5, migration 176 applied it to APR, and the K=5 label map was implemented in regime_writer. But the P2-SUMMARY explicitly deferred the regime_writer execution, leaving feature_vectors with K=3 regime labels (trending_up, ranging, trending_down) rather than the validated K=5 (trending_up, transition_up, ranging, transition_down, trending_down). This affects IC stratification in Phase 141 — the regime column in feature_vectors does not reflect the validated state count.

**Gap 2 — ic_engine not run after integration (P4):** All ic_engine cross-sectional infrastructure is correctly wired — market_regimes is populated (9 regime labels x 4 TFs, 0 NULL labels), equity_model_enabled=true in APR, _compute_cross_sectional_tf is implemented, forward_returns has 54M rows available. However ic_engine was never run after the P3/P4/P5 integration, so feature_ic_scores has 0 rows. The P4 must-have explicitly requires POOLED rows to exist as evidence the cross-sectional pooling produces output.

**Root cause relationship:** Gap 1 and Gap 2 share a common root: both require running long-running batch services (regime_writer ~2-4h, ic_engine multi-hour) as the final validation step of their respective plans. Both were deferred by the executing agent. Gap 2 is the more consequential one for Phase 141 — Phase 141 is the "IC scoring run" and would regenerate feature_ic_scores, but regime labels in feature_vectors need to be K=5 before that run (fixing Gap 1 first).

**Recommended fix order:** (1) Run regime_writer --refit with K=5 to update feature_vectors regime column. (2) Run ic_engine with equity_model_enabled=true to populate feature_ic_scores including POOLED cross-sectional rows.
