  <action>
    Create production/scripts/bic_k_selection.py as a standalone analysis script.

    Script design:
    - Imports: hmmlearn.hmm.GaussianHMM, sklearn.preprocessing.StandardScaler, numpy, psycopg2, math, csv, sys
    - Symbols to study: ['SPY', 'TLT', 'GLD', 'EWT'] at TF='5m' (most data, most sensitive to K)
    - K range: [2, 3, 4, 5, 6]
    - DSN: read from Settings (same as regime_writer)

    BIC formula (diag GaussianHMM, d=5 observation dimensions):
      n_params = K*(K-1) + 2*K*d   # transition free params + emission means + emission variances
      BIC = -2 * model.score(obs_scaled) * n_obs + n_params * math.log(n_obs)
    Note: model.score() returns AVERAGE log-likelihood per obs; multiply by n_obs for total.

    For each (symbol, K):
    1. Fetch OHLCV from market_data_ohlcv WHERE symbol=? AND timeframe='5m' ORDER BY timestamp ASC (psycopg2)
    2. Call _build_obs_matrix() from regime_writer — import or copy the function. The function uses: APR feature.hmm.vol_window (default 20), feature.hmm.obs_momentum_window (default 20), feature.hmm.obs_vol_of_vol_window (default 20). Load these from config_state via direct SQL SELECT.
    3. Apply StandardScaler fit_transform on the valid obs rows (same as regime_writer)
    4. Fit GaussianHMM(n_components=K, covariance_type='diag', n_iter=200, random_state=42, tol=1e-4) on obs_scaled
    5. Record: symbol, K, log_likelihood (model.score(obs_scaled) * n_obs), n_obs, n_params, BIC

    Output:
    - Print BIC table to stdout in aligned columns: symbol | K | log_lik | n_obs | n_params | BIC
    - Write CSV to docs/analysis/bic_k_selection.csv with same columns
    - Print winner per symbol (min BIC K)
    - Print overall recommendation: if K=3 wins in >=3 of 4 symbols → "DECISION: keep K=3"; else "DECISION: update K to {most_common_winner}"

    Run the script:
    ```
    INDICAGENT_ENV=production .venv/bin/python production/scripts/bic_k_selection.py 2>&1 | tee docs/analysis/bic_k_selection_run.log
    ```

    Document results in docs/analysis/bic_k_selection.md:
    - BIC table (copied from stdout)
    - Winner per symbol
    - Final K decision with rationale
    - Note if K is ambiguous (different K per symbol) — default to K=3 in that case per todo 002
  </action>

      a. Update _build_label_map() in regime_writer.py to handle N states. The current 3-state map assigns: highest mean return → 'trending_up', lowest mean return → 'trending_down', middle → 'ranging'. For 4 states: add 'transition' assigned to the state with highest entropy (most uncertain: lowest max probability in decoded states). For K=2: just 'trending_up' and 'trending_down'. For K=5+: extend similarly with 'transition_up', 'transition_down' as needed.
      b. Create production/migrations/176_hmm_k_update.sql:

         UPDATE config_state SET config_value = 'N', version = version + 1 WHERE config_key = 'feature.hmm.n_components';

         FROM config_state WHERE config_key = 'feature.hmm.n_components';
