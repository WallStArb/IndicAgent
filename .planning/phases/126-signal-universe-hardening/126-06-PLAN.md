<objective>
Move extrinsic context annotation from plugin bodies to the pipeline layer (Root Cause behind Root Crime 2). Currently `capture_signal_features()` lives in plugin bodies, producing a biased heterogeneous training corpus: `ctf_score` is null for Phase-118 canonical plugins, the 30-key curated subset is a baked-in human judgment, `zone_friction_score` is produced by one plugin only, and `_I7_I6_EXEMPT` is a symptom. After this plan, `signal_processor._annotate_signal()` attaches the full `flat_features` snapshot to every signal uniformly.

Purpose: Infrastructure annotates, detectors detect. A clean replay (Phase 127) on a corpus where context_features is populated by 22 of 30 plugins and null for the rest carries a plugin-identity confound and is unfit for context_features-dependent ML training. This plan makes annotation uniform and extensible (new tier outputs appear automatically).

Output: _annotate_signal() in signal_processor.py, zone_friction_score formalized in a tier, capture_signal_features() stripped from all plugin bodies and deprecated, make_signal_from_frame() ECL kwargs removed, _I7_I6_EXEMPT + requires_i6_confluence enforcement deleted, SIGNAL_SCHEMA_VERSION bumped, unit tests.

NOTE ON WAVE 2 INTERACTION (D-06): Wave 2 (P126-02) wires the 8 formerly-exempt plugins with requires_i6_confluence=True and capture_signal_features() and deletes _I7_I6_EXEMPT. This plan THEN strips capture_signal_features() from ALL 30 plugins (including those 8) and removes the requires_i6_confluence ClassVar + its validate_tier() enforcement entirely. If Wave 2 already deleted _I7_I6_EXEMPT, Step 6 here only needs to confirm it is gone and remove the remaining requires_i6_confluence enforcement.
</objective>
