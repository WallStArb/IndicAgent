# Phase 107.5 Plan 01: Remove is_backfill Guard from _ingest_signal Summary

**One-line fix removes the is_backfill guard from signal_tracker's TTL fast-path, ensuring all stale pending signals are expired at restart regardless of their backfill flag**

## Decisions Made

- Removed the guard entirely rather than replacing it — elapsed bars is the only meaningful criterion; the is_backfill field is a provenance label, not a lifecycle gate

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Two unit tests used stale timestamps that hit the newly-broadened TTL fast-path**

- **Found during:** Task 1 (verify step)
- **Issue:** `test_ingest_new_signal` and `test_ingest_multiple_signals_same_symbol` used `"2026-01-01T10:00:00+00:00"` timestamps. With the is_backfill guard removed, `bars_elapsed >= ttl_bars` is now `True` for these signals, so they hit the fast-path and never enter the active index. Both tests then asserted on `_active_index` and failed.
- **Fix:** Changed both tests to compute a fresh timestamp: `datetime.now(UTC) - timedelta(seconds=30)`, which is well within the 10-bar (10-minute) TTL window for 1m signals.
- **Files modified:** `tests/unit/services/test_signal_tracker_compute_agent.py`
