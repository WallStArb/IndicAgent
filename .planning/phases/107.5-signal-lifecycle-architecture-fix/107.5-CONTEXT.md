# Phase 107.5: Signal Lifecycle Architecture Fix - Context

**Gathered:** 2026-05-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix four structural defects in signal lifecycle that caused 96% of signals to be permanently pending and mask real performance data. After this phase: signal records are self-contained, TTL evaluation is deterministic and unified, the live tracker handles restarts correctly, and the replay auditor is a true canary processing near-zero signals in steady state.

Four fixes, in execution order:
1. Remove `is_backfill` guard from startup fast-path in `signal_tracker_compute_agent.py`
2. Fix field name mismatch in `signal_writer_agent.py` + backfill `entry_zone_low/high` for historical signals
3. Add `expires_at` column, unify TTL evaluation to wall-clock, update both evaluators atomically
4. Remove LATERAL JOIN from replay auditor, restore canary parameters via Settings

</domain>

<decisions>
## Implementation Decisions

### Renaissance Design Principles (apply to all four fixes)
- **D-01:** Every fix ships as an independent, verifiable deployment — one change, one observable outcome, confirm before proceeding. Never batch unrelated changes.
- **D-02:** No dual code paths in production, even temporarily. Migration-first, then deploy. The backfill is the safety gate, not a fallback.
- **D-03:** Fail loudly, not silently. NULL data or wrong state surfaces as an error metric + DLQ, never a silent fallback that masks upstream bugs.
- **D-04:** Business logic belongs in application code. DB stores. No generated columns, no schema-embedded CASE expressions.
- **D-05:** Operational parameters go in `src/config/settings.py`. Never hardcode values that affect production behavior — they require a deploy to tune.

### Fix 1: is_backfill Guard
- **D-06:** Remove the `is_backfill` guard at `services/signal_tracker_compute_agent.py:408`. Any signal loaded at startup where `elapsed >= ttl_bars * tf_secs` immediately fires `_publish_ttl_expired_transition_sync`, regardless of `is_backfill` flag.
- **D-07:** Ships alone. Success metric: after the next restart, stale pending signals fire TTL-expired transitions immediately rather than accumulating. Confirm before proceeding to Fix 2.

### Fix 2: entry_zone_low/high
- **D-08:** Root cause is a field name mismatch: `signal_writer_agent.py:207-208` reads `sig.get("entry_zone_low")` but the signal dict uses `zone_low` (set in `signal_schema.py:223-224`). Fix is two lines: change to `sig.get("zone_low")` and `sig.get("zone_high")`.
- **D-09:** Historical backfill: run a standalone idempotent SQL script (no JOIN to other tables needed for the `entry_zone_low/high` backfill — it joins `signal_ledger` to `intelligence_features` JSONB on `(symbol, feature_ts, feature_tf)`).
- **D-10:** Backfill script is batched (10k rows per batch) to avoid lock contention on the hypertable.
- **D-11:** Backfill script generates a reconciliation report: rows matched, rows unmatched (signal_ids with no corresponding intelligence_features row), NULL count before and after. Review and sign off before proceeding to Fix 3.
- **D-12:** Backfill is a separate step after the writer fix is deployed and verified in prod (new signals have zone fields populated). DDL (schema) is separate from DML (backfill). Migration file contains schema-only changes.

### Fix 3: expires_at + TTL Unification
- **D-13:** `expires_at` is written at signal creation in `signal_writer_agent.py`, computed as `signal_ts + ttl_bars * tf_to_seconds(tf)`. Not a generated column.
- **D-14:** `tf_to_seconds(tf: str) -> int` extracted as a shared utility in `src/core/service_utils.py`. All callers import from there — one implementation.
- **D-15:** `expires_at` backfill is self-contained within `signal_ledger` (no JOIN needed): `UPDATE signal_ledger SET expires_at = timestamp + (ttl_bars * tf_to_seconds_expr(feature_tf)) * interval '1 second' WHERE expires_at IS NULL`. Run, verify zero NULLs, then deploy evaluator changes.
- **D-16:** `lifecycle_tracker.py` and `signal_tracker_compute_agent.py` switch to `expires_at` in a single atomic deployment — not split across separate deploys. Zero window where the two evaluators disagree on TTL model.
- **D-17:** No NULL fallback in evaluators post-backfill. A NULL `expires_at` after deployment is a data integrity bug — surface it immediately.

### Fix 4: Replay Auditor Canary
- **D-18:** Remove LATERAL JOIN from `signal_replay_auditor_agent.py` after Fix 2 and Fix 3 are confirmed complete. Auditor reads `entry_zone_low`/`entry_zone_high` directly from `signal_ledger` columns.
- **D-19:** No NULL fallback for zone fields. NULL zones post-backfill = error metric increment + DLQ the signal. No silent fallback to `entry_price`.
- **D-20:** Expose `REPLAY_BATCH_SIZE` and `REPLAY_INTERVAL_SECONDS` in `src/config/settings.py`. Revert to canary-appropriate defaults on Fix 4 deploy (e.g., `REPLAY_BATCH_SIZE=100`, `REPLAY_INTERVAL_SECONDS=300`). Emergency triage values (2000/30s) stay until Fix 4 ships.

### Execution Order
- **D-21:** Fix 1 → verify → Fix 2 (writer + migration) → verify → zone backfill script → reconciliation sign-off → Fix 3 (expires_at backfill verified → both evaluators atomic deploy) → Fix 4. No parallelism across fixes.

</decisions>

## Existing Code Insights

### Reusable Assets
- `_publish_ttl_expired_transition_sync` in `signal_tracker_compute_agent.py` — already exists, Fix 1 just removes the `is_backfill` guard that gates it
- `service_utils.py` — home for new `tf_to_seconds()` utility; existing pattern established by `format_iso_ts()`, `min_bars_for_tf()`, etc.
- `signal_ledger_repository.py` — `SignalLedgerRecord` dataclass already has `entry_zone_low`/`entry_zone_high` fields (lines 82-83); just needs the writer to pass correct values

### Established Patterns
- **DDL separate from DML:** migrations contain schema-only changes; backfill scripts are separate idempotent files
- **Settings for operational params:** all agent operational parameters (batch sizes, intervals) in `src/config/settings.py`
- **Reconciliation reports:** pattern established in previous backfill work — count rows before/after, log unmatched IDs
- **Error metric + DLQ:** `BaseWriterAgent` DLQ pattern for unprocessable payloads; apply same pattern in replay auditor for NULL zone signals

### Integration Points
- Fix 3 touches both `lifecycle_tracker.py` and `signal_tracker_compute_agent.py` — must deploy together
- `tf_to_seconds()` utility must be consistent with values used in `_publish_ttl_expired_transition_sync` (currently inline at `signal_tracker_compute_agent.py:466`)
- `signal_writer_agent.py` zone field fix must be verified before backfill script runs (otherwise new signals written during backfill window would still be NULL)

## Specific Ideas

- **Jim Simons standard applied throughout:** atomic deployments, scientific method (one change → one measurement → confirm), no silent fallbacks, no dual code paths in production, operational parameters in config
- **Backfill reconciliation report** must be reviewed and signed off before Fix 3 begins — it is the safety gate, not a formality
- `expires_at` backfill is simpler than zone backfill (self-contained within signal_ledger, no JOIN) and should run fast even on 958k rows
