## Summary

This phase correctly implements wall-clock TTL evaluation via `expires_at`, removes the `is_backfill` guard from TTL checks, fixes zone field key mapping (`zone_low`/`zone_high`), and adds `tf_to_seconds()`. The core signal lifecycle logic is sound. One BLOCKER was found: `_publish_bootstrap_failed_event` uses the wrong Kafka publish kwarg (`value=` instead of `msg=`), causing silent publish failure which suppresses a health alert on the most dangerous startup failure path. Four additional warnings cover correctness edge cases in replay and tracker logic.

## Critical Issues

### CR-01: Wrong kwarg to `KafkaProducerClient.publish()` silently drops bootstrap-failed health event

**File:** `services/signal_tracker_compute_agent.py:1000`

**Issue:** `_publish_bootstrap_failed_event` calls `self._producer.publish(..., value=payload)`. Per CLAUDE.md: "KafkaProducerClient.publish() kwarg is `msg=` — not `value=`. Wrong kwarg silently fails at flush." This means the bootstrap-failed health event is never actually published. The worst-case startup failure (DB returned 0 signals after retries, ledger has rows) produces no Kafka alert, defeating the health monitoring purpose of the call.

**Fix:**
```python
await self._producer.publish(
    topic_health_events(self.env_name),
    msg=payload,               # was: value=payload
    key=message_key("signal_tracker_compute"),
)
```

## Warnings

### WR-01: `_build_signal_dict` return type annotation declares `dict` but returns `None`

**File:** `services/signal_replay_auditor_agent.py:209`

**Issue:** `_build_signal_dict` is annotated `-> dict[str, Any]` but returns `None` when zone fields are missing (line 226). The caller at line 172 checks `if signal_dict is None: return False`, which works at runtime, but the type annotation is incorrect and will cause mypy/pyright to flag every call site as a type error. More importantly, this is a `None` being returned from a non-Optional annotated function, which is a latent correctness hazard if any future caller skips the None check.

**Fix:** Change the return type annotation to `dict[str, Any] | None`.

### WR-02: `_evaluate_zone_track` drops bars_elapsed increment on terminal transition

**File:** `services/signal_replay_auditor_agent.py:307-311`

**Issue:** When a terminal transition is detected (line 307), the function immediately returns without executing the `bars_elapsed += 1` at line 313. This means `bars_elapsed` is one short on the exiting bar. For the live tracker this doesn't matter (bars_elapsed is not passed to the Transition), but in replay the `bars_elapsed` value fed into `bars_to_activation` on the immediately-preceding activation transition can be off by one. It also means the TTL check on the last bar uses the count from the previous bar, which is generally harmless but inconsistent with the live tracker.

**Fix:** Increment `bars_elapsed` before the terminal return, or document explicitly that the exiting bar is not counted.

### WR-03: `_ingest_signal` fast-path publishes TTL-expired transition without `expires_at` data-integrity path

**File:** `services/signal_tracker_compute_agent.py:427-436`

**Issue:** When a signal's `expires_at` has elapsed at ingest time, `_ingest_signal` fires `_publish_ttl_expired_transition_sync` and returns early. However, `_load_signal` (line 331-355) does not copy `expires_at` from the raw dict into the canonical dict — there is no `"expires_at"` key in the canonical dict built by `_load_signal`. This means `canonical.get("expires_at")` at line 411 will always be `None` for signals coming through `_ingest_i7_payload` (Kafka path), because the I7 signal payload does not include `expires_at` (it is computed by `signal_writer_agent`). The fast-path at line 427 can therefore never fire for live Kafka signals — only for bootstrap DB signals where the raw dict already has the field. This is not a crash, but the fast-path is effectively dead for the consumer path it was designed to handle.

**Fix:** Add `expires_at` to the canonical dict in `_load_signal`, parsing it via `parse_iso_ts` if present:
```python
"expires_at": parse_iso_ts(raw.get("expires_at")) if raw.get("expires_at") else None,
```

### WR-04: `asyncio.get_event_loop()` deprecated in Python 3.10+ — may warn or fail

**File:** `services/signal_tracker_compute_agent.py:511`

**Issue:** `_publish_ttl_expired_transition_sync` calls `asyncio.get_event_loop()` to check if a loop is running. In Python 3.10+ this emits a `DeprecationWarning` when called without a running event loop (exactly the edge case it is trying to detect). In Python 3.12 it raises `RuntimeError` in that case. The try/except around it catches `RuntimeError`, so the Python 3.12 case is handled, but the deprecation warning will spam logs on 3.10/3.11 during startup. The correct approach is `asyncio.get_running_loop()` inside a try/except `RuntimeError`.

**Fix:**
```python
try:
    loop = asyncio.get_running_loop()
    loop.create_task(self._publish_transition(lt))
except RuntimeError:
    pass  # No running event loop — startup edge case
```
Note: replace `asyncio.ensure_future` with `loop.create_task` which is the modern equivalent.

## Info

### IN-01: `_count_unresolved` connection leak risk — result consumed outside `async with` block

**File:** `services/signal_replay_auditor_agent.py:129-142`

**Issue:** `_count_unresolved` closes the `async with self._pool.acquire()` block at line 141 (the `return int(cnt or 0)` is inside it in this case) — upon inspection, the `return` is inside the `async with` block (the indentation is correct), so there is no actual leak. However, this is worth verifying carefully: the `return` at line 142 is at the same indentation as `async with`, which means it executes *after* the context manager exits. This is correct, but the close proximity of the `return` outside the block is a readability hazard for future editors. No bug here, flagging for clarity.

**Fix:** Add an inline comment `# conn released here` or restructure to make the intent unambiguous.

### IN-02: Magic number `1.0` for `point_value` in replay has no constant

**File:** `services/signal_replay_auditor_agent.py:240`

**Issue:** `"point_value": 1.0  # replay assumes single-contract base` is a magic number. If this assumption ever changes, the comment is easy to miss. The live tracker uses `get_point_value(symbol)`. The comment explains why, but a named constant (e.g., `_REPLAY_DEFAULT_POINT_VALUE = 1.0`) would make intent clearer and be easier to find when debugging P&L discrepancies between live and replay.

**Fix:** Define `_REPLAY_DEFAULT_POINT_VALUE = 1.0` at module level with a docstring, and reference it here.
