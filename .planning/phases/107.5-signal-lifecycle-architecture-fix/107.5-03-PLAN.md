<objective>
Write and run an idempotent batched backfill script that populates `entry_zone_low` and `entry_zone_high` in `signal_ledger` for historical signals by joining to `intelligence_features.trading_signals` JSONB.

Purpose: The writer fix in Plan 02 populates zone fields for new signals only. The 958k existing signals have NULLs. This plan repairs historical data. The reconciliation report produced at the end is the safety gate — it must be reviewed and signed off before Fix 3 (expires_at) begins.

Output: `production/scripts/backfill_zone_fields.py` — a standalone script that joins `signal_ledger` to `intelligence_features` JSONB, updates in 10k-row batches, and prints a reconciliation report.
</objective>

  <action>
    Create `production/scripts/backfill_zone_fields.py` as a standalone async script using asyncpg directly (same DATABASE_URL pattern as other scripts in production/scripts/).

    Script structure:

    1. RECONCILIATION BEFORE: Run these two queries and print results:
       a. Count of signal_ledger rows where entry_zone_low IS NULL
       b. Count of signal_ledger rows total

    2. BACKFILL LOOP (10k rows per batch, idempotent):
       UPDATE signal_ledger sl
       SET
           entry_zone_low  = (tf_sig.value->>'zone_low')::numeric,
           entry_zone_high = (tf_sig.value->>'zone_high')::numeric
       FROM intelligence_features f,
            jsonb_array_elements(f.trading_signals) AS tf_sig(value)
       WHERE sl.symbol     = f.symbol
         AND sl.feature_ts = f.ts
         AND sl.feature_tf = f.tf
         AND tf_sig.value->>'signal_id' = sl.signal_id::text
         AND sl.entry_zone_low IS NULL
         AND sl.signal_id IN (
             SELECT signal_id FROM signal_ledger
             WHERE entry_zone_low IS NULL
             ORDER BY timestamp ASC
             LIMIT 10000
         )

       Loop until rows_affected == 0. Print batch count and cumulative updates after each batch. Sleep 100ms between batches to avoid lock contention.

    3. UNMATCHED COUNT: After loop completes, count signal_ids where entry_zone_low IS STILL NULL (signals with no matching intelligence_features row). Print this as "unmatched signals — no intelligence_features row found".

    4. RECONCILIATION AFTER: Repeat the before-query and print NULL count after.

    5. Print final report:
       === ZONE FIELD BACKFILL COMPLETE ===
       Before: {before_null_count} NULL zone rows (of {total} total)
       Updated: {total_updated} rows in {batch_count} batches
       Unmatched: {unmatched} signals (no intelligence_features row)
       After: {after_null_count} NULL zone rows remaining

    Use DATABASE_URL from environment (os.environ["DATABASE_URL"] or default "postgresql://postgres:postgres@localhost:5432/indicagent"). Use asyncpg.connect (not create_pool — single connection for a batch script is fine). Use PGPASSWORD=postgres pattern for manual verification.

    The script must be idempotent: WHERE entry_zone_low IS NULL means re-running it produces zero updates.

    Do NOT use transaction wrapping for the batch loop — each batch commits independently to avoid 10k-row lock hold times.
  </action>
