<objective>
Amend the EXISTING feature_registry state machine to route feature lifecycle transitions — not build a
parallel one. Three amendments per LIFECYCLE-01: (1) automated ic_demotion targets shadow_only, never
deprecated (deprecated becomes operator-only) — demotion itself stays the single-run materiality gate
ROADMAP already specifies (weight x |ic_ci_lower| > alpha.decay.materiality_threshold), no consecutive-fail
counter invented on top of it; (2) add the missing shadow_only -> active promotion, gated purely on
evidence (>= alpha.decay.recovery_min_passes consecutive passing corpus runs AND >= alpha.decay.recovery_min_observations
new independent observations since demotion, both APR-sourced, NO calendar cooldown — Fable's
reconciliation rejected cooldowns); (3) add pre_shadow_weight and a shadow-run pass counter as REGISTRY
columns. Provide the synchronous record_transition_sync method ic_engine's post-run hook (Plan 03) will
call — the existing async record_transition() cannot run in ic_engine's psycopg2/no-event-loop context.
Drop the three dead decay columns on feature_ic_scores (D3).

Purpose: Give Plan 03's hook a correct, blocking, transactional write path into the one authoritative
state machine, and encode the evidence-only recovery bar so recovered features re-earn their weight the
same way everything else in this codebase does.

Output: 2 migrations, new sync methods + eligibility predicate on FeatureRegistryService, extended unit
tests (TestRecordTransitionSync).

Do NOT: add is_decaying/decay-style columns to feature_ic_scores (regression to the superseded design);
add a feature_deprecations table; add a feature_transition_log.note column (intel-14 embellishment, not
in ROADMAP's locked LIFECYCLE-01 — flag as a future idea if worth capturing, do not build); add a
calendar/cooldown clock to promotion. Do NOT touch the existing async record_transition() /
_write_transition_record() — leave the async path as-is (its fire-and-forget task-loss risk is a real
bug worth a separate todo, but out of scope here).
</objective>
