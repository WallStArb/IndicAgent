Purpose: The design doc identified 3 plugins with supports_incremental=True but compute_next just calls compute_full (no genuine incremental optimization). This is misleading -- executor expects _state returns and invokes incremental path, but plugins gain no performance benefit. Setting the flag correctly removes them from incremental validation and clarifies actual capability.

Output: 3 plugins have supports_incremental=False. Conformance test validates that supports_incremental=True plugins have genuine incremental logic (non-delegation compute_next).
