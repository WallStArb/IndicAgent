<threat_model>
**Threat:** Allocation-shaving changes touching the hot path could silently alter data shape (e.g., dropping fields, swapping None vs missing key) and break downstream plugins/consumers.

- **PERF-02 (flat features dual-write removal):** Some plugin may still read from `frames["features"]` instead of the tiered dict. Mitigation: grep every plugin file for `frames["features"]` and `frames.get("features")` reads BEFORE deletion; if any consumer exists, do NOT delete — document the necessity (this is what PERF-02 explicitly allows).
- **PERF-05 (pre-filtered tier dicts):** Changing the construction site from comprehension to pre-filter must preserve the exact key set in the resulting IntelligenceEvent fields. Mitigation: acceptance test compares event-field key sets before/after on a sample bar.
- **PERF-08 (model_construct):** Skips Pydantic validation; if upstream producers send malformed messages, they'll now propagate further. Mitigation: confirm Phase 086 DLQ wiring catches invalid payloads at the message-parse boundary (it does — `_parse_payload` in BaseWriterAgent). Trusted internal producer assumption is consistent with PERF-08 acceptance criteria.
- **PERF-09 (gap flag as parameter):** Removing `model_copy` means the BarMessage instance no longer carries `gap_preceding`. Any downstream code that reads `bar.gap_preceding` directly must instead receive the gap flag explicitly. Mitigation: grep for `gap_preceding` reads in the pipeline tree and thread the parameter through.
- **No new endpoints, no auth surface, no DB writes.**
</threat_model>

<objective>
Eliminate per-bar allocation overhead identified in PERF-01/02/05/08/09 by operating on the clean post-Plan-01 structure. The wins are individually small (microseconds) but cumulative — measured via the per-bar latency gauge `intelligence_pipeline_pipeline_latency_ms` (D-13).

Purpose: Per-bar latency budget is the Renaissance bottleneck — every microsecond saved here is a microsecond available for new compute. After this plan, no allocation in the hot path is structurally avoidable.

Output: Single `_build_features_from_event` call site per bar (PERF-01); deleted or justified flat features path (PERF-02); pre-filtered tier dicts replacing comprehensions (PERF-05); `BarMessage.model_construct` on trusted path (PERF-08); gap flag threaded as parameter (PERF-09).
</objective>
