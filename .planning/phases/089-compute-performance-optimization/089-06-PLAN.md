<threat_model>
**Threat:** Per-key concurrent dispatch is the highest-leverage and highest-risk change in this phase. Concurrency bugs here cause subtle signal corruption that is undetectable without metric drift.

- **Cross-key state contamination:** Already mitigated by Plan 04 (PERF-03) — plugin state is per-call parameter, never shared via plugin instance. This plan PRESUMES Plan 04 is in place; without it, this plan would corrupt signals.
- **Within-key ordering:** Bars for ES:1m MUST be processed in arrival order (gap detection depends on sequence). Mitigation: per-key worker uses a single asyncio.Task consuming from a per-key asyncio.Queue — FIFO guaranteed.
- **Per-key queue back-pressure:** If one key's worker stalls (e.g., DB write hang during journal), its queue fills. Acceptable behavior: block the producer (the consume loop) for that key only — other keys continue. Mitigation: use bounded `asyncio.Queue(maxsize=N)`; producer awaits `put()` (blocking).
- **Worker leak on shutdown:** Per-key tasks must be cancelled and awaited on agent teardown. Mitigation: `PerKeyWorkerManager.stop()` cancels all tasks and `await asyncio.gather(*, return_exceptions=True)` to drain.
- **Symbol filter (D-28):** If filter is non-empty, only listed symbols get workers; bars for other symbols arriving on the topic must be dropped silently (this is the shard's "not my key" path). Mitigation: filter check is the FIRST step in `enqueue()`.
- **Thread pool saturation (D-27):** Per-key dispatch to the same shared thread pool — if all 12 workers (post-Plan 01, no min cap) are busy, asyncio dispatch waits. This is a measurement requirement, not a correctness issue.
- **No new endpoints, no auth, no DB writes.**
</threat_model>

<objective>
Convert the bar processing loop from sequential-per-bar to per-(symbol, tf)-concurrent. Each `(symbol, tf)` key gets a dedicated `asyncio.Queue` and a long-running consumer task. Independent keys run concurrently with no coordination overhead.

Purpose: Renaissance microservices-DAG principle within the process. The bar-processing topology mirrors the service DAG topology: each `(symbol, tf)` is a node, the orchestrator is a router. ES:1m never blocks NQ:5m.

Output: New `PerKeyWorkerManager` class (per Claude's discretion in CONTEXT.md — prefer new class if >50 lines); orchestrator's consume loop fans bars out to per-key queues; per-key workers call back into `_process_bar_inner`; symbol_filter (D-28) controls which keys get workers in this process.
</objective>

    ```
    class PerKeyWorkerManager:
        def __init__(
            self,

            symbol_filter: frozenset[str] | None = None,                 # D-28: which symbols to own

            self._tasks: dict[tuple[str, str], asyncio.Task] = {}
            self._background_tasks: set[asyncio.Task] = set()
            self._stop_event = asyncio.Event()
            self._logger = structlog.get_logger(__name__)
    ```

    Methods:

    1. `async def enqueue(self, bar: BarMessage, gap: bool) -> None`:
       - Apply symbol_filter first: `if self._symbol_filter is not None and bar.symbol not in self._symbol_filter: return` (drop, this shard does not own this symbol — D-28).
       - Key: `key = (bar.symbol, bar.tf)`.
       - If key not in `self._queues`: lazily create queue + worker task via `_spawn_worker(key)`.
       - `await self._queues[key].put((bar, gap))` — blocking on full queue (back-pressure).

    2. `def _spawn_worker(self, key: tuple[str, str]) -> None`:
       - Create `asyncio.Queue(maxsize=self._queue_maxsize)` and store in `self._queues[key]`.
       - Create task `task = asyncio.create_task(self._worker_loop(key), name=f"per_key_worker_{key[0]}_{key[1]}")`.
       - Track: `self._tasks[key] = task` AND `self._background_tasks.add(task); task.add_done_callback(self._background_tasks.discard)` (lifecycle pattern from critical_research_findings #5).

    3. `async def _worker_loop(self, key: tuple[str, str]) -> None`:
       ```
       queue = self._queues[key]
       while not self._stop_event.is_set():
           try:
               bar, gap = await asyncio.wait_for(queue.get(), timeout=1.0)
           except asyncio.TimeoutError:
               continue
           try:
               await self._processor(bar, gap)
           except Exception as exc:
               self._logger.error("per_key_worker_error", key=key, error=str(exc), exc_info=True)
           finally:
               queue.task_done()
       ```

    4. `def start_per_key_workers(self) -> None` (D-16):
       - For empty queues dict, this is a no-op — workers are spawned lazily on first `enqueue` for that key. The method exists to mirror `CacheManager.start_refresh_loops()` symmetry; document this in a docstring.

    5. `async def stop(self) -> None`:
       - `self._stop_event.set()`.
       - Cancel all tasks: `for task in self._tasks.values(): task.cancel()`.
       - `await asyncio.gather(*self._tasks.values(), return_exceptions=True)`.
