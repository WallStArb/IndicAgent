<threat_model>
**Threat:** Algorithmic conversion from full-recompute to incremental can introduce numerical drift or session-boundary bugs that silently corrupt the i3 structure features.

- **MarketProfile (D-07): incremental volume bucket update** — POC/VAH/VAL must match the full-recompute reference on every bar. Mitigation: parity test that runs `compute_full(bars[:N])` and compares to N successive `compute_next(bars[i])` calls; assert POC/VAH/VAL equality (tolerance for floating-point).
- **SessionLevels (D-07): rolling session high/low + session boundary detection** — rolling-update logic must correctly reset state at session boundaries (US RTH vs ETH transitions). Mitigation: parity test crosses a session boundary in the fixture.
- **BOCPD / HMM (D-06): incremental path empirical confirmation** — these are `supports_incremental=True` already; PERF-03 fix should have made the incremental path fire. The risk is misdiagnosis — if profiling shows p95 still high, the cause may be the algorithm itself, not the state race. Mitigation: profile FIRST; only modify the algorithm if profile confirms incremental is the path and it's still slow. If statistically bounded, DOCUMENT the bound; do not force O(1).
- **Plugins MovingAverages / Stochastic / ACOscillator / BollingerBands / WilliamsR**: confirmation-only — assert `supports_incremental=True` and that `compute_next` is being called after PERF-03 fix.
- **No new endpoints, no auth, no DB writes.**
</threat_model>

<objective>
Convert plugins identified by OBS-01 (D-05, 12 plugins with p95 > 20ms) to incremental compute where an algorithm exists, OR verify+document the incremental status after PERF-03 fix, OR document the algorithmic bound (HMM/BOCPD).

Purpose: O(N) full-recompute on every bar is the dominant cost in i3 structure plugins. Incremental compute drops per-bar work from O(N) to O(1) where the math admits.

Output: MarketProfile + SessionLevels gain `compute_next()` and `supports_incremental=True`; HMM/BOCPD/Stochastic/BB profiled to confirm incremental fires post-PERF-03; SUMMARY contains the full 12-plugin before/after table.

This plan runs strictly AFTER Plan 04 (PERF-03) — the incremental path cannot be benchmarked correctly without the state-threading fix in place.
</objective>

      - State shape: `state["volume_buckets"]: dict[float, float]` mapping bucket-price → cumulative volume. Bucket size = `self.tick_size * self.ticks_per_bucket` (existing config).
      - State shape: `state["session_id"]: str` — current session identifier; on session change, reset buckets.
      - State shape: `state["bar_count"]: int` — used to assert deterministic resume.

    `compute_next(self, windows, *, state):`
      1. If `state` is empty or `state["session_id"]` differs from current bar's session → reset state (call existing session-reset helper or initialize dict).
      2. For the current bar's price range (low → high at bucket size), increment `state["volume_buckets"][bucket]` by the bar's volume (TPO method: distribute equally OR weighted — match the algorithm used by `compute_full`).
      3. Recompute POC (highest-volume bucket), VAH (upper edge of 70% volume area), VAL (lower edge) from `state["volume_buckets"]` — this is O(K) where K = number of buckets in session, NOT O(N) where N = bar count.
      4. Return the same output dict shape as `compute_full`.
      5. Update `state["bar_count"] += 1`.

      - Run `compute_next(bars[i], state=state)` for i in 0..99 with a fresh `state = {}`.
      - Assert: final POC matches reference (exact), VAH/VAL match within bucket-size tolerance.
  </action>
