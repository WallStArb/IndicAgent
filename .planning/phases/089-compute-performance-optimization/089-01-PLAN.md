<threat_model>
**Threat:** Architectural refactor of hot path could introduce silent state-loss or cross-key contamination.

- **Carry-forward state migration (`_prev_i1_features`, `_last_events`):** Currently mutated inside orchestrator's `_run_i1_to_i6`. After extraction these become FPE-owned dicts. Risk: forgetting to migrate the writes leaves stale empty dicts and silently breaks I1 prev-features inputs. Mitigation: acceptance criteria require the orchestrator dict initializations to be DELETED, and FPE to contain identical write sites.
- **Stream cache migration (D-19):** The `_process_loop` writes to `_cross_asset_cache`/`_macro_cache`/`_htf_intel_cache` on every upstream message. If the new CacheManager methods do not perform identical writes, downstream FPE reads return stale/empty data and IntelligenceEvent silently loses fields. Mitigation: write sites in `_process_loop` must call `cache_mgr.update_*` with the same payload shape; acceptance criteria assert orchestrator no longer assigns to these dicts.
- **CacheSnapshot constructor (signal_processor.py):** Adding fields with non-default values would break the existing call site (lines 538-545). Mitigation: new fields default to empty dict / None; one call site updated to pass them explicitly.
- **Alpha decay ownership move (D-21):** If both orchestrator AND SignalProcessor apply alpha decay, signals would be decayed twice. Mitigation: orchestrator's call at line 532 must be deleted; SignalProcessor applies it exactly once at top of `process()`.
- **No new network endpoints, no new auth surface, no new DB writes — pure in-process refactor.**
</threat_model>

Purpose: Renaissance design principle — the orchestrator is a router, every computation lives in a named DAG node. Plans 02-06 build on this clean structure.

Output: `feature_pipeline_executor.py` (new file), `run_i7_complete()` method, 3 CacheManager stream methods, CacheSnapshot extension, 5 OTel counters, deleted dead code, Settings additions.
</objective>
