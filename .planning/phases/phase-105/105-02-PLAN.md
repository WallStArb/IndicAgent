<objective>
Eliminate three correctness bugs in writer services (HF-4, HF-5, HF-7): FeatureWriterAgent ghost-run
on DB failure (highest data-loss rate in the system, ~160 rows/min), BarWriterAgent stall-watchdog
blindness, and SwarmLedgerWriterAgent committing Kafka offsets before the DB write succeeds.

Purpose: Make writer failures loud and recoverable instead of silent. Fail-fast lets systemd restart;
stall detection lets service_auditor see a dead bar_writer; deferred commit lets failed swarm writes
re-deliver safely.

Output: All three files corrected, existing unit tests green.
</objective>

<threat_model>
Risk vectors for this bug-fix plan:
- **Crash loop (HF-4):** Raising on DB connect makes the service exit. Acceptable: systemd
  Restart=on-failure provides backoff. The alternative (ghost-run) is worse — silent data loss.
  Do NOT add a retry loop here; that is BaseAgent._setup_with_retry territory and out of scope.
- **Missing liveness (HF-7):** If `_record_message_consumed()` is placed before the contract-update
  routing `continue`, contract-update-only traffic would falsely keep the agent "alive". Place it
  AFTER the contract-update routing check so only genuine bar consumption marks liveness.
- **At-least-once duplication (HF-5):** enable_auto_commit=False with no manual commit wiring relies
  on the existing `ON CONFLICT (signal_id)` UPSERT for idempotent re-delivery. Do NOT add manual
  commit plumbing (out of scope per research) and do NOT remove the UPSERT.
</threat_model>
