<objective>
Fix the AttributeError data-loss bugs and stall-watchdog blindness in CtxWriterAgent and
LLMWriterService (HF-2, HF-3, HF-6, HF-10, HF-11). These are silent-failure bugs: flush loops
crash on AttributeError and leave buffers undrained; the llm parse-update path silently drops
every message; the stall watchdog can never fire.

Purpose: Restore guaranteed persistence and stall detection in two writer services so v2.8 work
sits on a trustworthy persistence layer.

Output: Both files corrected, existing unit tests green, no .inc() / self._pool / _last_msg_ts
references remain.
</objective>

<threat_model>
Risk vectors for this bug-fix plan:
- **Double-flush regression (HF-11):** Adding `await super()._teardown()` as the first statement may
  double-flush if BaseWriterAgent._teardown() and the custom flush both drain the same buffers.
  Mitigation: read `src/core/agent/base_writer.py` _teardown() FIRST; the custom `_flush()` below
  super() must be guarded to skip when buffers are already empty (they will be after super flush).
- **Lost-offset regression (HF-10):** Removing dead subscriptions must not change the consumer group
  id or remove the live `calls_topic` subscription. Only `topic_intelligence_i8` and
  `topic_llm_outcomes` and their handler branches are removed.
- **Earliest-replay duplication (HF-10):** auto_offset_reset="earliest" replays on first run; safe
  only because llm_calls upsert is `ON CONFLICT (call_id, called_at) DO NOTHING`. Do not change the
  upsert.
</threat_model>
