Purpose: this is the phase's point, the first evidence under the E15 framework. The owner has
pre-authorized the run; there is no human checkpoint.

Rules that override any instinct to "fix and retry":
- A refusal (fewer than 600 shifts, underpowered at IC 0.002, a guard failure) is a valid,
  recorded outcome. Stop, record it, and do not change any spec or parameter to re-run.
- A spec runs once (D-02). A failed or crashed run cannot be re-run under the same spec; a new
  spec is a new, recorded (and for a book, charged) test, which is the owner's decision. So on
  a `failed` status or a crash: stop, record the row and the error, and report. Do not edit
  specs.
- Only infrastructure knobs that are in no hash may change between attempts to start a run
  that never got a row (for example `--workers` when memory is short): a pre-row refusal
  (exit 2) leaves no row and may be retried after fixing its cause (for example a dirty tree).

Worktree discipline (D-18): work only in `/home/bg/dev/indicagent-183`; every Bash command
starts with `cd /home/bg/dev/indicagent-183 &&`; never read or write `/home/bg/dev/indicagent`.
