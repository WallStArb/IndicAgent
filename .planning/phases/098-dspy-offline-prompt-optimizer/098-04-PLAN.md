Build the auto-promotion runner and A/B comparison report (OPT-04). The comparison report is the measurable-improvement artifact required before promotion.

Purpose: Close the loop — compiled candidates become active only on evidence, with a confound guard against single-regime windows.

    - Module constants: `_PROMO_PARSE_DELTA = 0.02`, `_PROMO_MIN_N = 100`, `_PROMO_MIN_PER_REGIME = 20`, `_AB_WINDOW_DAYS = 7`.
    - `async def _fetch_active_candidates(self) -> list`: SELECT version_id, agent_id, version_tag, created_at FROM prompt_versions WHERE status='candidate' AND created_at <= NOW() - INTERVAL '7 days'. (Candidates younger than 7 days are not yet evaluable; extension is automatic because un-promoted candidates stay 'candidate' and get re-checked next run.)
    - `async def _fetch_active_version_tag(self, agent_id) -> str | None`: SELECT version_tag FROM prompt_versions WHERE agent_id=$1 AND status='active' ORDER BY promoted_at DESC LIMIT 1. If None, the baseline is the un-tagged/default prompt_version string used before any DSPy variant — handle None by treating all non-candidate prompt_version rows in llm_calls as baseline.
    - `async def _fetch_ab_stats(self, agent_id, window_start, candidate_tag, baseline_tag) -> dict`: GROUP BY prompt_version over llm_calls WHERE agent_id=$1 AND called_at >= window_start; compute per version: n_calls=COUNT(*), parse_success_rate=AVG(parse_success::int), win_rate=AVG(CASE WHEN win IS NOT NULL THEN win::int END), and regime counts via `COUNT(*) FILTER (WHERE regime = '0')`, `... regime = '1'`, `... regime = '2'`. Regime values are the strings '0','1','2' (RESEARCH pitfall 3) — NEVER 'bullish'/'bearish'/'ranging'.
    - `def _promotion_decision(self, candidate_stats: dict, baseline_parse_rate: float) -> tuple[bool, str]`: pure function (no I/O, unit-testable). Returns (promote, reason). promote=True only if ALL: candidate parse_success_rate > baseline_parse_rate + _PROMO_PARSE_DELTA; candidate n_calls >= _PROMO_MIN_N; each of n_ranging/n_trending_up/n_trending_down (the '0'/'1'/'2' counts) >= _PROMO_MIN_PER_REGIME. The reason string names the first failing criterion (e.g. "regime_balance_unmet", "insufficient_n", "no_parse_improvement") or "promote".
    - `async def _promote(self, candidate_version_id, agent_id) -> None`: in a single transaction, `UPDATE prompt_versions SET status='retired' WHERE agent_id=$1 AND status='active'` then `UPDATE prompt_versions SET status='active', promoted_at=NOW() WHERE version_id=$2`.
    - `async def _check_promotion(self) -> list[dict]`: for each candidate from _fetch_active_candidates, resolve baseline_tag, fetch A/B stats, compute baseline parse rate, call _promotion_decision; if promote -> _promote + log `dspy_optimizer.promoted` (agent_id, version_tag); else log `dspy_optimizer.promotion_deferred` (agent_id, version_tag, reason). Collect per-agent comparison dicts (parse_success baseline vs candidate, win_rate delta, regime breakdown, n per version, decision).
    - `def _write_report(self, report: dict) -> None`: write `logs/dspy_optimizer_report_{datetime.now(UTC):%Y%m%d}.json` atomically (tmp + replace) per the ml_trainer _write_report style.
    - Wire `_run_optimization` (Plan 02) to call `report = await self._check_promotion()` after the compile loop, then `self._write_report(report)` and emit a structlog summary `dspy_optimizer.run_summary`. The promotion pass must run even when zero agents were eligible for compilation this week (candidates from prior weeks still need evaluation) — but the data-gate skip-all early return in Plan 02 short-circuits before compilation; restructure so promotion runs before the skip-all return, OR move the skip emission to only gate the compile loop while still running _check_promotion. Choose the latter: compile is gated, promotion always runs.
