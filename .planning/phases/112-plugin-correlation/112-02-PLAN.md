<objective>
Build the weekly oneshot batch that measures plugin redundancy and auto-suppresses redundant plugins, plus its systemd timer.

Purpose: This is the analytical core of the phase. It scans 90 days of signal_ledger, builds a plugin direction matrix, computes pairwise directional_r and the effective independent plugin count via participation ratio, writes both result tables, and flips correlation_suppressed on inferior plugins that meet all three gates. Suppression is self-expiring through data starvation — no manual re-activation.
Output: `production/scripts/plugin_correlation_batch.py` plus the service + timer units, following roll_batch.py exactly.
</objective>

    PURE FUNCTIONS (no DB, no I/O — independently testable):
    1. `build_direction_matrix(rows) -> tuple[np.ndarray, list[str]]`:
       - Group rows by `(feature_ts, symbol, timeframe)` (the bar key). Each group is one "bar event".
       - Columns = sorted unique setup_plugin names. Rows = bar events.
       - Cell value = the plugin's `direction` (integer +1/-1) for that bar, else 0 (Pitfall 5: absence of a row means did-not-fire = 0; initialize matrix to zeros, overwrite from rows where direction != 0).
       - Return (matrix [n_bars x n_plugins], plugin_names list).
    2. `compute_pairs(matrix, plugin_names, min_co_fire=30) -> list[tuple]`:
       - For each plugin pair (i<j by name): `dir_a`, `dir_b` are the columns.
       - `co_fire_count = int(((dir_a != 0) & (dir_b != 0)).sum())` (Pitfall 7: bar-level joint events via vectorized masks, not per-plugin grouped counts).
       - `agree_count = int(((dir_a == dir_b) & (dir_a != 0)).sum())`.
       - `directional_r = agree_count / co_fire_count` if co_fire_count > 0 else 0.0 (D-05).
       - Enforce canonical ordering `(a, b) = (min, max)` by name BEFORE appending (Pitfall 8 — code must enforce, CHECK is backstop).
       - Skip pairs with `co_fire_count < min_co_fire` (D-04: 30) — not written to DB.
       - Return list of `(plugin_a, plugin_b, directional_r, co_fire_count)`.
    3. `compute_effective_n(pairs, plugin_names) -> float`:
       - Build symmetric correlation matrix: `np.eye(n)`, fill `[i,j]=[j,i]=directional_r` for each pair.
       - `eigenvalues = scipy.linalg.eigvalsh(corr_matrix)` (symmetric — use eigvalsh not eig).
       - Clip: `eigenvalues = eigenvalues[eigenvalues > 1e-10]` (Pitfall 6: float-error negatives break the formula).
       - `total = eigenvalues.sum()`; `effective_n = 1.0 / ((eigenvalues / total) ** 2).sum()` (D-07 participation ratio).
       - Return float.
    4. `select_suppressions(pairs, ci_by_name) -> tuple[set[str], int]`:
       - `redundant_pairs` = count of pairs with `directional_r >= 0.80` (the redundancy metric for the gauge).
       - For each pair meeting ALL THREE gates (D-08): (1) `directional_r >= 0.80`, (2) `co_fire_count >= 100`, (3) one plugin has strictly lower performance — suppress the inferior plugin.
       - Performance source (RESEARCH correction): use `shadow_registry.last_eval_ci_lower` from `ci_by_name`. If both values are valid (not None, not float('-inf')): suppress the one with the strictly lower value; if tied, suppress neither. If both are -inf/None, fall back to `last_eval_ev_r` comparison (pass ev_r in ci_by_name too, or a second dict); if that is also tied/missing, skip suppression for that pair (require valid data — never guess).
       - Return (set of plugin names to suppress, redundant_pairs count).

    ASYNC DB FUNCTIONS (receive asyncpg.Connection):
    5. `fetch_signals(conn) -> list[dict]`: 90-day scan.
       ```sql
       SELECT setup_plugin, feature_ts, symbol, timeframe, direction
       FROM signal_ledger
       WHERE timestamp >= NOW() - INTERVAL '90 days'
         AND signal_schema_version >= 'v1'
         AND direction != 0
       ```

    7. `write_pairs(conn, pairs, computed_at, dry_run)`: UPSERT via `executemany` ON CONFLICT (plugin_a, plugin_b) DO UPDATE SET directional_r, co_fire_count, computed_at = EXCLUDED.* (latest snapshot only, D-11).
    8. `write_summary(conn, computed_at, effective_n, redundant_pairs, dry_run)`: plain INSERT into plugin_correlation_summary (history, D-12).
    9. `apply_suppressions(conn, to_suppress, dry_run)`:
       - Set: `UPDATE shadow_registry SET correlation_suppressed = true WHERE component_name = ANY($1)` for the to_suppress set.
       - Clear stale (D-09 self-expiry): `UPDATE shadow_registry SET correlation_suppressed = false WHERE correlation_suppressed = true AND component_name != ALL($1)` — any plugin currently suppressed but NOT in this run's to_suppress set gets cleared. This is the reversibility mechanism: when co_fire decays below 30 the pair drops from `pairs`, so the plugin is no longer selected, so it gets cleared here.
       - Only touch correlation_suppressed — never is_shadow/promoted_at (D-10 exclusive ownership).
