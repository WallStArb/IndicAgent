    1. CREATE TABLE plugin_correlation_pairs:
       - `plugin_a text NOT NULL`
       - `plugin_b text NOT NULL`
       - `directional_r double precision NOT NULL` (agreement rate agree/co_fire, range [0,1] — drives the suppression gate, D-05)
       - `signed_r double precision NOT NULL DEFAULT 0.0` (signed correlation (agree - disagree)/co_fire, range [-1,1] — drives effective-N eigenvalue computation per Codex HIGH #3; DEFAULT 0.0 so the column is back-fill-safe and the batch always writes a real value)
       - `co_fire_count integer NOT NULL`
       - `computed_at timestamptz NOT NULL`
       - `PRIMARY KEY (plugin_a, plugin_b)` (enables UPSERT — latest snapshot only, D-11)
       - `CHECK (plugin_a < plugin_b)` (canonical ordering, prevents duplicate pairs, D-06/D-11)
       Use `CREATE TABLE IF NOT EXISTS` for idempotency. Immediately AFTER the CREATE, also emit `ALTER TABLE plugin_correlation_pairs ADD COLUMN IF NOT EXISTS signed_r double precision NOT NULL DEFAULT 0.0;` so a re-run against an older table (created before signed_r existed) upgrades it in place.

    2. CREATE TABLE plugin_correlation_summary:
       - `computed_at timestamptz NOT NULL PRIMARY KEY`
       - `effective_n double precision NOT NULL`
       - `redundant_pairs integer NOT NULL`
       This table keeps full history (plain INSERT, one row per weekly run, ~52/year, D-12). Use `CREATE TABLE IF NOT EXISTS`.

    3. ALTER TABLE shadow_registry ADD COLUMN IF NOT EXISTS correlation_suppressed boolean NOT NULL DEFAULT false (D-13). This column is owned exclusively by the correlation batch (D-10).

    4. CREATE OR REPLACE VIEW shadow_registry_active AS SELECT * FROM shadow_registry WHERE NOT is_shadow AND NOT correlation_suppressed.

       CRITICAL: The original spec (D-14) says `WHERE promoted = true AND NOT correlation_suppressed`. This is WRONG — shadow_registry has NO `promoted` column. It has `is_shadow boolean NOT NULL DEFAULT true` (inverted semantics: is_shadow=false means live/promoted). The correct predicate is `WHERE NOT is_shadow AND NOT correlation_suppressed`. Confirmed against live `\d shadow_registry`.

    5. CREATE INDEX IF NOT EXISTS idx_signal_ledger_corr_scan ON signal_ledger (timestamp) WHERE direction != 0 (Codex MEDIUM #5). This partial index supports the batch's 90-day access pattern (`WHERE timestamp >= NOW() - INTERVAL '90 days' AND direction != 0`), which the existing `idx_signal_ledger_symbol_tf (symbol, timeframe, timestamp DESC)` index does not serve well. signal_ledger is a TimescaleDB hypertable — CREATE INDEX on a hypertable transparently creates per-chunk indexes, so this is safe and idempotent with IF NOT EXISTS. Plan 02's EXPLAIN ANALYZE confirms whether this index is actually chosen; if EXPLAIN shows it is NOT used, Plan 02's SUMMARY records that for a possible follow-up drop — but create it here so the batch has it available on first run.

    The VIEW must be the single interface for future suppression types — design the WHERE so additional suppression columns only extend this VIEW, never the consumers.
