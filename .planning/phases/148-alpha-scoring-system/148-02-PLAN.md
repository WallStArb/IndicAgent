<objective>
Build the AlphaScorer (SCORE-01): a BaseBatch weekly oneshot that reads closed primary
alpha_frames, buckets alpha_score into per-cohort deciles, and writes a per-(symbol, tf,
regime, alpha_score_decile) diagnostic table (alpha_strategy_scores) including an
ic_alpha_score_corr monotonicity signal. All statistics are composed from the frozen,
already-tested day-clustered bootstrap machinery; this plan writes zero new statistics.

Purpose: Produces the decile-level signal-quality diagnostic that the promotion decision
record cites. Output: services/alpha_scorer.py plus GREEN unit tests plus a real-data write.
</objective>

<review_revisions>
Revised from cross-AI review (148-REVIEWS.md). Changes traceable to specific findings:
- Consensus Concern 1 ("evaluate_frame_gate group-key reuse is structurally risky" -- Antigravity
  MEDIUM on 148-02's `(symbol, tf, regime, alpha_score_decile)` mapping): the original plan passed
  a 4-TUPLE group_key into evaluate_frame_gate. Verified against the live source
  (services/counterfactual_tracker.py line ~954): the helper unpacks the group key as
  `for (dim_a, dim_b), bucket in groups.items()` -- it ONLY supports a 2-TUPLE. A 4-tuple would
  raise `ValueError: too many values to unpack (expected 2)` -- a hard crash at the call site,
  not a mis-mapping. This plan is corrected to iterate per-(symbol, tf, regime) cohort and call
  evaluate_frame_gate with a 2-tuple group_key `(alpha_score_decile, regime)`, reassembling the
  4-key output grain in Python. A new Task 1 verify-first step forces the executor to confirm
  the 2-tuple round-trip in isolation BEFORE writing the full remap loop.
The output table grain (symbol, tf, regime, alpha_score_decile) is UNCHANGED -- only the internal
call shape to evaluate_frame_gate changed. Waves, dependencies, and scope are unchanged.
</review_revisions>
