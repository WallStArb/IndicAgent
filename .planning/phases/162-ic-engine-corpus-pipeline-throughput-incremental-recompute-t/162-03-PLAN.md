<objective>
Introduce the `ic_cell_fingerprints` table and a per-cell validity check that lets a re-run of the
80-symbol corpus with unchanged inputs skip fingerprint-valid cells entirely (fetch + compute, not
just the final insert) and recompute exactly the invalidated subset. A fingerprint mismatch must
REPLACE stale rows via DELETE-then-insert — the existing `ON CONFLICT DO NOTHING` write path would
otherwise silently discard the recompute and serve stale IC downstream into `ensemble_trainer` ->
`alpha_publisher`. This is the phase's highest-severity data-integrity surface (the 2026-07-12
checkpoint-staleness failure class, recurring cross-run).

The whole-cell fingerprint gate becomes the SOLE skip mechanism: the legacy `existing_keys`
parameter and its four inner per-feature/whole-regime skip sites are removed outright (Codex review
finding, verified against live code). Layering the fingerprint gate on top of a stale pre-delete
`existing_keys` snapshot would let a just-DELETEd invalidated cell be silently skipped inside a
worker, leaving its rows permanently MISSING — a silent *absence* that is worse than the silent
staleness the fingerprint exists to prevent.

Purpose: Close todo 134 core and absorb todo 122 (checkpoint APR drift) as a special case of the
fingerprint. Deliver the throughput win (skip the fetch, not just the write) with defense-in-depth
against silent staleness: code content-key + APR-snapshot key + upstream watermarks + a crash-loud
field-classification test, and against silent absence: the single, structurally-unavoidable skip gate.

Output: Migration 250 (`ic_cell_fingerprints`); an ICEngineConfig computational-vs-operational field
classification with a crash-loud test; per-table upstream watermark functions; a fingerprint
compose + `_fingerprint_is_valid` check wired into `main()` before `worker_args` AND before each
cross-sectional cell call; a DELETE-then-insert invalidation path leaving the 3 INSERT constants
untouched; removal of the `existing_keys` parameter and all 4 inner skip sites; `--refresh` and
`--dry-run-validity` CLI flags; deletion of the `.pkl` checkpoint system.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ic_cell_fingerprints (skip decision) -> feature_ic_scores served downstream | a wrong "skip" serves stale IC into ensemble_trainer -> alpha_publisher — the phase's highest-severity surface |
| feature_ic_scores DELETE (invalidation) | must be scoped to the exact stale cell key only |
| main() fingerprint gate -> compute worker | the ONLY skip decision; workers hold no independent skip state that could diverge from it |

Internal batch service — no HTTP/auth/session/injection surface. ASVS web categories (authentication,
session management, access control, injection) are **N/A**: no attacker-reachable input crosses any
boundary. The entire threat surface here is data-integrity ("silent wrong answers are worse than loud
crashes"), which is this project's analogue of ASVS "fail loud, not silent."
