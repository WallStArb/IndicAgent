<threat_model>
- No auth (per D-10): endpoints are exposed only on the internal API listener. Any operator on the local network can mutate instruments. Acceptable per CONTEXT.md - flagged as v2.7 follow-up.
- Pydantic input validation: prevents malformed JSONB. Reject unknown asset_class values via Literal type.
- Race with concurrent writes: ON CONFLICT (symbol) DO UPDATE in POST means two concurrent POSTs for the same symbol both succeed (last write wins). Acceptable.
- pg_notify already fires via DB trigger (Plan 091-01); explicit notify in route is NOT needed and would risk double-notification.
- DELETE is soft-delete only: hard-deleting an instrument would lose audit history. The trigger still fires on UPDATE (is_active=false) so listeners are notified.
</threat_model>

  <action>
    In `src/api/routes/instruments.py`, add a Pydantic request model `InstrumentUpsert(BaseModel)` with fields matching the Instrument dataclass: `symbol: str`, `base: str`, `name: str = ""`, `asset_class: Literal["equity","futures","fx","crypto"]`, `exchange: str = ""`, `sector: str = ""`, `tick_size: float = 0.0`, `point_value: float = 0.0`, `session_id: str = "futures_24_5"`, `provider_meta: dict = {}`, `expiry: str | None = None`. Add a partial-update model `InstrumentUpdate(BaseModel)` with all fields Optional including `is_active: bool | None = None`.

    Add three endpoints (use the existing `router` instance and existing `Depends(get_db_manager)` pattern):

    1. `@router.post("/instruments", status_code=201)` async `create_instrument(payload: InstrumentUpsert, db = Depends(...))`: executes `INSERT INTO instruments (symbol, base, contract_details, is_active) VALUES ($1, $2, $3::jsonb, true) ON CONFLICT (symbol) DO UPDATE SET contract_details=EXCLUDED.contract_details, is_active=true, updated_at=NOW()`. The contract_details JSONB is `payload.model_dump(exclude={"symbol","base"})` plus `{"symbol": payload.symbol, "base": payload.base}` (asset_class and other fields all live inside contract_details). Returns `{"status":"created","symbol": payload.symbol}`. The DB trigger handles pg_notify - do not call it explicitly.

    2. `@router.put("/instruments/{symbol}")` async `update_instrument(symbol: str, payload: InstrumentUpdate, db = Depends(...))`: builds a dynamic UPDATE based on which fields are set. For `is_active`: `UPDATE instruments SET is_active=$2, updated_at=NOW() WHERE symbol=$1`. For contract_details fields: merge into existing JSONB via `UPDATE instruments SET contract_details = contract_details || $2::jsonb, updated_at=NOW() WHERE symbol=$1` passing only the non-None fields. If symbol doesn't exist: return 404 with detail. Returns `{"status":"updated","symbol": symbol}`.

    3. `@router.delete("/instruments/{symbol}")` async `delete_instrument(symbol: str, db = Depends(...))`: executes `UPDATE instruments SET is_active=false, updated_at=NOW() WHERE symbol=$1`. If 0 rows affected: return 404. Returns `{"status":"deactivated","symbol": symbol}`. This is soft delete (sets is_active=false); the trigger fires NOTIFY so the listener invalidates the cache.

    Use `await db.execute_command(sql, *params)` if that's the existing pattern in `DatabaseManager`, else `await db.execute_query(...)`. Match the existing routes' style for response shape and error handling. Add structured logging on each successful write: `api.instruments.created`, `api.instruments.updated`, `api.instruments.deactivated` with the symbol.
