<threat_model>
- Connection exhaustion: listener holds 1 dedicated connection for its lifetime. Acceptable - one extra connection per pipeline service. Monitor via `pg_stat_activity`.
- Silent listener death: the loop catches all exceptions except `asyncio.CancelledError`. Logs at WARNING level on reconnect so a slow-burn DB outage is observable.
- Callback runs sync on event loop thread: if `_on_instrument_notify` does heavy work it blocks the loop. Mitigation: callback schedules `asyncio.ensure_future` and returns immediately.
- LISTEN payload size: pg_notify max payload is 8000 bytes; we send only the symbol string (~10 bytes). No risk.
</threat_model>
