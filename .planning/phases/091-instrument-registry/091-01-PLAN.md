<threat_model>
- SQL injection in trigger: NONE - trigger reads NEW/OLD row values directly via pg_notify, no string interpolation
- Idempotency: CREATE OR REPLACE FUNCTION + CREATE OR REPLACE TRIGGER means SQL script is safe to re-run; safer than DROP TRIGGER IF EXISTS + CREATE
- Live-DB risk on upsert fix: changing PK column from c.base to c.symbol on next upsert call could re-insert a duplicate USDJPY row keyed at `USD` (the old broken PK). Mitigation: this plan does NOT call upsert on production - it only fixes the function. Plan 091-04's migration script is what actually re-runs upsert, and it explicitly DELETEs/upserts the legacy `USD` row.
- NOTIFY payload leak: payload is the symbol name only (e.g. "EURUSD"). No secrets.
</threat_model>
