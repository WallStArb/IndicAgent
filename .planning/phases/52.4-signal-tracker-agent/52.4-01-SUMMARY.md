# Phase 52.4 Plan 01: SignalTrackerAgent Refactor Summary

Renamed `signal_lifecycle_service.py` / `SignalLifecycleService` to `signal_tracker_agent.py` / `SignalTrackerAgent`, conforming to the Agentic DAG taxonomy. Extracted all direct SQL into `SignalLedgerRepository` methods and delegated all DB writes through the repository — making the agent DB-ignorant in its core processing path. Inherits `BaseAgent` for SIGTERM drain, lag reporting, and metrics.

## What Was Built

**SignalTrackerAgent** (`services/signal_tracker_agent.py`):
- Class name: `SignalTrackerAgent` inheriting `BaseAgent(name="signal_tracker_agent")`
- SIGTERM drain via `_stop_event` (BaseAgent) + `_pending_tasks` drain in `stop()`
- All SQL delegated to `SignalLedgerRepository` — zero direct SQL in agent class
- Log file: `logs/signal_tracker_agent.log`
- `_report_consumer_lag()` overridden to emit pending task count as lag proxy
- Metrics labels: `lifecycle_transitions_total`, `lifecycle_active_signals_count`, etc.

**SignalLedgerRepository enhancements**:
- `update_lifecycle_state()` — canonical transition method
- `update_mae_mfe()` — dedicated MAE/MFE persistence
- `fetch_active_signals(symbol, tf)` — scoped query for agent
- `fetch_pending_signals()` — cross-symbol pending query
- `update_chandelier_state()` — Chandelier trailing stop + staleness
- `update_chandelier_vol_source()` — initial chandelier vol source write
- `update_shadow_outcome()` — post-condition_expired shadow tracking
- `set_shadow_tracking_start()` — shadow mode entry timestamp

**Systemd unit**: `indicagent-signal-tracker.service`
