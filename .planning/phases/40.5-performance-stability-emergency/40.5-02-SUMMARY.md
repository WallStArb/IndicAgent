# Phase 40.5 Plan 02: Thread Pool, ndarray Pre-alloc, Shared Refresh Loop Summary

Three independent Python-only performance fixes: plugin CPU work offloaded to thread pool, calibration curves stored as np.ndarray at load time, and 5 identical refresh loops replaced by a shared helper.

## What Was Built

### PERF-05: Calibration ndarray Pre-alloc (signal_generator_service)

Changed `_load_calibration_curves_from_db()` to store `np.array(breakpoints, dtype=np.float64)` and `np.array(values, dtype=np.float64)` instead of Python lists. Eliminates per-bar list-to-ndarray conversion inside `_build_all_ranked()` during the hot path. Updated `_calibration_curves` type annotation from bare `dict` to `dict[tuple[str, str], tuple[np.ndarray, np.ndarray]]`.

### PERF-06: Shared `_run_refresh_loop` Helper (signal_generator_service)

Replaced 5 identical boilerplate refresh loop methods with a single shared helper:

```python
async def _run_refresh_loop(self, name, interval_s, fn, backoff_s=30) -> None
```

The helper sleeps `interval_s` via `asyncio.wait_for(shutdown_event.wait())`, calls `fn`, and on any exception logs the error and sleeps `backoff_s` before retrying — preventing spin loops on persistent DB errors. The 5 deleted loops were `_drift_penalties_refresh_loop`, `_perf_weights_refresh_loop`, `_cis_weights_refresh_loop`, `_calibration_curves_refresh_loop`, and `_tod_multipliers_refresh_loop`. The `start()` method now uses `_run_refresh_loop` for all 5 tasks.

### PERF-03: Thread Pool Offload (market_analysis_service)

Plugin `compute_full()` calls are CPU-bound Python work that blocked the asyncio event loop during the entire I2→I6 tier pipeline, preventing Kafka consumer from processing the next bar message. Changed `_plugin_states_locks` from `dict[..., asyncio.Lock]` to `dict[..., threading.Lock]` (required for cross-thread use), updated `_get_state_lock()` return type accordingly, and wrapped each `compute_full()` call in a `_sync_compute` closure dispatched via `await asyncio.to_thread(_sync_compute)`. The event loop is now free to process Kafka messages during plugin execution.
