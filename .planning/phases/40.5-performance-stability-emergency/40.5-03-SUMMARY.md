# Phase 40.5 Plan 03: Feature Writer i7/i8 Batching + Lifecycle O(1) Index Summary

**Feature writer i7/i8 messages now batch-flushed (PERF-02); lifecycle active-signal lookup is O(1) via in-memory index with 60s reseed (PERF-04); 328K stale pending signals expired**

## Accomplishments

- Eliminated per-message i7/i8 DB round-trips: buffered in `_i7_buffer`/`_i8_buffer`, flushed in batches alongside I1-I6 via `_flush_i7_i8()` — called in `finally` block of `_maybe_flush` and explicitly on shutdown
- Replaced O(N) `get_active_signals()` DB query per bar with O(1) dict lookup from `_active_index[(symbol, tf)]`; new signals picked up every 60s via `_active_index_reseed_loop`
- Added chandelier write guard: DB update only fires when `abs(new_stop - last_written) / last_written >= 0.0001` (0.01%), tracked in `_last_written_stop` field
- Applied migration 046: expired 328,079 stale pending signals accumulated from contract rolls; used `SET timescaledb.max_tuples_decompressed_per_dml_transaction = 0` to handle compressed chunk limit
- Added 14 new tests (6 for buffering, 8 for index/chandelier guard)

## Decisions Made

- Used `finally` block in `_maybe_flush` for i7/i8 flush so it piggybacks on every main flush event, and also added explicit `_shutdown` call so it fires even when main buffer is empty
- Index uses full replacement (not incremental update) in `_reseed_active_index` — simpler, consistent with DB state, O(symbols * active_signals) cost is acceptable at 60s intervals
- `_remove_from_index` uses `getattr(self, '_active_index', None)` guard so existing tests using `__new__` without setting this attribute don't break
- Migration 046 uses `status='expired'` (not `'ttl_expired_pending'`) because `chk_signal_ledger_status` constraint only allows `pending|active|regime_suppressed|expired`
