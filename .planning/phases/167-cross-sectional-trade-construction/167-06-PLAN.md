<objective>
Run the construction for real and record what it says.

Purpose: every prior plan in this phase proves the CODE is correct. None of them answers the
question the phase exists to answer. 167-VALIDATION.md states this explicitly in its Manual-Only
Verifications table: "a unit test can prove the gate-evaluation code is correct, but cannot
substitute for the real measurement the phase's goal is about." This plan backfills the full
corpus, runs both gates live, and transcribes the actual verdicts - pass or fail - into the
governing research documents.

Codex's review sharpened one thing about how that recording happens: the docs must not be the
only record. Plans 04 and 05 now write timestamped JSON verdict artifacts, so this plan's
transcription step has a durable source of truth to be checked against rather than a session log
that rotates away. The review also asked that the live-run recording be explicit about what
"equivalence" with the original script means versus what would count as a bug - so the tolerance
bands are fixed in Task 1 BEFORE the backfill runs, not chosen after seeing the numbers.

This is a Renaissance-discipline plan: the deliverable is a measured answer, not a favorable one.
Phase 148 is this project's precedent - it ran its irreversible gates, got Gate 2 FAIL, and
recorded DO NOT PROMOTE. If Gate 1 or Gate 2 fails here, that verdict gets written down with the
same fidelity a pass would.

Output: a populated `construction_spreads` table, two live gate verdicts as JSON artifacts and as
prose, updated research docs, and an operational runbook entry.
</objective>
