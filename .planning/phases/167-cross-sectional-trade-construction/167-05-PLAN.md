<objective>
Implement Validation Gate 2 - attribution honesty - as a second read-only
`--evaluate-attribution` CLI mode: decompose the realized spread return into the part explained
by a fixed, time-invariant leg membership (a static factor tilt) and the part attributable to the
time-varying forecast, then gate on the latter.

Purpose: this is the one genuinely new piece of statistical work in Phase 167. RESEARCH.md's
Open Question 1 and Assumption A5 are explicit - no script, service, or shared statistics function
in this codebase implements the design doc's Gate 2, and without it the phase could ship a
construction that clears Gate 1's bootstrap CI while actually being a permanent tilt toward, say,
low-vol sector ETFs. That is edge thesis T4 wearing cross_sectional_relative_value's clothes, and it is exactly the failure
mode `docs/research/trade-construction-layer.md` warns against.

Codex's review named this the phase's most fragile wave and raised one framing risk directly:
"the static-tilt benchmark is retrospective by construction and can be misread as causal if the
docs are not precise." Design decision 8 below makes that caveat a first-class output field, not
an afterthought in a doc.

Output: three pure functions, a read-only evaluation entrypoint, a `--evaluate-attribution` CLI
flag, a durable JSON verdict artifact, and unit tests including a construction that is
deliberately built to FAIL the gate.
</objective>

- `static_tilt_weights(leg_rows: Sequence[Mapping[str, Any]]) -> dict[str, float]`
  For each symbol appearing in any leg over the window, returns its time-invariant net exposure:
  `(bars_in_long_leg - bars_in_short_leg) / n_bars`. This IS the "static bucket membership" the
  design doc names - one fixed weight per symbol for the whole window, carrying no timing
  information whatsoever.

- `static_tilt_series(panel_by_bar: Mapping[Any, Mapping[str, float]],
  weights: Mapping[str, float]) -> tuple[list[Any], list[float]]`
  Returns `(bar_ts_list, static_return_list)` ordered by `bar_ts`, where each element is
  `sum(weights.get(symbol, 0.0) * return[symbol])` over the symbols present at that bar, skipping
  symbols whose return is `None`. This is the return the construction would have earned holding
  its average exposure and never rebalancing. Raises `ValueError` if `panel_by_bar` contains a
  duplicate bar key or if the resulting `bar_ts_list` is not strictly increasing.

- `attribution_verdict(spread_values: Sequence[float], static_values: Sequence[float],
  cluster_ids: Sequence[Any], bar_keys: Sequence[Any], max_static_r2: float, min_n: int,
  bootstrap_max_n: int, bootstrap_batch: int, bootstrap_random_state: int) -> dict[str, Any]`
  Returns a dict with `beta`, `intercept`, `static_r2`, `static_dominates`, `n_bars`,
  `n_clusters`, `residual_ci_lower`, `residual_ci_upper`, `residual_passes`, `gate2_passes`, and
  `benchmark_kind` (always the literal `"retrospective_time_averaged_membership"`). Raises
  `ValueError` when the four input sequences differ in length or when `bar_keys` contains a
  duplicate or is not strictly increasing.

<design_decisions>
This section operationalizes the design doc's Gate 2 sentence, which is stated in prose and has
no code anywhere in this codebase. RESEARCH.md Open Question 1 explicitly asks the planner to
resolve "what 'static bucket membership' concretely means operationally." The resolution:

1. **Static bucket membership = each symbol's time-averaged net leg membership over the
   evaluation window.** For symbol `s`, `w_s = (n_bars_long_s - n_bars_short_s) / n_bars`. This
   is the single fixed weight vector that best summarizes "which side of the book was this
   symbol usually on," and it deliberately discards all timing. A construction whose P&L comes
   from being permanently long low-vol sectors will have a `w` vector that reproduces most of its
   return; a construction whose P&L comes from the forecast will not.

2. **The benchmark is a returns series, not a dummy-variable regression.** The design doc says
   "regress spread returns on static bucket membership." The naive reading - one dummy regressor
   per symbol - has 80 regressors against a scalar-per-bar dependent variable and would overfit
   catastrophically. The correct object is the single-regressor form: collapse the static
   membership into ONE benchmark return series `static_t = sum_s w_s * r_{s,t}`, then regress
   `spread_t = alpha + beta * static_t + eps_t`. One regressor, one intercept, no
   multiple-comparisons problem, and a directly interpretable `static_r2`.

3. **The gate is on the RESIDUAL, not on R-squared alone.** `static_r2` answers "how much does a
   fixed membership explain," but the binding question is "does anything survive after removing
   it." Compute `residual_t = spread_t - beta * static_t` (the intercept is deliberately NOT
   subtracted - it is the constant excess return the forecast contributes, and it is exactly what
   the gate wants to test), then feed `residual_t` and the same day `cluster_ids` into the SAME
   `frame_gate_passes` Gate 1 uses. `gate2_passes` is true iff `residual_passes` is true AND
   `static_dominates` is false. This means: something is left over, and a fixed membership does
   not explain most of it.

4. **`static_dominates = static_r2 > alpha.construction.attribution_max_static_r2`** (seeded at
   `0.50` by Plan 01). The design doc's phrase is "if a fixed membership explains most of it" -
   `0.50` is the literal reading of "most." No empirical basis for a different value exists in
   this codebase, so the APR key's description says so explicitly and marks it as an
   `[initial_estimate]` open to recalibration.

5. **OLS by `numpy.linalg.lstsq`, not statsmodels.** A single-regressor-plus-intercept fit needs
   no extra dependency, and `numpy` is already pinned. `apply_bh_fdr` from
   `src/intelligence/statistics/ic_math.py` is NOT needed here - Gate 2 produces one verdict, not
   a family of tests, so there is no multiple-comparisons correction to apply.

6. **No todo 185 per-entity demeaning primitive.** RESEARCH.md's Todo 185 Scope Assessment is
   explicit: cross_sectional_relative_value ranks symbols relative to each other within the same bar, and ranking already
   differences out any within-bar-constant per-symbol term, so the construction cannot leak a
   per-entity fixed effect the way nonlinear_interaction_combiner's absolute per-symbol regression did. Gate 2 measures a
   portfolio-level aggregate exposure, which is a different object from a per-entity mean and
   needs no demeaning primitive. Do not add a task for todo 185.

7. **Both lookahead scales get their own verdict.** Gate 1 reports per scale; Gate 2 must too, or
   the two gates would not be comparable. The binding Gate 2 verdict requires BOTH scales to pass.

8. **The benchmark is retrospective and time-averaged, and the code says so in a field, not just
   in a docstring.** Addresses Codex's HIGH concern: "Wave 5's static-tilt attribution is easy to
   interpret too strongly. Time-averaged bucket membership is a retrospective benchmark, not a
   live causal decomposition, so the documentation must keep that distinction explicit."
   Concretely, `w_s` is computed from realized leg membership over the SAME window whose returns
   are being explained - it could not have been known in advance, and no live strategy could have
   held it. That makes Gate 2 a falsification test in one direction only: a HIGH `static_r2` is
   strong evidence the P&L is a disguised fixed tilt, while a LOW `static_r2` plus a surviving
   residual is evidence only that the P&L is NOT explained by this particular retrospective
   summary. It is emphatically NOT proof that the forecast is what generated the return, and it
   identifies no mechanism. To keep that distinction from eroding, `attribution_verdict` returns
   a literal `benchmark_kind = "retrospective_time_averaged_membership"` field that flows into
   the log payload, the verdict artifact, and (via Plan 06 Task 3) the research doc. A future
   reader who sees "the residual survives" alongside that field cannot mistake it for "we proved
   WHY it survives."

9. **Series alignment is validated structurally, not trusted.** Addresses Codex's suggestion:
   "require the regression to fail loudly on misaligned series lengths, duplicate timestamps, or
   non-unique bar keys. Silent alignment bugs would invalidate the attribution result."
   `attribution_verdict` now takes `bar_keys` as a fourth parallel sequence and raises
   `ValueError` on any length mismatch across the four, on any duplicate bar key, and on a
   non-strictly-increasing key order. `static_tilt_series` performs the same duplicate and
   ordering check on its own output. A duplicate `bar_ts` cannot arise from
   `construction_spreads` (its PK forbids it) but CAN arise from a mis-built panel mapping or a
   later refactor that joins the two sources differently, and a silently misaligned regression
   produces a confident, plausible, wrong `static_r2` - the exact class of failure this project
   treats as worse than a crash.
</design_decisions>
