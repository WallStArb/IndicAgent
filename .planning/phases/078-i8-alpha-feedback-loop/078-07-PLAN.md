<objective>
Move narrative generation off the real-time hot path. Today, `indicagent-ai-narrative` is a Kafka consumer that calls Ollama gemma4:e4b on every bar across 4 timeframes (60s budget per call), competing for LLM tokens with the alpha swarm. The text it produces is consumed at click-time by a human, not in real time.

Per CONTEXT D-29 / D-30 / D-31, this plan converts narrative to an on-demand HTTP endpoint:

1. New FastAPI route `src/api/routes/narrative.py` exposes `GET /api/signals/{signal_id}/narrative`. The handler:
   - Validates `signal_id` as UUID via FastAPI Path typing (422 for invalid input).
   - Looks up the signal row in `signal_ledger` joined to `intelligence_features` via parameterized asyncpg query.
   - Builds an `AIContext` using the typed schemas.py fields delivered by Plan 05 — NO `dict[str, Any]` escape hatch.
   - Instantiates `NarrativeComputeAgent` (untouched class, per D-31), awaits `.compute(context)`, returns `{"signal_id", "narrative", "model"}`.
   - Returns 404 / 502 / 500 / 422 with sanitized messages.
   - Caches `Settings()` and `LLMProviderChain` via `@lru_cache(maxsize=1)` per the `sse.py` pattern.

2. The Kafka consumer wrapper service (`services/ai_narrative_agent.py`) and its systemd unit file (`production/systemd/indicagent-ai-narrative.service`) are deleted via `git rm`. The skipped orchestrator test file is also removed.

3. The DAG single-source-of-truth (`services/service_auditor_agent.py`) loses three entries: `_DAG_ORDER["indicagent-ai-narrative"]`, `_LAG_THRESHOLDS["indicagent-ai-narrative"]`, `_AGENT_ID_TO_UNIT["NarrativeGroupComputeAgent"]`.

4. `CLAUDE.md` is updated: the L7 DAG layer description drops `ai-narrative`, a one-line note documents the new API endpoint, and the version-status header appends Phase 78. The plan SUMMARY documents the manual operator steps to stop/disable/remove the running systemd unit on the production host.

The `NarrativeComputeAgent` class itself is NOT modified — only its consumer wrapper is retired (D-31).
</objective>
