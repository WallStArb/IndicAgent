Populate the dict, add a shadow-mode `enabled` flag so plugin breakers are transparent by default (shadow-mode-first per project principles), and add state-transition observability (structlog warning + OTel gauge).

<threat_model>
- **Circuit breaker short-circuit incorrectly blocking live plugins:** If a plugin breaker defaults to enabled and opens on a transient blip, healthy live plugins get skipped, producing degraded features with no obvious cause. Mitigation: plugin breakers are constructed with `enabled=False` (shadow mode) so `allow_request()` returns `True` (transparent passthrough). Global force-enable only via `PLUGIN_CB_ENABLED=true`. Record state transitions in shadow mode so we can validate thresholds before flipping the flag.
- **Shadow mode semantics ambiguity — record paths skipped (cross-AI review HIGH concern):** `allow_request()` alone does NOT update failure state — that is done by `record_failure()`. If the executor only calls `allow_request()` and returns True (shadow mode), but skips `record_failure()`/`record_success()` around the plugin invocation, the shadow breaker NEVER accumulates failure data. The breaker remains perpetually CLOSED in shadow mode regardless of plugin health, making shadow observation meaningless. Mitigation: the executor MUST call `record_failure()` on plugin exception and `record_success()` on plugin success around EVERY plugin invocation — even in shadow mode. Only the blocking effect of `allow_request()` is suppressed by `enabled=False`; the record paths run unconditionally.
- **Executor currently does not call record_success/record_failure per-plugin (cross-AI review HIGH concern):** Check whether `executor.py`'s per-plugin invocation loop already calls `record_success()`/`record_failure()` on the circuit breaker. If it only calls `allow_request()` (lazy-init pattern at line ~199-204), add the record calls around the plugin invocation. This ensures shadow breakers accumulate real failure data before any decision to enable gating.
- **Breaking existing IBKR/LLM callers:** `CircuitBreaker` is shared — `src/providers/ibkr.py:105` and `src/core/llm/providers.py:48,61` construct it WITHOUT an `enabled` kwarg and rely on it actively gating. Mitigation: the new `enabled` parameter defaults to `True`, preserving the active-gate behavior for every existing caller that does not pass it. Only the plugin-pipeline construction passes `enabled=False` explicitly to opt into shadow mode.
- **Circular import on metrics:** Importing `_meter` from `src/observability/metrics.py` into the circuit breaker module risks a cycle. Mitigation: use `opentelemetry.metrics.get_meter("indicagent")` directly (PATTERNS shared pattern).
</threat_model>
