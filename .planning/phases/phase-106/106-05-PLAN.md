<threat_model>
- **Circuit breaker short-circuit incorrectly blocking live plugins:** If the breaker defaults to enabled and opens on a transient blip, healthy live plugins get skipped, producing degraded features with no obvious cause. Mitigation: `enabled` defaults to `False` (shadow mode) — `allow_request()` returns `True` (transparent passthrough) when disabled. Global enable only via `PLUGIN_CB_ENABLED=true`. Record state transitions in shadow mode so we can validate thresholds before flipping the flag.
- **Class mismatch:** `executor.py` currently uses the lighter `src.observability.circuit_breaker.CircuitBreaker`, while the 584-line `PluginCircuitBreaker` lives in `src.core.plugin_circuit_breaker`. PATTERNS flagged this ambiguity. Mitigation: read both classes; choose the one the executor's `_get_plugin_cb` already type-hints, and add the `enabled` flag to THAT class. Do not introduce a second breaker type into the executor.
- **Circular import on metrics:** Importing `_meter` from `src/observability/metrics.py` into the circuit breaker module risks a cycle. Mitigation: use `opentelemetry.metrics.get_meter("indicagent")` directly (PATTERNS shared pattern).
</threat_model>
