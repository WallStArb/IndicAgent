<objective>
Replace hand-rolled infrastructure with the shared implementations: `bar_aggregator_agent`'s manual `_MAX_ATTEMPTS` retry loop becomes `BaseAgent._setup_with_retry()` via class attributes; three services that call `asyncpg.create_pool()` directly switch to `database_manager.create_pool` (which registers JSONB codecs and emits pool gauges); and `BaseWriterAgent._teardown()` gains `hasattr` auto-close guards so any writer subclass closes its consumer/pool/db connections on shutdown even when it forgets to call `super()._teardown()`.

Purpose: The direct `asyncpg.create_pool` bypass is a latent JSONB bug — those services get raw strings for jsonb columns instead of dicts. The manual retry loop duplicates tested backoff logic. The missing teardown guards leak connections for any writer that overrides `_teardown()` without chaining to the base.
Output: Less duplicated code; correct JSONB handling; pool gauges for three more services; leak-proof writer teardown.
</objective>

<threat_model>
- **Behavior drift on retry:** The manual loop is 4 attempts at 2s base with exponential backoff. `BaseAgent` defaults are 3 attempts. If the class attributes are not overridden to `SETUP_RETRY_ATTEMPTS = 4` and `SETUP_RETRY_BACKOFF_S = 2.0`, the aggregator retries fewer times — a silent reduction in resilience. Mitigation: set both class attributes explicitly.
- **Double-wrapped retry:** `BaseAgent` already calls `self._setup_with_retry()` which calls `self._setup()`. If the manual loop is left inside `_setup()`, retries get squared. Mitigation: the manual loop MUST be fully removed from `_setup()`, leaving only the single-attempt body.
- **Wrong pool kwargs:** `database_manager.create_pool` may take a `pool_name` and different signature than raw `asyncpg.create_pool`. Mitigation: read `database_manager.create_pool` signature before editing and pass a distinct `pool_name` per service.
- **Pool-name collision (cross-AI review HIGH concern):** Duplicate pool names across services sharing the same process or metrics scrape target will cause metric ambiguity (gauge values overwritten by last-created pool) and may cause unexpected pool reuse if there is any global pool registry. Mitigation: before choosing a pool_name, grep the entire codebase for all existing `pool_name=` values (`grep -rn "pool_name=" src/ services/`) and confirm the three new names (`swarm_ledger_writer`, `bar_replay_provider`, `signal_replay_auditor`) are unique. If any collision is found, choose a more specific name.
- **asyncpg JSONB contract:** Per CLAUDE.md, with codecs registered, jsonb columns return dicts — pass dicts, never `json.dumps()`. Verify these services were not manually `json.loads()`-ing jsonb reads (which would now double-decode and crash). Audit each service's read paths.
- **Double-close on teardown:** Adding auto-close to `BaseWriterAgent._teardown()` could double-close a connection if a subclass ALSO closes it and chains to super. Mitigation: guard each close with `hasattr` AND a None/closed check; closing an already-closed asyncpg pool/consumer must be tolerated (wrap in try/except and log, never raise). The base `_teardown()` already swallows flush failures — match that crash-safe style.
</threat_model>
