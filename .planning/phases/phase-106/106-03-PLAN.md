<threat_model>
- **Behavior drift on retry:** The manual loop is 4 attempts at 2s base with exponential backoff. `BaseAgent` defaults are 3 attempts. If the class attributes are not overridden to `SETUP_RETRY_ATTEMPTS = 4` and `SETUP_RETRY_BACKOFF_S = 2.0`, the aggregator retries fewer times — a silent reduction in resilience. Mitigation: set both class attributes explicitly.
- **Double-wrapped retry:** `BaseAgent` already calls `self._setup_with_retry()` which calls `self._setup()`. If the manual loop is left inside `_setup()`, retries get squared. Mitigation: the manual loop MUST be fully removed from `_setup()`, leaving only the single-attempt body.
- **Wrong pool kwargs:** `database_manager.create_pool` may take a `pool_name` and different signature than raw `asyncpg.create_pool`. Mitigation: read `database_manager.create_pool` signature before editing and pass a distinct `pool_name` per service.
- **asyncpg JSONB contract:** Per CLAUDE.md, with codecs registered, jsonb columns return dicts — pass dicts, never `json.dumps()`. Verify these services were not manually `json.loads()`-ing jsonb reads (which would now double-decode and crash). Audit each service's read paths.
</threat_model>
