<threat_model>
- **DAG mismatch causing auditor blind spots:** A service absent from `_DAG_ORDER` gets the default priority 99 and is never properly ordered; if also absent from `_AGENT_ID_TO_UNIT`, its consumer-lag metric cannot be mapped to a unit, so stall detection silently skips it. Mitigation: add all 9 services with correct priorities; verify keys against actual `name=` args.
- **Auditor fighting systemd timers (restart thrash):** Adding oneshot timer services (weight-updater, shadow-auditor, ml-*) to `_DAG_ORDER` without a guard makes the graduated restart loop restart them on the auditor's schedule instead of letting systemd timers fire them — they then look "failed" between runs. Mitigation: add `_ONESHOT_UNITS` frozenset and guard ALL restart paths (stall loop ~line 381, graduated restart ~line 470/522, AND any other helper that calls `_restart_service_by_unit`).
- **Incomplete oneshot guard (cross-AI review HIGH concern):** The guard must cover ALL call sites of `_restart_service_by_unit`, not only the two originally-named paths. Future helper functions added to the auditor that call `_restart_service_by_unit` without the guard would bypass protection. Mitigation: grep ALL `_restart_service_by_unit(` call sites after adding the frozenset; verify each one checks `_ONESHOT_UNITS`.
- **Undocumented priority assignment causing cascading restart failures (cross-AI review HIGH concern):** Incorrect priorities cause the auditor to restart services in the wrong order during recovery, cascading failures downstream. For example, restarting intelligence-pipeline before its producers means it starts with stale state. Mitigation: add an inline comment next to every priority value in `_DAG_ORDER` justifying its position relative to actual upstream/downstream dependencies.
- **Phantom entries:** Do NOT add `indicagent-hmm-training` or `indicagent-feature-validation` — RESEARCH.md confirmed these are not in the live system.
</threat_model>
