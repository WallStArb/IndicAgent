<objective>
Eliminate two reliability/scaling weaknesses in the hot path and add a missing span. (1) Lines 507 and 598 of `intelligence_pipeline_agent.py` use non-blocking `enqueue` which silently drops intel and journal messages under backpressure — switch to `await enqueue_blocking`. (2) `PluginStateManager.get_all_states_for()` is an O(N) scan across all plugin states; add a `_states_by_key` secondary index for O(1) lookup. (3) Wrap `_process_bar_inner` in `observed_span` recording symbol and tf.

Purpose: Silent drops corrupt downstream feature/journal continuity; the O(N) scan grows linearly with symbol count; the missing span leaves the hottest code path un-traced.
Output: Lossless output queueing, O(1) state lookup, traced hot path.

Depends on 105-03 because that plan adds histogram infrastructure to `intelligence_pipeline_agent.py`; this plan also edits that file and must apply on top of 105-03's changes to avoid conflicts. The `observed_span` here is span instrumentation, distinct from 105-03's metric-type histogram fix.
</objective>

<threat_model>
- **Deadlock from blocking enqueue:** Switching to `enqueue_blocking` means the producer awaits when the queue is full. If the queue drain task is itself stalled, the whole pipeline backs up rather than dropping. This is the desired behavior (backpressure beats silent loss) but must not be applied to the signal enqueue at line 529, which is ALREADY blocking — only lines 507 and 598 change. Mitigation: change exactly two call sites; confirm line numbers by reading.
- **Secondary index drift:** If `_states_by_key` is updated in only some write paths, reads return stale/partial state — worse than O(N) correctness. Mitigation: update the index in EVERY write path (`update`, `update_batch`, and any direct `_plugin_states[...] =` assignment). Add a unit test asserting index/primary parity.
- **Checkpoint duplication:** Serializing `_states_by_key` doubles checkpoint size and risks divergence on restore. Mitigation: do NOT serialize it; rebuild it in a loop after `_plugin_states` is loaded from checkpoint.
- **Span overhead on hot path:** `observed_span` per bar is acceptable (one span per bar, not per plugin). Do NOT wrap per-plugin execution in spans here. Mitigation: single span around `_process_bar_inner` only.
</threat_model>
