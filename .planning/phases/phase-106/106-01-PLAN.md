- **Incomplete deletion leaving orphan imports (startup crash):** Deleting `guardrails.py` without first removing its import in `chain.py:24` and the `_guardrails` usage crashes ALL LLM operations at import time. Mitigation: remove consumers FIRST, then delete the file, then run `python -c "import src.core.llm.chain"` to confirm.
- **Removing a field that has a live caller:** A Settings field with even one production reader will raise `AttributeError` at runtime if removed. Mitigation: grep `src/ services/` (excluding `settings.py` itself) for every field before deletion; the SWARM_QUEUE_TIMEOUT_MS field is confirmed to have ZERO production callers (only a test kwarg).
- **Breaking a test contract:** `_audit_payload` and `_on_guardrail_violation` in base_agent.py are documented "Future phase" hooks with a test contract (`test_audit_payload_property_returns_empty_dict`). They are NOT in scope for deletion — leave them untouched.
- **`self._llm` declaration shadowing subclass assignment:** Subclasses (skeptic, narrative, counterfactual, etc.) assign `self._llm = llm_chain` in their own `__init__`. Declaring `self._llm = None` in the BaseAIAgent `__init__` must happen BEFORE `super().__init__()` does any work that triggers an LLM call (it does not — `__init__` only sets timing/lineage attrs), and subclasses must still overwrite it. Mitigation: add the declaration as a plain attribute init in BaseAIAgent.__init__; subclass assignments run after `super().__init__()` and correctly overwrite it.
</threat_model>
