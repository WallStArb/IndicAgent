<objective>
Wire tail-risk metrics from Plan 02 into the shadow governance promotion gate. Block promotions when skewness or recovery_factor falls below configured thresholds, emit OTel observability counter on every block, and add unit-test coverage for the None-safe boolean semantics.

Purpose: Close the measurement→action loop. Without this plan, Plans 01 and 02 are instrumentation theater — distribution shape exists in the DB but nothing acts on it. With this plan, a setup with Sharpe 1.5 and skewness -2.5 (left-tail blowup risk) cannot graduate from shadow to live.

Output: Pure `_tail_risk_blocks_promotion()` gate function consistent with `_should_promote()` pattern; integrated into `_check_promotion()` BEFORE the existing promotion check; new OTel counter; full unit test coverage.
</objective>

<threat_model>
ASVS L1 — security and integrity threats addressed by this plan:

- **Integrity - silent suppression from None comparisons (mitigated):** Naive `if skewness < threshold` raises TypeError on None. `_tail_risk_blocks_promotion()` explicitly guards `if skewness is not None and skewness < min_skewness`. NULL metrics (n below threshold) skip the gate, never block.
- **Integrity - reading wrong signal_metrics row (mitigated):** Tail gate query filters `symbol = '*' AND entry_type = '*' AND track = 'market'` — reads the global market-track aggregate. Without these filters, it could read per-symbol or per-entry_type rows with smaller n and wrong distribution shape.
- **DoS via extra DB load (mitigated):** Tail gate query is one `fetchrow` per plugin per 30-minute audit cycle. Plugin count ~22. Total: ~22 fetches per cycle. Reuses existing pool.acquire() context. No new timer, no daemon.
- **SQL injection (mitigated):** Query uses parameterized binding `$1` for plugin name. No string interpolation.
- **Governance bypass (out of scope):** Promotion still requires `n >= min_n AND ci_lower > min_ev_r`; tail gate is ADDITIVE — it can only block, never approve. A failing tail gate can never falsely promote.
</threat_model>
