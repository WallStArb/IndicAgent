<objective>
Add per-symbol and per-entry_type grouping to compute_signal_metrics() so that every (plugin, tf, regime, window) emits up to three result row families: global ('*','*'), per-symbol (sym,'*'), and per-entry_type ('*', et). Each family uses the same _build_metrics_result() call so distribution shape and core stats are computed identically across all three.

Purpose: Close the segmentation gap. Plan 01 made it safe; Plan 02 makes it real. Per-symbol reveals cross-instrument masking. Per-entry_type reveals that at_limit and at_close entries for the same setup have fundamentally different risk profiles. Both are required before Plan 03 can wire the tail gate on meaningful denominators.

Output: compute_signal_metrics() emits three row families gated at n >= 30 (except global which uses MIN_SAMPLE_SIZE). signal_metrics_compute_agent publishes all three with entry_type-aware Kafka keys. Integration test confirms end-to-end persistence.
</objective>

<threat_model>
ASVS L1 — security and integrity threats addressed by this plan:

- **DoS via row explosion (mitigated):** Per-entry_type accumulation gated by `n >= 30` matches existing per-symbol gate. Research D-09 estimates max 29k rows total — well below operational limits. Per-symbol × per-entry_type cross product is deferred to 092.1 (sparse cells filter aggressively).
- **Integrity - NULL entry_type leakage:** Signal ledger rows with NULL entry_type must NOT contribute to any per-entry_type accumulator (they have no classifiable entry pattern). They DO contribute to global '*' and per-symbol accumulators. Enforced via `if entry_type_val is not None:` guard.
- **Integrity - unknown entry_type handling (Gemini Suggestion):** If signal_ledger contains an entry_type outside the D-10 allowed list (`at_close`, `at_pullback`, `at_limit`, `at_reclaim`, `zone_proximal`), the accumulator MUST still emit a row keyed by that literal value rather than silently dropping or remapping it. Downstream tail gate (Plan 03) only queries `entry_type = '*'` so orphan rows do not corrupt governance; they remain visible in DB for diagnostic inspection. This explicitly avoids silent data loss for future entry_type additions.
- **SQL injection (mitigated):** _QUERY is a static string; entry_type column added to SELECT only. No user input.
- **Kafka key collision (mitigated):** Kafka key extended with entry_type suffix to prevent two messages with identical (track, plugin, tf, regime, window, symbol) but different entry_type from being deduplicated/overwritten at the partition level. Even though writer ON CONFLICT uses PK with entry_type (consistent), keys should be unique-per-PK for debuggability.
- **Backward compatibility (mitigated):** MetricsComputedEvent schema in Plan 01 already accepts entry_type with default '*' — old code paths that don't emit entry_type remain valid.
</threat_model>
