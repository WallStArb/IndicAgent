<objective>
Establish all schema and compute primitives required for distribution-shape metrics and per-entry_type segmentation. This plan is foundational: it migrates the DB schema, extends the typed event bus, adds the pure compute helper, updates the writer upsert, and patches all signal_metrics consumers to filter entry_type='*'. No grouping logic changes yet (that is Plan 02).

Purpose: Eliminate the deploy-order risk. After this plan, Plan 02 can safely emit per-entry_type rows without (a) MetricsComputedEvent DLQ rejection (extra="forbid"), (b) ON CONFLICT mismatch errors, or (c) consumer queries inflating perf_weights with duplicate global+per-entry_type rows.

Output: signal_metrics table with seven new columns and updated PK; SignalMetricsResult dataclass with seven new fields; DistributionShape dataclass; _distribution_shape() pure helper with unit tests; MetricsComputedEvent extended; three consumer queries guarded with entry_type='*'.
</objective>

<threat_model>
ASVS L1 — security and integrity threats addressed by this plan:

- **SQL injection (mitigated):** All DDL in _ensure_schema() uses static SQL strings with no user-controlled interpolation. All consumer query updates only add a literal `AND entry_type = '*'` clause - no dynamic construction.
- **DoS via PK rebuild race (mitigated):** PK migration wrapped in `DO $$ ... $$` block with `information_schema.key_column_usage` guard; `DROP CONSTRAINT IF EXISTS` semantics ensure idempotency. Two simultaneous startups: second sees entry_type already in PK and skips.
- **Integrity / silent data loss (mitigated):** `extra="forbid"` on MetricsComputedEvent is intentional. Adding new fields as optional-with-default preserves rejection of truly unknown fields while admitting the new schema.
- **Data integrity - consumer duplication (mitigated):** Three consumer queries (cache_manager perf_weights, signals.py alpha table, setup_performance_updater) are patched in THIS plan, BEFORE Plan 02 writes per-entry_type rows. Without this, perf_weights would double-count.
- **Migration partial-failure (mitigated):** Each ALTER TABLE ADD COLUMN is independently idempotent via IF NOT EXISTS. A failure mid-migration leaves the table in a consistent partial state and the next startup completes remaining steps.
</threat_model>
