# Phase 143.1 Plan 04: Sign-Symmetric Ensemble Eligibility Redesign Summary

**Made ensemble eligibility, walk-forward validation, quality weighting, the E2 mean-variance combination, and the post-run lifecycle demote hook all sign-symmetric under a new `alpha.ensemble.sign_symmetric` APR flag, closing three independent sign-asymmetric gates (plus a mathematically-wrong locked E2 formula) that together excluded 100% of negative-IC features from ever reaching ensemble weight — root cause of `alpha_events` being 99.99% long-only.**

## Accomplishments

- Sign-consistent walk-forward fold-pass criterion in all three `ic_engine.py` blocks (per-symbol, cross-sectional/POOLED, daily context-features), unconditional and equivalence-preserving for `ic_sign=1` features — the cross-sectional block is the load-bearing one since it's the only output `_eligibility_where()` reads.
- New `alpha.ensemble.sign_symmetric` boolean APR key (migration 224, default `false`) as the real champion/challenger behavior switch, replacing the previously-proven-vacuous `weight_version`-only approach.
- `ensemble_trainer.py`'s `_ELIGIBILITY_BASE_WHERE`/`_ELIGIBILITY_WHERE` module constants replaced with a flag-gated `_eligibility_where(sign_symmetric)` builder — byte-identical to the old predicate when the flag is off (tested equivalence), admits `(ic_sign=-1 AND ic_ci_upper<0)` contrarians when on. `--sign-symmetric/--no-sign-symmetric` CLI override mirrors `--weight-version`.
- `compute_quality_weight` (feature_selector.py) made sign-aware: `(ic_sign * nearest_ci_bound) * max(sharpe_floor, ic_sign * ic_sharpe)` — byte-identical to the old formula for `ic_sign=1`, preserves positive-magnitude weight for contrarians without naive `abs()` (which would incorrectly up-weight decay-signature rows).
- E2 mean-variance sign path corrected per Fable BLOCKER 3: `resolve_stratum_weights` now signs the OUTPUT of `mean_variance_weights(cov, ic_shrunk, ...)` (`ic_signs * mv_raw`), never the input — the previously-locked `mean_variance_weights(cov, ic_signs * ic_shrunk, ...)` formula was mathematically wrong (`Σ⁻¹.(s·μ) ≠ s·(Σ⁻¹.μ)` once a contrarian correlates with another selected feature).
- `services/ic_engine.py`'s `_run_lifecycle_hook` demote predicate made sign-aware under the same flag — closes a third, mid-plan-discovered sign-asymmetric gate (landed by Phase 143, not in the original CONTEXT.md/RESEARCH.md read range) that would have silently re-demoted every contrarian one lifecycle cycle after this plan's other fixes landed them in the ensemble.
- Methodology-change-ledger entry E9 recording the full redesign, pre-committed before any corpus re-run under the new criterion exists.
