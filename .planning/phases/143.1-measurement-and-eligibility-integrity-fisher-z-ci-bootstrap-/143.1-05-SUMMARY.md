### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Extended column computation to all 3 row-dict-building paths, not just the one named in the plan's interfaces section**
- **Found during:** Task 2
- **Issue:** The plan's `<interfaces>` section named only `_compute_cross_sectional_tf` (line 1184) as the write-path target. Investigation of `services/ic_engine.py` found the module-level `_INSERT_BODY` SQL template is shared verbatim by `_POOLED_INSERT_SQL`, `_REGIME_INSERT_SQL`, and `_CROSS_SECTIONAL_INSERT_SQL` -- i.e. by `_compute_symbol_tf`'s two row-generation blocks (main scale loop + daily context-features loop) as well as `_compute_cross_sectional_tf`. - **Fix:** Computed `sign_hit_rate`/`magnitude_conditional_ic` in all 3 blocks, reusing each block's already-assembled raw (unranked) prediction/return arrays (`X_raw_scale`/`Y_scale` in the two array-shaped blocks, `x_daily`/`y_daily` in the scalar daily-cadence block).
- **Files modified:** `services/ic_engine.py`
- **Verification:** `.venv/bin/python -c "..."` module-level import + `_INSERT_BODY` substring check confirms all 3 row dicts populate both keys; full `.venv/bin/pytest tests/unit/ -q --ignore=tests/unit/providers` run (5741 passed, 42 skipped, 1 pre-existing unrelated failure) confirms no `KeyError` regression anywhere in the suite.
