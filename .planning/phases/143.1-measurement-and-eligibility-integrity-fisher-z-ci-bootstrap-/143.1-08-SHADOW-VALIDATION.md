# 143.1-08 Shadow Validation: Component E (sign-symmetric eligibility)

**Status at file creation: PRE-COMMITMENT ONLY. No training, scoring, or frame run has
executed yet. This section is written and committed to git BEFORE any result-producing
command runs, per this plan's own goalpost-integrity requirement and CONTEXT.md's

## 1. What this shadow validation is testing

Component E (Plan 04, `todo 094`) replaced two sign-asymmetric gates in
`ensemble_trainer.py`/`ic_engine.py` with sign-aware equivalents, so that features with a
statistically reliable NEGATIVE information coefficient (contrarian / short-side signal)
can enter the ensemble instead of being excluded by construction. Before Component E, the
live system was 99.99% long-only (11.81M long vs 1,479 short `alpha_events`) — not because
short-side alpha doesn't exist, but because the eligibility gate never let it through.

Flipping `alpha.ensemble.sign_symmetric` from `false` to `true` is a real behavior change
to what ends up in the ensemble that will eventually size the owner's live trades. This
file records the pre-committed rule for deciding whether that flip is warranted, then
(after the runs below execute) the actual measured result and the promote/hold verdict.

## 2. Mechanism (recorded before any run, per plan interface notes)

- **Champion** (old, long-only-eligible behavior): `services/ensemble_trainer.py
  --weight-version 143.1-08-champion --no-sign-symmetric`
- **Challenger** (new, sign-symmetric-eligible behavior): `services/ensemble_trainer.py
  --weight-version 143.1-08-challenger --sign-symmetric`
- Both train from the **same, single** Plan 07 corpus (`feature_vectors` /
  `feature_ic_scores` as they exist live right now) — the *only* difference between the
  two runs is the `--sign-symmetric` CLI override. No other config, corpus, or code
  changes between the two runs.
- `services/alpha_publisher.py --weight-version <tag> --skip-kafka` scores each
  weight_version into its own `alpha_events` rows (`event_id` embeds `weight_version`, so
  champion and challenger never collide).
- `services/alpha_frame_writer.py --backfill` then `services/counterfactual_tracker.py
  --backfill` process the full `alpha_events` backlog (anti-join checkpoint, no flag
  needed) into `alpha_frames`, distinguishable per run via `alpha_frames.weight_epoch`
  (a copy-through of `alpha_events.weight_version`).
- Promotion mechanic, if the rule below clears: a `ConfigService.set("alpha.ensemble.
  sign_symmetric", True, changed_by="143.1-08-shadow-validation", reason=...)` call —
  a `config_state` UPDATE recorded in `config_history`, not a code change.

## 3. PRE-COMMITTED decision rule (written before any result exists)

All quantities below are evaluated on **GROSS** `alpha_frames.counterfactual_pnl_r`
(matches SHADOW-REVIEW.md's D-01 gross-cost-basis convention — `net_expected_r` is
reported alongside as context, never gated on), restricted to
**`frame_variant = 'primary'`, `status != 'open'`** (closed frames only — an open frame
has no realized `counterfactual_pnl_r`).

The **day-clustered block bootstrap** used for criterion 2 below is the exact,
unmodified `frame_gate_passes` / `evaluate_frame_gate` core already shipped in
`services/counterfactual_tracker.py` (BCa via `scipy.stats.bootstrap` up to
`alpha.scoring.bootstrap_max_n` day-clusters, analytic one-sided CLT lower bound above
that; `alpha.scoring.bootstrap_random_state` seed = 42) — reused verbatim, not
reimplemented, with an added `weight_epoch = $tag` filter on the input query so it scores
one weight_version at a time instead of the whole table.

### Criteria (SHADOW-REVIEW.md's frozen 5, applied per weight_epoch)

1. **Minimum sample:** the challenger's OOS (`bar_ts >= alpha.validation.oos_start` =
   `2025-12-24T05:15:00Z`) closed-frame population spans **>= 60 distinct trading days**
   (`COUNT(DISTINCT bar_ts::date)`).
2. **Mean P&L positive at 95% CI:** the challenger's pooled (all OOS cells combined),
   day-clustered block-bootstrap 95% CI **lower bound on mean `counterfactual_pnl_r` is
   > 0** (`frame_gate_passes` reused verbatim, `weight_epoch = '143.1-08-challenger'`).
3. **Sharpe:** annualized Sharpe of the challenger's OOS `counterfactual_pnl_r` series
   **> 0.5** (`mean / std(ddof=1)` of per-trading-day pooled mean pnl_r, annualized by
   `sqrt(252)` — matches SHADOW-REVIEW's "Sharpe of counterfactual_pnl_r" definition at
   daily granularity, consistent with criterion 2's own day-level clustering unit).
4. **Max drawdown:** the max peak-to-trough decline of the challenger's OOS cumulative
   `counterfactual_pnl_r` equity curve (ordered by `bar_ts`, summed in R units) **< 25%**
   of the running peak cumulative R at the trough. Edge case (frozen, WR-03): if
   `peak_cumulative_R_at_trough <= 0` at the point of max decline, this criterion **fails
   outright** regardless of the ratio.
5. **No IC-Sharpe cliff:** from `alpha_ensemble_ic` (`weight_version =
   '143.1-08-challenger'`), the trailing-20-trading-day IC Sharpe over the shadow period
   must be **>= 50%** of the full-shadow-period IC Sharpe. Edge case (frozen, WR-03): if
   `full_period_IC_Sharpe <= 0`, this criterion **fails outright** regardless of the
   ratio.

### Component-E-specific additions (this is a champion/challenger shadow comparison, not
Phase 147's from-scratch live-promotion decision — SHADOW-REVIEW's 5 criteria alone don't
test whether the flag itself is a net improvement over the status quo)

6. **Non-regression vs. champion:** the challenger's criterion-2 pooled CI lower bound
   must be **>= the champion's** own pooled CI lower bound, computed identically
   (`weight_epoch = '143.1-08-champion'`, same OOS window, same bootstrap core). If
   sign-symmetric eligibility dilutes the pre-existing long-only edge rather than adding
   to it, this fails.
7. **Short-side sanity (informational gate):** among the challenger's newly-eligible
   `direction = 'short'` OOS frames specifically, the day-clustered bootstrap CI **must
   not show a confident loss** (`ci_upper < 0`) — i.e., `frame_gate_passes`-style CI
   computed on the short-only subset must not have its whole interval below zero. If
   short-side `n` is below `alpha.scoring.min_strategy_n` (30), this check is
   **informational only** (reported, does not itself block promotion) given insufficient
   shadow-period short-side volume to draw a confident conclusion either way — but a
   *confident* loss (enough short-side n to form a CI, and that CI is entirely negative)
   is disqualifying regardless of sample size, since it would mean the flag is actively
   harmful on the exact population it exists to admit.

### Verdict rule

**PROMOTE** (flip `alpha.ensemble.sign_symmetric` APR default `false` -> `true`,
recorded in `config_history` + this ledger) **if and only if criteria 1-6 all pass AND
criterion 7 is not a confident loss.**

**Otherwise: HOLD.** The flag stays default-`false`, the champion keeps long-only
eligibility, and the challenger's `alpha_frames` rows remain as shadow evidence
(`weight_epoch = '143.1-08-challenger'`) for future re-evaluation once more OOS data
accumulates or the diagnosed weakness is fixed.

**No post-hoc renegotiation:** if the measured result is close to a threshold, the
threshold does not move. If the gate fails, the next step is diagnosis (why did it fail,
which criterion, which cells), not adjusting criteria 1-7 above.

## 3a. Pre-run correction: criterion 5 is not measurable this round (discovered before
any training/scoring/frame command executed — still pre-commitment-safe)

Before invoking any training run, a schema check of `alpha_ensemble_ic` found that
criterion 5 as literally stated in Section 3 (a "trailing 20 trading day IC Sharpe vs.
full-shadow-period IC Sharpe" split) requires a **time series of `EnsembleICEngine` runs
across calendar time** — i.e., a recurring measurement cadence that would let "trailing 20
days of the shadow period" mean something distinct from "the full shadow period." No such
recurring cadence exists: `services/counterfactual_tracker.py`'s own docstring records this
explicitly ("A recurring `ensemble_ic_engine` cadence is explicitly out of scope for this
phase (D-09, follow-on todo 089)"). A single `EnsembleICEngine --weight-version <tag>` run
against a static historical corpus produces exactly **one** `scored_at` vintage per cell,
with `ic_sharpe` computed once over the full corpus window — there is no live monitoring
period over which a trailing-20-day subwindow is a different quantity than the full period
in this backtest-style shadow validation.

**Correction applied (before seeing any result — this is a measurability gap, not a
post-hoc renegotiation of a threshold after an unfavorable number):** criterion 5 is
**N/A** for this round of Component E shadow validation. The PROMOTE rule in Section 3 is
corrected to: **PROMOTE iff criteria 1-4 and 6 all pass AND criterion 7 is not a confident
loss.** Criterion 5 remains a **frozen, unmodified requirement of Phase 147's actual live
promotion gate** (SHADOW-REVIEW.md is not edited by this correction) — it simply cannot be
evaluated against a one-shot historical backtest and must be checked once Phase 147's live
shadow monitoring accumulates a real trailing-vs-full-period split. This is recorded here,
not silently dropped, and is committed to git before the champion/challenger training runs
that produce Section 6's result.

**Important context for interpreting this HOLD, found during write-up (not a re-gate, the
verdict above stands unchanged):**

- **A real, separate data-quality finding surfaced while sanity-checking these numbers before
  trusting them:** `counterfactual_pnl_r` has a long tail down to **-57.27R** (champion: 766
  frames, challenger: 3,439 frames with `abs(pnl_r) > 5`), traced to `compute_frame_geometry()`
  (`services/alpha_frame_writer.py:64`) guarding only against `atr <= 0`, not against a small-but-
  valid ATR on thin-absolute-volatility instruments (FXY, FXE, DBB, DBC, GLD, SLV, EWT, MCHI,
  INDA — concentrated at 5m) producing razor-thin stop distances (0.02%-0.3% of price) that
  ordinary price noise blows through by 10-50x. Filed as **todo 162** (this worktree's
  `pending/`), independent of this phase — it affects any corpus-wide statistic computed from
  `alpha_frames.counterfactual_pnl_r`, not just this comparison.
- **This does not change the verdict**: trimming `abs(pnl_r) > 10` still leaves both champion
  (mean -0.136) and challenger (mean -0.040) net-negative over the OOS window. The qualitative
  result — both underwater, challenger not a statistically robust improvement — is robust to the
  outlier population; only the *magnitude* of Sharpe/drawdown is inflated by it. Per this
  document's own "no post-hoc renegotiation" rule, the reported criteria above use the full,
  untrimmed, GROSS population exactly as pre-committed — the trimmed view is diagnostic
  context only, not a substitute gate.
- **Emission-layer behavior change is confirmed working as designed**, independent of the P&L
  outcome: champion is 99.665% long / 0.335% short (1,149,371 / 3,863 of 1,153,234 total
  `alpha_events`), matching the documented pre-fix baseline. Challenger flips to 30.17% long /
  **69.83% short** (6,640,003 / 15,369,153 of 22,009,156 total) — Component E's sign-symmetric
  eligibility gate is unambiguously admitting the short-side population it was built to admit.
  The mechanism works; the OOS P&L result for what it admits does not clear the promotion bar
  this round.
