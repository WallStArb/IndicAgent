## H-1 DEFERRED VERIFICATION GATE (do not lose - the single most load-bearing review finding)
The F3 evidence-mass floor (in plan 160-02's pure core) blocks re-eval when
`(eval_n - last_eval_n) < min_new_observations` (2000). `eval_n` here is the summed challenger
`n_independent` over the compared strata (computed by `_registry_outcome`), NOT a count of newly
accrued observations. Under rolling-window corpus rebuilds (fixed backfill depths per TF: 5m:5y,
1h:15y, etc.), successive corpus builds SLIDE the window rather than grow it, so the delta between
builds may be ~0 or negative. With `min_promotion_consecutive=2`, promotion needs a SECOND passing
eval, so if the delta never grows by 2000 between builds, NO candidate can promote through the
automated path, and D-02's "feature migration only after one real promotion/demotion cycle" gate
waits on an event that may be structurally unreachable. This CANNOT be checked now: `alpha_ensemble_ic`
has 0 rows (corpus rebuild in flight). BEFORE the first live `--challenger-concept` promotion run,
run the one-query empirical check (source doc Suggestion 1 / review H-1): measure
`sum(n_independent)` in `alpha_ensemble_ic` across two successive corpus-build vintages and confirm
the delta plausibly clears `min_new_observations=2000` for at least one real stratum-pair. If it does
NOT, redefine the F3 delta (against per-stratum `n_independent` growth over the SAME strata set, or
against the corpus build's new-bar count) and/or revisit migration 232's seed of
`ensemble_strategy_min_new_observations` before the floor is trusted as load-bearing. This gate is
ALSO recorded in follow-on todo 118 (filed by plan 160-04) so it is not lost if the corpus rebuild
finishes after this phase's execution. The recording path being unit-test-only in this MVP means no
live promotion is attempted before this check runs - the gate is a precondition, not a blocker on
shipping this phase.

## M-1 (documented residual risk, tied to H-1 - accepted, no code guard now)
`_registry_outcome` sums `n_independent` over ALL compared strata, so `eval_n` is
composition-sensitive: dropping strata gives a negative delta (permanent block); adding strata or
switching `alpha.ensemble_ic.gate_lookahead` (APR, currently 'fast') inflates the delta with zero
new data; and HOLD-verdict strata (degenerate p-values, no verdict rendered) still contribute their
full `n_independent` toward passing `min_gate_n`. No code guard (e.g. excluding HOLD-verdict strata
from the `eval_n` sum) is added now, because the entire F3 delta definition is under the H-1
empirical review and may be redefined; guarding HOLD prematurely would optimize a formula that may
change (Musk step: do not optimize what may be deleted). ACCEPTED as documented residual risk pending
the H-1 check; if H-1 redefines the F3 delta, re-evaluate the HOLD-strata contribution then.

## L-3 (flag for automation - documented, no change now)
All `REGISTRY: FAILED` paths in the recording block `return 0` (exit code 0), consistent with this
script's informational-exit-0 convention today. When the recording path is later invoked from
`ops_corpus_pipeline_run.sh` automation, a failed registry write becomes a silent failure - the exact
class this project's principles forbid. This is recorded in follow-on todo 118 (automation hardening).
No change now, since the path is operator-invoked and unit-test-only in this MVP.
