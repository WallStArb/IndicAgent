<objective>
Refactor trad_PatternCompletion to fix the data flow bug, raise quality gates, restrict to trending regime, and replace the exhaustion-boosted single-factor confidence with a 4-factor intrinsic composite.

Purpose: PatternCompletion has 897K historical firings, most on marginal I5 confidence (above the low 0.50 threshold). The current formula multiplies I5 confidence by 0.9 then applies apply_exhaustion_boost — meaning exhaustion state (an extrinsic regime state) inflates confidence above the I5 detector's own score. The data flow bug means pattern fields (pattern_name, pattern_raw_confidence, pattern_count) are not persisted as structured numeric fields — they exist only in string supporting_factors, making them unavailable as ML features. Fixing the threshold (0.70), restricting to trending regime, and adding structured field persistence corrects all three problems.

Note: PatternCompletion is NOT in Wave 0 scope (Wave 0 did not modify this file). The exhaustion_boost removal happens here. Also set requires_i6_confluence = True (removes the TODO).

Output: pattern_completion.py with threshold 0.70, regime_type "trend", structured field persistence, 4-factor confidence, requires_i6_confluence=True, shadow_only=True; unit tests.
</objective>

**Data flow fix:** Before the signal return, add explicit pattern field assignment to the signal dict:
```python
signal["pattern_name"] = pattern_name
signal["pattern_raw_confidence"] = round(best_confidence, 4)
```

These fields flow through to the i7 JSONB bucket in `intelligence_features`, making them available as structured ML features. Place these assignments after `pattern_name` and `best_confidence` are determined, before the final signal return.

**4-factor confidence formula** (replace the existing `raw_conf = best_confidence * 0.9`):
```python
# Factor 1: Pattern score — I5 confidence post-threshold (>0.70)
pattern_score = min(1.0, best_confidence)

# Factor 2: Strength relative to threshold — how far above 0.70 gate
above_threshold = (best_confidence - 0.70) / 0.30  # 0.0 at 0.70, 1.0 at 1.0
strength_score = min(1.0, max(0.0, above_threshold))

# Factor 3: Convergence — multiple patterns agreeing is stronger
convergence_score = min(1.0, len(candidates) / 3.0)

# Factor 4: Direction purity — all candidates agree on direction
if len(candidates) > 1:
    direction_purity = 1.0 if all(d == direction for _, d, _ in candidates) else 0.4
else:
    direction_purity = 0.7  # single pattern, neutral conviction

raw_conf = (
    0.45 * pattern_score
    + 0.25 * strength_score
    + 0.20 * convergence_score
    + 0.10 * direction_purity
)
```

Adjust the candidates tuple unpacking to match the actual tuple structure in the file — read how `candidates` is built before writing the direction_purity loop (it may be `(name, direction, confidence)` or a different order).

Pass raw_conf through `compose_confidence(raw_conf)` for final clamping.
