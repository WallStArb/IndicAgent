```yaml
server:
  http_listen_port: 3200
  log_level: info

distributor:
  receivers:
    otlp:
      protocols:
        http:
          endpoint: 0.0.0.0:4318

ingester:
  lifecycler:
    ring:
      replication_factor: 1

storage:
  trace:
    backend: local
    local:
      path: /var/tempo/traces
    wal:
      path: /var/tempo/wal

compactor:
  compaction:
    block_retention: 168h

usage_report:
  reporting_enabled: false
```

2. Edit `production/docker-compose.yml`:
   - Add a `tempo` service block AFTER the `grafana` service (before the `volumes:` section).
   - The service definition:

```yaml
  tempo:
    image: grafana/tempo:2.10.3
    container_name: tempo
    restart: unless-stopped
    command: ["-config.file=/etc/tempo/tempo.yaml"]
    ports:
      - "4318:4318"   # OTLP HTTP receiver — host agents send spans here
      - "3200:3200"   # Tempo HTTP API — Grafana queries traces here
    volumes:
      - ./tempo.yaml:/etc/tempo/tempo.yaml:ro
      - tempo-data:/var/tempo
```

   - Add `tempo-data:` to the `volumes:` section at the bottom (after `grafana-data:`).

Key details:
- Image pinned to `grafana/tempo:2.10.3` (not latest) per RESEARCH.md recommendation.
- `restart: unless-stopped` matches all other containers.
- Port 4318 published to host so systemd agents can reach Tempo at localhost:4318.
- Port 3200 published so Grafana container can also be verified from host.
- WAL path `/var/tempo/wal` is separate from traces path `/var/tempo/traces` (Pitfall 4 from RESEARCH.md).
- `block_retention: 168h` (7 days) — upper end of the 72h-7d discretion range; sufficient for post-mortems.
- `usage_report.reporting_enabled: false` — no telemetry to Grafana Labs.
- gRPC port 4317 deliberately NOT exposed (Python SDK uses HTTP only).

- `jsonData.httpMethod: GET` — standard for Tempo queries.
