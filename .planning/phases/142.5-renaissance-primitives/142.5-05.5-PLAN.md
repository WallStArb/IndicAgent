## Price-Volume Interaction Primitives (8)

From `docs/ideas/signal-renaissance-primitives-ohlcv.md` (Interaction Primitives section,
lines 388-453). Each primitive combines two parent features already computed earlier in the
same `compute()` pass. Parent provenance in parentheses:

| Feature | Formula | Parents (source) | Window / APR |
|---|---|---|---|
| `vol_body_product` | `body_ratio * volume_z` | body_ratio (Plan 01) x volume_z (baseline) | None |
| `ret_vol_product_fast` | `ret_lag_fast * volume_z` | ret_lag_fast (Plan 01) x volume_z (baseline) | None (inherits ret_lag_fast) |
| `price_vol_corr_fast` | rolling Pearson(`abs(ret_lag_1)`, `V`) over N | closes + volumes arrays | `feature.price_vol_corr.fast` |
| `price_vol_corr_slow` | same, over N | closes + volumes arrays | `feature.price_vol_corr.slow` |
| `range_vol_product` | `range_vs_atr * volume_z` | range_vs_atr (Plan 01) x volume_z (baseline) | None |
| `up_vol_body_diff` | `up_vol_ratio_fast - body_ratio` | up_vol_ratio_fast (Plan 02) - body_ratio (Plan 01) | None |
| `ret_vol_ratio_fast` | `ret_lag_fast / atr_z` | ret_lag_fast (Plan 01) / atr_z (baseline) | None (inherits ret_lag_fast) |
| `vol_skew_product` | `ret_skew_z * volume_z` | ret_skew_z (baseline) x volume_z (baseline) | None |

Only `price_vol_corr_fast/slow` need new APR windows (rolling correlation lookback). The other
six are O(1) scalar arithmetic on already-computed feature values — they require NO new APR key
and NO new window (spec: "no window beyond parents"). Do NOT invent APR params for the six
window-free interactions.

**Natural score ranges (spec):** products and ratios are unbounded, symmetric around 0
(cold-start fallback 0.0). `price_vol_corr_*` are bounded [-1, 1] (cold-start fallback 0.0).
`up_vol_body_diff` bounded approximately [-1, 1] (cold-start fallback 0.0).

## Wiring dependency (critical)

These are `1_interaction`-tier features: they consume the SCALAR outputs of parent primitives.
In `compute()`/`compute_batch()`, the 8 interaction assignments MUST be placed AFTER the parent
values (`body_ratio_val`, the `volume_z` output, `ret_lag_fast_val`, `range_vs_atr_val`,
`up_vol_ratio_fast_val`, the `ret_skew_z` output, the `atr_z` output) are computed. Reuse the
existing scalar variables — do not recompute the parents. If a baseline scalar (e.g. volume_z)
is currently passed directly into the FeatureVector constructor without a named local, capture it
into a local variable first.

`volume_z`, `atr_z`, `ret_skew_z` are baseline features computed in `compute()`. Read `compute()`
(around line 1111) to locate the exact variable names before wiring.
