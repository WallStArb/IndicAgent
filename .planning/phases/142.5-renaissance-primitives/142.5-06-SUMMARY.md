# Phase 142.5 Plan 06: APR Entries + Schema Migration + Feature Registry Seeding Summary

remaining non-breakout APR parameters, added the 77 remaining non-breakout

  10 `feature.breakout.*` keys (54 unique keys total, each appearing exactly
  twice in the file).
- **Task 2:** Added 77 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` statements
  covering every non-breakout Renaissance category (Bar Anatomy, Lagged
  Returns, Open-to-Close Split, Temporal Coordinates + month_sin/cos, Volume
  Structure, Return Distribution, Realized Variance, Alternative Volatility,
  Volatility Dynamics, Price-Volume Interactions), each `DOUBLE PRECISION`

  the pre-existing 61 baseline test columns + this migration's 91 total new
  columns (77 non-breakout + Plan 05's 14 breakout) equals exactly the 152
  dataclass fields with zero missing and zero extra names.

  section — the 77 non-breakout rows from this plan's scope AND Plan 05's 14
  breakout rows (Plan 05 deliberately left the registry unseeded for those;
  this plan's own scope explicitly owns "the single registry-seeding home for
  the whole phase"). Mapped every category to its CHECK-constrained
  `group_name` (momentum/volume/volatility/structure/session/oscillator/
  calendar/cross_tf/macro/regime — never `"quant"`, which is a separate
  `FEATURE_VECTOR_DOMAIN` dict key, not a `feature_registry.group_name`
  value) per the plan's own category table. Set the 8 Price-Volume
  Interaction rows to `tier='1_interaction'` with `parent_features` arrays
  populated (e.g. `vol_body_product -> {body_ratio, volume_z}`) so the
  existing `trg_cascade_parent_deprecation` trigger has a concrete target.
