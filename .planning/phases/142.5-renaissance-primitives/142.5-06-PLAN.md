## feature_registry seeding (antigravity H2 — the crash fix)

`FeatureRegistryService.load()` hard-gates on `len(feature_registry rows) == _REGISTRY_ROW_COUNT`
(now 152). Migration 172 seeded the 61 baseline rows. This plan seeds the 91 new rows so DB rows == 152.

CRITICAL: feature_registry.group_name has a CHECK constraint — allowed values are ONLY
`momentum, volume, volatility, structure, session, oscillator, calendar, cross_tf, macro, regime`.
"quant" (used in FEATURE_VECTOR_DOMAIN, a separate dict) is NOT valid here. Map each category:

| Category | group_name | tier |
|---|---|---|
| Bar Anatomy | structure | 0_atomic |
| Lagged Returns | momentum | 0_atomic |
| Open-to-Close (open_ret/intraday_ret/open_vs_intraday) | structure | 0_atomic |
| Open-to-Close (session_time_pos) | calendar | 0_atomic |
| Temporal new + month_sin/cos | calendar | 0_atomic |
| Volume Structure | volume | 0_atomic |
| Return Distribution (ret_autocorr_1/5) | momentum | 0_atomic |
| Return Distribution (kurtosis/updown/streak) | volatility | 0_atomic |
| Realized Variance | volatility | 0_atomic |
| Alt Volatility | volatility | 0_atomic |
| Vol Dynamics | volatility | 0_atomic |
| Breakout Distance | structure | 0_atomic |
| Price-Volume Interactions | volume | 1_interaction (parent_features set) |

Insert columns follow migration 172 exactly: (feature_name, group_name, tier, formula_short,
normalization, linear_ready, requires_htf, status, added_phase). status='active', added_phase='142.5',
requires_htf=false (Cross-TF deferred). For the 8 `1_interaction` rows, also set parent_features arrays
(e.g. vol_body_product -> {body_ratio, volume_z}) so the cascade trigger works. ON CONFLICT
(feature_name) DO NOTHING.
