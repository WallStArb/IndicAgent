## Bar Anatomy Ratios (8 primitives)

| Feature | Formula | Range | APR Key |
|---|---|---|---|
| `body_ratio` | `(C - O) / (H - L)` | [-1, 1] | None |
| `upper_wick_ratio` | `(H - max(O,C)) / (H - L)` | [0, 1] | None |
| `lower_wick_ratio` | `(min(O,C) - L) / (H - L)` | [0, 1] | None |
| `range_vs_atr` | `(H - L) / ATR_N` | unbounded | None (uses existing ATR) |

## Open-to-Close Split (4 primitives) — NEW, verified absent from codebase

From signal-renaissance-primitives-ohlcv.md (Open-to-Close Split section, lines 254-268):

| Feature | Formula | Range | APR Key | Domain |
|---|---|---|---|---|
| `open_ret` | `log(O_t / C_{t-1})` | unbounded | None | quant |
| `intraday_ret` | `log(C_t / O_t)` | unbounded | None | quant |
| `open_vs_intraday` | `open_ret - intraday_ret` | unbounded | None | quant |
| `session_time_pos` | `clamp((bar_ts - session_open) / session_length, 0, 1)` | [0, 1] | None | calendar |

**Deviation from source spec, decided explicitly (Round 2 review M3):** the source doc
(`signal-renaissance-primitives-ohlcv.md`) describes `session_time_pos` as a discrete
`bar_index_in_session / total_session_bars` ratio. This plan implements a continuous timestamp
fraction instead — `clamp((bar_ts - session_open) / session_length, 0.0, 1.0)` — because the
discrete formula requires knowing `total_session_bars`, which is timeframe-dependent (a 5m bar and
a 1h bar have different session bar counts) and would require extra config plumbing per TF. The
continuous formula is TF-independent and numerically equivalent in the limit. `session_time_pos`
is pure timestamp arithmetic (no OHLCV). Derive the session-open boundary the same way the existing
calendar helpers do (grep for `in_ny_session` / `opening_range` in feature_factory.py to reuse the
session boundary logic). No APR key needed.

## Existing helper pattern (feature_factory.py ~line 240)

`_bar_close_pos(high, low, close, eps=1e-10)` returns `(close - low) / (high - low + eps)`, 0.5
when high == low. Epsilon-guarded, pure, docstring with formula + range. Replicate this style.

## Cold-start contract (critical — antigravity H1)

`FeatureVector` is a frozen dataclass with NON-optional fields; the constructor requires every
field. `_cold_start_vector()` (feature_factory.py ~line 1506) explicitly constructs FeatureVector
with a kwarg for every field. EVERY new field this plan adds MUST get a neutral fallback there or
the first cold-start bar (history < 2) raises TypeError and crashes the pipeline daemon.
