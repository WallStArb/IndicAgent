# Phase 52.6 Plan 03: ProcessManifest — Replace AgentRegistry Summary

One-liner: ProcessManifest replaces singleton AgentRegistry with an explicit-DI topology container providing per-agent health, topic union, and coordinated lifecycle via asyncio.gather.

### ProcessManifest API

```python
manifest = ProcessManifest([agent_a, agent_b])

manifest.topology()          # DAG dict: {name: {consumes, produces, lag_threshold}}
manifest.health()            # {name: {"running": bool}}
manifest.topics_consumed     # set union across all agents
manifest.topics_produced     # set union across all agents
await manifest.start_all()   # asyncio.gather(*[a.start() ...])
await manifest.stop_all()    # asyncio.gather(*[a.stop() ...])
await manifest.validate_topics(admin_client)  # NotImplementedError (Phase 52.7)
```

Duplicate agent names raise `ValueError` at construction time — fail-fast, not silent override.

### Why DI Over Singleton

AgentRegistry used `__new__` to enforce a global singleton. ProcessManifest is constructed with an explicit agent list — one per systemd service process. This makes the dependency graph inspectable, tests don't require singleton reset between runs, and multiple processes can each have their own manifest without interference.
