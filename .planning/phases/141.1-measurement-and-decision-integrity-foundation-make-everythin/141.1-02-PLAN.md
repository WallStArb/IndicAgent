<objective>
`feature_ic_scores.regime` currently mixes two disjoint label vocabularies in one column with no scope qualifier: the 9 cross-sectional labels from `market_regimes` (e.g. `high_bull`, `low_bear`) and the 5 per-symbol HMM labels from `feature_vectors.regime` (e.g. `trending_up`, `ranging`), plus the `_pooled` cross-regime sentinel. A consumer that filters on `regime` cannot tell which system produced a row. Before Phase 142A stratifies ensemble IC by regime, this ambiguity must be resolved so no measurement is done against labels of unknown provenance.

Add a `regime_scope` column that disambiguates `cross_sectional` vs `symbol_hmm` vs `pooled`, write it correctly from `ic_engine`'s three insert paths, and backfill existing rows. Scope is derived from the label SOURCE (which array/provenance the label came from), never inferred from the label string — a pure resolver owns the insert-time decision, and the historical backfill drives off the existing `regime_label_source` provenance column so per-symbol HMM rows keep their true scope.

Partial-corpus note: if run against a partially-built Phase B corpus, the migration backfills whatever rows exist correctly — scope resolves per-row from `regime_label_source`, independent of how complete the corpus is; it does not require full corpus completion.

Tightly scoped per the roadmap: this plan ONLY adds and populates the column. It does NOT stop writing per-symbol-HMM rows, does NOT delete the HMM regime subsystem (todo 026 owns that evidence-gated decision), and does NOT change the equity_regime_model causality (already causal per todo 026 P1a). No consumer read path changes — the column is purely additive.
</objective>
