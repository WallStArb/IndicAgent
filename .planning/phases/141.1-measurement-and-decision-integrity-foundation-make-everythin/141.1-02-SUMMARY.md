# Phase 141.1 Plan 02: regime_scope Column Summary

**Added a NOT-NULL, CHECK-constrained `regime_scope` column to `feature_ic_scores` that disambiguates the 9-label cross-sectional (`market_regimes`) vocabulary from the 5-label per-symbol HMM (`feature_vectors.regime`) vocabulary and the `_pooled` sentinel, backfilling 256,566 existing rows from the `regime_label_source` provenance column and wiring a pure `_resolve_regime_scope()` resolver into all three of `ic_engine`'s INSERT paths.**

## Decisions Made
- Backfill CASE expression derives `regime_scope` from `regime_label_source` (the existing provenance column), matching the exact mapping specified in the plan: `regime='_pooled' -> pooled`; `symbol='POOLED' OR regime_label_source='market_regimes' -> cross_sectional`; `regime_label_source='forward_filter' -> symbol_hmm`; else `cross_sectional`. This was the strongest consensus review finding (Codex + AGY) — a bare pooled/non-pooled split would have misclassified live DIA/EEM/SPY `forward_filter` rows.
- `cross_sectional` is computed once per `(symbol, tf)` call as `mr_dict is not None`, immediately after the existing `if mr_dict is not None:` branch point (line ~785), and reused for every regime pass in that call — avoids recomputing or risking drift between passes.
- Context-feature pooled and cross-sectional insert sites use scope literals (`"pooled"`, `"cross_sectional"`) directly rather than calling the resolver, since those sites are unconditionally one scope by construction — the resolver is reserved for the per-symbol path where `is_pooled` varies per regime pass.
