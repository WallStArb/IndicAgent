<objective>
Implement `LLMAdapter` as a pydantic-ai `FunctionModel` factory (`make_llm_adapter()`) at `src/core/ai/llm_adapter.py`. The returned FunctionModel routes pydantic-ai's structured-output request through `LLMProviderChain.generate()`, passing the result_type JSON schema as `response_format` (grammar-constrained Ollama output) and the pre-built `audit_context` (preserving the `llm_calls` trail and circuit breaking).

Purpose: This is the only novel bridge code in the phase (RESEARCH.md). pydantic-ai owns validation and retry; `LLMProviderChain` owns circuit breaking, rate limiting, budget, and audit. The bridge intercepts pydantic-ai's ToolOutput-mode request, extracts the schema, calls the chain, and wraps the raw JSON in a `ToolCallPart` that pydantic-ai validates against `result_type`.

Output: `make_llm_adapter()` returning a `FunctionModel`; per-call construction with audit_context captured by closure; unit tests covering schema extraction, response_format pass-through, audit pass-through, ToolCallPart wrapping, and the None-response path.
</objective>

Import `Any` and `TYPE_CHECKING` from typing; under TYPE_CHECKING import `WorkerContext` from `src.core.ai.worker_context`. Import from pydantic-ai: `FunctionModel`, `AgentInfo` from `pydantic_ai.models.function`; `ModelResponse`, `ToolCallPart`, `ModelRequest`, `UserPromptPart` from `pydantic_ai.messages` (verify exact paths via the read_first import probe first).

    Define `def make_llm_adapter(worker_context, system, max_tokens, timeout, audit_context) -> FunctionModel` with types `worker_context: "WorkerContext"`, `system: str`, `max_tokens: int`, `timeout: float`, `audit_context: dict[str, Any]`. Capture `chain = worker_context.llm_chain` in the closure.

    Define an inner `async def _request(messages: list, info: AgentInfo) -> ModelResponse`:
    1. Schema + tool name: default `tool_name = "final_result"`, `schema = None`. If `info.output_tools` is non-empty, set `tool = info.output_tools[0]`, `tool_name = tool.name`, `schema = tool.parameters_json_schema`.
    2. Prompt extraction: iterate `reversed(messages)`; for each `ModelRequest`, scan its `.parts` for the last `UserPromptPart` and take its `.content` as the prompt; break once found.
    3. Build a `response_format` value from `schema` suitable for litellm/Ollama JSON-schema grammar (litellm expects an OpenAI-style `{"type": "json_schema", "json_schema": {"name": tool_name, "schema": schema}}` wrapper). If `schema is None`, pass `response_format=None`.
    4. Call `raw = await chain.generate(prompt=prompt, system=system, max_tokens=max_tokens, timeout=timeout, audit_context=audit_context, response_format=response_format)`. Do NOT call litellm/acompletion directly (D-06, anti-pattern).
    5. If `raw is None`, return `ModelResponse(parts=[])` (pydantic-ai will surface this as a model behavior error which the agent's compute() wrapper converts to neutral).
    6. Otherwise return `ModelResponse(parts=[ToolCallPart(tool_name=tool_name, args=raw, tool_call_id=str(uuid4()))])`. Pass `raw` (the JSON string) directly as `args` — do NOT json.loads it first (Pitfall 4). Import `uuid4` from uuid.

    Return `FunctionModel(_request)`. Add a module + function docstring noting the FunctionModel is single-use per `_run_typed()` call (Pitfall 3 — audit_context is closured at construction, so it must be rebuilt per call).
  </action>
