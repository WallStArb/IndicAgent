<threat_model>
Attack vectors analyzed for AgentDeps dependency container:

**1. LLM Prompt Injection via signal_context**
- Threat: Malicious signal_context (e.g., crafted market data) attempts to influence agent behavior
- Mitigation: signal_context is read-only within AgentDeps (frozen=True); agents cannot modify source context
- Validation: signal_context constructed internally by AIContext factory, not from LLM output

**2. Dependency Injection Attacks**
- Threat: Adversarial AgentDeps with poisoned db_pool or memory_client
- Mitigation: AgentDeps constructed internally by PydanticAIAdapter._build_deps(); agents receive validated container
- Validation: db_pool and memory_client are None by default; only set by trusted service layer

**3. Resource Exhaustion via memory_client**
- Threat: Unbounded memory recall requests exhaust Ollama VRAM or database connections
- Mitigation: Memory latency gated (MEM-04: 50ms p95); memory_client behind feature flag
- Validation: ZEP_MEMORY_ENABLED=false by default; opt-in after shadow validation

**4. Data Exfiltration via llm_chain**
- Threat: Prompts constructed from AgentDeps leak sensitive patterns (symbol names, regime configs)
- Mitigation: llm_chain is existing infrastructure; no new data paths introduced
- Validation: Prompts already logged to llm_calls table; AgentDeps adds no new fields

**5. Type Confusion Attacks**
- Threat: Malicious caller passes wrong types to AgentDeps constructor
- Mitigation: Python type hints + TYPE_CHECKING imports catch errors at dev/test time
- Validation: Unit tests verify correct type construction; frozen=True prevents runtime mutation
</threat_model>
