<objective>
Create `IndicAgentModel`, a custom Pydantic AI `Model` that is the BRIDGE between Pydantic AI's execution engine and IndicAgent's invariants. Pydantic AI normally owns the LLM call; IndicAgent requires every LLM call to be audited to `llm.calls`. `IndicAgentModel` resolves that tension: it uses Pydantic AI's native `LiteLLMModel` as the inner engine (so structured output, auto-retry, tool calling all work), then publishes the IndicAgent audit record after each request via `LLMProviderChain._publish_audit`.

Purpose: This is the architectural keystone the cross-AI review flagged as unresolved. With `IndicAgentModel`, `agent.run()` and the audit trail coexist — no bypass.
Output: `src/core/ai/indicagent_model.py` (new) + unit tests.
</objective>

Create `src/core/ai/indicagent_model.py`. `IndicAgentModel` subclasses the Pydantic AI `Model` abstract base (from `pydantic_ai.models`). Constructor signature:

```python
def __init__(self, llm_chain: LLMProviderChain, audit_context: dict[str, Any]) -> None:
```

Implementation requirements (adapt names to the verified installed API from <read_first>):

1. Store `self._llm_chain = llm_chain` and `self._audit_context = audit_context`.
2. Build the inner engine once: `self._inner_model = LiteLLMModel(<provider_model_string>, ...)` where the model string is taken from `llm_chain._inner.providers[0]` (already litellm-formatted, e.g. `ollama/gemma4:e4b`) and the api_base from `settings.ollama_base_url` (read via `llm_chain._settings`). Pass whatever provider/base-url kwargs the installed `LiteLLMModel.__init__` actually accepts.
3. Implement the required abstract members. At minimum:
   - `model_name` property → return the inner model's name (or the provider string).
   - `system` property → return the provider family string (e.g. `"litellm"` or the value the inner model exposes).
   - `async def request(self, messages, model_settings, model_request_parameters)` (match the installed signature) →
     a. Select provider + circuit breaker: `provider = llm_chain._inner.providers[0]`; `cb = llm_chain._inner._circuit_breaker_for(provider)`. If `not cb.allow_request()`: raise a `ModelHTTPError`/`RuntimeError` ("circuit open for {provider}") so the run fails loudly rather than silently bypassing infra.
     b. Acquire the rate limiter: `limiter = llm_chain._rate_limiters.get(provider) or next(iter(llm_chain._rate_limiters.values()), None)`; `if limiter: await limiter.acquire(tokens=<max_tokens-from-model_settings-or-512>)`.
     c. `t0 = time.monotonic()`; `response = await self._inner_model.request(messages, model_settings, model_request_parameters)`; `latency_s = time.monotonic() - t0`.
     d. On exception: `cb.record_failure()` then re-raise. On success: `cb.record_success()`.
     e. Extract token usage + text: get `tokens` from `response.usage` (total_tokens; fall back to a `len//4` estimate) and the response text from the response parts (concatenate text parts).
     f. Publish audit: `await self._llm_chain._publish_audit(self._audit_context, provider, latency_s, tokens, response_text, provider)`. Wrap in try/except logging only — a publish failure must NOT fail the inference (matches `_publish_audit`'s own behavior, which already swallows internally; this outer guard covers the extraction step).
     g. Return the Pydantic AI `response` object unchanged so the Agent can parse structured output.
   - Implement `request_stream` only if the installed Model ABC marks it abstract; otherwise omit. (Streaming not used in Plan 04.)
4. Threat-model note in a docstring: each call to `request()` (including Pydantic AI's internal auto-retry on validation failure) publishes its own audit record because `request()` is invoked per attempt. If the installed API exposes a retry/attempt counter, add it to the audit_context copy as `retry_count`; otherwise document that each attempt is a distinct audit row sharing the same `call_id`.

Use `structlog.get_logger(__name__)`. Import `LiteLLMModel` from `pydantic_ai.models.litellm`. Use `from __future__ import annotations` + TYPE_CHECKING for `LLMProviderChain`.

<threat_model>
- **Audit bypass (PRIMARY)**: This plan EXISTS to close it. Pydantic AI's `agent.run()` delegates the LLM call to `IndicAgentModel.request()`, which always calls `_publish_audit` on success. Test `test_audit_published_after_request` proves it. Each retry attempt re-enters `request()` → its own audit row.
- **pydantic-ai API drift**: <read_first> mandates verifying the installed Model ABC signature before coding; Plan 05 pins `>=1.0,<2`. Develop/test against the real installed version, not training-data recollection.
- **Circuit-breaker / rate-limiter bypass**: `request()` consults `cb.allow_request()` and the rate limiter from `llm_chain` before calling the inner model — reusing the exact module-level breakers in `litellm_backend.py`. Test `test_circuit_open_provider_skipped` proves a closed circuit blocks the call.
- **Prompt injection**: prompts are built upstream from pipeline-controlled `AIContext` (no user strings). IndicAgentModel forwards messages verbatim; no new injection surface.
- **Shadow leak**: N/A here (shadow filtering is Plan 05).
- **Audit publish failure cascading into inference failure**: extraction + publish wrapped in try/except (log only) — a Kafka hiccup must not drop a valid LLM response.
</threat_model>
