Database driver (decided here, not left open): this repo's standard for async database access is
**asyncpg**, not psycopg — `src/core/database_manager.py`, `src/config/config_service.py`,
`src/core/agent/base_batch.py` and every async service import `asyncpg`. The only psycopg usage in
`src/config/` is the SYNC path inside `settings.py` (lines 503, 614). Since `onboard_instrument()`
must be `async def` (it awaits `qualify_instrument()`), `conn` is typed
`asyncpg.Connection`. Concrete consequences the implementation must honor:

- Placeholders are asyncpg positional `$1, $2, ...` with values passed as trailing positional
  arguments to `await conn.execute(sql, *args)` / `await conn.fetchval(sql, *args)`. asyncpg has
  no `%(name)s` named-placeholder form; do not write one.

  `create_pool()` has it; a bare `asyncpg.connect()` does not (root CLAUDE.md gotcha). The

  `src.core.database_manager._setup_codecs(conn)` on a bare one, before writing
  `contract_details`.

Create `src/config/instrument_onboarding.py` exporting `onboard_instrument`, `OnboardResult`,
and `OnboardingRejected`.

Do NOT import `src/providers/ibkr.py` from this module — `ibkr.py` already imports settings and
a reverse import would create a cycle, and the Ring rule keeps provider specifics inside
`src/providers/`. Instead declare a minimal `typing.Protocol` (e.g. `InstrumentQualifier`)
with the single member `async def qualify_instrument(self, instrument, *, ibkr_symbol: str = "", trading_class: str = "") -> bool`
and accept the provider as an injected parameter. This also makes the unit tests provider-free.

Signature:
`async def onboard_instrument(conn: asyncpg.Connection, instrument, *, qualifier, tags, timeframes, metadata=None, metadata_skip_reason="", compute_eligible=False, live_tradeable=False) -> OnboardResult`

- `conn`: an open **`asyncpg.Connection`**, annotated as such, owned by the caller. Type it
  explicitly — do not accept an untyped `conn` and do not accept a sync psycopg connection.
  Running blocking psycopg cursor calls inside this `async def` would stall the event loop, and
  mixing the two drivers' placeholder styles is a silent correctness hazard. asyncpg is this
  repo's async standard (see `<interfaces>`).
- **Transaction contract.** The helper wraps all of its writes in exactly one
  `async with conn.transaction():` block and calls **no** `commit()`, `rollback()`, `BEGIN`,
  `COMMIT` or `ROLLBACK` of its own — those verbs must not appear in the module. asyncpg's
  `Connection.transaction()` opens a top-level transaction when the connection is idle and a
  `SAVEPOINT` when the connection is already inside one, so:
  - a single-symbol caller gets all-or-nothing atomicity across the four tables, and
  - a bulk caller (Plan 08's `--commit` loop, Plan 12's run) may hold its own outer
    `async with conn.transaction():` across hundreds of onboardings, and one rejected symbol
    rolls back only that symbol's savepoint while the outer batch stays open and under the
    caller's control.
  The helper must never close the caller's transaction out from under it — partial onboarding
  and stolen commit boundaries are both failures this helper exists to prevent.
- `tags`: a sequence of `(tag, weight, evidence_dict)`. Before writing, verify every tag exists
  in `tag_vocabulary`; raise `OnboardingRejected` naming the missing tags if not (ITR rule: a
  tag must be registered vocabulary, not invented at insert time).
- `timeframes`: defaults to `("5m", "15m", "1h", "1d")`.
- `metadata`: a dict with keys `listing_date`, `underlying_index`, `issuer`, `description`.
- `compute_eligible`: defaults to **False** — a newly onboarded symbol has no history yet, so
  it is backfill-eligible but not compute-eligible until Plan 12 promotes it. This is the
  concrete reason Plan 02's 3-way split exists; do not default it to True.
- `live_tradeable`: defaults to **False** and this plan provides no path to set it True.

Order of operations, all inside the transaction:

1. **Qualification gate (V5 / T-174-02).** `await qualifier.qualify_instrument(instrument)`.
   If it returns False, raise `OnboardingRejected` naming the symbol and stating that the
   ticker did not resolve to a real IBKR contract. No DB write happens. This is the de facto
   allowlist standing between an externally-downloaded ticker string and the `instruments`
   table — never bypass it, and never add a `force=True` escape hatch.
2. **Metadata mandate (D-08).** If `metadata` is None, require `metadata_skip_reason` to be a
   non-empty string; raise `ValueError` naming both parameters if it is empty. When a reason is
   supplied, emit `structlog` event `instrument_onboarding.metadata_skipped` carrying `symbol`
   and `reason` at WARNING level. A silent omission must be unrepresentable in this API.
3. `INSERT INTO instruments (symbol, base, contract_details, is_active, compute_eligible, live_tradeable) VALUES (%(symbol)s, ...) ON CONFLICT (symbol) DO NOTHING`
   with `is_active = true`. Build `contract_details` from the `Instrument` using exactly
   migration 296's ten-key set.
4. `INSERT INTO instrument_tags (symbol, tag, weight, source, evidence) VALUES (...) ON CONFLICT (symbol, tag) DO NOTHING`
   with `source = 'human'` for every tag written here (these are definitional seed priors, not
   measurements — `TagCalibrator` owns `source='empirical'` rows and must never be
   impersonated).
5. `INSERT INTO instrument_metadata (...) ON CONFLICT (symbol) DO UPDATE SET listing_date = EXCLUDED.listing_date, underlying_index = EXCLUDED.underlying_index, issuer = EXCLUDED.issuer, description = EXCLUDED.description, updated_at = NOW()`
   when `metadata` is supplied.
6. One `backfill_status` upsert per timeframe using the exact SQL from
   `services/backfill_feature_factory.py`, with `status='pending'` and `fetch_complete=false`.

Every statement is a constant SQL string with asyncpg positional placeholders (`$1`, `$2`, ...)
and values supplied as trailing positional arguments to `await conn.execute(...)`. Every database
call is awaited. There must be zero f-string or `%`-format SQL construction in this module — a
symbol string originating from a downloaded holdings file reaches the database only as a bound
parameter. Rewrite the `backfill_status` upsert and the migration-296 INSERT shapes named above
from their psycopg `%(name)s` form into asyncpg `$n` form; the SQL semantics are unchanged, only
the placeholder syntax is.

The `tag_vocabulary` existence check is `await conn.fetch("SELECT tag FROM tag_vocabulary WHERE tag = ANY($1::text[])", list(tag_names))` — one query for all tags, not one per tag.

Return `OnboardResult` (a dataclass) carrying `symbol`, `qualified: bool`,
`instrument_inserted: bool`, `tags_inserted: int`, `metadata_written: bool`,
`backfill_rows_seeded: int`. The caller aggregates these into a single end-of-run summary log
— this helper must not log once per symbol (CLAUDE.md's no-per-row-logging-in-a-corpus-loop
rule; Plan 12 calls this hundreds of times).

Use `except X as error:` throughout. Module docstring names todo 282, todo 274, Phase 174 D-08,
and states that this is the only sanctioned add-an-instrument path.
