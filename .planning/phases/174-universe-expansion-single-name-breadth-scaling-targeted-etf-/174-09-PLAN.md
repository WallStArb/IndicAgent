<objective>
Eliminate the two remaining whole-cell allocations in `_compute_one_cross_sectional_cell` that
defeat Plan 05's disk-bounded accumulation: the `np.corrcoef(X_nd.T)` float64 copy inside
`_cluster_features`, and the `X_nd = X_raw[:, cluster_input_mask]` boolean-column-index copy.
Then measure and record what allocations proportional to cell size still remain.

Purpose: Plan 05 stops `X_raw` from being anonymous RAM, but numpy's boolean fancy-indexing
always materializes a fresh copy — even from a memmap — so `X_nd` re-allocates most of the cell
one line later. Worse, and unnamed by todo 371 or RESEARCH.md, `_cluster_features` then calls
`np.corrcoef(X_nd.T)`, which internally casts to float64: at the 15M-row `alpha.ic.max_cell_rows`
ceiling with ~250 features that is a 30GB transient on a 29GB machine — larger than the
accumulation Plan 05 just fixed, and the likeliest true cause of the 2026-09-07 OOM. Declaring
D-04 done after Plan 05 would leave the dominant allocation in place, which is precisely the
"fixed the named symptom, missed the real one" pattern `docs/foundation/performance-investigation-sop.md`
exists to prevent.

Output: a blocked two-pass streaming correlation, a column-wise `X_nd` build, migration 340's
block-size APR key, and equivalence tests proving cluster labels are unchanged.
</objective>

Two changes, both inside `services/ic_engine.py`.

**(a) Replace `np.corrcoef` with a blocked two-pass streaming correlation.**

Add a module-level helper (name it descriptively, e.g. `_streaming_feature_correlation(X, mask, row_block)`)
that computes the Pearson correlation matrix over the mask-selected columns of `X` without ever
materializing a float64 copy of the whole array:

- Pass 1: accumulate per-column sums in float64 over row blocks of `row_block` rows, deriving
  column means. Read each block as a basic row slice (`X[start:stop]`, a view on a memmap) and
  select columns inside the block only.
- Pass 2: accumulate the centered Gram matrix `Σ (x-μ)(x-μ)ᵀ` in float64 over the same row
  blocks, giving the covariance, then normalize by the square root of the diagonal outer product
  to get the correlation matrix.

Two passes, not the single-pass `Σx²`-minus-`(Σx)²` shortcut: over tens of millions of rows of
z-scored features the single-pass form suffers catastrophic cancellation, and the existing code
at line 3621 already documents this module's precision stance (`np.std(..., dtype=np.float64)`
chosen specifically because "variance is sensitive to accumulation precision in a way rank order
is not"). The extra disk pass is cheap relative to a 30GB allocation.

Peak transient for this step becomes `row_block x n_features_nd x 8` bytes plus the
`n_features_nd²` accumulator — at the defaults roughly 2GB and 0.5MB respectively, versus
`n_rows x n_features_nd x 8` today. Record that arithmetic in the helper's docstring.

Change `_cluster_features` to accept a precomputed correlation matrix rather than the raw array:
`_cluster_features(corr: np.ndarray, cluster_max_corr: float) -> np.ndarray`, keeping every line
from `np.nan_to_num` onward byte-identical, and keeping the `n < 2` early exit (now on
`corr.shape[0]`). Update both call sites. This keeps the linkage/fcluster logic untouched, so any
behavior change can only come from the correlation values themselves — which Task 3 pins.

**(b) Build `X_nd` column-by-column instead of by boolean fancy-index.**

Replace `X_nd = X_raw[:, cluster_input_mask]` with a construction that never issues a fancy index
over the full array. When `X_raw` is disk-backed (Plan 05's mode is active for this cell), build
`X_nd` as a second `np.memmap` of shape `(n_raw, cluster_input_mask.sum())` in
`config.memmap_scratch_dir`, filled by copying one source column at a time

`n_raw x 4` bytes, about 60MB at the 15M-row ceiling). When `X_raw` is in-RAM (small cell), keep
today's single boolean-index expression — it is correct and cheaper at that size. Gate on the
same `disk_backed` decision Plan 05 records for the cell rather than re-deriving a threshold.

**`X_nd` lifecycle — route teardown through Plan 05's existing `finally`, and only after the last
reader.** Do not introduce a second, independent cleanup path and do not add a nested
`try`/`finally` around the `X_nd` build alone: a `finally` scoped tighter than the cell would
unlink `X_nd` while the per-scale loop is still reading `X_sub_nd`, which is a view over it, and
that is the same premature-close failure Plan 05's `finally` scoping exists to prevent — one
array over.

Concretely: `_compute_one_cross_sectional_cell` is called from inside Plan 05's `try`, so
register `X_nd`'s teardown so it fires from that same `finally`. Either
(i) allocate `X_nd` through `Float32ChunkAccumulator`'s disk-backed machinery and hand its
`close()` up to the caller, or (ii) allocate a direct `np.memmap` via the same
`tempfile.NamedTemporaryFile(dir=config.memmap_scratch_dir, suffix=".memmap", delete=False)`
pattern Plan 01 uses and register a closure that closes the mmap, closes the `NamedTemporaryFile`
handle (the fd-leak fix Plan 01 landed applies identically here), and unlinks the path. Option
(ii) is acceptable only if its teardown runs from Plan 05's `finally` — pass the cleanup callable
or an `ExitStack` down, do not let `_compute_one_cross_sectional_cell` clean up its own `X_nd`
before returning while the caller may still hold derived state.

Whichever option is used, after this task the file must satisfy: exactly one `finally:` block in

Preserve exactly: `n_skipped` accounting, the `if X_nd.shape[1] == 0: return [], n_skipped`

Use `except X as error:`. Do NOT change `alpha.ic.max_cell_rows`. Do NOT add any

5. **Single-column and zero-column inputs.** `n < 2` returns `np.ones(n, dtype=int)` and a
   zero-column mask does not raise.
6. **Numerical stability on a large-mean input.** Columns with a large offset relative to their
   variance (the catastrophic-cancellation case the two-pass form exists to handle) still match
   `np.corrcoef` within `atol=1e-6` — a single-pass implementation would fail this case, so it
   pins the design decision.
7. **Column-wise X_nd equals the boolean-index result.** Build a small `X_nd` via the new

   change labels. Construct column pairs whose true Pearson correlation is deliberately placed at
   `cluster_max_corr - delta`, exactly `cluster_max_corr`, and `cluster_max_corr + delta` for
   `delta` in `(1e-3, 1e-5, 1e-7)`, by generating `y = rho*x + sqrt(1-rho**2)*z` with orthonormal
   `x`/`z` so `rho` is exact by construction rather than approximate. For each case assert

   Run this at `row_block` values of 1, 7 and full-length so block-size does not interact with
   the boundary.
9. **Documented boundary-tolerance policy.** If any `delta` in case 8 cannot hold exact label
