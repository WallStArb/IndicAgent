**Method to match exactly** (same document):
- Window 2018-01-01 to 2026-09-02 (2,175 trading days), `timeframe='1d'`.
- Returns `ln(close[t] / close[t-1])`, close-to-close. This is a descriptive correlation-structure
  characterization, NOT an IC/alpha measurement — the `executable_open_to_open` invariant that
  governs `forward_returns`/`ic_engine` does not apply here and must not be imported. Say so in
  the script's docstring, so a future reader does not "fix" it into a violation of the method.
- Coverage filter: drop symbols with <95% daily-bar coverage over the window.
- Pairwise correlations via `pandas.DataFrame.corr(min_periods=20)`; report mean and median of the
  strict upper triangle.
- PC variance share via `np.linalg.eigvalsh` on the filled correlation matrix; PC1 share and PC1-3
  share as eigenvalue fractions of the total.
- `n_eff = N / (1 + (N - 1) * avg_pairwise_corr)`.
- Regime conditioning: inner-join the daily return rows to `market_regimes` on date, then
  recompute the whole set of statistics within each `regime_label` subset.

**Script conventions to follow** — `scripts/analysis/instrument_compute_eligibility_audit.py` is
the in-phase analog: `sys.path.insert(0, str(Path(__file__).resolve().parents[2]))` bootstrap,
`setup_service_logging("logs/<script_name>.log")`, `structlog.get_logger(__name__)`, `argparse`,
accumulate-then-log-once (never per-symbol logging over a multi-hundred-symbol cohort),
parameterized SQL only, `except X as error:`.

**The two D-10 thresholds, fixed by CONTEXT.md before any pilot data exists:**
- unconditional average pairwise daily-return correlation ≤ **0.10**
- `high_bear`-conditioned average pairwise correlation ≤ **0.30**

Both must clear. Either failing means the full-scale draw does not proceed.

**Why the gate uses raw correlation, not market-factor-residualized correlation (verified against
the live `ic_engine.py` source, not assumed):** `services/ic_engine.py` computes IC via
`rankdata(X_raw_block[idx], axis=0)` / `rankdata(X_sub_nd, axis=0)` — `numpy`'s `axis=0` ranks
each feature column across ALL rows in the pooled `(tf, regime)` cell, i.e. across every symbol
AND every timestamp in that cell together, not within each timestamp's cross-section separately.
A closer read confirms ic_engine never demeans or z-scores per-timestamp before this ranking step.
This means a common market-wide move on a given day is NOT automatically netted out of the pooled
rank correlation that becomes IC — raw co-movement between symbols directly pollutes it. Raw
pairwise correlation is therefore the metric that actually corresponds to what limits ic_engine's
realized effective breadth; a SPY-beta-residualized correlation (computed once, informally,
during this phase's planning: unconditional avg corr dropped from 0.317 raw to 0.042
residualized, n_eff rose from 3.10 to 20.05 for the existing 117-name book) measures something
real but does not match ic_engine's own methodology, so it must not become the gate's primary
metric — it is reported for interpretability only, per the truth above.
