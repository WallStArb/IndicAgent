<objective>
Build the market-cap-stratified random sampler that turns Plan 04's validated Russell 3000
population into the concrete symbol list this phase onboards (D-02), with an APR-seeded RNG so
the draw is reproducible and auditable, and with the target sample size left deliberately unset
until Plan 11 measures what the infrastructure actually supports (D-01).

Purpose: D-02's rationale is that hand-picking promising small-caps is selection bias by
construction — it smuggles in a prior about where signal lives before any measurement happens.
The current 128 single-names are almost entirely large/mega-cap (only 1 tagged `eq_small_cap`),
which is exactly the segment where `alpha_score_residual_single_security_15m` was measured DEAD.
A full-population definition plus unbiased stratified sampling tests the down-cap hypothesis
empirically instead of assuming it. That property only holds if the draw is mechanical and
reproducible, which is what the APR-seeded RNG and the recorded population file deliver.

Output: migration 339 (applied live + committed), a dry-run-capable sourcing script, and unit
coverage proving reproducibility and stratum balance. Plan 12 runs it for real.
</objective>

Create `scripts/infrastructure/universe_expansion_stratified_sourcing.py` exporting
`stratified_sample` and `main`.

`stratified_sample(population: pd.DataFrame, *, target_size: int, bucket_count: int, seed: int, exclude: set[str]) -> pd.DataFrame`
— pure, no I/O, so it is unit-testable without a database:
- Raise `ValueError` naming the parameter if `target_size <= 0` — this is the D-01 guard, and it
  must fire before any draw, not after.
- Drop symbols in `exclude` (symbols already in `instruments`) from the population BEFORE
  bucketing, so the strata are computed over the addressable population rather than over a
  population the draw can only partially use.
- Bucket by `market_cap` using `pandas.qcut(population["market_cap"], q=bucket_count, labels=False, duplicates="drop")`.
  Do not hand-roll quantile boundaries.
- Allocate `target_size` across buckets as evenly as possible, distributing the remainder to the
  lowest-numbered buckets deterministically (never randomly — the allocation must not consume
  RNG draws, or the sample stops being reproducible under a changed target size). If a bucket
  holds fewer names than its allocation, take all of them and redistribute the shortfall to
  buckets that still have capacity, iterating until the allocation is satisfied or the population
  is exhausted.
- Draw within each bucket with a single `np.random.default_rng(seed)` generator created once and
  used across all buckets in ascending bucket order, so the draw sequence is fully determined by
  (seed, population, target_size, bucket_count).
- Return a frame with columns `symbol`, `name`, `market_cap`, `cap_bucket`.

`main()` — argparse entry point wiring it together:
- `--holdings <path>` (required), `--dry-run` (default True), `--commit` to actually write.
  Writing must be opt-in, not opt-out.
- Fetch `alpha.universe.stratified_sample_random_state`, `alpha.universe.cap_bucket_count` and
  `alpha.universe.target_sample_size` live from `config_state` at start of run. Never hardcode
  any of the three. Fail loud with the key name if `target_sample_size` is 0.
- Load the population via Plan 04's `parse_holdings`.
- Build `exclude` from a parameterized `SELECT symbol FROM instruments` query — the sample must
  not attempt to re-onboard a symbol the corpus already has.
- Call `stratified_sample`.
- In dry-run mode: write the drawn list to a timestamped CSV under `/var/tmp/` and print a
  per-bucket summary table (bucket index, market-cap range, population count, drawn count). Make
  no database writes of any kind.
- In `--commit` mode: for each drawn symbol, build an `Instrument` with the migration-296 ten-key
  `contract_details` shape (`asset_class='equity'`, `exchange='SMART'`, `session_id` matching the
  existing single-name equity rows — read one from `instruments` rather than guessing) and call
  `onboard_instrument(...)` with `compute_eligible=False`, `live_tradeable=False`, the four
  standard timeframes, and the exposure tags chosen for a single-name equity. A symbol that
  raises `OnboardingRejected` is counted and skipped, not retried and not force-inserted — the
  qualification gate is the allowlist standing between a downloaded ticker string and the
  database (V5).
- Record the run's provenance in the output: the holdings file path and its sha256, the three APR
  values used, the exclude-set size, and the drawn-symbol count. A sample that cannot be traced
  back to a specific population file and seed is not reproducible.
- Accumulate counters and log ONCE at end of run (`n_population`, `n_excluded`, `n_drawn`,
  `n_onboarded`, `n_rejected`, per-bucket counts). Never log per symbol — this loop runs over
  hundreds of symbols and CLAUDE.md forbids per-row logging in a full-corpus loop.
- Emit `JOB_COMPLETED_TOTAL{job, status}` at exit and call `flush_and_shutdown_metrics()`.
- Use `except X as error:` throughout. All SQL uses `%(name)s` placeholders; never f-string a
  symbol into SQL.

Do NOT run this script in `--commit` mode in this plan. Plan 12 owns the real run, after Plan 11
has set `alpha.universe.target_sample_size` from a measurement.
