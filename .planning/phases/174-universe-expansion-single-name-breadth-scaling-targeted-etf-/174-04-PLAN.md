<objective>
Answer the two open data-availability questions that gate Plan 08's stratified sampling, by
inspecting real artifacts rather than assuming: (1) what columns the iShares IWV (Russell 3000
ETF) holdings export actually contains, and whether per-constituent market cap is directly
available or must be derived (RESEARCH.md Open Question 1 / Assumption A1); (2) whether
historical bars for delisted Russell 3000 constituents are obtainable from IBKR or any
reachable source at all (D-03 / todo 376 action item 1).

Purpose: D-02 makes Russell 3000 the definitional target population and a market-cap-stratified
random sample the actual backfill scope. Without a confirmed market-cap field, the stratifier
has nothing to stratify on and Plan 08 would be designed against a guess. D-03 deliberately
does not let survivorship bias block the pilot, but it does require the feasibility question be
researched in parallel so the answer exists when the fold-in decision is made — this plan
delivers that answer without touching the pilot's critical path.

Output: a reusable fetch/parse module, a unit-tested defensive parser, and a research note
recording the real file schema plus the delisted-data verdict.
</objective>

Implement `parse_holdings(path) -> pandas.DataFrame` against the schema recorded in Task 1, and
cover it with `tests/unit/scripts/test_universe_expansion_fetch_iwv_holdings.py`.

The parser must treat the file as untrusted input (T-174-03). Required behavior:

- Skip the issuer's metadata preamble using the recorded header row index; raise a
  `ValueError` naming the expected and actual header if the header row does not match the
  recorded column list — a silently changed issuer schema must fail loud, not produce a
  half-parsed population.
- Drop non-equity filler rows by the recorded asset-class/sector column value (cash, futures,
  FX forwards), and return the dropped count alongside the frame rather than discarding it
  silently.
- Validate each retained row: ticker is a non-empty string matching `^[A-Z][A-Z0-9.\-]{0,9}$`
  (uppercase, bounded length — anything else is rejected, not coerced); market cap (or its
  derivation inputs) parses to a finite positive float after stripping thousands separators and
  currency symbols. Rejected rows are counted and the count is returned; they are never
  silently coerced into the population.
- Return a normalized frame with exactly the columns `symbol`, `name`, `market_cap` — Plan 08
  depends on this narrow contract, not on the issuer's column names.
- Accumulate rejection counts and log once at the end (`n_rows_raw`, `n_filler_dropped`,
  `n_rejected`, `n_accepted`) — never one log line per row.

Unit tests use small inline CSV fixtures written to `tmp_path`, not the real download. Required
cases: preamble skipping; header mismatch raises `ValueError`; filler rows dropped and counted;
a ticker containing SQL metacharacters (`AAPL'); DROP TABLE instruments;--`) is rejected by the
regex and counted, not returned; a malformed/negative/`NaN` market cap is rejected and counted;
thousands separators and `$` are handled; the returned frame has exactly the three contract
columns.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet (issuer holdings endpoint) → local filesystem | An unauthenticated third-party file is downloaded onto the server |
| downloaded file → in-process population frame | Untrusted rows become the candidate universe that Plan 08 samples and Plan 12 writes to the database |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-174-03 | Tampering | Untrusted external holdings file driving the candidate universe | mitigate | `parse_holdings()` validates header-against-recorded-schema (loud `ValueError` on drift), enforces a `^[A-Z][A-Z0-9.\-]{0,9}$` ticker regex, requires a finite positive market cap, and counts rather than coerces rejections. Task 2 tests prove each rejection path |
| T-174-02 | Tampering | A ticker string carrying SQL metacharacters | mitigate | The ticker regex rejects it at parse time (defense in depth ahead of Plan 03's parameterized writes and `qualify_instrument()` allowlist); Task 2 includes the explicit injection-string case |
| T-174-12 | Spoofing | A substituted or MITM'd holdings file silently changing the sampled population | mitigate | Download over HTTPS from the issuer's own domain; the raw bytes are persisted to disk before parsing so the exact file behind any given sample stays auditable; schema drift fails loud rather than silently reshaping the population |
| T-174-13 | Information Disclosure | Outbound network request from the server | accept | A public, unauthenticated, no-API-key holdings export; no credentials, no project data leaves the host |
| T-174-SC | Tampering | package-manager installs | accept | No packages installed by this plan — `pandas` and the HTTP client are pre-existing project dependencies |
</threat_model>
