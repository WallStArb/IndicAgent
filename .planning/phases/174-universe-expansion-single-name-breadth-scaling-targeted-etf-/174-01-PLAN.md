<objective>
Give `Float32ChunkAccumulator` a disk-backed (np.memmap) accumulation mode so peak anonymous
RSS during cross-sectional cell materialization is bounded by one chunk's size rather than
the whole cell's size, and register the two APR keys that mode needs. This is the first half
of D-04's structural fix — the ic_engine wiring that consumes it is Plan 05.

Purpose: `Float32ChunkAccumulator.finalize()`'s `np.vstack(self._chunks)` currently holds both
the full chunk list AND the vstacked result in RAM simultaneously (2x the cell size). At the
182-symbol scale that OOM-killed ic_engine on 2026-09-07 (todo 371), that is the dominant
allocation. Fixing it here, in the shared class, keeps both callers on one implementation
rather than forking a parallel accumulator (the exact mistake migration 249 already corrected
once for `_check_cell_size`).

Output: migration 336 (applied live + committed), a `disk_backed=True` constructor mode with
explicit `close()` cleanup, and unit coverage proving row-identity with the in-RAM path.
</objective>

  <action>
Extend `Float32ChunkAccumulator` in `services/_batch_utils.py` with an additive disk-backed
mode. Do NOT fork a parallel class — RESEARCH.md's Don't-Hand-Roll table names that as the
specific mistake to avoid.

Constructor becomes:
`__init__(self, flush_at: int | None = None, *, disk_backed: bool = False, estimated_rows: int | None = None, n_cols: int | None = None, scratch_dir: str | None = None) -> None`

All new params are keyword-only, so every existing positional call site is unchanged.

Behavior:
- `disk_backed=False` (default): byte-for-byte the current behavior. No new branches on the
  hot path beyond a single boolean check.
- `disk_backed=True`: require both `estimated_rows` and `n_cols`; raise `ValueError` naming
  both missing-parameter names if either is falsy. Call `os.makedirs(scratch_dir, exist_ok=True)`
  before allocating anything — the class must not depend on the directory having been created
  out-of-band, or a containerized test runner or a fresh scratch mount raises `FileNotFoundError`
  at the first cell. Then allocate a
  `tempfile.NamedTemporaryFile(dir=scratch_dir, suffix=".memmap", delete=False)`, keep the handle
  on `self._tmpfile`, and allocate
  `np.memmap(self._tmpfile.name, dtype=np.float32, mode="w+", shape=(estimated_rows, n_cols))`.
  Track `self._write_offset`.
- `append_chunk(rows)`: in disk-backed mode, convert to `np.array(rows, dtype=np.float32)`,
  write it into `self._memmap[self._write_offset : self._write_offset + n]`, advance the
  offset. Empty batch is still a no-op. Raise `ValueError` (crash-loud, per CLAUDE.md "silent
  wrong answers are worse than loud crashes") if the write would exceed `estimated_rows` —
  a pre-flight estimate that undercounts must fail loud, never silently truncate the cell.
- `append_row(row)`: in disk-backed mode, buffer into `self._buf` exactly as today and route
  `_flush_buf()` through the same memmap write path, so both append modes work disk-backed.
- `finalize()`: in disk-backed mode, call `_flush_buf()` first, then return
  `self._memmap[: self._write_offset]` — a view, no `np.vstack`, no copy. Return `None` (and
  clean up the scratch file immediately) when `self._write_offset == 0`, matching the in-RAM
  mode's empty contract.
- New public `close(self) -> None`: flush the memmap, close its underlying mmap
  (`self._memmap._mmap.close()` after dropping the array reference), THEN call
  `self._tmpfile.close()` on the `NamedTemporaryFile` handle, THEN unlink the path. Closing the
  mmap without closing the `NamedTemporaryFile` leaks one Python file descriptor per accumulator;
  across the thousands of cells in a corpus run that exhausts the process fd limit. Wrap each
  step so a failure in one does not skip the others, and use `except X as error:` with a
  structlog warning rather than swallowing silently. `close()` is idempotent (safe to call
  twice, safe to call in in-RAM mode where it is a no-op). This is what Plan 05's caller will
  invoke in a `finally` block. Also add `__enter__`/`__exit__` delegating to `close()`.

Document the memmap ownership contract explicitly in both the class docstring and `finalize()`'s
docstring, because Plans 05 and 09 depend on it and both reviewers flagged it as the phase's
highest-risk ambiguity:
- `finalize()` returns a VIEW over the memmap, not a copy.
- That view stays readable until, and only until, the caller calls `close()`.
- The caller owns `close()` and must not call it while any consumer still holds or reads the
  returned view — doing so raises `ValueError: mmap closed or invalid` at best and produces a
  platform-dependent invalid-memory read at worst.
- Therefore the caller's `try`/`finally` must span every downstream consumer of the returned
  array, not just the accumulation loop.

Use `except X as error:` for any new exception handling — never `exc`. Extend the class
docstring in the existing convention: name todo 371 and Phase 174 D-04, name why the mode is
additive rather than a fork, and state that `estimated_rows` is expected to be a conservative
upper bound (the caller's pre-flight estimate) with `finalize()` trimming to actual rows
written.

Do not import `ConfigService` here — `_batch_utils.py` stays config-agnostic; the caller
(Plan 05) reads the APR keys and passes `scratch_dir` in.
