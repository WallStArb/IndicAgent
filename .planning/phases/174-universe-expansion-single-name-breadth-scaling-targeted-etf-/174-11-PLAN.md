<objective>
Prove D-04's structural fix empirically on the exact cell that killed ic_engine, remove the 96GB
swapfile stopgap and confirm the fix holds without it, then determine the largest feasible
instrument count for the D-09 1d-only down-cap cohort and — if and only if Plan 15's D-10 gate
PASSED — write that measured number into `alpha.universe.target_sample_size` (D-01).

Purpose: D-04 explicitly rejects the "bigger box" workaround — the 96GB swapfile applied
2026-09-07 "does not survive further scale-up and is not a substitute for the structural fix."
Leaving it in place after landing the fix would hide whether the fix actually worked, and would
carry the same stopgap into a much larger universe. And D-01 forbids locking a target instrument
count before the supported scale is known: `alpha.universe.target_sample_size` is deliberately
`0`/unset until this plan measures what the infrastructure supports.
`docs/foundation/performance-investigation-sop.md` governs the method — measure before theorizing,
never trust a read-only test for a write-path question, treat chunk count and compression status
as first-class suspects.

Output: a verification document carrying real before/after numbers, a removed swapfile, and an APR
key holding a number derived from a measurement — or, on a gate FAIL, that key still at `0` with
the reason recorded.

## What D-09 changed about this plan, and what it did not

D-09 restricts the down-cap cohort to 1d bars only. Two consequences, both load-bearing here:

**Tasks 1 and 2 are unaffected.** The 5m `high_bear` cell that OOM-killed `ic_engine` belongs to
the *existing* corpus, which stays four-timeframe. D-04's structural fix must still be proven on
it. A 1d-only down-cap cohort does not make the 5m memory problem go away; it means the problem
does not get worse. Do not treat D-09 as a reason to skip or soften the verification.

**Task 3's question changed.** The supported count is no longer "how many more symbols can the 5m
cross-sectional cells carry" — the down-cap cohort never enters them, structurally, via Plan 13's
`compute_eligible_1d` split. The question is now "how many 1d-only symbols can the 1d
cross-sectional cells carry," which is a different and far larger number, because a 1d cell has
roughly 250 timestamps per year where a 5m cell has tens of thousands. Measure it; do not assume
a number from this paragraph.
