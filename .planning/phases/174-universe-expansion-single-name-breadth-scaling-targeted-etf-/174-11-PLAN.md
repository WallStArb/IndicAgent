<objective>
Prove D-04's structural fix empirically on the exact cell that killed ic_engine, remove the 96GB
swapfile stopgap and confirm the fix holds without it, then run one incremental scale-up test to
determine the largest feasible instrument count and write that measured number into
`alpha.universe.target_sample_size` (D-01).

Purpose: D-04 explicitly rejects the "bigger box" workaround — the 96GB swapfile applied
2026-09-07 "does not survive further scale-up and is not a substitute for the structural fix."
Leaving it in place after landing the fix would hide whether the fix actually worked, and would
carry the same stopgap into a much larger universe. And D-01 forbids locking a target instrument
count before the supported scale is known: `alpha.universe.target_sample_size` is deliberately
`0`/unset until this plan measures what the infrastructure supports. `docs/foundation/performance-investigation-sop.md`
governs the method — measure before theorizing, never trust a read-only test for a write-path
question, treat chunk count and compression status as first-class suspects.

Output: a verification document carrying real before/after numbers, a removed swapfile, and an
APR key holding a number derived from a measurement.
</objective>
