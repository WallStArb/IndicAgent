<objective>
Expose Plan 02's three eligibility dimensions through `get_active_contracts()` without changing
behavior for any of the 37 existing call sites, and fix the module-level cache so it cannot
serve one dimension's result to a caller asking for another (D-07).

Purpose: the schema split is inert until consumers can address it. `get_active_contracts()` is
the sole read API for the active universe — no consumer queries `instruments` directly — so this
one function is where the split becomes real. The cache is the subtle part: today
`_active_contracts_cache` is a single module-level list with a 60-second TTL and no key, so
adding a `dimension` parameter without also keying the cache would let a `dimension="live"` call
poison every subsequent `dimension="compute"` caller for up to a minute. That is a silent
wrong-answer bug of exactly the class this project treats as worse than a crash.

Output: a `dimension`-parameterized function with a per-dimension cache, plus the regression test
that proves RESEARCH.md's Assumption A5 (default-equivalence) rather than asserting it in a
comment.
</objective>

<interfaces>
Current function (`src/config/settings.py` lines 476-599):
`def get_active_contracts(settings: Settings | None = None) -> list[Instrument]`

It runs three queries on one connection: (1) futures templates from `instruments` where
`contract_details->>'asset_class' = 'futures'`; (2) front-month futures from `contract_metadata`
where `is_front_month = true AND asset_class = 'futures'`; (3) non-futures from `instruments`
where `is_active = true AND contract_details->>'asset_class' != 'futures'`. Only query (3)
gets a dimension clause — futures are out of Phase 174's scope entirely and query (2)'s
`contract_metadata` table has no eligibility columns.

Module-level cache state (lines 368-382): `_active_contracts_cache: list[Instrument] | None`,
`_active_contracts_last_refresh: float`, `_ACTIVE_CONTRACTS_TTL = 60.0`, guarded by
`_settings_lock` (an `RLock`), with `invalidate_active_contracts_cache()` resetting the refresh
timestamp (called by services handling `ContractUpdateEvent`).

Error-handling convention already in the function (lines 584-599): `except Exception as error:`,
a structlog warning `get_active_contracts.db_query_failed`, fall back to the warm cache, and a
`critical` `get_active_contracts.cold_start_db_unavailable` plus empty list on a cold start.

Sibling-function precedent: `get_all_futures_contracts(settings)` at line 602 — "Same as
get_active_contracts() but queries without the is_front_month filter."

Schema delivered by Plan 02's migration 337: `instruments.compute_eligible boolean NOT NULL
DEFAULT true` (true for every existing row) and `instruments.live_tradeable boolean NOT NULL
DEFAULT false` (false for every row).

Change the signature to
`def get_active_contracts(settings: Settings | None = None, dimension: str = "compute") -> list[Instrument]`.

Map the dimension to the non-futures WHERE clause (query 3 only):
- `"backfill"` → `is_active = true`
- `"compute"` → `is_active = true AND compute_eligible = true`
- `"live"` → `is_active = true AND compute_eligible = true AND live_tradeable = true`

An unrecognized dimension raises `ValueError` naming the value and listing the three valid
options — never silently falls back to a default. Build the clause from a literal dict lookup
keyed by the validated dimension; the resulting SQL is assembled from module-owned constants
only, never from caller-supplied text.

`dimension="compute"` is the default because migration 337 set `compute_eligible = true` for
every existing row, making it behaviorally identical to today's unparameterized query. Task 2
proves that equivalence rather than assuming it.

Convert the cache from a single list to a per-dimension mapping:
- `_active_contracts_cache: dict[str, list[Instrument]]` (initialized empty)
- `_active_contracts_last_refresh: dict[str, float]`

Read and write both under `_settings_lock`, preserving the existing discipline exactly: check
the cache under the lock, release it before the DB query, re-acquire to write. Do not hold the
lock across the DB call.

`invalidate_active_contracts_cache()` keeps its current no-argument signature (services calling
it on `ContractUpdateEvent` must not break) and now invalidates every dimension.

The error path keeps its current shape but becomes dimension-aware: fall back to the warm cache
*for the requested dimension only*. If that dimension has no warm entry, log the existing
`get_active_contracts.cold_start_db_unavailable` critical (now carrying a `dimension` field) and
return `[]` — never substitute another dimension's cached list, which would hand a caller a
universe it did not ask for.

Add `dimension` as a structlog field on both existing log events.

Update the docstring to document all three dimensions, state that `"compute"` is the default and
why it is behavior-preserving, and state that `"live"` is expected to return an empty list until
a subscription whitelist is deliberately chosen (IBKR's 80-simultaneous-subscription cap binds
that dimension and nothing else).

Do not change `get_all_futures_contracts()`. Do not touch the futures or `contract_metadata`
queries. Keep `except Exception as error:`.
