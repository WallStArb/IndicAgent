## Phase Boundary

8 targeted architectural corrections to Phase 091 (Instrument Registry). Phase 091 shipped correct behavior but with 4 architectural violations (dead state, wrong dependency direction, manual operations, no observability) plus 2 correctness bugs (deprecated asyncio API, no startup guard). This phase fixes all 8 issues without changing external behavior or public API surface.

No new tables. No schema changes. No API changes. Pure internal hardening.

<decisions>
## Implementation Decisions

### Fix 1: Callback Injection (correct dependency direction)
- `CacheManager.__init__` gains `on_instruments_changed: Callable[[], None] | None = None` stored as `self._on_instruments_changed = on_instruments_changed or (lambda: None)`
- `_reload_instruments_cache()` replaces the lazy import block with `self._on_instruments_changed()`
- In `intelligence_pipeline_agent._setup()`, wire at construction: `self._cache_mgr = CacheManager(..., on_instruments_changed=invalidate_active_contracts_cache)`
- The lazy import, its `noqa: PLC0415` comment, and the `# Lazy import to avoid circular import` comment are ALL deleted
- CacheManager has zero imports from `src.config.settings` after this fix

### Fix 2: Remove Dead State
- `self._instruments_cache: list = []` (line ~164 in cache_manager.py) is deleted entirely
- No code reads this attribute — it is dead state, not commented out
- Future consumers that need the post-reload list call `get_active_contracts()` after the callback fires

### Fix 3: Startup Fail-Fast
- After `self._contracts = get_active_contracts(self.settings)` in intelligence_pipeline_agent.py line ~114:
- Add guard: `if not self._contracts: raise RuntimeError("intelligence_pipeline_agent: no active instruments at startup. DB unreachable or instruments table empty. Check DB connectivity and ensure production/scripts/migrate_instruments.py has been run.")`
- Zero instruments at startup = broken deployment, not tolerable degraded state

### Fix 4: One psycopg2 Connection Per Cache Miss
- `get_active_contracts()` in settings.py currently opens 3 separate `psycopg2.connect()` calls sequentially
- Rewrite to one `with psycopg2.connect(s.database_url) as conn:` block with 3 cursor operations inside
- The 3 queries (futures templates, front-month contracts, non-futures) remain unchanged in content
- Same semantics, one-third the connection overhead

### Fix 5: asyncio.get_running_loop()
- In cache_manager.py `_on_instrument_notify()`: `asyncio.get_event_loop().call_soon_threadsafe(...)` → `asyncio.get_running_loop().call_soon_threadsafe(...)`
- Callback fires inside asyncpg's event loop dispatch; running loop always exists here
- Removes Python 3.10+ DeprecationWarning

### Fix 6: Listener Health Metric
- Add OTel up-down gauge in `CacheManager.__init__`: `from src.observability.metrics import gauge; self._listener_connected = gauge("instruments_listener_connected", "1 when LISTEN instruments connection is active, 0 when reconnecting")` (Note: metrics.py exports `gauge`, not `up_down_counter` — gauge wraps create_up_down_counter internally)
- In `_run_instruments_listener()`: after `await conn.execute("LISTEN instruments")` call `self._listener_connected.add(1)`; in exception handler before `asyncio.sleep(5)` call `self._listener_connected.add(-1)`
- Uses existing `up_down_counter` from `src/observability/metrics.py` (OTel SDK, NOT prometheus_client)

### Fix 7: Automated Trigger Installation
- Add `async def ensure_instruments_trigger(self) -> None` to `DatabaseManager` in `src/core/database_manager.py`
- Method body: executes `CREATE OR REPLACE FUNCTION notify_instrument_change()` + `CREATE OR REPLACE TRIGGER trg_instruments_notify` in one `await self.execute_command(sql)` call
- `CREATE OR REPLACE` makes it idempotent — safe to call every startup
- Call from `intelligence_pipeline_agent._setup()` before starting the listener: `await self._db_manager.ensure_instruments_trigger()`
- `production/scripts/add_instruments_trigger.sql` stays for documentation/emergency manual use — no longer the operational mechanism

### Fix 8: Automated Integration Test
- New file: `tests/integration/test_instrument_registry.py`
- `pytestmark = pytest.mark.integration` (matches existing integration test pattern)
- Three tests: `test_get_active_contracts_returns_nonzero()`, `test_all_required_symbols_present()` (checks SPY, USDJPY, EURUSD), `test_trigger_installed()` (queries information_schema.triggers for trg_instruments_notify)
- Runs via `pytest tests/integration/ -m integration` (already wired in pytest.ini)
- Also update `tests/unit/pipeline_tests/test_cache_manager.py` to pass the new `on_instruments_changed` param in any `CacheManager()` constructor calls

### What Does NOT Change
- `invalidate_active_contracts_cache()` stays in settings.py — public API unchanged
- 60s TTL cache stays — safety net for the sync call path
- `get_active_contracts()` stays synchronous — 20+ call sites
- LISTEN reconnect loop logic is correct as-is
- `production/scripts/add_instruments_trigger.sql` stays for documentation

### Exact code for Fix 7 trigger SQL
```sql
CREATE OR REPLACE FUNCTION notify_instrument_change()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    PERFORM pg_notify('instruments', COALESCE(NEW.symbol, OLD.symbol));
    RETURN COALESCE(NEW, OLD);
END;
$$;
CREATE OR REPLACE TRIGGER trg_instruments_notify
AFTER INSERT OR UPDATE OR DELETE ON instruments
FOR EACH ROW EXECUTE FUNCTION notify_instrument_change();
```
