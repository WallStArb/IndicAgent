# Phase 39.1 Plan 03: Pre-commit Hooks + Documentation Summary

**One-liner:** Shell-based pre-commit hooks with 4 blocking checks (plugin naming, file naming, I7 regime_type, dead imports) + intelligence-workflow-audit.md consolidated to v2.0 as single source of truth.

## What Was Built

### Task 1: Pre-commit Hook Infrastructure

Created `.git/hooks/pre-commit` — a shell-based hook with 4 blocking checks:

**Check 1: Plugin class naming**
- Scope: `src/intelligence/**/*.py` staged files
- Rule: All uppercase-starting class names must end in `Plugin` suffix
- Exclusions: Test, Data, Protocol, Enum, Error, Exception, Config, Result, State, Score, Frame, Entry, Event, Spec, Type, Info, Registry, Manager, Builder, Handler, Tracker, Scorer, Aggregat
- Remediation message: "Rename class to end with 'Plugin' (e.g., 'MACDPlugin')"

**Check 2: Plugin file naming**
- Scope: `src/intelligence/**/*.py` staged files
- Rule: Filenames must match `^[a-z][a-z0-9_]*\.py$`
- Exclusions: `__init__.py`, `conftest.py`
- Remediation message: "Rename file to snake_case.py (e.g., 'bollinger_bands.py')"

**Check 3: I7 regime_type validation**
- Scope: `src/intelligence/trading/*.py` staged plugin files only
- Rule: Any file with a `*Plugin` class must contain `regime_type` declaration
- Exclusions: Infrastructure files (signal_ledger, lifecycle_tracker, trade_framer, signal_aggregator, cis_scorer, weight_updater, confidence_calibrator)
- Remediation message: "Add 'regime_type: ClassVar[str] = \"trend\" | \"mean_reversion\" | \"any\"'"

**Check 4: Dead imports**
- Scope: All Python files in commit
- Tool: `.venv/bin/ruff check --select F401` (falls back to system ruff)
- Remediation message: "Remove unused imports or add '# noqa: F401' if intentional"

**Implementation details:**
- `set -euo pipefail` — strict bash mode
- `exec > >(tee -a "$LOG_FILE") 2>&1` — all output logged to `.git/hooks/pre-commit.log` with timestamps
- Each check returns 0 (pass) or 1 (fail); FAILURES counter accumulates; exit 1 blocks commit on any failure
- ruff F401 output filtered via `grep -E '\.py:[0-9]+'` to exclude summary/success lines

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed grep -c comparison integer error in Check 3**
- **Found during:** Task 2 testing
- **Issue:** `HAS_PLUGIN_CLASS=$(grep -c '^class.*Plugin' file || echo "0")` — when grep finds no matches it exits 1, causing `|| echo "0"` to add a second `0`, resulting in `"0\n0"` which fails `[ "0\n0" -eq 0 ]` integer comparison
- **Fix:** Replaced with `if ! grep -q '^class.*Plugin' "$file" 2>/dev/null; then continue; fi`
- **Files modified:** `.git/hooks/pre-commit`

**2. [Rule 1 - Bug] Fixed ruff "All checks passed!" treated as violation**
- **Found during:** Task 2 testing
- **Issue:** `VIOLATIONS=$(ruff check ...)` — ruff prints "All checks passed!" to stdout on success, which was being captured and treated as violations
- **Fix:** Filter output via `grep -v "^All checks passed"` to only capture actual violation lines; actual violations contain `.py:[0-9]+` patterns
- **Files modified:** `.git/hooks/pre-commit`
