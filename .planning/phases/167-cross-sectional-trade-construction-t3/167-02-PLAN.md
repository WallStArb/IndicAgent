<design_decisions>
1. **Flat equal-weight legs, NO vol-scaling.** RESEARCH.md Pitfall 1: the design doc's Minimal
   Design step 3 says "vol-scaled per symbol," but the T3 script that actually earned this phase
   uses `long_leg[return_col].mean() - short_leg[return_col].mean()` - flat, unscaled. Build
   exactly what was proven. Vol-scaling is a separate, testable enhancement with its own
   before/after comparison, not a silent upgrade. A task adding vol-scaling in this phase would
   be a scope violation.

2. **Deterministic tie-break by symbol.** The T3 script ranks with pandas `sort_values(feature)`,
   whose tie order depends on input row order - acceptable for a one-off script, unacceptable for
   a table whose rows must be reproducible across runs. `decile_legs` sorts by
   `(feature_value, symbol)` ascending. On a continuous float feature exact ties are effectively
   measure-zero, so this does not change what T3 proved; it makes the persisted output
   reproducible. Document this reasoning in the function docstring.

3. **`None`, not `0.0`, for an uncomputable turnover.** Pitfall 4's stated warning sign is a
   turnover of exactly 0 or 1.0 at every incremental run boundary. Returning `None` when no
   predecessor legs exist makes the broken case structurally detectable rather than
   indistinguishable from a legitimate zero-turnover bar.

4. **`len(cur_long)` is the turnover denominator**, matching the T3 script's `_cost_hurdle_check`
   exactly (`n_leg = len(cur_long)`), NOT `len(prev_long)`. The universe size can change between
   bars, and the script's choice is the one whose result was measured.
</design_decisions>
