Table `construction_spreads`, primary key `(construction_name, tf, bar_ts)`, hypertable on
`bar_ts`. Columns and their meaning:

- `construction_name text NOT NULL` - logical construction identity. Phase 167 writes exactly
  one value: `ctf_momentum_decile_ls`.
- `tf text NOT NULL` - timeframe. Phase 167 writes exactly one value: `15m` (D-04).
- `bar_ts timestamptz NOT NULL` - the cross-section's bar timestamp; hypertable partition column.
- `n_universe int NOT NULL` - count of symbols in this bar's ranked cross-section.
- `n_leg int NOT NULL` - symbols per leg, `max(1, round(n_universe * decile_fraction))`.
- `long_leg_symbols text[] NOT NULL` - top-decile symbols (highest `ctf_momentum`).
- `short_leg_symbols text[] NOT NULL` - bottom-decile symbols (lowest `ctf_momentum`).
- `gross_spread_fast double precision` - `mean(long return_fast) - mean(short return_fast)`.
- `gross_spread_slow double precision` - `mean(long return_slow) - mean(short return_slow)`.
- `one_way_turnover double precision` - NULLABLE. `mean(long_changed_frac, short_changed_frac)`
  vs. the immediately prior bar's legs. NULL only for the single genuinely-first bar of the
  whole corpus, where no predecessor exists (Pitfall 4: never fake this as 0.0).
- `net_spread_fast_by_cost_bps jsonb` - `{"1": x, "3": x, "5": x, "10": x}`, gross_spread_fast
  minus `(bps/10000) * one_way_turnover`. NULL when `one_way_turnover` is NULL.
- `net_spread_slow_by_cost_bps jsonb` - same for the slow scale.
- `compute_version text NOT NULL` - writer's `compute_version` class attribute.
- `created_at timestamptz NOT NULL DEFAULT now()`.

APR keys this plan seeds (read by plans 02-05):

- `alpha.construction.decile_fraction` (float, `0.10`)
- `alpha.construction.cost_hurdle_bps_round_trip` (json, `[1, 3, 5, 10]`)
- `alpha.construction.null_shuffles` (int, `40`)
- `alpha.construction.attribution_max_static_r2` (float, `0.50`)
- `infra.cross_sectional_spread_tracker.itersize` (int, `5000`)
- `infra.cross_sectional_spread_tracker.chunk_size` (int, `5000`)

<design_decisions>
Two deliberate deviations from RESEARCH.md's migration template, both recorded here so no
downstream executor "fixes" them back:

1. **Two `net_spread_*_by_cost_bps` jsonb columns, not one.** RESEARCH.md's template has a
   single `net_spread_by_cost_bps` column, but the construction measures TWO lookahead scales
   (`return_fast`, `return_slow`) and cost applies to a scale-independent turnover - so net
   spread genuinely differs per scale. One column would require a nested
   `{"fast": {...}, "slow": {...}}` shape that is harder to query and easy to mis-key. Two
   flat columns are explicit.

2. **`one_way_turnover` is NULLABLE and NULL for the corpus's genuinely-first bar.** Pitfall 4
   names "a turnover value of exactly 0 or exactly 1.0 for the first bar processed in every
   incremental run" as the warning sign of a broken incremental implementation. Persisting NULL
   for the one bar that truly has no predecessor makes the broken case detectable: a NULL count
   greater than 1 in this table is a bug, not a data property. The T3 falsification script seeds
   `one_way_turnover = 0.0` for its first bar; that is correct for a single-shot script and
   wrong for an incremental service.

Two APR-key decisions:

3. **`alpha.construction.null_shuffles` IS an APR key** (RESEARCH.md left this open). The T3
   script's `_N_NULL_SHUFFLES = 40` was a one-off constant, but Plan 04 re-runs the
   shuffled-ranking null on EVERY `--evaluate-gate` invocation, and its runtime cost is linear
   in this value - an operator will genuinely want to tune it (APR mandate category 3:
   infrastructure performance constants). `_DEFAULT_BOOTSTRAP_RANDOM_STATE` stays a plain
   reused Python constant per RESEARCH.md.

4. **`_TF` and `_FEATURE` are NOT APR keys.** D-02 and D-04 lock these to `ctf_momentum` / `15m`
   for this phase. Exposing them as tunable config would invite running unvalidated
   feature/timeframe combinations, the exact trap D-01 through D-04 exist to prevent. They stay
   module-level Python constants in Plan 02 with the D-number cited inline.

5. **The json-typed APR key is validated at BOTH ends, not just seeded.** Addresses Codex review
   concern (MEDIUM): "the plan should say... whether JSON-typed APR values are validated
   consistently in the migration and config loader."
   `alpha.construction.cost_hurdle_bps_round_trip` is the only `value_type='json'` key this
   phase introduces, and `_batch_utils.cfg`'s `type(default)(val)` cast provably breaks on a
   list default (`get_dict_config`'s own docstring documents the same failure in dict form),
   which is why Plan 03 reads it through `json.loads` rather than `cfg`. Task 3 asserts the
   seeded value round-trips through `json.loads` to the exact Python list of ints the cost sweep
   consumes, and that its `value_type` is literally `json`. A key mistakenly seeded as `str`
   would be consumed as the text `"[1, 3, 5, 10]"` and the sweep would iterate its characters -
   a wrong answer that raises nothing.
</design_decisions>
