<objective>
Thread signal_id from build_ledger_entries() through the signals:aggregated stream into llm_calls
so outcome back-fill WHERE signal_id = $1::uuid can match rows.

Purpose: The winning LedgerEntry's UUID is assigned inside build_ledger_entries() but never injected
into the stream message. ai_narrative_service reads the stream, finds no signal_id, and writes "" to
llm_calls.signal_id. The _UPDATE_OUTCOME_SQL WHERE signal_id = $1::uuid then matches 0 rows — every
outcome back-fill is a no-op. The entire feedback loop (score recompute → adaptive routing) depends
on this linkage. Additionally: per CONTEXT.md locked decision, stream publish must move BEFORE
insert_signals (hot tier first / cold tier second — consistent with platform architecture).

Output: 3 surgical changes across 2 service files + new unit tests. Zero schema changes.
Zero new services.
</objective>
