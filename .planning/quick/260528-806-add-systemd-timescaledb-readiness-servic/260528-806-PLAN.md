Create two new unit files in `production/systemd/`, mirroring the existing Redpanda ready pattern.

**File 1: `production/systemd/indicagent-timescaledb-ready.service`**

```ini
[Unit]
Description=TimescaleDB readiness gate — blocks dependents until Postgres accepts connections
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/bin/bash -c '\
  for i in $(seq 1 60); do \
    PGPASSWORD=postgres pg_isready -h localhost -p 5432 -U postgres -d indicagent >/dev/null 2>&1 && \
    echo "TimescaleDB ready" && exit 0; \
    echo "TimescaleDB not ready yet, retrying in 5s..."; \
    sleep 5; \
  done; \
  echo "TimescaleDB did not become ready within 300s"; \
  exit 1'
TimeoutStartSec=310

[Install]
WantedBy=multi-user.target
```

Notes:
- Matches Redpanda ready service: 60 attempts x 5s = 300s, TimeoutStartSec=310.
- Uses `pg_isready` (standard Postgres tool, available on host since psql client is installed).
- Requires `docker.service` because TimescaleDB runs in a container.

**File 2: `production/systemd/indicagent-infrastructure.target`**

```ini
[Unit]
Description=IndicAgent infrastructure ready — TimescaleDB + Redpanda accepting connections
Requires=indicagent-timescaledb-ready.service indicagent-redpanda-ready.service
After=indicagent-timescaledb-ready.service indicagent-redpanda-ready.service

[Install]
WantedBy=multi-user.target
```

Do not install or enable yet — Task 3 handles install + reload + verify.

<task type="auto">
  <name>Task 2: Wire all 30 app service files to indicagent-infrastructure.target</name>
  <files>production/systemd/indicagent-*.service (excluding redpanda-ready, timescaledb-ready, redpanda-watchdog)</files>
  <action>
Update every indicagent app service unit in `production/systemd/` that currently has `After=network-online.target` to also depend on `indicagent-infrastructure.target`.

Run this script (touches `production/systemd/` only; Task 3 will sync to `/etc/systemd/system/`):

```bash
cd /home/bg/dev/indicagent
EXCLUDE='indicagent-(redpanda-ready|timescaledb-ready|redpanda-watchdog)\.service'
TARGETS=$(grep -l "^After=network-online.target" production/systemd/indicagent-*.service \
  | grep -Ev "$EXCLUDE")
echo "Updating $(echo "$TARGETS" | wc -l) files"
for f in $TARGETS; do
  # Skip if already wired
  if grep -q "indicagent-infrastructure.target" "$f"; then
    echo "SKIP (already wired): $f"
    continue
  fi
  # Replace After=network-online.target with the extended form, and add Requires= after it.
  sed -i \
    -e 's|^After=network-online.target.*$|After=network-online.target indicagent-infrastructure.target\nRequires=indicagent-infrastructure.target|' \
    "$f"
  echo "UPDATED: $f"
done
```

Notes:
- Exclude the two ready services and the redpanda-watchdog (it monitors the broker itself; must not depend on its own target).
- Idempotent: `grep -q` check skips files already updated.
- If a file has `After=network-online.target docker.service` style trailing tokens, the sed replaces the whole line. That's intentional — docker.service is implied via `indicagent-infrastructure.target`'s transitive deps. If audit shows any service genuinely needs docker.service directly (e.g., dashboard), re-add manually.

After running, verify:

```bash
grep -c "indicagent-infrastructure.target" production/systemd/indicagent-*.service | grep -v ":0$"
```

Should show every modified service has 2 occurrences (After + Requires).

If any expected file is missing the wiring, edit it manually using the same pattern.

  <verify>
`grep -L "indicagent-infrastructure.target" production/systemd/indicagent-*.service | grep -Ev "(redpanda-ready|timescaledb-ready|redpanda-watchdog)"` returns empty (no app service is missing the wiring).
`systemd-analyze verify production/systemd/indicagent-bar-writer.service` (spot check) returns no errors.
